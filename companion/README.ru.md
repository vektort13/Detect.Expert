# Detect.Expert Proxy Companion

Необязательный помощник для Windows к вкладке Proxy в расширении.

</div>

Браузеры сами не умеют кое-что из прокси: SOCKS5 с паролем, HTTP/HTTPS-прокси с логином, VLESS, OpenVPN. Для этого и нужен помощник. Это небольшая программа, с которой расширение разговаривает через native messaging браузера. Она запускается только по запросу расширения, работает от вашего пользователя и не лезет в остальную систему.

Для обычных профилей SOCKS5, HTTP и HTTPS без логина он не нужен: их расширение настраивает через родной прокси-API браузера.

## Что нужно

- Windows 10 или 11, x64.
- Detect.Expert 2.0.0 в Chrome 153+ или Firefox 128+.
- Windows PowerShell (он уже есть в системе). Права администратора не нужны.

Другие системы: прямой SOCKS5 без пароля работает через браузер везде. Родные VLESS и OpenVPN там потребуют отдельно собранного и зарегистрированного помощника со своим хранилищем ключей. Этот пакет только для Windows.

## Что в пакете

| Путь | Что это |
|---|---|
| `detect-expert-proxy.exe` | Хост, с которым говорит браузер (Go). Поднимает локальное реле и запускает движки. |
| `engines/xray.exe` | Xray-core v26.3.27 для VLESS (MPL-2.0). |
| `engines/openvpn2socks.exe` | OpenVPN в пользовательском пространстве, собран из go-openvpn с моими патчами (AGPL-3.0-or-later). Без драйвера TUN и без изменения маршрутов системы. |
| `engines/source/` | Исходники движков, патчи, тексты лицензий и инструкция сборки. |
| `source/companion/` | Исходники самого хоста. |
| `Install.ps1`, `Uninstall.ps1` | Установка и удаление для текущего пользователя. |
| `companion.json` | Список всех файлов пакета с SHA-256. По нему сверяется `Install.ps1`. |
| `LICENSE` | Лицензия проекта (MIT). У движков свои, см. [Лицензии](#лицензии). |

## Точно ли это от меня

Три исполняемых файла подписаны (Authenticode) издателем **Vektor T13 Technologies B.V.** (Роттердам, Нидерланды). Проверьте до установки:

```powershell
Get-FileHash .\Detect.Expert-Proxy-Companion-windows-x64.zip -Algorithm SHA256   # сверьте с описанием релиза
Get-ChildItem -Recurse -Filter *.exe | ForEach-Object { Get-AuthenticodeSignature $_.FullName } |
  Format-Table Path, Status, @{n='Signer'; e={$_.SignerCertificate.Subject}} -AutoSize -Wrap
```

В колонке `Status` должно быть `Valid`, а Subject подписи должен начинаться с `CN=Vektor T13 Technologies B.V.`. Если это не так, ничего не запускайте и напишите мне.

Ещё `Install.ps1` перед копированием сверяет каждый файл с `companion.json`. Это ловит битую загрузку, но не доказывает, кто собрал пакет: `companion.json` лежит внутри него же. Доказывает подпись.

## Установка

1. Скачайте `Detect.Expert-Proxy-Companion-windows-x64.zip` со страницы [Releases](https://github.com/vektort13/Detect.Expert/releases).
2. Щёлкните правой кнопкой, **Извлечь всё**, и положите куда-нибудь обычное, например в «Загрузки». Не в ту папку, которую будет использовать установщик в `%LOCALAPPDATA%\Detect.Expert\ProxyCompanion`: скрипт остановится с сообщением «Extract the package outside the installation directory first».
3. Узнайте ID расширения. Как, написано ниже.
4. Откройте PowerShell в распакованной папке (наберите `powershell` в адресной строке Проводника) и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\Install.ps1 -ChromeExtensionId obbkkjmpgaajcggbhajpdeeadkkchbeo
```

Этот ID относится к версии из Chrome Web Store (карточка пока на проверке). Если вы загрузили расширение распакованным, подставьте свой ID.

Вы увидите `Installed Detect Expert Proxy Companion: <папка>` и `Browser proxy settings, system routes and services were not changed.` Дальше откройте в расширении вкладку **Proxy**, блок **Companion** и нажмите **Check companion**. Когда вы сохраните первый защищённый профиль, расширение попросит необязательное разрешение `nativeMessaging`. Соглашайтесь, через него оно достучится до помощника.

**Только Firefox:**

```powershell
powershell -ExecutionPolicy Bypass -File .\Install.ps1 -FirefoxExtensionId 'detect.expert@detect.expert'
```

Без `-ChromeExtensionId` регистрируется только Firefox. С ним за один раз регистрируются Chrome, Chromium, Microsoft Edge и Firefox.

### Какой ID брать

- **Версия из Chrome Web Store:** `obbkkjmpgaajcggbhajpdeeadkkchbeo`.
- **Распакованная или локальная сборка:** ID другой, потому что Chrome считает его от папки, из которой вы загрузили расширение. Его видно на вкладке Proxy в расширении (Companion, «Setup steps») и на `chrome://extensions` при включённом режиме разработчика, под названием расширения. Это 32 буквы от `a` до `p`.

Грабли: ID должен совпасть до символа, потому что хост отвечает только тому расширению, для которого его зарегистрировали. Профили хранятся отдельно для каждого ID, так что у распакованной сборки и у сборки из магазина свои сохранённые профили. Если поставить помощник ещё раз с другим ID, появится вторая папка, а регистрация будет указывать на самую новую.

## Зачем в команде `-ExecutionPolicy Bypass`

`Install.ps1` и `Uninstall.ps1` это обычные текстовые скрипты, и они **не** подписаны Authenticode. На обычном Windows 10/11 политика PowerShell по умолчанию вообще не разрешает запускать скрипты, а у файлов из интернета есть ещё и пометка «загружено из интернета». Поэтому команда выше запускает PowerShell с `-ExecutionPolicy Bypass`. Это действует только на этот один процесс и не меняет политику ни для компьютера, ни для пользователя.

Скрипты короткие. Прочитайте `Install.ps1` до запуска, он для этого и написан читаемым. Если Bypass не хочется, прочитайте скрипт, снимите блокировку с распакованных файлов (`Get-ChildItem -Recurse | Unblock-File`) и запустите под той политикой, которая вас устраивает.

## Что делает установщик

- Сверяет каждый файл с `companion.json`.
- Копирует пакет в `%LOCALAPPDATA%\Detect.Expert\ProxyCompanion\<версия>-<пакет>-<id>\`.
- Пишет туда `allowed-callers.json`: ID расширений, которым разрешено говорить с хостом. Для кого-то другого хост сразу завершается.
- Кладёт рядом манифесты native messaging и регистрирует их в `HKCU\Software\...\NativeMessagingHosts\com.detect_expert.proxy`. С ID Chrome это ключи Google\Chrome, Chromium и Microsoft\Edge, для Firefox это Mozilla.

Он не просит прав администратора, не ставит службу, не настраивает автозапуск, не добавляет драйвер, не меняет системные маршруты и не меняет настройки прокси в браузере. Настройки прокси в браузере меняет расширение, и только когда вы нажимаете Connect (или включили «Connect when the browser starts»).

## Как это работает

Браузер запускает `detect-expert-proxy.exe` через native messaging. Для защищённого профиля хост поднимает локальное реле SOCKS5 на `127.0.0.1` со случайным портом, и браузер направляется на него. Дальше:

- **SOCKS5 с паролем** и **HTTP/HTTPS с логином:** реле само входит на ваш сервер. HTTP- и HTTPS-прокси получают `CONNECT` с Basic-авторизацией. Работает только Basic, а при обычном `http` логин идёт по сети открытым текстом, так что по возможности берите `https` или SOCKS5. Многие HTTP-прокси разрешают `CONNECT` только на порт 443: если порт 80 отклонён, увидите `proxy-denied`.
- **VLESS:** туннель держит закреплённая версия Xray. Профиль превращается в конфиг Xray из белого списка полей. Произвольный JSON для Xray и небезопасный TLS не принимаются.
- **OpenVPN:** клиент в пользовательском пространстве со своим сетевым стеком. DNS идёт только через туннель.

Движки запускаются дочерними процессами внутри Windows Job Object, поэтому они завершаются вместе с хостом, даже после сбоя. Конфиг уходит в движок через stdin, учётные данные через приватное окружение, и файл конфига в открытом виде не создаётся. Во время работы движки ничего не скачивают и не обновляют.

Kill Switch остаётся включённым: если помощник или туннель отказали, запросы, идущие через прокси, блокируются, а не уходят напрямую.

Сохранённые профили лежат в одном файле на каждый ID расширения в `%APPDATA%\Detect.Expert\Proxy\`, зашифрованном Windows DPAPI для вашего пользователя Windows. В хранилище самого расширения остаются только имена, адреса, порты и маршрутизация, никогда не логины и пароли.

Помощник не звонит домой. Он соединяется только с серверами ваших профилей, когда вы подключаетесь или запускаете проверку.

## Обновление

Скачайте новый пакет и снова запустите `Install.ps1` с тем же ID. Профили останутся на месте. Новый пакет ставится в новую папку, регистрация переезжает в неё, а старую папку можно удалить.

## Удаление

Сначала выключите **Proxy** в расширении. Потом запустите деинсталлятор из установленной копии:

```powershell
powershell -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Detect.Expert\ProxyCompanion\<ваша папка>\Uninstall.ps1"
```

`<ваша папка>` это имя папки, которое напечатал установщик. (Список можно посмотреть так: `Get-ChildItem "$env:LOCALAPPDATA\Detect.Expert\ProxyCompanion"`.)

Что он удаляет, предупреждаю заранее: **только записи реестра** этой установки. Файлы программы и ваши зашифрованные профили остаются. Так сделано нарочно, чтобы переустановка не стирала ваши серверы. Если нужно убрать всё, удалите вручную:

```powershell
# файлы программы (все установленные версии)
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Detect.Expert\ProxyCompanion"

# зашифрованные профили: логины, пароли, ссылки VLESS, конфиги OpenVPN. Это нельзя отменить.
Remove-Item -Recurse -Force "$env:APPDATA\Detect.Expert\Proxy"
```

Если отключить помощника, пока Proxy в расширении ещё включён, трафик через эти профили будет блокироваться, пока вы не выключите Proxy. Это Kill Switch делает свою работу.

## Ограничения

- Только Windows x64 и только трафик самого браузера. Это не системный VPN.
- Мои автотесты идут на loopback-серверах. Каждого коммерческого провайдера OpenVPN или VLESS я не пробовал. Если ваш профиль не подключается, заведите issue и напишите, какого он типа, без учётных данных.
- Проверка соединения ручная и одноразовая: один запрос через выбранный прокси на адрес, который можно поменять.

## Лицензии

Проект, включая хост, распространяется по MIT, см. `LICENSE` в пакете. Движки это отдельные программы:

- **Xray-core**: MPL-2.0.
- **go-openvpn** (с патчами, как `openvpn2socks.exe`): AGPL-3.0-or-later.

Их полные исходники, мои патчи и тексты лицензий лежат в `engines/source/`, а `BUILD-SOURCE.md` объясняет, как их пересобрать. В `engines/pins.json` указаны точные версии и контрольные суммы.

## Сборка самостоятельно

Нужны Windows x64, Node.js 24 или 25 и репозиторий.

```powershell
node scripts/build-proxy-engines.mjs     # скачивает закреплённые Go, Xray и исходники go-openvpn, сверяет SHA-256, собирает движки
node scripts/build-proxy-companion.mjs   # vet и тесты, сборка detect-expert-proxy.exe, запись companion.json, упаковка в ZIP
```

Результат: `release/proxy-native/windows-amd64/` и `release/Detect.Expert-Proxy-Companion-windows-x64.zip`. Загрузки происходят только когда вы запускаете скрипт движков. Локальная сборка не подписана, а релизные файлы подписываются отдельно.
