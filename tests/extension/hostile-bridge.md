# Регрессии враждебного канала

Трассировка: F008, F160, F161, F162, F168; REQ-004/006/009/011; ADR-003/004.

`hostile-bridge.html` ждёт вызова `__runHostile` из стенда. `hostile-boot.js`
перехватывает настоящий `sensor-hello`; boot ID используется только для маршрутизации,
не как подтверждение подлинности. Каждый сценарий запускается в отдельном контексте.
До атаки проверяется настоящий readback без флагов ошибок; после — ещё три readback
с неизменными пикселями. Для несовместимого handshake атака выполняется до первого
батча через синхронный `dispatchEvent`.

Flood направляет поддельные ID и привилегированные запросы на существующий отчёт
второй вкладки. Сравнивается вся проекция вместе с revision. Проверка экспорта
опирается на наблюдение вызовов `chrome.runtime.sendMessage` в ISOLATED: настоящие
`sensor-events` проходят через наблюдатель, `ui-*` не проходят. Авторизованные
preview и clear служат положительными контролями. Preview не сохраняется в storage;
clear удаляет отчёт целиком.

Array/Set изменяются временно, исходные дескрипторы восстанавливаются таймером.
Для Set отдельно отправляется `bridge-pause`: обычные readback не вызывают
`Set.prototype.add`, а добавление нового флага паузы вызывает его.

Проверка 2026-09-12:
`pnpm.cmd test:extension hostile-bridge.spec.ts late-start.spec.ts` — exit 1,
**7 passed, 4 failed**. Test-профиль собран этой же командой.

| Сценарий | Фактический результат |
| --- | --- |
| Flood 100 000, второй отчёт, privileged isolation, popup `throttled` | Пройден |
| Настоящий boot: MAX_COUNT и отдельный DET-040 | Пройден; принимается продолжение счёта или явный `channel-gap`; принятый DET-040 обязан быть `page-controlled` |
| Вытеснение boot, поддельные status/stop/pause | Пройдены |
| Scope off и localhost без host grant | Пройден: `no-access`, нет техник |
| Несовместимый handshake до первого батча | Ошибка: пустой `partial`, нет явного gap |
| Array.push во время наблюдения | Ошибка: счётчик остаётся 1, состояние `active`, нет gap |
| Set.add при добавлении флага паузы | Ошибка: счётчик остаётся 1, состояние `active`, нет gap |
| Статически разрешённый документ без инъекции | Ошибка: `partial` до инъекции; последующие проверки поздней инъекции выполняются |

Оставшиеся ошибки требуют изменений вне `tests/` и `fixtures/`:

- `packages/sensors/src/runtime.ts`: защитить операции с Array/Set и доставку
  диагностик от исключений наблюдателя; сообщать остановку до завершения handshake.
- `packages/collector/src/collector.ts`, `packages/collector/src/deliver.ts`:
  обеспечить доставку диагностик при отсутствии наблюдений. Ограничение
  `PageBatch.observations >= 1` нельзя обходить выдуманным событием; изменение
  контракта требует review владельца `packages/contracts` и ADR-004.
- `packages/background/src/documents.ts`, `packages/background/src/runtime.ts`:
  различать наличие разрешения и фактическую инъекцию при выводе coverage.
  Отсутствие сенсора не должно выглядеть как состоявшееся частичное наблюдение.

Это регрессии, оставленные падающими; `skip`/`fixme` не используются. Прогон не
подтверждает защиту от всех возможных изменений прототипов или аутентификацию boot ID.
