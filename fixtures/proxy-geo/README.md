# fixtures/proxy-geo

Ответы четырёх провайдеров геолокации для проверки разбора `geoParseResponse` (`apps/production-extension/proxy-geo-providers.js`): ADR-109 и
`docs/coverage/proxy-geolocation.md`. Читаются только тестом `scripts/test/proxy-geo-providers.test.mjs`; в расширение и в сборку не входят.
В файлах нет ключей, паролей и адресов пользователей: адреса — публичные адреса из документации и общеизвестные резолверы.

## Формат файла

Один файл — один принятый ответ провайдера.

| Ключ | Смысл |
| --- | --- |
| `provider` | `maxmind`, `ipgeolocation`, `ipdata` или `ipapi` |
| `ip` | канонический публичный адрес, который тест передаёт разбору как запрошенный |
| `service` | только MaxMind: `geolite-city`, `geoip-city` или `geoip-insights` (служба запроса) |
| `security` | только ipgeolocation.io: в запросе был `include=security` |
| `note` | необязательное пояснение |
| `status`, `headers` | HTTP-статус и заголовки ответа (имена в нижнем регистре) |
| `body` | тело как JSON-значение (тест превращает его в текст); вместо него — |
| `text` | точный текст тела: живые ответы побайтно, пустые и не-JSON тела, враждебные тела |

Заголовки образцов из документации — предположение, кроме типов содержимого MaxMind (они указаны на его странице); у живых ответов заголовки такие, как сообщены.
Ожидаемый результат в файле не хранится: он записан вручную в тесте (таблицы по имени файла), чтобы реализация не проверяла саму себя.
Сырых невидимых символов в файлах нет: RTL-переопределения и прочие управляющие знаки записаны в `text` как escape-последовательности JSON,
это проверяет тест. Тексты ошибок провайдеров лежат здесь только как входные данные разбора; в записи, состояние и ошибки они не копируются.

## Обозначения происхождения

- **live 2026-11-06, verbatim** — ответ записан на стороне владельца из страницы расширения (заведомо неверный ключ либо адрес 8.8.8.8 / 10.0.0.1), текст тела побайтно как сообщён;
- **verbatim** — данные образца с официальной страницы без изменений (отступы JSON нормализованы, формат файла другой); пример из OpenAPI-файла (YAML), записанный как JSON, тоже verbatim;
- **adapted** — образец с официальной страницы с названной правкой (что именно — в столбце «Происхождение»);
- **synthesized** — собрано по описанию полей и правилам документации; это не записанный ответ, в столбце указано, на что опирается сборка.

## Статус проверки (REQ-015)

| Провайдер | Проверено живьём 2026-11-06 | Только по документации (кандидат) |
| --- | --- | --- |
| MaxMind | HTTP 401 `AUTHORIZATION_INVALID` на `geolite.info` и на `geoip.maxmind.com` | успешные ответы City Plus, Insights, GeoLite City; остальные ошибки |
| ipgeolocation.io | HTTP 401 `{"message": …}` на неверный ключ; тело побайтно совпало с примером `invalidApiKey` из OpenAPI-файла провайдера | успешные ответы; остальные ошибки: тела взяты дословно из OpenAPI-файла `ip-location-api.yaml` (ссылка на него — на странице документации), живьём не проверялись |
| ipdata | HTTP 401 `{"message": …}` на неверный ключ | успешные ответы; остальные ошибки (тексты — из таблицы статусов документации) |
| ip-api.com | бесплатная точка: успех для 8.8.8.8 с заголовками `X-Rl` / `X-Ttl`, `private range` для 10.0.0.1; Pro: HTTP 403 `invalid/expired key` | успех Pro, HTTP 429, остальные сообщения `fail` |

Адрес Pro-запроса `https://pro.ip-api.com/json/{ip}?key=…&fields=…`: **live-verified for the invalid-key path; success path not verified (no key)**.
Живой ответ на неверный ключ показывает, что сервер узнаёт и хост, и параметр `key`; форма успешного ответа Pro взята с бесплатной точки и остаётся кандидатом.

Обозначения «verbatim» у MaxMind, ipgeolocation.io и ipdata означают точные данные образцов из документации; это не ответы, записанные с настоящим ключом.
Страница MaxMind сама оговаривает, что её образцы показывают «illustrative values» и «do not describe a single real lookup»: значения (город, ASN, оценки) вымышлены, важны форма и имена полей.
Образцы ipgeolocation.io отмечены на странице датой 2026-10-29 (поле `current_time`), образцы ipdata частично старые (пример часового пояса — 2019 год): разбор опирается на форму, а не на значения.

## Не хранится в файлах (создаётся в тесте)

Слишком большие для репозитория случаи строит сам тест:

- название города в 1 МиБ — тело больше `GEO_LIMITS.responseBytes`, разбор отвечает `bad-response`, не читая его;
- название города в 60 000 знаков (в пределах лимита) — очищается и обрезается до 80 символов;
- `subdivisions` из 100 000 элементов — больше лимита, `bad-response`; и из 30 000 элементов (в пределах лимита) — читается только элемент 0 (проверяется подменой `JSON.parse` на обёртку-Proxy, считающую обращения);
- вложенность массивов в 30 000 уровней; объект `names` с 5000 ключей; корневые значения не-объекты (`[]`, `null`, строка, число, `true`, пустой текст, пробелы, оборванный JSON);
- заголовки `x-rl` / `x-ttl` с мусором, отрицательными, дробными и огромными числами.

## Что не включено

- Сообщения об ошибках пакетных запросов ipdata («You did not provide a valid JSON Array», «Bulk requests should not contain more than 100 IP addresses»): расширение не отправляет пакетных запросов.
- Ответы MaxMind Country: расширение использует City и Insights.
- Ответы MaxMind, ipgeolocation.io и ipdata, записанные с настоящим ключом: ключей нет; настоящую проверку выполняет пользователь кнопкой «Проверить ключ».
