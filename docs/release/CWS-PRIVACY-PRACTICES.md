## 1. Single purpose (черновик)

**EN (dashboard):** Detect.Expert helps users see and control how their own browser presents itself to websites. It shows which browser APIs a page uses to recognize the browser, lets the user choose what their own browser reports to pages and in request headers, route the browser through a proxy they supply, inspect and move their own cookies and browser data, and run a test tab through addresses they enter. It does not judge website safety, solve CAPTCHAs or send data to the developer.

**RU:** Detect.Expert помогает увидеть и настроить, как собственный браузер пользователя выглядит для сайтов: показывает, какие API страница использует для распознавания браузера, позволяет выбрать значения, которые браузер сообщает страницам и в заголовках запросов, направить браузер через прокси пользователя, просматривать и переносить свои cookies и данные браузера, пройти тестовой вкладкой по введённым адресам. Оценок безопасности сайтов, решения CAPTCHA и отправки данных разработчику нет.

Риск: расширение объединяет несколько заметных функций (наблюдение, Antidetect, Proxy, Cookies, Автосерфер, Browser Debug, Cloudflare, «Защита»). Ревью может счесть часть из них выходящей за единственную цель. Решение владельца: оставить одну формулировку «инструмент проверки и настройки того, как браузер выглядит для сайтов» либо вынести функции в отдельные расширения.

## 5. Ответ про удалённый код (Remote code)

**Answer: No, I am not using remote code.** All executable code and recognition rules are inside the package. The extension fetches no scripts, WebAssembly, rule lists or configuration; its only network request code is a fixed read of two Cloudflare API addresses after the user connects a zone, fixed GET lookups of one IP address at the geolocation provider the user configured (Proxy Manager Geolocation API), and a re-load of a tab's icon image. Antidetect registers user scripts through the userScripts API, but the script text is assembled on the user's device from packaged functions and the user's own selections and is not downloaded. There is no eval, no Function constructor and no interpreter for downloaded data (enforced by `scripts/lint.mjs`). Checks: `scripts/production/lint-inventory.json` allows runtime network references only in `precursor-modes-service.js`, `proxy-geo-client.js` and `site-favicon.js`.

Ограничение формулировки: если ревью отдельно спросит про `userScripts`, ответ — выше; новые разрешения не добавлять по образцу чужих расширений.

## 6. Что отвечать про сетевые соединения расширения

Не «соединений нет», а точный перечень (источник — [data-inventory.md §4b](../data-inventory.md)): по умолчанию без команды пользователя — только повторная загрузка значка вкладки для кэша значков; по команде пользователя — чтение зоны Cloudflare (`api.cloudflare.com`, GET, токен пользователя, около раза в минуту, пока подключено), трафик через прокси/VPN, который настроил пользователь, проверка прокси на редактируемый адрес (по умолчанию `api.ipify.org`), запросы Proxy Manager Geolocation API (после включения и ввода ключа: `GET` публичного внешнего IP прокси и ключа пользователя выбранному провайдеру — MaxMind, ipgeolocation.io, ipdata или ip-api.com; без таймера и без запросов при открытии списка), навигация Автосерфера и нативной сессии по адресам пользователя, ссылки по клику. Аналитики, телеметрии, учётной записи и автоматической выгрузки отчётов нет.

## 7. Сертификации и Limited Use

Три сертификации в Dashboard владелец подтверждает сам, не автоматически и не по данным Git. Ниже — соответствие фактам кода, а не подтверждение.

1. «Не продаю и не передаю данные пользователей третьим лицам вне одобренных сценариев» — данные не продаются и не отправляются разработчику. Передачи по команде пользователя в его же сервисы: токен — в Cloudflare API, внешний IP прокси и ключ — выбранному пользователем провайдеру геолокации, трафик — на прокси/VPN-сервер пользователя, файлы — куда пользователь их сохранит. Владелец решает, считать ли это «одобренными сценариями» (обеспечение пользовательской функции).
2. «Не использую и не передаю данные для целей, не связанных с единственной целью» — не используются ни для рекламы, ни для профилирования, ни для обучения моделей.
3. «Не использую и не передаю данные для оценки кредитоспособности или кредитования» — не используются.

Limited Use (EN, для поля или политики): *Data accessed by Detect.Expert is used only to provide the disclosed local inspection, recording and the optional tools the user starts or enables, in compliance with the Chrome Web Store User Data Policy, including Limited Use. It is not sold, used for advertising, unrelated profiling, credit decisions or model training, or automatically transferred to the developer or other parties.*

## 9. Заметки для проверяющего (Distribution → Test instructions, черновик)

No account or key is needed. Install the package, open the popup and the Options page. Observation starts automatically; open any HTTP(S) page and reload it to see the Light report. Antidetect: enable the extension's "Allow user scripts" switch in Chrome, choose values in Options, apply them, reload a page and check the result on a test page (owner to confirm these steps). Proxy: a plain SOCKS5 or HTTP proxy works without the companion; password-protected, VLESS and OpenVPN profiles need the optional Windows companion (see the listing). Cookies, Browser Debug and Cloudflare ask for their optional permissions when their buttons are pressed; Cloudflare needs the tester's own API token. Autosurfer and the native profile session are Chrome-only and show Chrome's debugging banner. The Firewall module is off until enabled after its consent screen. No feature sends data to the developer.

## 10. Вопросы и риски, требующие решения владельца продукта

1. **Single purpose** (раздел 1): широта набора функций.
2. **`debugger`** — обязательное разрешение (в Chrome не бывает optional), заметный риск отказа ревью; решить, оставлять ли Автосерфер и нативную сессию в одном пакете с остальным.
3. **Наблюдение по умолчанию без экрана согласия** (ADR-041): для политики CWS о раскрытии пользователю важно, чтобы листинг и политика прямо это говорили (раздел 8). Решить, нужен ли экран согласия снова.
4. **Архив Pro на диске с значениями Cookie** (ADR-097, ADR-037): «Save» пишет значения исходящих Cookie в IndexedDB без шифрования. Решить, исключать ли значения из архива или предупреждать при сохранении.
5. **Firefox `data_collection_permissions: { required: ['none'] }`** (`scripts/build-production.mjs:37–40`): заявлено «ничего не собирается», тогда как Firefox-сборка тоже передаёт введённый пользователем токен в Cloudflare API, ведёт трафик через прокси пользователя и обрабатывает cookies локально. Решить, какой набор категорий заявлять в AMO.
6. **Строки интерфейса**, противоречащие политике: ключи `inventory_sync` («Browser account sync, disk and external servers are not used» — на диске есть три базы IndexedDB, а Cloudflare и прокси используют внешние серверы), `inventory_local` (перечисляет только область, сайты и язык) и `inventory_pro` (не упоминает архив на диске) в `_locales/*/messages.json`. Они остались от детекторной редакции; правка идёт через таблицы переводов (этот черновик их не меняет).
7. **Ключ шума** (`profile-noise-root:v1`, ADR-106): действия «сбросить ключ» в интерфейсе нет; ключ исчезает только вместе с расширением. Решить, нужна ли кнопка.
8. **Файл vault companion остаётся** после `Uninstall.ps1` и после удаления расширения. Решить, добавлять ли удаление в скрипт или предупреждение при установке (в тексте листинга уже есть).
9. **Откуда скачивается companion** — в черновике не указано (поле для URL).
10. **Контакты и издатель**: не менялись (Vektor T13 Technologies B.V., info@detect.expert).
11. **Proxy Manager Geolocation API** (ADR-109): передача IP прокси и ключей сторонним провайдерам по включению пользователя — раскрыть в листинге (раздел 8) и политике; решить, оставлять ли незашифрованную бесплатную точку `http://ip-api.com` в CSP (удаляется одной строкой, остаётся Pro по HTTPS); в Firefox это ещё один довод пересмотреть `data_collection_permissions` (пункт 5).
