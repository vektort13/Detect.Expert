# Иконки систем

ADR-080. Общий реестр предназначен для подбора сайтов, каталога Inspector и
последующего отображения распознанных систем в главном popup.

- Вход: `packages/catalog/data/system-icons.v1.json`.
- Runtime: `system-branding-data.js`, `system-branding.js`, `system-mark-ui.js`.
- Новые PNG: `apps/production-extension/icons/systems/`, 96×96.
- Ранее проверенные marks переиспользуются из `icons/brands/` без изменения.

`systemBrand(idOrExactName)` возвращает неизменяемую запись с локальным `src`,
id/name, `brand | generic` и необязательным brandId. Есть только явные aliases;
подстроки, URL, имя похожей компании и нестроковые значения не выбирают марку.
`createSystemMarkUi({h})` возвращает `SystemMark` и `SystemLabel`. Размер 20/28,
иконка декоративна, доступное имя отображается отдельно. Все поверхности используют
один asset по одному identity. Модуль не является источником detector evidence.

Для 212 систем подтверждены corporate/product marks; у 67 — собственные нейтральные
пиктограммы без букв. Последние не выдаются за логотипы компаний. Неактуальные
домены, неподтверждённые совпадения и иконки платформ вместо продукта исключены.
Источники, контрольные суммы, преобразования и применимые лицензии —
`icons/systems/PROVENANCE.json` и `LICENSE.txt`. Метаданные каталога по ADR-079 сохранены.

Обычная сборка полностью offline: `node scripts/build-system-icons.mjs`, проверка
`--check` обязательна в production preflight. При обновлении сначала проводится
сбор и identity review источников, затем нормализация и обновление входного JSON.
Результаты и инструменты подготовки: внутренний отчёт.

Новые PNG проверяются по структуре/размерам, SHA и общему бюджету; исходные
downloads не исполняются. Контактные листы проверяют внешний вид. Нативные тесты
декодируют все 279 значков в Chrome/Firefox и проверяют отсутствие сетевого egress.
