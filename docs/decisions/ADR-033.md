# ADR-033 — отдельная страница настроек блокировки API

Статус: принято по прямому решению пользователя от 2026-10-09; независимое review и проверки фиксируются в отчёте задачи.

## Решение

Под Light/Pro находится общий launcher с кнопкой настроек и отдельным master ON/OFF. Настройки открываются в собственной extension-вкладке `protection.html`. Она использует существующий entrypoint `options.js`, language picker и consent gate. Общая реализация `protection-ui.js` используется Chrome и Firefox. CSP, permissions, backend, wire-схема и регистрация защитных hooks не меняются.

Нажатие master ON является явной активацией существующей блокировки, заменяя прежний checkbox подтверждения. При открытии страницы и переключении строки API master автоматически не включается. Новый профиль остаётся выключенным.

Тройной переключатель сохраняет существующие правила: ON = `block`; BYPASS = отсутствующее индивидуальное правило, наследование preset/global; OFF = `allow`. Значения global и точного hostname применяются в прежнем порядке. API занимает одну строку. Указанные владельцем подписи об установке, разрешении API и высоком риске удаляются из всех локализаций.

## Идентификация вкладки и сохранение

Launcher передаёт только валидный числовой `tabId`. Хост и текущий `documentId` читаются через `ui-protection-get`, а не из адреса страницы. Открытие настроек не меняет целевую вкладку на extension-вкладку. Перед записью читается свежая revision; существующая проверка optimistic concurrency в controller сохраняется. Reload относится к свежему native document и проходит прежнюю проверку controller.

`verifyUiSender` уже принимает страницы с собственным runtime ID и точным extension origin. Новая страница использует этот существующий UI channel; origin-проверка не расширяется. В Firefox `options.js` получает прежний UI adapter. Не создаётся новый privileged channel.

UI подписывается на изменение локального `protection:v1`, чтобы master показывал одно состояние во всех открытых окнах. При внешней записи несохранённые правила сохраняют старую revision и не получают права перезаписи новой политики. Собственное уведомление SET не сбрасывает черновик. Для подписок Firefox используются native browser events с тем же runtime ID: adapter не предоставляет `removeListener` для нормализованных navigation events. Команды и проверки native document ID по-прежнему проходят через прежний adapter; изменение не затрагивает его trust boundary.

## Проверки

Повторяемая интеграция: `scripts/production/sync-protection-ui.mjs --check`. Проверяются сохранение правил/ревизий, отвергаемые sender/request, отсутствие включения при открытии, переключатели и native Chrome/Firefox на локальной fixture. Никакие тесты не запускают блокировку на пользовательских аккаунтах.
