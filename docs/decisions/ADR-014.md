# ADR-014. Tenant isolation, export и support access

Статус: **Proposed**. Владелец: backend/security (TBD). Реализация — E14-01 (экспорт, Local), E19 (tenant backend).

## Контекст

Backend появляется после качества Local; для первого внедрения достаточно модульного монолита, реляционной БД, очереди и объектного хранилища. Отчёты могут указывать на чувствительные сайты; администратор не должен получать историю посещений сотрудников; поддержка не должна иметь глобальный обход RBAC.

## Решение (предлагаемое)

1. Три потока с отдельными схемами, endpoint, retention и разрешениями: конфигурация; health (версии расширения/правил/major Chrome, код ошибки датчика, наличие политики — без URL, заголовков, fingerprint-значений, перечня посещений); выбранные пользователем отчёты (`POST /v1/reports`, только `ReportUploadMode=manual`, только redacted preview).
2. Endpoints: `POST /v1/enrollments`, `POST /v1/health-batches`, `POST /v1/reports`, `GET /v1/rule-packs/{version}`, `DELETE /v1/reports/{id}`, admin policy/release. Идемпотентность (ключ повторения), лимит размера, deadline, bounded retries с jitter; истечение авторизации не останавливает локальный анализ; отключение функции удаляет её очередь.
3. RBAC: Organization Owner, Policy Administrator (без чтения отчётов по умолчанию), Analyst (только явно переданные отчёты своего tenant), Auditor (read-only аудит), Support (временная, ограниченная tenant/срок/задача, отдельное одобрение, полный аудит), Rule Publisher (отдельный контур, без browsing-отчётов).
4. Изоляция tenant в API и persistence: scoped queries, отдельные object prefixes, неугадываемые и срочные download URL; cross-tenant тесты на чтение/изменение/поиск/выгрузку/webhooks/кеши/фоновые задачи.
5. Retention: health 14 дней; отчёты 30 дней или меньше по tenant; аудит 365 дней без содержимого посещений; backup 35 дней с документированным истечением; tombstones при восстановлении. Удаление немедленно закрывает доступ и запускает удаление индексов.
6. Аудит: actor, tenant, действие, объект, время, request id, безопасный diff; без секретов и URL отчётов.
7. Экспорт на клиенте (Local): только preview-проекция; передача организации — отдельное подтверждение с указанием получателя (REQ-014). Подпись отчёта удостоверяет неизменность после создания, не истинность page events.
8. SLO v1 (предложение): доступность 99,9 %/мес, RPO 24 ч, RTO 8 ч, подтверждённые учениями; локальный анализ от SLO не зависит.

## Последствия

- Enterprise Local (E18) выпускается без этого ADR; Connected — только после cross-tenant suite и deletion drill.
- Никаких рейтингов сотрудников, интересов, продуктивности, межсайтовых профилей, продажи агрегатов.

## Приёмка

Cross-tenant suite проходит (0 успешных adversarial cases); deletion drill: отчёт удалён → недоступен через API, индексы и восстановление из backup (tombstone); support-доступ ограничен и аудируем; экспорт клиента равен preview; отключение backend не мешает локальной работе.
