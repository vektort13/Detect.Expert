# ADR-061 — немедленное применение переключателей API Guard

Статус: реализовано и проверено, E22-12. Итоговый отчёт. Продолжает ADR-048/049, REQ-002/003/004/012/015. Нажатие ON/BYPASS/OFF/Custom меняет сохранённое правило, а не только подсветку черновика.

## Решение

Клик сохраняет единственный выбранный API в выбранной области через существующий доверенный ui-api-config-set с optimistic revision. Основа записи — подтверждённая конфигурация; остальные draft значения, preset, master, native WebRTC policy, строки/сайты не записываются этим действием. При переходе в Custom включается явно выбранное значение этой строки. После ответа подтверждённая база и revision обновляются, остальные черновики остаются черновиками. Ошибка записи не объявляется успешным применением.

Immutable MAIN hooks ADR-049 не получают stop/restore или команд страницы. Для уже открытого сайта используется существующий доверенный exact-document reload: исходные tabId/documentId/host фиксируются до записи, после неё проверяются повторно. Указанный сайт должен совпадать с редактируемой областью; навигация во время записи, ошибка регистрации и отсутствие target исключают автоматический reload. Не перезагружаются все вкладки и случайно выбранная активная вкладка. После собственной навигации идентичность обновляется без потери черновиков, чтобы следующее нажатие применялось к новому документу.

Без target режим действует при следующих посещениях; состояние уже открытых документов нельзя объявлять обновлённым. Статус и действия размещаются рядом с управлением, а не только в конце длинного списка. Общий выключатель по-прежнему определяет, активны ли настроенные правила.

Сам ACK reload не подтверждает новый документ: отдельный observer ставится до команды, ожидает проверенный новый documentId той же revision максимум2s/8reads. Timeout сохраняет явный pending-reload статус, позднее подтверждение связано с той же операцией. Unmount закрывает ожидание. Native tabs.reload не предоставляет атомарный document lock; Chrome pendingUrl и текущий native URL перепроверяются непосредственно перед вызовом, Firefox-эквивалент pendingUrl не обещается. Loading ресурсов текущего документа не запрещает его reload.

Семантика и переносимый JSON не меняются: ON блокирует, OFF явно разрешает, BYPASS наследует общую настройку/пресет. BYPASS отдельного сайта может наследовать общий Custom, что явно показывается. Сохранённые selected/userValues вне Custom остаются библиотекой и не применяются в другом эффективном режиме.

## Проверки

Выполнены реальные UI clicks без Save, первые inline WebGL1/2, последовательные переключения, отсутствие посторонних записей/перезагрузок, ошибки storage/revision/registration, pending navigation и held reload, сохранение черновиков, no-target и светлые/тёмные/узкие/RTL layouts. WebGL object-contextId проверен по87 assertions в Chrome153/155 и Firefox138; Canvas2D и native DOMString/brand/errors сохранены. Общие unit3457 и release:verify PASS. Точные команды, hashes и ограничения — в итоговом отчёте.

Новых permissions, схем/wire enum, MAIN restoration channel, внешнего соединения и зависимостей нет. Модуль Firewall и vendor/protect не меняются.
