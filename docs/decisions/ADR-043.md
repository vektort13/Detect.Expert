# ADR-043. Forter Fraud Prevention: CDN и CloudFront в рабочем распознавании

Дата: 2026-10-10. Статус: реализовано; проверки и независимое review — в отчёте задачи. Трассировка: E12-02, ADR-009/019/034/036, REQ-008/010/011. Основание — запрос пользователя о Forter на eBay, показанный Pro-граф с `forter.com` и `d3nocrch4qti4v.cloudfront.net`.

## Причина

В production существовало только правило `forter-3ds-loader-v1` для `sdk.checkouttools.com/v1.2/managedOrders.js`. Отдельная исследовательская база содержала событие `ftr:tokenReady`, но не подключала его к production. Метка `Forter 3DS` описывала только прежний ресурс. Network listener Light принимал script/XHR/subframe/other, но пропускал image/ping.

## Решение

1. Добавить три статические группы ресурсов в существующий production registry (61 правило вместо 58): CDN Forter, 12 точных CloudFront connect endpoints, 3 точных CloudFront script endpoints. Исследовательские кандидаты и seed остаются выключенными.
2. Разрешённый CDN namespace: `cdn` с необязательным числом до трёх цифр под `forter.com`; допускается один валидный DNS tenant/visitor label перед CDN. Источник — официальная интеграция Computop, где приведены `cdn3`, `cdn4`, `cdn9`, visitor/site hostname и CSP `*.forter.com`. Corporate `forter.com`, `www`, `docs`, `portal`, backend `api` не входят в правило.
3. CloudFront — только точный список из HTML документации Computop; не wildcard `cloudfront.net`, не произвольные поддомены этих distributions. Shared `1.1.1.1` и `siteperformancetest.net` не добавляются. Script endpoints принимают только script; connect endpoints — XHR/image/ping. CDN принимает script/XHR/image/ping. Навигации, стили, шрифты и WebSocket не классифицируются этими правилами.
4. Сопоставление выполняется на transient URL завершённого browser request с HTTP 2xx/304, до redaction. Сохраняется фиксированный rule ID, существующий redacted host и browser document identity; path/query/tenant label/body/token не входят в результат matcher. Никаких запросов к Forter из расширения, выполнения vendor JS или чтения токенов.
5. Сохраняются все проверки scope, host permissions, ownership, паузы, OFF и бюджеты. Внутренний сетевой listener дополнительно принимает image/ping; wire-схемы, permissions, manifest, CSP и enum не меняются.
6. Название общей карточки — `Forter`. Существующий локальный логотип отображается и в интерфейсе, и в Pro-отчёте. Прежнее 3DS правило остаётся отдельным rule ID под этим поставщиком. Pro сохраняет совпадения текущего и дочерних документов всех записанных посещений.
7. Источник проверен 2026-10-10; review due 2027-01-10. По истечении срока новые правила отключаются, старые ID не переинтерпретируются. Отключение до срока: удалить три записи из `vendors_runtime_default.rules` и пересобрать оба пакета; hardcoded matcher без записей не выдаёт результаты.

## Проверки и границы

`scripts/test/forter-resources.test.mjs` проверяет shipped matcher, positive/negative случаи, 58 прежних правил, даты, удаление правила, ID/URL redaction, scope и browser listener. `scripts/test/forter-native.mjs` использует реальные Chrome webRequest события с локальными перехваченными ответами: ни Forter, ни eBay не получают тестовый трафик. Проверяются DOM-only/ошибки/abort, Light image-only, script/XHR/ping, child document, несколько посещений, UI logo и Pro/PDF.

Fixture проверяет распознавание наблюдённых ресурсов, а не выполнение алгоритма Forter или факт решения по платежу. Self-hosted/новые неопубликованные распределения требуют отдельного источника и правила. Для Firefox действует прежнее ограничение browser document identity: в старых версиях доступны сетевой журнал и Pro resource map, но нельзя приписывать vendor request выдуманному document ID. Это исправление не меняет Firefox attribution adapter.

Политика и точные списки: `scripts/production/forter-resource-plan.mjs`; повторяемая синхронизация: `node scripts/production/sync-forter-resources.mjs`.
