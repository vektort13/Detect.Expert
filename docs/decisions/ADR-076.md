# ADR-076: режимы Precursor из Cloudflare API и Firefox Resource Timing

Дата: 2026-10-30. Прямое решение владельца продукта: реализовать Off / Monitor / Armed,
уведомления о смене и максимально расширить обнаружение Firefox.
Дополняет ADR-074; DET-CF-PRECURSOR-001; REQ-004/005/006/008/009/010/011/015.

## Авторитетный режим

Новый источник — явно подключённая пользователем зона Cloudflare. Фиксированные
GET `https://api.cloudflare.com/client/v4/zones/{zone_id}` и
`https://api.cloudflare.com/client/v4/zones/{zone_id}/precursor`, bearer token
только из собственной страницы `precursor-settings.html`. Заголовок версии
`Cloudflare-Version: 1.0`. Первый запрос проверяет ID и имя зоны; второй
принимает только `success: true` и mode `off|monitor|arm` (UI Armed).
Legacy default_mode и отсутствующий mode не преобразуются в Off.
Источники и extract официального OpenAPI: внутренний отчёт.
GET zone требует Zone Read; внутреннее read permission Precursor подтверждено
OpenAPI как `com.cloudflare.api.account.zone.precursor.read`.

Результат — конфигурация зоны на момент чтения, не доказательство исполнения
в каждом запросе. В карточке документа зона сопоставляется только с точным
apex hostname. Суффикс не доказывает принадлежность делегированного поддомена.
Собственная страница подключения всегда показывает выбранную зону.
Публичные JSD, cookie, interstitial и отсутствие загрузчика режим не определяют.

## Узкое изменение границ

Разрешён один явный исходящий API-канал: только фиксированный host/path, GET,
без redirect, cookie credentials, referrer, произвольного URL, remote code
или записи настроек Cloudflare. CSP extension_pages получает ровно
`connect-src https://api.cloudflare.com`. Уже существующие host permissions
не расширяются. До явного подключения никаких запросов этого модуля нет.
Опциональное permission `notifications` запрашивается только кнопкой UI.

Токен хранится в памяти UI на время ввода и в памяти браузерной сессии
`storage.session['precursor-credential:v1']` с TRUSTED_CONTEXTS. Поле очищается
после передачи. Токена нет в storage.local, IndexedDB, MAIN/ISOLATED, снимках,
отчётах, диагностике, ошибках и экспорте. Остановка worker сохраняет мониторинг:
новый worker восстанавливает сессионный токен, заново проверяет зону и режим.
Закрытие браузерной сессии удаляет credential; последнее значение остаётся
не текущим, а последним известным. Disconnect/revoke/global Clear удаляют vault.
Общий репозиторий получает только точные report/index/fence keys, а selective clear
перечисляет только ключи. Native getKeys предпочтителен. Firefox 138 не имеет getKeys:
узкий привилегированный `sessionStorageKeys` выполняет get(null) и возвращает только
Object.keys, не обращаясь к значениям. Сырой объект не покидает helper; репозиторий
затем отдельно читает allowlist ключей. Если getKeys существует, но завершился
ошибкой, fallback запрещён. Firefox default trusted-only подтверждён нативно:
ISOLATED get запрещён, события session change отсутствуют при живом control listener.
Chrome без необходимого ключевого API не включает connector. Это исключение
только для локальной памяти доверенного SW; чужие заголовки/страницы не читаются.
Это отдельное исключение, не разрешение читать Authorization посетённых сайтов.
Port принимает только native sender своей top-level precursor-settings.html.
Read-only карточка использует обычную проверку собственного UI и documentKey.

Локально сохраняются ограниченные данные проверенной зоны, последнее известное
значение/время, флаг monitoring, настройки уведомлений и история переходов.
Отдельный redacted transport record сохраняет cooldown/backoff через idle worker
restart, включая Retry-After до первого успешного определения. Нет истории посещений,
URL страниц, токенов или ответов API. Clear/disconnect/revoke немедленно обрывают
поколение операций; поздний ответ не может восстановить соединение.

Опрос ограничен одним источником и интервалом, HTTP response ограничен размером,
таймаутом и числом физических незавершённых операций. Timeout не освобождает
физический слот до завершения fetch/body. Ошибки/429 имеют backoff. Ошибка,
unknown, stale и первый baseline не являются сменой. Уведомляется только
различие двух подтверждённых значений одной зоны; время записи — время
наблюдения различия. История ограничена и не является полным аудитом Cloudflare.

При откате системных часов transport задержка переносится в новое время с
ограничением 10 секунд–1 час; не ждёт возвращения ошибочной даты. Redacted флаг
resetBaseline сохраняет разрыв сравнения через перезапуск worker. Следующий
подтверждённый ответ устанавливает новый baseline без события смены; прежняя
история сохраняется. Последующие различия снова создают обычные события.
OS notification ID использует случайный nonce worker и монотонный номер,
независимый от сбрасываемого номера истории. Нажатие удаляет уведомление и
открывает только собственную страницу настроек. Количество отслеживаемых
уведомлений ограничено; позднее завершение create после очистки удаляется снова.

## Firefox

Дополнительное наблюдение использует нативные PerformanceResourceTiming getters
в ISOLATED, проверенный приватный token текущего документа, успешный статус,
JavaScript MIME, script initiator и точный same-origin HTTPS path ADR-074.
Наружу выходят только allowlisted rule IDs и признаки доступности/ограничений.
Никаких DOM-текстов, cookie, тел, запросов сети от сенсора или MAIN канала.
`evidenceSource: browser-resource-timing`, `integrity: browser-observed` —
отдельное расширение sidecar-контракта; основной enum отчётов не меняется.
Покрытие partial: ранние/вытесненные записи могут отсутствовать. Отсутствие
getters или достоверной идентичности не создаёт положительного наблюдения.

Первое чтение может принять уже накопленное нативное наблюдение того же живого
документа в пределах TTL 10 минут. Время снимка — время подтверждения background,
не точное время выполнения скрипта. Кэш, который уже читал прежний worker,
сбрасывается при новом session ID; clear/pause/reset также очищают producer.

## Проверка

Нужны независимые review, строгие schema/adversarial fixtures, lifecycle
clear/revoke/restart/late replies, bounded HTTP и реальные Chrome/Firefox UI.
Live переключение собственной зоны без предоставленного доступа непроверяемо;
контролируемый transport fixture должен обозначаться именно fixture.
Фактические команды, версии, хэши и ограничения фиксируются в результате задачи.
