# ADR-066 — профили отпечатка и Canvas projection в Antidetect

> Уточнено [ADR-106](ADR-106-antidetect-continuation.md): приватный ключ Canvas живёт весь срок профиля (локальный корень в `storage.local`), по умолчанию алгоритм `sparse-rgb-v1`; упоминания session key ниже описывают версию до ADR-106.

Статус: реализация по прямому решению владельца продукта от 2026-10-21, E22-19. Продолжает ADR-048/049/060/064/065. [Исследование 45 семейств](../coverage/fingerprint-surfaces.md) разделяет существующие возможности, новые проверенные поверхности и кандидатов; наличие строки в исследовании не является заявлением о реализации.

## Навигация и профили

В Antidetect — вертикальное меню Profiles / Hardware / OS / Network / All / Browser. Network остаётся начальной страницей; у каждой категории собственные цвет и SVG. На узких экранах категории переносятся; логический порядок, клавиатура, RTL и существующие черновики сохраняются.

Profiles содержит явный Generate → preview → Apply. Создание, загрузка профиля и импорт не применяют параметры. Save as profile сохраняет библиотеку отдельно от активации; rename/delete требуют явного действия и не меняют активные API. Полный профиль содержит все 143 глобальные строки с режимом/выбранным значением/settings, preset и отдельной native WebRTC policy. Он сохраняет отсутствие значения и намеренные null/undefined в рамках типа API. Применение профиля сохраняет общий master, exact-site исключения, библиотеки отдельных API и остальные сохранённые профили. Общий master никогда не включается генерацией.

Генератор использует связанные наборы CPU/deviceMemory; у Chrome147+ desktop допустимы2/4/8/16/32, Android1/2/4/8, старые варианты остаются для старых движков. В default OS/UA/GPU/timezone сохраняются; нет выдуманной версии браузера, мобильной CSS-среды, поддерживаемого кодека или разрешения. Явная OS simulation сохраняет engine/version/настоящие brands, связывает platform/UA/appVersion/Client Hints. Она не меняет HTTP headers, CSS, worker или сетевой TLS. Язык связывается с первым элементом languages; экран — с avail dimensions, depth/pixelDepth, DPR и orientation. Строгий рецепт дополнительно выбирает имеющиеся API запреты, что видно в preview.

Профиль включает существующие Math farbling и реальные WebRTC device aliases. Если WebRTC раньше был Allow/Bypass/Block, dormant Custom IP/relay/certificate values не активируются рецептом; alias profile начинает с addresses:null/preserve/no freshCertificates. При действующем Custom сохраняется явная выбранная маршрутизация/политика сертификатов. Media enumeration Custom отключается при включении случайных aliases, чтобы не создавать конфликтующую таблицу устройств.

Проверка связей сообщает конкретные противоречия ОС/UA/CH, language/languages, screen/avail/depth/orientation и GPU vendors; отдельно показывает фактические границы HTTP/CSS/timezone/worker. Это проверка внутренней согласованности, не статистическое доказательство сходства с массовым устройством. Профили API используют общие cookies, storage и учётные записи браузера; изолированные браузерные контейнеры и сетевой source IP не создаются.

## Один формат и один писатель

FormatVersion4 / CatalogVersion6 сохраняет 143 ID и порядок. Canvas-readback получает типизированный Custom; остальные прежние метаданные не меняются. Frozen V5 сохраняет исходные143 записи SHA-256 `c10b94ac123076d428a254367649a4cc168c97947aa3787bf41f9b320bccf7e1`. Пять опубликованных пар формата/каталога строго валидируются до миграции: 1/1, 1/2, 2/3, 3/4, 3/5.

Новое обязательное поле `fingerprintProfiles:[]` принадлежит прежней конфигурации. До128 записей `{id,label,preset,webrtcNetworkPolicy,apis}`; все143 scope rows обязательны, ID и порядок канонические. Профили не содержат sites/master/вложенные библиотеки/seed. Device conflicts проверяются и для dormant профилей при выключенном master. Общие лимиты4MiB, глубины и node count сохраняются; дубли, unknown fields/versions и произвольный код отвергаются до записи. Export JSON включает всю библиотеку и все параметры. Большие diff отображаются постранично, полный JSON доступен в preview.

Нового storage key или второго backend writer нет. Exact own top Options controller использует прежние `ui-api-config-get/set` и CAS revision. Смена revision, разрешений, видимости и dispose учитываются до/после await. Library-only commit не заменяет импортированную pending библиотеку: изменения перебазируются и валидируются до CAS. Конфликт по profile ID не затирается. Записанная конфигурация с registration:error показывается как ошибка применения, а не как ложный rollback. Parent draft блокирует конкурирующее применение профиля.

Изменение только `fingerprintProfiles` сохраняет прежние active API, application/pending state и legacy revision. Оно не останавливает wrappers открытых документов, не вызывает повторную регистрацию и не имитирует успешное применение при существующей ошибке. CAS и общий config revision действуют также для библиотечных изменений.

## Узкое расширение opt-in Custom для Canvas

По прямому запросу владельца разрешается отдельная обработка результатов Canvas, только когда выбран `canvas-readback: Custom` и включён master. Это исключение из REQ-001/002/005 разрешает временно читать пиксели запроса страницы и создавать приватные производные canvas-копии для кодирования выбранного результата. Оно не разрешает самостоятельные fingerprint probes, пиксели/хеши в bridge/storage/логах/отчётах, изменение исходного bitmap, новые permissions, внешний трафик или toString masking. Наблюдающий сенсор остаётся прежним.

Профиль `{algorithm:'stable-rgb-v1'}` меняет покрываемые RGB каналы полностью непрозрачных пикселей на один уровень. Alpha и полупрозрачные/прозрачные пиксели не меняются. Проекция стабильна по session/origin/координатам/каналу/исходному значению; повторные чтения и эквивалентные независимые холсты совпадают. Результат getImageData и закодированные PNG сравниваются с независимым decoder в тестах. Производные copies не выставляются в DOM и не публикуют native handles.

Поверхности: CanvasRenderingContext2D/OffscreenCanvasRenderingContext2D.getImageData, HTMLCanvasElement.toDataURL/toBlob и OffscreenCanvas.convertToBlob в Window realms. После успешной установки запрета диагностического захвата native метод исходного объекта вызывается ровно один раз для его brand/taint/error/coercion семантики; отдельные captured native вызовы на приватных copies разрешены для кодирования. Если запрет невозможно установить, Canvas отказывает до вызова исходного метода: исходный метод уже может быть диагностической обёрткой. Ошибка native не подавляется. Async snapshot снимается до изменения страницы после возврата; callback вызывается единожды. Тип/quality не преобразуются повторно. Неоднозначные object coordinates/options, неизвестный pixel format/metadata и превышение4M pixels удерживаются ошибкой/пустым результатом соответствующего API, без выдачи исходного изображения.

Асинхронное кодирование ограничено четырьмя одновременно ожидающими копиями и суммарно8M pixels на экземпляр bootstrap с общей квотой для унаследованных дочерних realm. Reservation освобождается при callback, отказе, ошибке подготовки/кодирования и синхронной ошибке Promise species. Превышение бюджета возвращает null через toBlob callback либо отказ convertToBlob; native source callback/Promise всё равно обрабатывается без выдачи исходного результата.

DOM bindings захватываются отдельно для каждого realm. Shared private context maps маршрутизируют заимствованные parent/child/sibling методы к metadata их настоящего receiver; неизвестный успешно прочитанный контекст закрывается отказом. Неизменяемые2D context attributes сохраняются при создании, изменяемый WebGL drawingBufferColorSpace читается native getter соответствующего realm. Приватные копии создаются в текущем Document через captured native getter, включая замену первоначального about:blank на srcdoc.

Private CSPRNG256-bit Canvas key не совпадает с Math key; хранится в storage.session, передаётся только в закрытый native registered source. Нет seed в профильном JSON или page message. Регистрация document_start и наследование доступны в прежнем immutable bootstrap. В inherited opaque realm без синхронного доступа к доверенному профилю отдельный static guard запрещает только покрываемые readbacks. Публичный marker не является аутентификацией.

Существующие ссылки до установки и документы до reload не отзываются. Старый private registered script может пережить browser restart до async reconciliation с новым session key; атомарная свежая ротация до первого restored документа не обещается. При смене зарегистрированного Canvas source выставляется reloadRequired. WebGL.readPixels, Worker/Worklet, WebAudio live samples, Font metrics, CSS и сетевой TLS этой Canvas проекцией не охвачены. Для этих семейств исследование содержит отдельные методы/ограничения; единый fictional fingerprint им не приписывается.

## Совместная работа Custom и диагностических сенсоров

Порядок установки MAIN-наблюдателя и Custom не считается гарантированным. Вызов сохранённого исходного метода может сначала пройти через старую диагностическую обёртку и передать реальный результат в публичный MAIN-канал. Проверка воспроизвела это для Canvas, CPU, языка, экрана и WebGL даже при выключенном Pro; этот путь закрыт общей политикой захвата значений.

Любой действующий Custom устанавливает до обращения к исходным API неизменяемый marker `Symbol.for('detect.expert/api-custom/value-capture-deny/v1')`. Он означает только запрет. Само наличие descriptor, включая false или accessor, запрещает захват; getter не выполняется. Отсутствие marker не является подтверждением доверия. Нельзя снять запрет конфигурацией страницы, Pro START/READ, lease, epoch или сменой history. Обычная установка, унаследованные и opaque guard-входы используют одинаковое правило.

Состояние находится в приватном WeakMap и объединяется для Runtime и его recorder. Все зарегистрированные realm проверяются перед чтением, хранением, snapshot и отправкой. Неизвестный, нерасширяемый или недоступный realm, ошибка descriptor и превышение1024 realm закрывают захват. Список callback очистки ограничен8; используются захваченные intrinsics и собственные data descriptors, без вызова page getters. Запрет необратим в данном документе, очищает накопленные значения, изображения, ожидающие отправки и RTC endpoint history, отменяет таймеры и снимает native RTC listeners. Следующий документ получает новое состояние.

При Custom технические значения и изображения не передаются через API results, Pro value previews, Visual или RTC details. Метаданные вызовов API, операции и счётчики сохраняются для анализа. Выбранные значения не выдаются за наблюдённые. Без Custom прежнее наблюдение остаётся действующим. Отдельный native composition-тест проверяет оба порядка установки, ранние и поздние hooks, очередь до Custom, дочерний и opaque realm и попытки вновь включить захват через страницу. Это ограничение предпросмотра значений, необходимое для предотвращения обхода подмены через собственный наблюдатель расширения.
