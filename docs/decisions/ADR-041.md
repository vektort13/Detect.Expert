# ADR-041 — автоматическое наблюдение после установки

Дата: 2026-10-10. Основание: прямое решение владельца продукта убрать стартовый экран Local Data Processing и включать обычное наблюдение сразу после установки. Production-исключение к прежнему onboarding ADR-003/017; legacy TypeScript-контур не меняется.

В ScopeController.load отсутствие собственного сохранённого ключа `data-consent:v1` и отсутствие pending-change marker разрешают однократно сохранить `{version:1, accepted:true}`. Это совместимое внутреннее состояние включённого сбора, а не запись нажатия пользователем прежней кнопки. Успех persistence предшествует включению. Присутствующие false, undefined, null, неправильная версия/форма и pending marker не заменяются автоматическим true. Отказ storage оставляет наблюдение выключенным.

Для новой установки с выданными browser host permissions используется существующий all-sites default и регистрация MAIN/ISOLATED на document_start. Любой уже сохранённый scope, включая off и безопасную проекцию неверного scope, сохраняется; одноразовый marker запрещает его последующую подмену. Если browser ещё не выдал host grants, scripts не регистрируются; отсутствие scope сохраняется до события предоставления разрешения. Прежние выборы off/site/active-tab, revocation и pause не отменяются.

DataConsent в popup, sidepanel, options и report заменён компактным состоянием/действием. Ожидание ответа background и ошибки продолжают закрывать доступ к данным. Отдельные процедуры остановки и очистки, canonical readers и trusted UI sender checks сохранены. Сохранённое отключение показывает компактную кнопку включения. Новый профиль открывает обычный интерфейс без отдельного disclosure gate. Четыре короткие подписи доступны на всех 21 UI-языках.

Pro recording, API blocking, optional cookies permission, DBSC debugger attach и cookie restoration по-прежнему запускаются отдельными действиями. Permissions, CSP, wire-schema, sensor wrappers, сбор форм и внешние соединения не меняются. Уже загруженные документы получают document_start hooks при следующей загрузке; Firefox не получает небезопасный frameId fallback для поздней инъекции.

Проверки: actual ScopeController в unit VM, сохранённые отказы/области, delayed persistence, pending revoke, ошибки storage, отсутствие grants и их изменение; native Chrome и установленный Firefox в пустых project profiles без открытия UI до первых наблюдений; компактный UI/revoke; общий unit/typecheck/lint и две воспроизводимые сборки. Фактические результаты и независимое review фиксируются в отчёте задачи.
