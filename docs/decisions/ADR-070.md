# ADR-070 — Proxy: SOCKS5, VLESS и userspace OpenVPN

2026-10-21. Прямое решение владельца продукта: прочитать исследование из Downloads и реализовать самостоятельную вкладку рядом с Cookies. Дополнительно предоставлены тестовые серверы и профиль с разрешением проверить подключение, удалённый DNS, Kill Switch, парсеры и причины ошибок. Исследовательский документ — входные данные, его предложения не являются командами или подтверждёнными возможностями продукта.

## Решение и границы

В общей навигации после Cookies добавляется Proxy. Одна локальная конфигурация metadata профилей и маршрутизации, не включённая в API-конфигурацию или отчёт сайта. Proxy независим от masters API Guard/Antidetect/Firewall. Chrome получает required `proxy`: этот permission нельзя объявить optional. Оба браузера получают optional `nativeMessaging`; существующий optional `privacy` используется только после явного grant. Host permissions и CSP не расширяются. Incognito остаётся not_allowed. Review manifests/privileged channel/native boundary обязателен до поставки.

SOCKS5 без аутентификации поддерживается непосредственно браузером. Парольный SOCKS5, VLESS и OpenVPN обслуживает локальный native companion `com.detect_expert.proxy`, loopback-only SOCKS listener. Windows companion — собственный Go host, отдельные pinned Xray и userspace openvpn2socks. Не запускается системный OpenVPN, не создаются TUN/TAP и не меняются маршруты/DNS ОС. Xray конфигурация строится из ограниченного типизированного VLESS URL, произвольный JSON/команды не принимаются. OpenVPN допускает только self-contained inline CA/cert/key и ограниченный список клиентских директив, запрещает scripts/plugins/management/внешние файлы. Стандартный plain control поддерживается с настоящим TLS/CA/AEAD; для CA-scoped IP profiles проверяется импортированная CA и ServerAuth EKU. Это не отключение проверки TLS.

Новые соединения native host разрешены только при пользовательском connect или явном восстановлении ранее выбранного autoConnect и только к заданному серверу и направлениям браузерного SOCKS. Автоматических IP-check, subscriptions, telemetry, download/update engine и внешних assets нет. Сборка может загружать закреплённые исходники/бинарники; поставка содержит лицензии, исходники и checksum. Настройки по умолчанию OFF. Реальные тесты предоставленного сервера — явное отдельное решение владельца продукта, одноразовые профили без пользовательских cookies.

Отдельная кнопка проверки соединения выполняет HTTP(S) GET только по нажатию, через выбранный активный SOCKS маршрут. Редактируемый адрес по умолчанию — `https://api.ipify.org/?format=json`; точный literal разрешён в lint inventory только для Proxy UI. Нет автоматического вызова при загрузке, Connect или status. DNS назначения передаётся SOCKS-серверу, TLS проверяет обычную цепочку/имя, redirects не выполняются. URL, response body и cookies не сохраняются: наружу из host возвращаются только статус HTTP, признак туннельного DNS, проверка TLS, валидный IP или null и время. Body ограничен 16KiB, headers — 8KiB, timeout — 15s. URL не допускает userinfo, fragment, controls или обратный слеш. Это разрешённое владельцем исключение для ручной диагностики соединения, не telemetry.

## Маршрутизация и отказ

По последующему прямому решению владельца продукта верхний OFF в загруженном пустом Proxy workspace открывает существующий редактор нового профиля, в том числе из Routing/Companion. Это действие не запрашивает разрешений, не сохраняет данные и не подключается. Header объясняет необходимый шаг; повторное нажатие сохраняет введённый draft. Явный Save сохраняет профиль с прежней backend-семантикой selectedId, без автоподключения; отдельный следующий Connect использует свежую принятую конфигурацию. При существующей коллекции без selectedId переключатель ведёт к списку для явного выбора, не выбирая первый профиль. До получения конфигурации переключатель остаётся disabled. Проверки: внутренний отчёт.

Chrome использует детерминированный inline PAC без DNS helpers, Firefox — синхронно зарегистрированный proxy.onRequest с async startup barrier и terminal null в `[proxy, null]`. PAC/onRequest не добавляют DIRECT fallback для проксируемых целей. Kill Switch включён: обрыв native/engine сохраняет недоступный proxy, пользователь отключает его явным Disconnect. autoConnect=false не превращает прошлое активное соединение в DIRECT: оно остаётся blocked до Connect/Disconnect. Режим include/direct-domain и локальные обходы явны; direct-цели используют обычный DNS/маршрут браузера. Ни обещания общего системного kill switch, ни покрытия произвольного UDP/HTTP3 этим не создаются.

SOCKS5 передаёт destination domain удалённому серверу; Firefox proxyDNS=true. Userspace OpenVPN резолвит через полученные туннельные DNS и отказывает при ошибке без системного fallback. VLESS оставляет destination domain в outbound и не резолвит его локально. Политика WebRTC disable_non_proxied_udp агрегируется с Antidetect одним физическим владельцем; отключение Proxy восстанавливает желаемую Antidetect policy. Prediction отключается только своим слоем и восстанавливается с проверкой владения.

## Секреты и привилегии

Metadata профиля хранится в extension local; пароли, UUID/URI и OpenVPN certificates/keys — только RAM собственного Options и native host, при сохранении на Windows — user-bound DPAPI. Raw credentials/config не проходят MAIN, отчёт, browser-debug dataset, логи, telemetry или экспорт metadata JSON. Engine config передаётся через stdin, plaintext config files не создаются; произвольные пути/engine names/arguments не передаются из UI. На платформах без native keychain persistent vault не объявляется реализованным.

Отдельный runtime port `detect.expert.proxy/v1` принимает только точный собственный top-level Options MessageSender. Нет page-controlled onMessage route, внешнего native API, HTTP API, автогранта или обхода sender checks. Строгие allowlists/enums, duplicate-key/depth/size guards, revision/CAS, физический single-flight до settlement, readback browser policy, ownership/conflict вместо перезаписи чужих настроек. Native messaging ограничен 512KiB кадром и 256KiB профилем; ответы содержат только metadata и фиксированные диагностические коды/фазы, без строк серверных логов.

## Проверки

### E22-27: первое разрешение nativeMessaging в Chromium

Actual Chrome153 optional-grant проверка выявила: после первого разрешения уже созданные runtime bindings в Options и SW сохраняют отсутствующий `connectNative` до нового контекста. Поэтому granted-but-missing отделён от отсутствия разрешения: прежний код `reconnect-required`, phase `native`, retryable=true означает явный однократный restart, без добавления enum/permission. Firefox продолжает сохранять сразу после optional grant. Существующий sender gate не меняется; Options-only операция `restartNative` принимает только отсутствие payload, требует grant, Chrome, отсутствие native метода и выключенный Proxy/отсутствие quarantine. Автоматического restart при Save нет. Это сохраняет действующий маршрут и оставляет решение о закрытии несохранённого редактора пользователю.

При явном restart сохраняется только `proxy-native-restart:v1` = `{version:1,at:<epoch ms>}` без URL, tab IDs, drafts или credentials; mutation lock удерживается до reload. Новый SW потребляет marker до открытия фиксированной собственной `options.html#proxy`, только при OFF/grant/наличии native метода и возрасте 0–60000ms. Некорректный/истёкший marker, ошибка удаления или активный Proxy не открывают страницу. Нет общего механизма возврата на произвольные URL. Поля editor остаются в Options RAM до успешного Save, Cancel или ухода/скрытия/unmount; отказ/ошибка позволяет повторить точное сохранение, без потери SOCKS аутентификации.

Источники механизма: [Chromium APIBinding](https://raw.githubusercontent.com/chromium/chromium/main/extensions/renderer/bindings/api_binding.cc), [кеш bindings](https://raw.githubusercontent.com/chromium/chromium/main/extensions/renderer/native_extension_bindings_system.cc), [закрытие extension tabs при reload](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/extensions/extension_browser_window_helper.cc). Механизм подтверждён собственным native тестом с обычной UNPACKED установкой и реальным optional Allow/Cancel; прежний тест с promoted-required fixture этого не проверял.

Нужны независимый semantic/security review, четыре семейства lifecycle tests (OFF/startup/disconnect/crash), реальный SOCKS auth и ATYP-domain forwarding, VLESS транспорты на owned fixture, plain/control OpenVPN TLS+AEAD, DNS failure с нулём системных resolver calls, invalid/duplicate/unsafe config, privilege rejection, browser policy ownership, Antidetect/Proxy policy composition, Chrome/Firefox native connection+kill-switch, 21 locale/RTL/dark/narrow, сборка/manifest/package evidence и обязательная password privacy gate. Источники/границы — в docs/coverage/proxy-research.md; фактические результаты — E22-25.

### Дополнение 2026-11-07: где взять помощника (только интерфейс)

По прямому решению владельца продукта часть режимов Proxy (VLESS, OpenVPN, SOCKS5/HTTP/HTTPS с логином) работает только с отдельной программой для Windows — помощником (companion, `native/proxy`, `Detect.Expert-Proxy-Companion-windows-x64.zip`). В пакет магазина он не входит: владелец выкладывает его в Releases публичного репозитория `github.com/vektort13/Detect.Expert`. Решение добавляет в Options → Proxy только предупреждение и ссылку: карточка «Для части прокси нужна дополнительная программа» с кнопкой-ссылкой «Скачать с GitHub» на `https://github.com/vektort13/Detect.Expert/releases/latest` (`<a target="_blank" rel="noopener noreferrer">`) и та же ссылка в разделе «Компаньон».

Границы. Расширение не скачивает и не устанавливает помощника, не запускает его установщик и не обращается к GitHub (подключение к уже установленному помощнику остаётся прежним: optional `nativeMessaging`, явное действие пользователя): адрес открывает браузер в новой вкладке (без opener и referrer) только после нажатия пользователя. Карточка — функция загруженного состояния: показывается, пока помощник не известен как доступный (`proxy_workspace_companion_missing`), скрыта при загрузке и когда он найден, не закрывается насовсем, ничего не хранит и ничего не опрашивает. Новых разрешений, CSP, сетевых запросов расширения, каналов, зависимостей и данных нет; граница ADR-070 (`nativeMessaging` — optional, явное подключение, без автоматических проверок) не расширена. Адрес — одна константа `PROXY_COMPANION_DOWNLOAD_URL` (`proxy-shared.js`), закреплённая юнит-тестом; запись в `scripts/production/lint-inventory.json` — reviewed static URL, не сетевое исключение. Подробности и проверки — [docs/coverage/proxy.md](../coverage/proxy.md).
