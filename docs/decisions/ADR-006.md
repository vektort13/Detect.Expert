# ADR-006. Семантика hooks и ownership-safe cleanup

Статус: **Accepted** (2026-09-12). Владелец: `packages/sensors` (общая hook-инфраструктура).

## Контекст

REQ-001: тот же результат нативного вызова, оригинал ровно один раз. AUD-16: маскировка `toString` провоцирует скрытие модификаций. Coercion аргументов вызывает пользовательский код; `.then/.catch` на чужом Promise меняет `unhandledrejection`. После нашей обёртки API мог обернуть сайт или другое расширение — безусловное «восстановление» ломает их.

## Решение

1. **Контракт обёртки** (`packages/sensors/core`): сохранить оригинальный дескриптор; проверить `configurable`/`writable` — иначе сенсор `unsupported`, страница не затрагивается; обёртка вызывает оригинал **ровно один раз** через `Reflect.apply(original, this, args)` (для конструкторов — см. раздел «Конструкторы») с исходными `this` и аргументами; возвращает исходный результат (включая `NaN`, `-0`, identity объектов и Promise); исходное исключение пропускается без изменений.
2. **Наблюдение**: fast path `enabled? → reentrancy guard → счётчик++ → bitmask`. Ошибка наблюдателя ловится отдельно и меняет только `sensorStatus`; никогда не подменяет ошибку оригинала и не отменяет вызов.
3. **Аргументы**: никакого `String()`/`Number()`/JSON/повторного чтения свойств (`options.name`, `url`, `toString`) — только `arguments.length`, `typeof` примитива, `instanceof` по сохранённым ссылкам на конструкторы без вызова getters. Для объектного аргумента безопасный fallback — счётчик без классификации.
4. **Promise/callback API**: не оборачивать в `async`, не добавлять `.then/.catch`, не оборачивать callback; `phase: async-returned`/`settlement-unobserved`. Специализированный success-sensor — отдельный ADR.
5. **Не маскировать**: `Function.prototype.toString` не патчится; копирование `name`/`length`/дескрипторов допустимо только как compatibility-мера с проверенными дескрипторами. Обёртка помечается внутренним маркером владения (WeakMap `wrapper → original`), не свойством, видимым странице.
6. Разные wrappers для методов, getters и конструкторов; проверять subclassing, `new.target`, brand checks, статические свойства.
7. **Пауза**: флаг `enabled=false` прекращает наблюдение и передачу; установка новых датчиков отключается. Обёртки остаются.
8. **Ownership-safe cleanup** (revoke/stop): для каждого API — если текущий дескриптор `=== наша обёртка` (по WeakMap), восстановить оригинальный дескриптор; иначе оставить как есть и сообщить `cleanup: partial`. UI различает «сбор приостановлен» и «для удаления датчиков перезагрузите страницу».
9. **Повторная установка**: второй bootstrap в том же realm обнаруживает существующий маркер и не оборачивает повторно; счётчики не дублируются.
10. Budget: при превышении измеренного бюджета — sampling или деактивация датчика (`sample-budget-exceeded`), не бесконечная переустановка.

## Последствия

- Обёртка обнаружима (identity, дескрипторы, timing) — известное ограничение, описано в UI (REQ-015).
- Сенсоры без `.then` не знают исхода асинхронных операций: UI показывает «результат неизвестен».
- Frozen/non-configurable прототипы → `partial`/`hook-failed`.
- Дифференциальный suite — обязательная часть DoD каждого hook.

## Приёмка

Differential suite (E06-01): без/с расширением совпадают результат, тип, порядок событий, исключения (тип+сообщение), identity возвращённых объектов и Promise, `instanceof`, `new.target`; coercion объекта-аргумента с `valueOf`-счётчиком вызывается ровно один раз (оригиналом); `unhandledrejection` не меняется; ошибка наблюдателя (инъекция throw) не влияет на страницу; non-configurable → `unsupported`; после revoke: наша обёртка убрана, чужая (установленная поверх) сохранена и cleanup помечен partial; повторная установка не дублирует.

## Уточнение интеграции 2026-09-12 (F051/F129/F176)

На момент интеграции constructor sensors оставались вне production: дифференциальные случаи показывали изменение constructor identity и отклонения Proxy/new.target. Повторное чтение prototype могло изменить результат либо исключение. Исправление F176 и сохранённое обнаружимое отличие F051 описаны ниже в решении P03; production-сенсоры этим решением не активируются.

Гарантия раннего захвата передаётся только собранным hook.early.js, зарегистрированным на document_start. hook.main.js использует консервативный browserEnv без supplemental getters и с hook-failed. Поздняя проверка дескрипторов не доказывает чистоту realm. При отсутствии handshake ISOLATED после ограниченного числа попыток отправляет coverage-only диагностику; это диагностическое утверждение page-controlled, не аутентификация сенсора. Ownership-safe cleanup сохраняется.

## Конструкторы

Статус решения P03: **Accepted — вариант A, 2026-09-13** (F051/F176, E06-01, REQ-001). `wrapConstructor` остаётся публичной инфраструктурой; это не разрешение включить DET-013/056/058 или E08 без проверки конкретного API.

Обычная функция с `Reflect.construct` внутри недостаточна: её собственный `[[Construct]]` выполняет `OrdinaryCreateFromConstructor` до тела, читая `new.target.prototype` лишний раз. Обёртка теперь использует захваченный `Proxy` с единственным `construct`-trap: без предварительного выделения экземпляра вызывает `Reflect.construct(Original, args, newTarget === Wrapper ? Original : newTarget)`. Адаптер через захваченный `Reflect.apply` сохраняет `IArguments` наблюдателя. Для subclass/Proxy сохраняется исходный `newTarget`; при прямом `new Wrapper()` оригинал видит себя. Число и порядок чтений определяет оригинал: одно чтение для проверенных нативных конструкторов и обычного базового класса, ноль для производного конструктора, возвращающего объект до `super()`.

Вызов без `new` делегируется `Reflect.apply(Original, this, args)`; текст и объект исключения создаёт оригинал, обёртка не синтезирует TypeError. Оригинал вызывается один раз, его возвращённый объект/Promise и исключение сохраняют identity. Наблюдатель вызывается после оригинала; его исключение подавляется отдельно. Пауза, reentrancy guard и ownership-safe cleanup сохраняются.

`Wrapper.prototype === Original.prototype`. `Original.prototype.constructor` не изменяется: `instance.constructor === Original`, а `instance.constructor !== Wrapper` — намеренно обнаружимое отличие F051. Вызов через сохранённый оригинал или `prototype.constructor` обходит наблюдение. Статические свойства копируются дескрипторами без вызова getters: объектные значения и функции остаются теми же объектами, цепочка наследования статик сохраняется. Дескрипторы `name`/`length` копируются целиком как compatibility-мера (опция отключения сохранена); `Function.prototype.toString` не патчится.

Уточнение ревью P03, 2026-09-13 (REQ-003): `Function.prototype.toString` не патчится, но callable Proxy по спецификации возвращает NativeFunction-синтаксис; в проверенном Chromium это `function () { [native code] }`. Для исходных Path2D/OffscreenCanvas строка содержит имя: `function Path2D() { [native code] }` / `function OffscreenCanvas() { [native code] }`. Квази-нативный вид — побочный эффект выбранной техники Proxy, а не маскировка инструментом; отсутствие имени остаётся обнаружимым отличием. Browser differential явно проверяет обе строки отдельно от равенства остальных фактов, не скрывая это расхождение.

Граница совместимости: копии статик не синхронизируют последующие присваивания; private static fields и статические getters/методы/`Symbol.hasInstance`, проверяющие identity `this`, могут отличать Wrapper от Original. Последующее присваивание writable `Wrapper.prototype` не меняет `Original.prototype`, используемый прямым конструированием; соглашение `instanceof` после такой замены не гарантируется. Bound-конструкторы без собственного data-дескриптора `prototype` не устанавливаются. Произвольные изменённые/Proxy-конструкторы, чужие realms и поздний захват испорченных intrinsics не объявляются универсально совместимыми.

Проверки: unit differential на базовые/производные классы, `new.target`, Proxy-порядок и исключения, возврат объекта/Promise, статики и `Symbol.hasInstance`; `tests/extension/constructor.spec.ts` загружает реальный `wrapConstructor` отдельным test-only bundle в MAIN fixture-страницы и сравнивает Path2D/OffscreenCanvas со свежим Chromium без расширения. В production test-only bundle не включается. Browser evidence относится к Chromium 153; AudioContext/RTCPeerConnection/WebSocket этим прогоном не проверены. Результаты команд и таблица сравнений: внутренний отчёт.

## Уточнение P04 — 2026-09-12 (DET-003/DET-004, F125)

Сеттеры размеров canvas оборачиваются с сохранением getter и исходных this/arguments/result/exception; cleanup проверяет владение обоими accessor slots, чтобы не затереть чужой getter. Успешное присваивание, в том числе того же значения, удаляет связь текста с canvas и контекстом. Сбросы не вызывают дополнительный coercion. Контекстный `reset()` и любой успешный `clearRect` также снимают связь; частичный clear даёт консервативную потерю полноты. История не пересекает паузу: первый наблюдаемый вызов после неё использует новое поколение WeakSet/WeakMap. Конструкторы этих коллекций захвачены при загрузке модуля.

Ограничения: frozen/неподдерживаемый setter, HTML-изменения размеров через атрибуты, сохранённые оригинальные API и последующая замена hooks могут обойти сброс. Поздняя установка не вызывает supplemental getters: перехваченный resize удаляет историю всех контекстов консервативно. Полного восстановления истории по пикселям или размерам нет. `convertToBlob` сохраняет исходный Promise без handlers и сообщает `settlement-unobserved`; успешный результат fixture известен только самой странице. Передача canvas указывает на пробел worker coverage, но не доказывает worker readback. См. внутренний отчёт для фактического прогона и review.
