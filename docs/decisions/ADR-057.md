# ADR-057 — распознавание успешно загруженного SDK после редиректа

Дата: 2026-10-20. Основание: REQ-005/008/009/011/012/015, проверка Cloudflare по решению владельца продукта; существующий curated `turnstile-loader-v1`.

Нативная проверка обнаружила самостоятельный дефект анализа в Light и Pro. Документированный `https://challenges.cloudflare.com/turnstile/v0/api.js` отвечает 302, затем браузер успешно загружает версионный путь того же origin. Старый обработчик проверял только URL последнего ответа 2xx/304. Точный matcher отклоняет версионный путь, и отчёт теряет Cloudflare при работающем SDK и нулевых ошибках engine/storage. Это не доказательство причины зацикливания challenge.

Matcher и каталог не расширяются. Отдельный `vendor-redirects.js` связывает browser-native `before → redirect → before → completed` для существующего документированного ресурса. Сохраняются только rule IDs, HTTPS origin, native request/tab/frame/document IDs, тип, access/session epoch и время. Полные URL, query, redirect target path, заголовки, тела и токены в состоянии отсутствуют. Страница не может создавать эту цепочку сообщениями.

Перенос допускается после минимум одного подтверждённого редиректа только в пределах того же HTTPS origin, с совпадающими native IDs/типом/эпохой и успешным конечным 2xx/304. Ответ 302 сам по себе, ошибка, отказ, другой origin/порт/схема, отсутствие native documentId, неполная цепь, повторное использование ID, неактивный документ, отзыв доступа и истёкший catalog review не дают vendor. Прямое распознавание существующего final URL сохраняется.

Лимиты: 128 записей вместе с tombstones, пять переходов, TTL 30 секунд. Превышение отражается существующим network-limited/event-limit. Перезапуск SW теряет неполную цепочку; вместо догадки остаётся неполное покрытие. Light и Pro имеют независимые экземпляры, чтобы один listener не потреблял результат другого. Оба очищаются при consent/scope/session boundaries и удалении вкладки; pause/clear очищают точный документ. Начальные browser-native события могут опередить модель документа; конечное подтверждение требует текущего доступного неприостановленного binding. Permissions, wire-схемы, сенсоры и DNR не меняются.

Firefox 138 не предоставляет поддерживаемую расширением авторитетную source-document identity для webRequest (ADR-018). Адаптер продолжает показывать network-limited; этот ADR не вводит догадок по frameId или page-controlled данным. Загрузка SDK и его работа проверяются отдельно от точной сетевой атрибуции.

Воспроизводимая интеграция: `scripts/production/sync-vendor-redirects.mjs`; build preflight проверяет отсутствие drift. Unit/adversarial cases используют также поставляемый matcher; native regression загружает настоящий SDK и проверяет Light и Pro snapshot, плюс отрицательный localhost redirect. Независимые review проверяют ложные совпадения, redaction, lifecycle и семантику. Артефакты и фактические результаты — в отчёте внутренний отчёт.

Источники последовательности browser events: [Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest), [Firefox onBeforeRedirect](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest/onBeforeRedirect).
