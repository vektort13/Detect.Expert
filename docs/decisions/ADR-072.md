# ADR-072 — исправления аудита: never-read, долговечность и инвалидация операций

2026-10-30. Прямое решение владельца продукта исправить все найденные проблемы комплексного аудита, сохраняя функционал. Задача E22-28. Продолжает ADR-006/007/017/020-protect/047/050/053/061/068/069/070/071. Разрешения, CSP, consent, вендорные пороги и holdout не расширяются. Необходимый additive reset-control для точной очистки описывается отдельно в ADR-073 и требует независимого review контрактов.

## Контекст

Аудит подтвердил PP-01…05, PROD-01, CORE-01…03 и устаревшие native gates. Штатный privacy gate пропускал длинные autocomplete-маркеры. Неуспешные purge/Proxy save/clear могли выглядеть успешными либо оставлять несовпадающие durable состояния. Pro-operation не участвовала в инвалидации документа. Пересборка старой TS-базы поверх production недопустима: это разные реализации.

## Решение

- **Never-read:** production adapter проверяет полные чувствительные атрибуты в ограниченном окне до vendor-классификации. Отсутствие password/OTP/payment-маркера в усечённом префиксе не считается доказательством его отсутствия. Превышение предела приводит к отказу чтения. Это сужение разрешённого чтения; новых readers/полей/каналов нет. Vendor snapshot неизменяем. Native tripwire в обоих мирах получает длинные маркеры и независимые положительные контроли.
- **Purge:** долговечный OFF подтверждается до разрушительной очистки. Ошибки хранилищ не подавляются с ложным успехом, согласие/настройки не теряются из-за неуспешной операции. Завершённый OFF не превращается в ON после restart. Неуспешный OFF должен оставаться явно неуспешным для вызывающего UI.
- **Proxy startup:** недоступное хранилище, как и повреждённая конфигурация, временно удерживает собственный закрытый маршрут. Ограниченное восстановление перечитывает настройки; реально отсутствующая конфигурация и явный Disconnect сохраняют прежний OFF. Настройки чужого proxy-owner не очищаются.
- **Proxy CRUD:** native vault изменяется через staging под отдельным ID. Один authoritative metadata-only item хранит валидированную конфигурацию, соответствия видимого ID и committed vault ID, а также ожидающие cleanup IDs. Запись journal предшествует native mutation; legacy configuration остаётся совместимой проекцией и восстанавливается из authoritative item до активации. Atomicity нескольких storage keys не предполагается: обе стороны torn-write восстанавливаются из одного item; неизвестный исход commit требует перечитывания до cleanup. Ошибка до commit сохраняет старый профиль; после commit cleanup идемпотентен. Секреты не попадают в journal/storage extension и не считываются обратно в JS ради rollback. Native→plain/Delete учитывают старую native запись. Native RPC и caller boundary не расширяются.
- **Очистка истории:** уточнена [ADR-073](ADR-073.md): baseline-only не покрывает ещё не доставленные ключи и не считается решением. Используется exact-document producer/collector reset barrier, fresh boot/session epoch и один authoritative metadata item для долговечной session-clear границы; скрытые пустые records не выдаются UI/экспорту/inspectors. Wire reset ограничен typed routing/control, новых privileges нет.
- **Ownership:** cleanup getter проверяет оба accessor slots, прежде чем восстановить весь descriptor. Чужой setter не уничтожается.
- **Pro:** один bounded operation token зарегистрирован на весь цикл START/READ/повторной авторизации. Pause/clear/revoke/transport stop/navigation инвалидируют его даже при последующем resume. Состояние документа и native identity перепроверяются после awaits. Разрешённые технические значения и существующая allowlist не расширяются.
- **Редакторы:** API master сохраняет только своё поле из актуального base revision, оставляя посторонний draft для явного Save. Cookie batch останавливает дальнейшие native writes после неизвестного исхода, отражает partial results/skipped remainder и сохраняет Undo подтверждённых изменений.
- **Gates:** ожидания актуализируются по canonical catalog и реальным historical fixtures. Удалённый по ADR-044 DBSC не возвращается; отсутствие legacy sessionBinding проверяется явно. Keyboard navigation обходит вложенный Browser Debug как прежде, видимые tabs и deep-link проверяются раздельно. Семантические/приватностные assertions не вырезаются ради зелёного gate.

## Приёмка и review

Обязательны fault injection до/после durable commit, restart/replay/paused-await и отрицательные fixtures. Для Protect — весь ADR-020-protect §15 с нулём запрещённых чтений и работающими независимыми tripwire controls. Отдельный reviewer проверяет false positives, native API semantics и immutable vendor. Независимое второе мнение по исправлениям — не замена фактическим тестам.

`pnpm typecheck`, `pnpm lint`, `pnpm test:unit`, `pnpm test:extension`, `pnpm test:privacy`, `pnpm test:perf`, catalog/build/release gates фиксируются с настоящими exit codes. Непроверенные external providers/native versions остаются unknown. Публикация/перезагрузка установленного расширения не входит в решение.
