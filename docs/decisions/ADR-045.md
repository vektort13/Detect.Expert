# ADR-045 — меню блокировок и 32 независимых правила

Дополнен [ADR-046](ADR-046.md) (2026-10-17): каталог 89 правил, 11 групп, фильтр категорий; семантика отказа и пресеты не изменены.

2026-10-10. Прямое решение владельца продукта: обновить меню в стиле Apple и расширить блокировки.
Продолжает ADR-033/042; REQ-002/004/009/010/011/012/015. Связанные наблюдаемые поверхности: DET-017/033/034/040/042/063/073.

## Решение

Шесть групп, 32 однострочных элемента, небольшие локальные SVG-пиктограммы, светлая и тёмная тема, компактный общий выключатель. ON/BYPASS/OFF сохраняют значения `block` / наследование / `allow`. Индивидуальные правила редактируются и при выключенном master. Изменения применяет существующая кнопка сохранения. Панель действий находится в потоке документа: нативная проверка Firefox выявила перекрытие строк закреплённым footer, поэтому закрепление удалено.

17 новых feature IDs добавлены в канонический `packages/contracts/src/protection-features.mjs`; структура wire/settings v1, порядок приоритета global/site, revision, доверенный UI channel и origin-проверки не меняются. Старые настройки читаются без миграции. Limited содержит прежние 4 правила, Strict — прежние 9. Новые правила включаются только явно, master по умолчанию выключен. Это продолжает уже разрешённое владельцем исключение для добровольных API-запретов, не вводит подмену успешных результатов.

Общая реализация `protection-runtime.js` порождает 32 самостоятельных MAIN-скрипта через `sync-protection-runtime.mjs`. Тот же скрипт сверяет списки feature IDs во всех шести потребителях. Preflight сборки требует синхронизации. Регистрация через существующий controller, exact-host правила, остановка и восстановление остаются прежними. Новых permissions, CSP, зависимостей, сетевых соединений или удалённых ресурсов нет.

Ошибки явно содержат `Blocked by detect.expert`; это отказ расширения, не утверждение о нативном разрешении. Аргументы страницы не читаются/не преобразуются, native original в запрещённой ветке не вызывается. После stop сохранённая ссылка на wrapper вызывает original ровно один раз, сохраняя this, аргументы, Promise identity и исключение. Восстановление не перезаписывает последующую замену страницы. Отсутствующее или non-configurable API не создаётся и учитывается в unavailable.

## Границы

Защита работает в зарегистрированных document realms. Ранее полученные ссылки, worker/worklet globals и уже существующие устройства/потоки не отзываются. Service Worker/Push/Sync правила блокируют новые вызовы register/subscribe из документа; они не удаляют существующие регистрации, подписки или фоновые задачи. Правило уведомлений относится только к запросу permission. Скрытие getVoices не останавливает уже известный синтез речи. Новое включение после stop в том же документе требует перезагрузки из-за прежнего once-per-document guard. Отдельные API отсутствуют в Firefox; интерфейс показывает общий каталог, а installer сохраняет отсутствие API.

## Проверка

35 новых semantic/privacy/adversarial cases: отказ без getters/coercion, exact recovery, page replacement, отсутствие/non-configurable API, совместимость старых пресетов, все 32 IDs/6 групп и 21 локализация. Native Chrome/Firefox: собственный loopback-origin, 17 новых правил, реальная регистрация, поддерживаемые API, возврат после master OFF. Prototypes используются как receiver, поэтому ошибка установки wrapper не может вызвать доступ к устройству или permission prompt. Геолокация/сенсоры проверяются через descriptors, активные probes не выполняются.

Артефакты и фактические результаты: отчёт, независимый review.
