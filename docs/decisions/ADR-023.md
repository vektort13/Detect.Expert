# ADR-023. Явный локальный просмотр значения cookie и статус TPM

Status: Accepted, implemented. Прямое решение владельца продукта 2026-10-09; REQ-004/005/007/011/012/013, ADR-021/022.

Дополнение 2026-10-10: [ADR-037](ADR-037.md) разрешает отдельный privileged
канал фактически отправленных Cookie в явно начатую локальную Pro-запись и
её preview/PDF. Это не меняет описанный здесь однократный live-view канал:
его handles и результаты не копируются в Pro; Light остаётся metadata-only.

Владелец явно запросил значение cookie и отметку аппаратной защиты. Это разрешает узкое исключение из запрета REQ-005 на передачу cookie values: по клику trusted extension UI одно текущее значение cookie current top-level сайта передаётся только в локальную live панель. Значение не включается в MAIN/ISOLATED sensor messages, Pro snapshots, preview/export/печать, browser storage, telemetry или логи. Автоматического сбора/декодирования/копирования всех значений нет. Закрытие/скрытие панели, refresh, clear, navigation, pause и permission/access changes сбрасывают отображение и отбрасывают устаревшие результаты. Все действующие permission/scope/consent ограничения сохраняются; новых permissions/CSP/dependencies нет.

`ui-get-cookie-view` получает существующий канонический metadata snapshot и отдельный массив opaque handles для ≤256 admitted rows. Metadata-only `ui-get-cookies` и старые Pro snapshots совместимы. Handles случайные 128-bit, живут ≤60 секунд в ограниченной памяти background (≤512/128 KiB identities) и не являются browser credentials. Native name/domain/path/hostOnly/store/partition остаются внутри background; value там не сохраняется. Ряды сторонних resource hosts без current-site ownership получают null handle. Handles согласованы с отсортированными строками текущего read, а не с индексом новой cookie выборки.

`ui-get-cookie-value` принимает только tab/frame/document identity и handle. Background проверяет UI sender, consent, канонический request/result и ту же document/handle identity. Backend повторно проверяет selected/top document, optional cookie permission, epoch/access generation, native tab store и current top partition; регистрирует operation в существующей системе invalidation. Native bounded getAll сопоставляет полную identity, затем читает own data descriptor value; getters/coercion не вызываются. Cookie get(url,name) не используется: одинаковые имена на разных путях не должны показывать другое значение. Ответ ≤16 384 UTF-16 code units, явный truncated status; ошибки не передают native сообщения или identities. UI выводит текстом с экранированием control/bidi символов, не HTML/URL/JWT.

Официальный Cookie API не предоставляет per-cookie TPM/DBSC flag. DBSC аппаратно защищает session proof key; header names не доказывают membership конкретной cookie или hardware-backed key. Точный функциональный статус в карточке: «TPM: браузер не сообщает». Красный замок с утверждением подтверждённой TPM-защиты не присваивается по Secure/HttpOnly/CHIPS, имени cookie, сроку жизни или page-level DBSC headers. CDP session membership потребовало бы новой debugger/DevTools интеграции и также не даёт TPM attestation; это вне данной задачи. Источники: исследование возможностей.

Acceptance: независимый privacy/trust/API semantics review; canonical accessors/bounds, duplicate masked names/path/domain/partition/store, reversed results, empty strings, unsafe text/control/bidi, expired handles, navigation/revocation/pause/clear/store races, no values in Pro/export/storage; native Chrome и установленный Firefox, truthful TPM status и отсутствие ложного красного замка.

Independent backend/UI/canonical/route privacy and API-semantics review accepted: 123 review cases; final full suite 1 157 Vitest + 414 Node. Native Chrome 19 checks and installed Firefox 29 assertion groups. Source freeze includes reviewed identity-memory accounting. Final evidence.
