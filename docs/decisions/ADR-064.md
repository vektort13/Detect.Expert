# ADR-064 — Antidetect и согласованные сетевые настройки

Статус: реализовано по прямому техническому заданию владельца 2026-10-20; проверка и результаты — E22-17. Название раздела — **Antidetect**. Продолжает ADR-048/049/055/060/063. Новых permissions, host grants, CSP, зависимостей, исходящего трафика расширения и каналов сообщений нет.

## Единая конфигурация

Вкладка находится рядом с API Guard. Категории Hardware / OS / Network / All / Browser, по умолчанию Network. Выделенные WebRTC overview и native policy перенесены из API Guard; общая строка каталога и JSON-библиотеки остаются совместимыми. Hardware/OS/Browser используют тот же редактор API. Antidetect адаптирует существующий `ui-api-config-get/set`, exact top Options sender и CAS revision; второго хранилища или писателя нет. Общий выключатель не включается выбором режима. Черновик сохраняется в RAM при переходах; внешняя revision блокирует Save до отмены/обновления.

Формат 3 / каталог 4 сохраняет 142 постоянных ID и порядок. WebRTC `addresses` принимает null либо обе записи `ipv4` и `ipv6`, каждая с `host/stun/turn: string|null`. Null роли означает намеренное удержание метаданных соответствующей семьи, без native fallback. `addresses:null` означает отсутствие IP-подмены. Исторические format1/catalog1, format1/catalog2 и format2/catalog3 строго проверяются по замороженным каталогам до миграции; старые смешанные IP-роли распределяются по настоящей семье без потери библиотек, сайтов и выбранных значений. Экспорт детерминирован; отклонённый импорт не пишет настройки.

## Режимы и применение

Allow соответствует `off`, Block — `on`, Spoof — `custom`; прежний Bypass показывается как наследование без ложного выбранного Allow. Сохранённые Custom значения не стираются и не используются в иных режимах. Block/Allow отключают поля Spoof в UI. Существующий независимый `media-enumeration` сохраняется; изменение WebRTC не стирает чужую настройку списка устройств. Отдельная browser-wide native WebRTC policy по ADR-060 сохраняет самостоятельную область действия.

Три протокола имеют одного владельца раннего перехвата. Legacy регистрации WebRTC/WebSocket/WebTransport удаляются из production-плана; иначе неопределённый порядок scripting/userScripts позволял старому публичному stop вернуть конструктор. Новый self-contained installer находится в закрытом immutable document-start bootstrap с синхронным наследованием доступным фреймам; для opaque origin-fallback поставляются три отдельных закрытых bundle. Нет публичного restore/stop и установки значений через сообщения страницы. Уже захваченные до установки ссылки и уже работающие соединения отозвать невозможно; изменения требуют нового документа. Успешно сохранённая ранняя регистрация обслуживает последующие переходы без дополнительной перезагрузки нового сайта.

WebRTC Block запрещает конструкторы PeerConnection, включая prefixed и prototype constructor пути. Он не ставит UDP/HTTP правила. Spoof меняет покрываемые candidate/event/getter/toJSON/SDP/stats/ICE metadata по семье и роли. Private inverse-map сохраняет нативный round-trip SDP; произвольный сетевой source IP не назначается. Реальный TURN используется только через предоставленный сайтом сервер. Media metadata не создаёт устройства/потоки/разрешения. Fresh DTLS создаёт настоящий новый сертификат для каждого соединения; fingerprint и ключ не подделываются. Один сертификат на всю сессию не реализован и не обещается.

## Leak Prevention

Chrome использует уже имеющийся DNR `block` только по resourceTypes `websocket` и `webtransport`. Зарезервированы **300000/300001**, priority 1000; даже соседний 300002 не принадлежит модулю. Firewall диапазоны, HTTP, заголовки и allow rules не меняются. Единственная операция native update атомарна, затем сверяется readback; ошибку/таймаут UI не считает успехом. Физический mutex удерживается до завершения native Promise, повторных мутаций по таймеру нет.

Полная browser-wide блокировка допустима только при all-sites HTTP+HTTPS и отсутствии эффективного exact-host исключения соответствующего протокола. DNR initiatorDomains включает поддомены и не представляет нашу точную область: в таком случае собственное native правило снимается и действует только ранний page guard. Firefox использует page guard, workers этим механизмом не покрыты. Фактическую область UI определяет по точному readback собственного правила. Native ошибка снятия блокировки показывается даже при выключенном master.

Общая блокировка UDP, QUIC или IPv6 WebExtensions API не предоставляется. Эти строки имеют отключённые controls и локализованную причину. `disable_non_proxied_udp` относится только к WebRTC и не обозначается как общий UDP firewall. Скрытый IPv6 ICE metadata не означает отключение сетевого IPv6.
