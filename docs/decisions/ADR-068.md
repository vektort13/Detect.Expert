# ADR-068 — независимые masters Antidetect и API Guard, launcher 2×2

2026-10-21, прямое решение владельца продукта, E22-22. Продолжает ADR-048/051/053/064/066/067.

## Решение

В popup, sidepanel и прежнем launcher настроек первая строка: Antidetect / API Guard, вторая: DPI Guard / Firewall. У каждой карточки отдельный компактный ON/OFF в существующем стиле. Название Antidetect открывает единое управление на соответствующей вкладке с текущим source tab; состояние переключает master. API Guard и Firewall сохраняют прежние действия. DPI Guard не реализован: обе кнопки disabled, состояние OFF, локализованная доступность «Скоро». В Firefox отсутствующий по ADR-047 Firewall представлен disabled OFF без новых permissions или фиктивного backend.

Разделение masters основано на режиме, а не на том, в каком редакторе пользователь изменил API: общий каталог и библиотеки остаются едиными. Существующий `enabled` управляет блокировками On и разрешёнными preset/Bypass. Новый `antidetectEnabled` управляет Custom, включая Math/Canvas/WebRTC/device/DTLS projections, и собственной native WebRTC network policy. Off остаётся разрешением. Site disabled выключает оба семейства для точного сайта. Сначала разрешаются site/global/Bypass, затем применяется соответствующий master; отключённый Custom не превращается в случайный запрет preset.

Antidetect Network также редактирует Block для RTC/WS/WT; это On-блокировки API Guard. Их effective state учитывает API master независимо от Custom master. Desired policy и пользовательские значения не стираются при OFF; снимается только собственный native policy layer. Настройки страниц, уже установленные в документе, сохраняют прежнюю границу reloadRequired; переключатель не обещает удалить удерживаемые native handles на лету.

## Совместимость и запись

Portable format5/catalog6 требует оба boolean. Каталог, 143 постоянных API IDs и порядок не меняются. Исторические форматы строго проверяются до миграции; старый `enabled` переходит в оба masters. Наличие dormant Custom/policy само по себе не включает Antidetect. Это сохраняет прежний opt-in для активных подмен, а ранее независимая native policy теперь подчиняется явному Antidetect master. Сохранённый выбор policy остаётся в конфигурации.

Legacy protection projection по-прежнему получает только API master. Старый API launcher не изменяет новый Antidetect master, Custom-библиотеки и профили. Применение fingerprint profile не включает ни один master. Импорт, экспорт, diff и preview включают оба выключателя; повреждённый импорт не применяется.

Новый launcher использует существующие `ui-api-config-get/set`, каноническую валидацию и CAS. Он считывает актуальную конфигурацию, меняет только один master и отправляет expected revision; прямой записи storage нет. Backend sender checks и privileged маршруты не расширяются. UI controller работает только в точных собственных top-level popup/sidepanel/options, не принимает page input. Одна физическая операция удерживается до settlement, включая timeout; stale/timeout не повторяет запись. Storage/permission/visibility изменения инвалидируют или подтверждают состояние чтением; dispose снимает подписки.

## Проверки

Нужны независимые semantic/lifecycle/contract reviews, четыре комбинации masters, site/Bypass/preset, отсутствие seed/Custom регистрации при Antidetect OFF, ранняя Custom регистрация при API Guard OFF, сохранение legacy/library/profile/import, native policy ownership и failure, настоящий Chrome/Firefox launcher/persistence/first-script UI proof, 21 локаль/dark/RTL и disabled DPI без записей. Для затронутой общей Firewall-обвязки обязательна прежняя privacy-проверка нечтения password/OTP/payment полей. Результаты и поставка — в отчёте E22-22.
