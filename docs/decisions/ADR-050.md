# ADR-050 — исправления восьми замечаний аудита production-порта

Статус: реализация по прямому решению владельца продукта от 2026-10-20. Основание — F1…F8 во внутреннем отчёте; приёмка и фактические результаты будут во внутреннем отчёте.

## Решение и границы

Исправления защиты выполняются проверяемыми production-adapter overrides; исходный vendor не редактируется. Новые разрешения, зависимости, сетевые соединения, DNR-действия и изменения согласия не требуются. Managed schema объявляет уже предусмотренный запрет организации.

- F1: до чтения значения необходима подтверждённая история чувствительного типа. Неотслеживаемые shadow/foreign/detached controls исключаются; обнаружение платёжных полей охватывает открытые shadow roots и останавливает чтение при неполной проверке. Исправляется тестовый счётчик и добавляются независимые положительные контроли.
- F2: неразобранное/усечённое структурированное JSON-тело не токенизируется как plain text и не включается в кольцо отпечатков запросов.
- F3: formData, включая ключи, расходует общий 64 КиБ UTF-8 бюджет до создания сканируемых представлений; превышение явно отмечается.
- F4: возврат фокуса окна повторно оценивает ожидающую активную вкладку через существующий surfacer, с сохранением актуальности, дедупликации и rate limit.
- F5: стандартный privacy/release gate включает production-проверку module-off, чувствительных чтений, adversarial/lifecycle сценариев. Старые проверки сохраняются.
- F6: Chrome объявляет `ProtectModuleDisabled:boolean` через managed schema, Firefox не получает модуль и его схему. false/отсутствие не включают модуль.
- F7: документ карты Pro ADR-020 сохранён. Историческая спецификация защиты восстановлена как ADR-020-protect; production-порт описан ADR-047.
- F8: ring-overflow останавливает SW только после подтверждения нужного DET-002 в удержанном пакете; семантические требования к переполнению и дедупликации сохраняются.

## Приёмка

Чек-лист ADR-047 и исторический ADR-020-protect §15 применяются к изменённым границам. Нативные тесты используют только временные профили и синтетические значения; tripwire не сохраняет значения полей. Тест доставки политики ограничен временным ID тестовой копии расширения, без изменения политик пользовательского экземпляра.

До завершения проверок не заявляется отсутствие всех чувствительных чтений или прохождение полного gate. Итог и нерешённые ограничения фиксируются в отчёте.
