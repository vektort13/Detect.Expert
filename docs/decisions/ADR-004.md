# ADR-004. MAIN/ISOLATED transport и недоверенные поля

Статус: **Accepted** (2026-09-12). Владелец: `packages/contracts` (один владелец).

## Контекст

AUD-03: `event.source`/`origin`/nonce трактовались как защита моста; AUD-04: `argsSummary`, полные URL и заголовки — сбор чувствительных данных; AUD-06: `frameId` добавлял мост. Chrome рекомендует считать сообщения content scripts потенциально изготовленными атакующим. SW может остановиться между приёмом, записью и ACK.

## Решение

1. **Имена сообщений** (единственный источник — `packages/contracts`, см. `docs/PROJECT_RULES.md` «Протокол v1»):
   - MAIN → ISOLATED (`window.postMessage`, `event.source === window`, `channel: 'detect.expert/v1'`, `sensorBootId`): `sensor-hello`, `sensor-batch`, `sensor-status`.
   - ISOLATED → MAIN: `bridge-hello`, `bridge-pause`, `bridge-resume`, `bridge-stop`.
   - ISOLATED → SW: `PageBatch { schemaVersion: 1, type: 'sensor-events', sensorBootId, bridgeSessionId, batchSeq, observations[≤32], coverageDelta[] }`; ответ `Ack { schemaVersion: 1, type: 'ack', lastCommittedBatchSeq, paused, protocolOk }`.
   - UI → SW: `ui-get-report`, `ui-pause`, `ui-resume`, `ui-clear`, `ui-set-scope`, `ui-export-preview`; ответ `ReportProjection`.
2. **Недоверенность**: всё из MAIN/ISOLATED получает `integrity: page-controlled`. `event.source`, `channel`, nonce, `sensorBootId`, `bridgeSessionId` — маршрутизация и дедупликация, не аутентификация; в документации и коде запрещено называть их «подписью» или «аутентификацией сенсора».
3. **Доверенные поля назначает только SW** из `MessageSender`: `tabId`, `frameId`, `documentId`, `origin`, `frameType`. Поля `observationId`, `documentKey`, `integrity`, `resourceRef` (доверенный), host permissions, policy fields в payload → батч отклоняется (`additionalProperties: false`).
4. **Allowlist содержимого**: `techniqueId` (enum DET), `count` (целое 0…2³¹−1, насыщаемое), `countQuality`, `phase`, `signalCodes` (enum ≤8), `intervalBucket`, необязательный `attributionHint` (sanitized origin ≤512, без path/query/fragment/userinfo), `coverageDelta` (enum причин). Нет HTML, исполняемых строк, аргументов вызова, пикселей, аудио, cookie values, SDP, полного URL, вложенных коллекций произвольной глубины.
5. **Валидатор**: ручной, в `packages/contracts`; порядок — дешёвые проверки формы (тип, размер массива, длина строки) до дорогого разбора; сериализованный размер ≤16 KiB проверяется до `JSON.parse` там, где применимо; неизвестная `schemaVersion` отклоняется; результат — `ok | reject(reasonCode)` без логирования payload.
6. **Бюджеты**: token bucket 20 batch/s/document, 100/tab, 200/extension с fair scheduling; мусор снижает бюджет отправителя; отклонённые батчи считаются в `dropped.transport` и `coverageFlags: throttled`.
7. **Доставка**: bridge хранит ring ≤512 до ACK; ACK только после согласованного сохранения snapshot + watermark; ключ дедупликации `(documentKey, bridgeSessionId, batchSeq)`; кумулятивные счётчики merge = max в namespace `sensorBootId`. Потеря ACK → повторная отправка, не удвоение. Потеря буфера → `channel-gap`.
8. **Привилегированный UI-канал**: `ui-*` принимаются только при `sender.origin === chrome-extension://<runtime.id>` и `sender.url` из extension pages; content script не может инициировать export/fetch/clear/pause/scope. Действия UI сверяют `documentKey` и `reportRevision`.
9. **Handshake**: MAIN и ISOLATED стартуют независимо; bounded startup queue в сенсоре (≤512 записей) до `bridge-hello`; несовместимая версия → `bridge-stop`, сенсор прекращает наблюдение.
10. Время: сенсорное время — локальный порядок; SW receipt time — собственная шкала; абсолютные миллисекунды разных процессов не сравниваются.

## Последствия

- JSON Schema (`page-batch.schema.json` из стартового пакета — исходная модель) и TypeScript-типы генерируются из одного источника; `ajv` в тестах проверяет, что ручной валидатор и схема согласны на корпусе валидных/невалидных примеров.
- Все ID и origin в отчёте — из Chrome; UI никогда не показывает `attributionHint` как доказанного инициатора.
- Стоимость: ручной валидатор нужно поддерживать при каждой смене схемы (мажорная версия → новый `schemaVersion`).

## Приёмка

Protocol fuzz (E04-01/E04-02): случайные/мутированные payloads, oversized (>16 KiB, >32 obs, строки >512), неизвестные поля, неверные enum, не-числа, вложенные объекты → reject без исключений и логов payload. Replay: повтор batch n не меняет счётчики. Forged `tabId/frameId/documentId` в payload → отклонение, `senderContext` из Chrome. Page `postMessage` с `type: 'ui-export-preview'` → игнор. Flood 10⁵ сообщений → `throttled`, UI и SW работоспособны. SW kill между receive/save/ACK → повтор без удвоения (E02-03).

- 2026-09-13 (P07, REQ-009/011): `DroppedCounters.ring?: number` — насыщаемая нижняя граница потерь кольца. Ожидающие hydration валидные батчи используют существующий бюджет `maxOutOfOrderEntriesGlobal` (128); лишние получают ACK 0 и учитываются в `dropped.transport` после readiness. Listener и проверка MessageSender сохранены.

- 2026-09-12 (интеграция, раунд 1). Без изменения wire-схем и enum. Уточнения протокола, зафиксированные в коде:
  1. `packages/contracts` экспортирует константу `UNBOUND_SENSOR_BOOT_ID = 'unbound'` — `sensorBootId` широковещательного `bridge-hello`, который мост посылает до появления сенсора (§9). Сенсор, увидев такой `bridge-hello` до рукопожатия, повторяет `sensor-hello`; мост отвечает одним `bridge-hello`, привязанным к boot. Значение уже проходило валидатор (алфавит id), новых полей нет; константа — единственный источник вместо литерала в двух пакетах.
  2. Семантика `sensor-batch.observations[].count` — **кумулятивный** итог сенсора по ключу `(techniqueId, phase, signalCodes)` (как в §7 для SW). Мост сливает по max, а не суммирует (ранее ring суммировал «дельты» — расхождение с сенсором, удвоение счётчиков). При BFCache restore мост перекладывает рост после восстановления в ключ с `bfcache-restore`, храня baseline (итог до восстановления); дорестарт-запись замораживается.
  3. §6 на стороне моста: отклонённые сообщения с тегом канала (malformed, неизвестный/вытесненный `sensorBootId`, replay `sensorSeq`) считаются в локальных счётчиках и поднимают `coverageDelta: ['throttled']` на следующем батче. Приёмка «flood 10⁵ → `throttled`» проверяется `tests/extension/hostile-bridge.spec.ts`.
  4. Проекция `techniques[].count` = насыщаемая **сумма** по ключам техники (ключи дизъюнктны: сенсор назначает одну фазу на вызов), а не max.
  5. Привилегированный UI-канал (§8) дополнен двумя запросами с теми же правилами отправителя (`sender.origin === chrome-extension://<id>`): `ui-inject-now { schemaVersion: 1, type, tabId }` — режим activeTab «Проверять с этого момента» (ADR-003): инъекция обоих миров в открытые документы вкладки, документы получают `late-start`; ответ `ok` или `error no-access`. `ui-clear-session { schemaVersion: 1, type }` — удаление всех отчётов сессии (страница настроек), настройки сохраняются; ответ `ok` (`reportRevision: null`). Оба добавлены в `UiRequest`, ручной валидатор и `ui-request.v1.schema.json` (сгенерирована `scripts/gen-schemas.mjs`); page sender по-прежнему получает `unauthorized-sender` на любой `ui-*`.

- 2026-09-12 (аудит, раунд 2; интеграция после внутренний отчёт). Несовместимые изменения wire-схем v1 (`node scripts/gen-schemas.mjs` перегенерирован, ручной валидатор и Ajv-корпус согласованы):
  1. **`PageBatch.observations` может быть пустым только в coverage-only батче** — вместе с непустым `coverageDelta` (`anyOf` в `page-batch.v1.schema.json`; валидатор отклоняет батч без наблюдений и без флагов). Мост доставляет диагностику сенсора (несовместимый handshake, `hook-failed`, пауза, `throttled` после отклонённых сообщений) без выдуманного наблюдения (F033/F034, F168). Уже подтверждённые флаги повторно не отправляются (bounded: ≤ числа значений enum за сессию моста). SW не создаёт boot-идентичность и счётчики для такого батча; `observedSince` не устанавливается. `sensor-batch` MAIN → ISOLATED по-прежнему требует ≥ 1 наблюдения.
  2. **`bridge-control`** — новое сообщение SW → ISOLATED (`chrome.tabs.sendMessage(tabId, { schemaVersion: 1, type: 'bridge-control', command: 'pause' | 'resume' }, { frameId, documentId })`, схема `bridge-control.v1.schema.json`). Мост принимает его только от собственного service worker (`sender.id === runtime.id`, нет `sender.tab`, origin/url расширения); страница до этого канала не дотягивается. Нужно, потому что приостановленный мост ничего не шлёт и никогда не получил бы `Ack.paused: false` (F030). `ui-pause`/`ui-resume` теперь отправляют команду документу после сохранения; ответ не ожидается.
  3. **`ui-resume` требует `reportRevision`** (как `ui-pause`/`ui-clear`): устаревшая ревизия → `stale-revision` (F039).
  4. **`VendorSummary.vendorConfidence`** — единственное wire-имя оси уверенности вендора (ADR-001 §1); прежнее `vendorMatch` отклоняется схемой, `vendorMatchIds` не переименовано (F040).
  5. **Новые `coverageFlags`: `network-limited`, `frames-inaccessible`** (F175). Назначаются только SW по доверенным данным (`frames-inaccessible` — родителю фрейма с opaque origin, чей мост получил отказ); из page payload оба отфильтровываются вместе с `revoked`, `paused`, `no-host-permission`, `restricted-page`, `truncated`, `late-start`. В engine оба дают `partial`.
  6. Задокументировано ранее реализованное, но не описанное (F039): `ui-get-scope { schemaVersion: 1, type }` → `{ type: 'scope', scope: ScopeState { scopeMode, hosts[], grantedAllSites, managed } }`; ответ `ui-export-preview` — `{ type: 'export-preview', preview: ExportPreview }`; `ReportProjection.observedSince` (SW receipt time первого наблюдения или `null`) и `ReportProjection.scopeMode`.
  7. Историческое состояние до финальной интеграции (заменено следующей записью Changelog): экспорт (`ExportPreview`) содержит `documentKey` и абсолютное `exportedAt` (округлено до минуты); чувствительные локальные host исключаются из preview. Порядковый номер документа и относительное время (F027/F108) требуют отдельной export-схемы — открыто, см. внутренний отчёт.

- 2026-09-12 (финальная интеграция, F020/F027/F054/F107/F108). `Ack.stopReason?: 'revoked'` отделяет терминальный отзыв от `protocolOk:false`; терминальный ответ не подтверждает данные. `ui-export-preview.includeHost?: boolean` доступен только привилегированному UI; по умолчанию любой host исключён. `ExportPreview` заменяет `documentKey`/`exportedAt` на `documentOrdinal: 1` (один документ в файле); вложенный `ExportReport` — отдельный allowlist без `documentKey`, `reportRevision`, `observedSince`. `observationAgeMinutes` — насыщенный возраст первого наблюдения в целых минутах; `firstBucket`/`lastBucket` относительны первому bucket отчёта. Независимый review требуется перед выпуском.
- 2026-09-12 (F168/F030): валидатор MAIN control захватывает intrinsics; позднее изменение Array/Set/RegExp не подавляет stop. При исчерпании startup hello мост отправляет один coverage-only `hook-failed` без MAIN вызовов. ACK старого control generation не меняет pause state после новой команды UI. Несовместимый подделанный hello не останавливает работающий сенсор: ISOLATED отмечает конфликт `channel-gap`; явный `bridge-stop(protocol-mismatch)` прекращает наблюдение. Ни hello, ни boot ID не являются аутентификацией.
