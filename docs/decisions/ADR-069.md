# ADR-069 — отдельная вкладка Cookies и перенос через native Cookie API

2026-10-21, прямое решение владельца продукта, E22-23. Продолжает ADR-063; не возвращает удалённый ADR-044 DBSC/debugger.

## Решение и границы

В общем Options добавляется Cookies непосредственно после Browser Debug. Только собственный верхний `options.html` получает прямой native `cookies` controller; существующие optional cookies/HTTP(S) host grants достаточны. Manifest, CSP, привилегированные SW маршруты, wire-контракты и пассивные отчёты не расширяются. Browser Debug по ADR-063 остаётся metadata-only.

Решение разрешает узкое исключение из запрета cookie values: явные Load, Reveal/Edit, Import и Export в Cookies обрабатывают значения в памяти собственной страницы и в явно созданном пользователем файле. Эти данные не передаются через MAIN/ISOLATED/SW, не пишутся в storage/IDB, логи, telemetry или отчёты. Открытие вкладки проверяет лишь доступ и список stores; cookie scan начинается по команде. Нет фоновой подписки на cookie.onChanged. Уход со вкладки, скрытие документа, отзыв разрешения и dispose очищают снимки, планы, undo и содержимое секретных диалогов.

## Переносимая модель

Собственный JSON имеет `format: detect.expert.cookies`, `formatVersion: 1`, source browser, список исходных stores и детерминированно упорядоченные записи с полями name/value/domain/path/hostOnly/secure/httpOnly/sameSite/session/expirationDate/storeId/partitionKey/firstPartyDomain. Пустое value сохраняется. Session означает отсутствие expirationDate при native set, а hostOnly — отсутствие domain. Исходный storeId требует явного назначения доступному store назначения. Cookies разных контейнеров, CHIPS partitions, hasCrossSiteAncestor и Firefox FPI не сливаются.

Импорт поддерживает собственный JSON и явно распознаваемые совместимые JSON/Netscape записи. Весь файл проходит ограниченный строгий разбор, проверку версии/полей/типов, дубликатов и collisions после mapping до первой записи. Secure/SameSite не исправляются автоматически. Несовместимый isolation context отклоняется, истёкшие записи не превращаются в неявное удаление. Netscape теряет атрибуты: экспорт требует явного выбора lossy-режима и не сливает partition/FPI. Скрытые native source scheme/port variants не восстанавливаются и при неоднозначной видимой identity изменения запрещены.

URL для native set строится из проверенного origin + `/`; оригинальный path передаётся отдельным полем без URL-нормализации `?`, `#` и dot segments. Identity включает store, hostOnly/domain, path, name, partition/HCA/FPI. Native get(URL/name), remove(URL/name) и возвращаемое set значение недостаточны: используется точное readback через getAll. Идентичность существующей записи неизменна в редакторе; для другой identity есть создание новой записи.

По результатам native-проверок setter использует HTTPS origin при обоих значениях Secure: флаг остаётся самостоятельным native полем, а снятие Secure не упирается в запрет HTTP overwrite. Native Chromium дополнительно нормализует само поле path; преобразуемые пути удерживаются до записи, а закодированные сохраняются. Firefox 138 поддерживает оба HCA states, но SameSite unspecified появился только в 140: capability gates проверяют версию, не преобразуют enum. Эти ограничения одинаковы для editor/import/delete/undo.

## Применение и восстановление

Preview не пишет cookies. Явное Apply запускает последовательную ограниченную партию с политикой skip/overwrite, fresh preconditions и readback после каждой записи. Нативного атомарного импорта нет: UI показывает фактические частичные результаты. Отмена выполненной партии хранится только в памяти; она откатывает исключительно собственные изменения при совпадении текущей записи с прочитанным результатом записи. Внешние изменения дают conflict. Удаление использует точный expired set, не URL-winner remove; нет broad clear. Таймаут не освобождает физический lock до settlement и не повторяет запись.

Экспорт показывает точный создаваемый текст. Дополнительный шифрованный JSON использует локальный WebCrypto AES-256-GCM с случайными 16-byte salt/12-byte IV, PBKDF2-SHA256 600000 iterations, фиксированной версией и аутентифицированным header. Все параметры и размеры строго ограничены до KDF; неправильный пароль/изменение файла не дают plaintext fallback. Пароль и файлы не сохраняются. Файл скачивается через локальный Blob, без downloads permission.

## Проверки и покрытие

Обязательны parser/schema/adversarial tests, callback/Promise native lifecycle и concurrency, stale/ambiguity/partial/undo, отсутствие values вне явных действий, неизменность metadata-only Browser Debug, native Chrome/Firefox на одноразовых профилях с собственными fixture cookies (не реальный пользовательский профиль), locale/dark/RTL/layout, exact source/dist/ZIP и privacy gate общей Options/Firewall обвязки. Реальные результаты фиксируются в E22-23 и отчёте; этот ADR не объявляет проверки выполненными.

API расширения переносит доступные cookie attributes. Браузер может изменить expiry по своей политике; это отражается результатом. Priority/source scheme/port/creation timestamps, DBSC/TPM/private keys и серверное состояние авторизации native Cookie API не экспортирует. Полная переносимость входа не утверждается. Источники и совместимость — [исследование](../coverage/cookie-transfer-research.md).

## Дополнение 2026-11-07 — список читается сам, когда доступ есть

Владелец показал, что после выдачи доступа вкладка оставалась пустой («Нажмите "Загрузить данные"»), и поручил показывать все cookies профиля, отсортированные по доменному имени. Поэтому, когда optional `cookies` и HTTP(S) host grants уже есть, раздел сам один раз за показ страницы (и сразу после выдачи доступа кнопкой) вызывает тот же `load` по всем доступным stores без фильтра домена и показывает метаданные. Сказанное в разделе «Решение и границы» о «cookie scan по команде» относится к этому моменту вызова и заменено им; всё остальное остаётся: значения лишь в памяти собственной страницы Options, строки списка metadata-only, Reveal/Edit/Import/Export — по-прежнему отдельные явные команды; без доступа ничего не читается и разрешение не запрашивается без нажатия; фоновой подписки на `cookies.onChanged` нет; контроллер выполняет одну операцию за раз; скрытие страницы, уход со вкладки и отзыв разрешения стирают список, следующий показ читает заново. Неудачное чтение само не повторяется, смена области (store, домен) читается кнопкой. Порядок — по домену (без регистра и ведущей точки), затем путь, имя и id; страница — 100 строк. Это изменение момента вызова, а не новый канал, permission, CSP или хранилище. Подробности — [coverage](../coverage/cookies-workspace.md).

## Дополнение 2026-11-07 — полнота окна изменения cookie и конвертер Unix-секунд

По прямому решению владельца продукта («в окне просмотра cookie отображается не вся информация и не все опции; добавить конвертацию Unix-секунд в дату и время и обратно двумя кнопками-стрелками») диалог «Изменить cookie» показывает каждое поле, которое отдаёт cookies API, объясняет блокировку identity и предлагает «Копировать как новую cookie», показывает вычисляемые локально подробности (срок датой и остатком, размер в байтах, область отправки) и предупреждения до записи, а рядом с полем Unix-секунд стоят две стрелки и поле даты и времени.

Это только интерфейс. Новых permissions, CSP, сети, хранилищ, каналов и зависимостей нет; значение cookie по-прежнему живёт лишь в памяти собственной страницы Options и в явно созданных пользователем файлах. Поле даты, выбранная зона и признак «набрано, но не переведено» — состояние открытого диалога: они стираются вместе со значением при закрытии, скрытии страницы, отзыве разрешения и dispose. Контроллер, правила identity, readback и Undo не менялись. «Копировать как новую» — обычное создание через тот же `save(null, …)` с проверкой, что identity отличается от исходной (иначе это была бы та же cookie).

Изменилось одно правило ввода: поле Unix-секунд принимает строго десятичные секунды (прежде `Number()` пропускал, например, `1e9`). Сохраняется только оно; дата, не переведённая стрелкой, запись не меняет, и Save об этом говорит. Перевод не угадывает: несуществующее местное время (часы вперёд) и повторяющееся (часы назад) отклоняются, пока не указано смещение или UTC. Cookies API по-прежнему не отдаёт время создания, priority, source scheme и source port, поэтому они не показываются и не выдумываются. Подробности и проверки — [coverage](../coverage/cookies-workspace.md).
