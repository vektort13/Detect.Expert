# ADR-054 — временное подтверждение включения Firewall

Статус: реализация по прямому решению владельца продукта от 2026-10-20. Дополняет ADR-047/053, не меняет positive-only условия ADR-052.

Из постоянных сообщений production launcher и Options убран нейтральный `protect_disabled_notice`. Launcher также не оставляет нейтральный результат включения `protect_reload_note`; ошибки, отказы разрешений и `protect_disabled_notice_rules_pending` остаются на месте. Vendor и ключи переводов сохраняются.

После успешного явного пользовательского `ui-protect-enable` открывается отдельное окно `activation-toast.html`: справа внизу рабочей области экрана, без перевода фокуса, с закрытием через 5 секунд после готовности. Есть × и Escape. Заголовок и статус используют существующие 21 локализацию, техническая строка — прежний RU/EN. Текст о выключенном модуле не выдаётся за результат включения.

Триггер находится после существующей проверки MessageSender, валидации запроса и успешного ответа контроллера. Требуются фактический `isActive`, состояние active и новое значение внутреннего счётчика activations. Восстановление сохранённого ON при старте, запросы состояния, автоматическое возобновление по разрешениям, no-op, отказ и отмена согласия окно не открывают. Счётчик используется только внутри SW; новых сообщений, storage-ключей и полей wire нет.

Операции остановки и изменения прав/политики инвалидируют ожидающее подтверждение. Условия перепроверяются до и после асинхронного создания. Открыто не более одного подтверждения; удаление разрешает только текущий собственный URL либо точный native TAB-контекст, а не один windowId. Страница дополнительно проверяет реальное состояние/согласие/политику и имеет независимые начальный deadline и lifetime, поэтому не зависит от жизни SW или исходного popup.

Новых permissions, зависимостей, чтения полей/тел, сетевых соединений и изменений DNR/consent нет. Новые HTML/JS — только Chrome; Firefox сохраняет stub модуля. Findings работает через прежнюю отдельную очередь и положительные evidence.

Приёмка: typecheck/lint/unit, meaningful deferred-create/ownership проверки, нативные ON/отмена/ошибка/no-op/startup/expiry/close/focus/ON→OFF и обязательные 7 production privacy-сценариев. Итоговый внутренний отчёт.
