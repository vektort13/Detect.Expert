# ADR-097 — Detector: источник, движения и сохранённые PRO-отчёты

Уточнение UI от 2026-11-01: по решению владельца продукта переключатель закреплён в первой строке с заголовком Detector, до изменяемых контролов выбора страницы. Отдельная grid-колонка переключателя, постоянный слот стрелки и scrollbar-gutter только активного раздела сохраняют положение при появлении отчёта. Это presentation-only изменение, без изменений обработчиков и границ ниже. Проверка: внутренний отчёт.

31.10.2026. Прямое решение владельца продукта: Detector доступен без выбранной страницы, подсказывает выбор стрелкой, позволяет действительно перезагрузить выбранный сайт, считает движения курсора и показывает сохранённые PRO-отчёты. Уточнение владельца отдельно разрешает счётчик самих перемещений, помимо обнаружения действий сайта.

## Источник и наблюдение

Пустое состояние, выбор вкладки, общий прежний переключатель наблюдения и история остаются доступны без исходной страницы. Неполученный/no-access результат не выдаётся за успешный анализ с нулевыми счётчиками. Обновление списка и перезагрузка сайта — разные явные кнопки. Tab проверяется native API перед действием; смена выбора/уход инвалидирует отложенные действия. Согласие и scope не включаются выбором вкладки или открытием Detector.

Для all-sites/site действующая регистрация document_start применяется при перезагрузке. Active-tab привязан к документу: после явной перезагрузки допустима отдельная существующая ui-inject-now для нового документа с прежними проверками доступа и поздним началом. Scope не расширяется. Ошибки доступа не изображаются успехом.

## Счётчик перемещений

Отдельный собственный Options controller использует существующий native scripting.executeScript с фиксированной локальной функцией в ISOLATED world. Только выбранная проверенная HTTP(S)-страница, активный Detector и разрешённое наблюдение. Пассивный listener считает доверенные mousemove; синтетические события игнорируются. Считаются доставленные браузером события, а не расстояние или все аппаратные пакеты.

Никаких координат, траекторий, кнопок, клавиш, текста, raw events или временного ряда в storage/экспорте. Только ограниченные счётчики и сведения покрытия возвращаются непосредственно native API в собственный UI; нового MAIN-моста или wire enum нет. Detector остаётся активен при переходе браузера на выбранный сайт: скрытие вкладки Options не останавливает движения. Только embedded Detector включает опрос Inspector при скрытии; остальные поверхности сохраняют прежний режим. Native committed навигация главного frame инвалидирует snapshot, загрузка дочернего frame не сбрасывает весь интерфейс. Уход из раздела, pagehide/закрытие UI и потеря авторизации вызывают best-effort cleanup. Аварийная потеря UI ограничена lease 120 секунд; при более долгом browser throttling пропуск отмечается partial, мгновенное физическое снятие listener при crash не обещается. Навигация верхнего документа создаёт новый счётчик. Действия сайта (регистрация обработчика и обращение к координатам DET-043) остаются отдельными наблюдениями: агрегированная прежняя проекция не позволяет приписать каждому свой точный count.

В Firefox sandbox globalThis отличается от DOM Window: add/remove listener получают DOM-окно, а private holder остаётся в ISOLATED globalThis. Native frame ID проверяется как неотрицательный safe integer: Firefox использует значения шире 32 бит. Это не меняет границы tab ID, count, generation или canonical wire frame ID; новый счётчик не передаёт frame ID в wire. Опрос ограничен 256 просмотренными/64 выбранными frame и проверяет совпадение native ID в запросе и ответе.

Firefox compatibility adapter заменяет documentId списка frame своим isolated token, тогда как scripting InjectionResult содержит native UUID. Для счётчика Options передаёт отдельную bound read-only getNativeFrames capability из native browser API, чтобы сравнивались именно native UUID. Эти ID остаются внутри controller и не попадают в wire/экспорт. Исполнение скриптов продолжает идти через прежний adapter, включая его отказ для documentIds; canonical adapter и sender verification не изменяются. Chromium сохраняет прежний native getAllFrames default. Оба пути ограничены прежним timeout и лимитами frame.

REQ-012 сохраняется независимо от оставшихся browser grants. Свежая авторизация возвращает scope policy: all-sites требует grantedAllSites; site допускает только точные hosts из scope, native scripting отдельно применяет фактические scheme/host permissions. Перед attach/renew фиксированная ISOLATED-функция повторяет проверку текущих protocol/hostname, поэтому навигация между снимком frame и выполнением не открывает доступ чужому host. Opaque about:blank/srcdoc не получают разрешение по одной строке URL: они исключаются с partial. Active-tab читает существующий доверенный storage.session active-tabs, требует единственный совпавший grant, сверяет native top documentId и использует только target.documentIds для этого документа. Прежний Firefox adapter guard на documentIds не обходится: такой режим остаётся недоступным там, где guard отказывает. Смена policy останавливает прежний controller и закрывает старые leases; интерфейс запускает новый период по свежему scope. Прямое boolean true не является frame policy.

## Локальная история

Существующая явная Save PRO сохраняет валидированный остановленный PRO-сеанс в локальный архив IndexedDB detect-expert-pro-report-history. Используются прежние разрешённые redacted/selected PRO-данные и существующий validateProSession, включая ранее явно записанные разрешённые поля ADR-036/037/039; не считываются браузерные PDF-файлы. Автосохранения каждого опроса нет. Максимум 20 записей и 8 МиБ JSON-содержимого, а не обещание физического размера базы; при переполнении сохранение отказывает, старые отчёты не вытесняются.

Список доступен без источника и не включает наблюдение. Viewer открывает архив по проверенному ID; архивная ссылка не подменяется live-сеансом после удаления. Прежняя live-ссылка сохраняет прежний маршрут. Удаление из истории — явное действие. Новый текущий PRO-сеанс, его отдельная очистка или переключение scope/OFF не стирают явно сохранённые отчёты. Live-запись и текущие кэши сохраняют свои прежние forget/access границы; расширение доступа к новому сбору не добавляется.

Глобальная очистка и отзыв согласия с очисткой удаляют архив в background даже при закрытых UI. Атомарные epoch-fences до и после сброса исключают восстановление удалённых записей поздним save. При ошибке purge успешная очистка не заявляется. Нет новых privileged message routes, sender exceptions, canonical wire-схем, разрешений, CSP, сети или изменений Protect.

Проверки: внутренний отчёт. Семантика injected counter, stale source/reload, all-UI-closed purge и поздние writes требуют независимого review и отрицательных fixtures.
