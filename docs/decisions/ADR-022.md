# ADR-022. Cookie totals, explicit site cleanup and richer purpose analysis

Status: Accepted, implemented. Explicit owner request of 2026-10-09. REQ-004/005/007/011/012/013; extends ADR-021.

The owner requested a visible total Cookie count, a top-of-panel “clear cookies for this site” button, coloured tracking cookies, local company marks and fewer unclassified common cookies. The cleanup command is a narrowly scoped exception to REQ-001's informational-only behaviour, authorized by that explicit request: it changes only local browser cookies for the selected site's registered domain and subdomains, through a trusted extension UI click. It is not an automatic anti-identification action; MAIN/page messages cannot invoke it.

The new canonical privileged request is `ui-clear-site-cookies` with tab/frame/document identity only. The background verifies the extension UI sender and collection consent, then authorizes the current selected document and trusted top-level document before querying/removing cookies. Native cookie-store selection comes from the selected tab. No caller-supplied domain, URL, store or partition override is accepted. Cleanup targets the current top-level registrable domain and paths/subdomains of that site in that store; cookies of externally loaded services, other sites/stores and other top-level partitions are excluded. Native identity/path/partition data is bounded transient API input; no Cookie value is read. Query/result and physical job budgets, epoch guards, navigation/revocation/clear races and uncertain remove timeouts stop further work and return actual partial counts.

The response is a canonical `cookies-clear-state` with the requested document identity, bounded `removedCount`, `failedCount` and `truncated`. There is no optimistic “all deleted” message. UI cannot replay a stale destructive request automatically; pending navigation/permission changes discard the old UI result and the backend stops future removals. The same-site Cookie snapshots and in-flight reads are invalidated before/after cleanup; metadata is read again on the current document after the explicit operation.

Cookie snapshots may carry optional `totalCount` and `siteCount`, leaving old Pro snapshots valid. `totalCount` is the number of unique accessible inventory identities observed before the display cap; `siteCount` is the subset belonging to the trusted top-level site. Display/scan/time/identity limits make counts lower bounds, indicated by “≥”. The existing tracking badge still counts classified tracking entries and is distinct from the total. Native scanning and memory remain bounded; snapshot entries stay ≤256 and do not acquire raw identities or values.

Tracking entries are visually distinct. Company images are packaged locally with provenance/licensing; an unknown owner uses a neutral fallback rather than an invented company attribution. There are no remote image requests or new permissions/dependencies. Purpose rules are expanded using primary documentation; stable conventional framework names can describe session/CSRF use without proving a vendor or judging a site legitimate. Unique documented mixed-purpose records may retain their documented owner/purpose with category unknown and tracking false. Unscoped community hints and competing owners do not become tracking merely to reduce unknown counts.

Acceptance: independent trust/privacy/API-semantics review; canonical request/result and backwards-compatible count validation; scoped native removals, Secure/HttpOnly/path duplicates, other domains/stores/partitions untouched, counts matching actual inventory, no value/getter/token export, cancellation after navigation/revocation, partial/failed removals, no double click/retry, local image resolution/offline assets, catalogue domain/auth false positives, Chrome and installed Firefox fixtures. Changes to active sensor hooks and GTM attribution are outside this task.

Review: independent A backend/privacy/count review, B catalogue false-positive review, C privileged request/background route review accepted. Native Chrome 17 and installed Firefox 25 assertion groups; 1 157 Vitest + 364 Node pass. Final evidence and measured limits: Cookie task report.
