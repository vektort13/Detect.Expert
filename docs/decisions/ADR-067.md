# ADR-067 — наблюдаемые API текущей страницы в API Guard и Antidetect

2026-10-21. Прямое решение владельца продукта: выделять пункты API и Antidetect, если соответствующая технология замечена на текущем сайте или его сторонних ресурсах. E22-21.

## Источник и границы

Используются существующие read-only `ui-get-report` и browser-owned frame identities. Permissions, сенсоры, пороги детекторов, Firewall и настройки блокировки не расширяются. В factory окна управления передаётся существующий `sendUiRequest`, который валидирует канонический response; сообщения страницы и новые privileged команды не добавляются. Единственное совместимое уточнение wire-валидации — верхняя граница существующего `ui-get-report.frameId`: неотрицательный safe integer вместо safe32. Firefox выдаёт frame IDs больше 32 бит. Ручные validators и JSON Schema синхронизируются; `tabId`, прочие числовые поля, команды и проверка отправителя сохраняют прежние границы.

Контекст наблюдения — единственная явно переданная вкладка `options.html?tabId=N`, которую передаёт существующий API launcher. ID строго проверяется через getAll: ровно одно decimal safe32 значение. Он не связан с редактируемым global/site scope. Нет автоматического выбора произвольной вкладки или страницы Options. Antidetect и API Guard используют один snapshot; смена вкладки интерфейса не сбрасывает настройки и черновики.

Controller работает только на точной собственной top-level Options, пока виден один из двух разделов и документ расширения не скрыт. Один физический refresh, polling1с, deadline4с с удержанием физического слота до settlement. Browser-owned frame identities проверяются до и после чтения. В Firefox используется существующий adapter, который восполняет document identity через isolated world; нативные события используются для снимаемых обработчиков инвалидации. Не более32 документов,4 параллельных child read; неполнота обозначается. Навигация, удаление/замена вкладки, отзыв доступа, consent/scope, скрытие и dispose инвалидируют ответы. Исходные URL используются только временно для origin/scheme сравнения; в UI передаются прежние redacted report hosts.

## Семантика соответствия

Чистый bounded mapper связывает существующие точные `apiOperations` с каталогом API. Technique fallback разрешён лишь для однозначного семейства. Общий DET-025 не доказывает чтение каждого navigator свойства; общий DET-032 — отдельно CPU/таймеры; DET-058 — отдельно WebSocket/WebTransport. Неоднозначные соседи не подсвечиваются. Событие только `threw-sync` означает попытку, не успешное использование и не подтверждённую блокировку.

Надпись о fingerprint pattern появляется только из уже имеющегося `interpretation: fingerprinting-pattern`; одиночный Canvas или WebGL вызов её не создаёт. Регистрация настроек Custom, наличие метода или загруженного скрипта не считаются наблюдением. Технические значения, изображения и Pro/API-results не нужны.

Report apiOperations не содержит hostname конкретного script caller. Метки стороннего контекста относятся к **исполняющему фрейму**. Внешний скрипт, исполняющийся в основном документе, включается в наблюдения этого документа, но не получает выдуманную атрибуцию. Нельзя приписывать API вендору по наличию его network resource.

Custom может порождать внутренние операции на приватных copies; UI показывает бинарное присутствие, а не «точное число вызовов сайта». Существующие насыщаемые counts используются для положительного predicate и bounded merge. Ненаблюдаемая строка не объявляется неиспользуемой: coverage сенсоров сохраняется.

## Интерфейс

Общая контрастная подсветка и текстовый badge в API Guard и Antidetect, контекст источника/coverage сверху, флажок фильтра наблюдаемых пунктов. Цвет не является единственным носителем смысла. Есть dark, forced-colors, RTL и21 локаль. Dedicated WebRTC/media/DTLS/network/Math cards используют тот же mapper; DTLS требует точного certificate события. Режимы, выбранные значения, CAS и сохранение независимы от обновления наблюдений.

## Проверка

Нужны независимые mapping/false-positive/lifecycle проверки; отсутствие getter/value чтений и записей настроек; late reply/navigation/frame reuse/revoke/timeout/dispose; фактический Chrome/Firefox UI с собственными parent/child fixtures, обновлением наблюдений и сохранением черновиков; локализации/узкий экран/dark/RTL; обе сборки и проверка package/source bytes. Результаты — в отчёте E22-21.
