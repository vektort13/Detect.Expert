# ADR-001. Уровни достоверности, claims и границы продукта

Статус: **Accepted** (2026-09-12). Владелец: архитектура/security (TBD). Заменяет: —.

## Контекст

Исходное ТЗ смешивало факт вызова API, вывод о цели и принадлежность вендору в одном `confidence` (AUD-02), использовало заголовок «легитимные антифрод-системы» (AUD-01) и писало «canvas даёт стабильный ID» как факт любого чтения пикселей (AUD-12). Продукт информационный (REQ-001, REQ-007): распознанный вендор ≠ доверие, отсутствие находок ≠ безопасность. Нужна модель, в которой каждое публичное утверждение имеет проверяемый тип evidence.

## Решение

1. Три независимые оси плюс coverage, с каноническими wire-именами (`docs/PROJECT_RULES.md`, ТЗ VI I1.1):
   - наблюдение: `evidenceSource`, `integrity`, `count`, `countQuality`, `phase`;
   - интерпретация: `interpretation`, `interpretationConfidence`;
   - атрибуция: `attributionConfidence`, `vendorConfidence`;
   - coverage: `coverageState`, `coverageFlags`, `dropped`.
   Один числовой «процент доверия» запрещён.
2. Три типа карточек UI: `api-use` («Использован API»), `possible-fingerprinting` («Есть признаки вычисления отпечатка»), `vendor` («Распознанные сервисы защиты и идентификации»). Карточка сначала показывает наблюдение, затем интерпретацию, затем назначение в целом.
3. Каталог утверждений (`PRD.md` §6): каждое утверждение UI/Store имеет тип **observed / inferred / catalog** и колонку «что не утверждается». Новое публичное утверждение добавляется в каталог до появления в коде.
4. Слово «защита» не используется для описания функции наблюдения. Нет «сайт безопасен», «утечка доказана», «легитимные», «невидимо», «100 %». Полный список требований — `docs/ui-copy.md` §8. Проверка локалей выполняется через `pnpm test:unit` (`packages/ui/test/locales.test.ts`): паритет ключей/placeholder и реализованный список запрещённых подстрок. Контекстные требования §8 пока покрыты не полностью (F089); `pnpm lint` эту проверку не запускает.
5. `integrity: page-controlled` для всего, что пришло из MAIN/DOM; `browser-observed` только для `webRequest`/`webNavigation`. Нонс и `event.source` — маршрутизация.
6. «Не обнаружено» допустимо только рядом с периодом и областью наблюдения: «За этот период в доступной области находок нет».
7. `interpretationConfidence: high` допустим только для fixture-verified шаблона в пределах наблюдаемости; до калибровки (ADR-010) — `low`/`unassessed`.

## Последствия

- Схемы `packages/contracts` содержат ровно эти поля; параллельные имена отклоняются review.
- UI обязан рендерить `coverageState` до списка находок; пустое состояние без coverage невозможно.
- Каталог вендоров показывает семейство, не «самый дорогой продукт»; описание назначения — catalog-утверждение.
- Дополнительная работа: content-тесты на все локали (E13-01), контекстные проверки запрещённых утверждений в unit-тестах (F089).

## Приёмка

- Нет неоднозначного слова «защита» для функции наблюдения ни в одной локали (grep по `_locales` и Store copy).
- Каждый экран/строка трассируется в `PRD.md` §6 с типом evidence.
- Screenshot/state-тесты для каждого неполного режима coverage (REQ-006).
- UX-проверка: участник отличает сервис от гарантии безопасности (ТЗ V §7).
