# ADR-002. Toolchain, API-floor и поддерживаемые Chrome builds

Статус: **Accepted** (2026-09-12, зафиксировано в `docs/PROJECT_RULES.md`). Владелец: release/supply chain (TBD).

## Контекст

ТЗ VI I2 предлагает WXT как сборочную оболочку и допускает прямую сборку с собственной генерацией manifest, если spike выявит несовместимость MAIN output/CSP. AUD-24: Node 20 EOL; AUD-25: WXT/Preact — проектный выбор, не консенсус. MV3 запрещает `eval`/`new Function` в extension pages (CSP `script-src 'self'`), поэтому Ajv-валидатор в runtime невозможен. Chrome 153 Stable с 08.09.2026, двухнедельный цикл; `documentId` 106+, `sidePanel.open()` 116+, `matchOriginAsFallback` 119+.

## Решение

| Область | Решение |
| --- | --- |
| Runtime/пакеты | Node 24 LTS как target (`engines: ">=24 <26"`); pnpm `10.17.1` (`packageManager`); lockfile обязателен; `latest` запрещён |
| Язык | TypeScript strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, ES2022, ESM, `verbatimModuleSyntax` |
| Сборка | `esbuild` через собственный `scripts/build.mjs`; **WXT не используется**: нулевой runtime-код фреймворка в MAIN-сенсоре, прозрачный аудируемый output, строгая CSP, отсутствие dev-server/HMR-инъекций в production |
| Manifest | Генерируется из типизированного `apps/extension/manifest.ts`; профили `local`, `test`, позже `managed-connected`; `manifest.json` не редактируется руками |
| UI | Preact (`jsxImportSource: preact`), обычный CSS с tokens, без внешних ресурсов; строки — `_locales/ru` (default), `_locales/en` |
| Валидация | Ручной runtime-валидатор в `packages/contracts` (без `new Function`); `ajv` — только в тестах для кросс-проверки JSON Schema с ручным валидатором |
| Тесты | `vitest` (unit, Node); Playwright `chromium.launchPersistentContext` + `channel: 'chromium'` с собранным production-пакетом и test-профилем manifest |
| Иконки | `@resvg/resvg-js` из `logo.svg` → `icons/16,32,48,128.png` |
| Chrome floor | API-floor 119; production `minimum_chrome_version` — из `browser-support.json` (точные build ID Stable/Beta/Extended Stable, ОС, дата последнего успешного прогона); проверка Beta каждый цикл |
| Namespace | `chrome.*`, не `browser.*`; `runtime.onMessage` — синхронный listener + `return true` + `sendResponse` |
| Команды | `pnpm typecheck`, `lint`, `test:unit`, `test:extension`, `test:privacy`, `test:perf`, `catalog:lint`, `build`, `release:verify` — каждая реально проверяет, а не возвращает 0 |
| Зависимости | Новые — только с записью в результате задачи и обоснованием; install scripts и транзитивные сетевые загрузчики проверяются при review |

## Последствия

- `hook.main.js` и `bridge.js` собираются как IIFE без импортов UI/фреймворков; build scan проверяет отсутствие `eval`, `new Function`, remote URL, `import()` по сети.
- Тесты в Playwright не используют брендированный Chrome с `--load-extension` (флаги удалены); ручные проверки Stable/Beta остаются отдельным этапом.
- Локальная разработка на Node 25 допустима; воспроизводимость на Node 24 — требование приёмки. Подтверждённого CI-прогона нет.
- Потеря удобств WXT (auto-manifest, HMR) компенсируется `manifest.ts` и watch-режимом esbuild.

## Приёмка

- Чистый checkout → `pnpm install --frozen-lockfile && pnpm build` воспроизводит пакет (hash совпадает на двух машинах).
- `browser-support.json` присутствует и заполнен фактическими прогонами до релиза.
- `pnpm release:verify` отклоняет output с dev-скриптами, `eval`, внешними шрифтами, source maps с секретами.
- Reproduction: документированная команда даёт тот же `manifest.json` и список permissions (diff пуст).

## Release preflight — 2026-09-12 (F087/F091/F147/F165)

release:verify до сборки печатает Node и отклоняет версии вне >=24 <26; .npmrc включает engine-strict. Выполняется настоящий pnpm install --offline --frozen-lockfile --ignore-scripts с уже установленным store; печатается SHA-256 lockfile и проверяется его неизменность. Ошибка несовпадения manifest/lockfile останавливает процесс до build. Сгенерированный minimum_chrome_version независимо сверяется с browser-support.json; permission/CSP allowlist сохранён, тестовый tabId override в local bundle запрещён.

Прогон интеграции: Node v25.2.1, pnpm 10.17.1, локальный offline preflight и упаковка прошли. Воспроизводимость SHA-256 между двумя независимыми Node 24 окружениями и owner review release-процедуры ещё не подтверждены (F076); этот прогон не заменяет их.

## P10 — гигиена релизного пакета (2026-09-13)

`pnpm sbom` создаёт минимальный CycloneDX-подобный инвентарь из lockfile/node_modules, отдельные таблицы встроенных и dev-зависимостей и NOTICE без сети. Release gate проверяет hash lockfile и соответствие артефактов генератору; build по esbuild inputs запрещает неучтённую внешнюю runtime-зависимость. Preact MIT, исходник PSL и MPL-2.0 уведомления доставляются вместе с ZIP. Код распространяется по MIT; название и логотип остаются за автором. Формат/ограничения: `docs/release/README.md`. Зависимости, manifest, permissions и CSP не изменены.

**Сравнение хэшей на второй машине: не выполнено.** Локальный повторный хэш не заменяет два независимых Node 24 окружения. Owner review release-процедуры обязателен перед публикацией.
