# ADR-098 — включение Firewall без отдельного подтверждения

Дата: 2026-11-01. Прямое решение владельца продукта: убрать показанное предупреждение «Включение модуля „Защита“» при включении Firewall. Это узкое изменение production UI поверх ADR-020-protect, ADR-047, ADR-053, ADR-062 и ADR-090.

Единственный явный клик по включению заменяет прежние дополнительный диалог и checkbox. Launcher popup/sidepanel и основная страница вызывают существующий `session.enable` непосредственно из события, до любого await, сохраняя возможность штатного запроса разрешений браузера. Открытие страницы, mount, refresh и смена policy не включают модуль.

Сохранённые непустые features/preset используются без изменения. Для первой активации и пустого набора применяются прежние canonical defaults: value-match, firewall, session-replay, режим normal. History и GPC по умолчанию остаются выключены. Изменение выбранных функций и режима после включения остаётся в прежних настройках.

Удаляются только production activation modal/inline UI и связанные с ними локальные состояния. Версия/digest протокола включения, проверка sender, managed policy, persist-before-activation, запрос native permissions, обработка ошибок, блокировка повторных кликов и отображение фактического ответа сохраняются. UI не записывает поддельное согласие и не меняет storage напрямую. Выключение верхним переключателем по-прежнему вызывает disable(false); отдельное подтверждение удаления всех данных сохраняется.

Vendor остаётся byte-identical. Backend/collector/field reader/MAIN, DNR, wire, permissions/CSP и Firefox unavailable не меняются. Переход на direct activation не ослабляет правило «пароль не читается ни одним слоем». Обязательны независимый review, unit/semantic tests и native password privacy gate по ADR-047. Результат и фактические ограничения: отчёт.
