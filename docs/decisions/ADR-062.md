# ADR-062 — настройки и согласие Firewall на странице

Обновление 2026-11-01: [ADR-098](ADR-098-direct-firewall-activation.md) по прямому решению владельца продукта убирает отдельную inline-форму подтверждения включения. Кнопка вызывает прежний enable из явного события; настройки, canonical defaults и backend проверки сохраняются.

Статус: реализовано, независимо проверено и прошло production gates 2026-10-20. Отчёт E22-15. Прямое решение владельца продукта; продолжает ADR-020-protect §6/§15, ADR-047/053/055.

Владелец попросил перенести настройки функций и режима из consent popup на основную страницу Firewall, сохранив их видимыми, но серыми при выключенном модуле. Разрешается только изменение presentation в production Options UI: реальная inline-секция вместо dialog/showModal/фокус-ловушки для этой страницы. Первое подтверждение включения остаётся явным действием пользователя на этой же странице.

Все прежние блоки согласия, предупреждение strict, обязательный checkbox, версия/digest и вызов существующего session.enable непосредственно в trusted click сохраняются. До успешного ответа controller нет ON, чтения полей, новых DNR или запрашиваемых расширением разрешений. Открытие страницы/редактирование черновика/Cancel не меняют настройки; отказ и managed policy не объявляются успешным включением.

Операционные функции и режим при OFF/ожидании/запрете имеют настоящие disabled-controls и остаются видимыми. Для первичной настройки после нажатия Enable временно редактируется локальный consent draft; это не активирует модуль. Просмотр/удаление сохранённых данных при OFF сохраняет прежние границы backend. Активные функции используют существующие session.setFeatures/setPreset и существующие проверяемые sender-пути.

Vendor остаётся побайтовой копией 722fae8. Адаптер production заменяет ProtectSection через существующий bundler redirect. Узкий onLoad transform для точного FirewallRulesPanel меняет единственный проверяемый gate формы режима running → firewallOn: когда функция блокировки выключена, собственный неактивный preview заменяет editable-форму, без дублирования. Это не расширяет permissions/CSP, wire enum, контракт, storage, DNR, сбор ввода или утверждения UI. Launcher popup/sidepanel сохраняют прежний первый consent dialog по ADR-053.

Приёмка: независимый review чувствительных границ; digest согласия сохранён; typecheck/lint794/unit3471, воспроизводимость module build, Chrome UI15/64 снимка и release:verify (privacy7/overlay11/management8/обе сборки) PASS. 28 native/dist/ZIP SHA-сверок и восемь неизменённых чувствительных исходных файлов подтверждены. Подробности и ограничения — в отчёте E22-15.
