# ADR-058 — Firewall popup внутри страницы

2026-10-20. Прямое решение владельца продукта: исправить пустое кратковременное окно при включении Firewall, использовать общий дизайн и собственный заголовок. После объяснения ограничения системной рамки Chrome владелец выбрал: «Popup внутри страницы с нашим заголовком». Заменяет автоматические отдельные окна ADR-052/054; остальные правила ADR-020-protect/047/053/055 сохраняются. REQ-002/003/004/005/010/011/012/015; E22-09.

## Решение

Активация и положительные находки показываются в точном верхнем документе HTTP(S)-вкладки через собственный ISOLATED `firewall-overlay.js`. Нативные `windows.create` для этих двух показов удалены из SW-маршрута. На внутренних страницах браузера и при недоступном документе отдельного окна-заглушки нет. При обычном восстановлении ON уведомление включения не показывается.

Внутри страницы используется closed ShadowRoot и немодальный manual popover верхнего слоя. CSS полностью локален, встроен в bundle и применяется как constructed stylesheet; политика CSP сайта не требует расширения manifest/CSP расширения. Переменные палитры определяются на закрытом внутреннем узле, оформление ограничено собственным деревом. Используются прежние логотип, glass-палитра, цвета тем, видимая полоса прокрутки и локализованное закрытие. Автоматический показ не переводит фокус. Ширина: 360 px у включения, до 600 px у находок, ограничена viewport; маленький viewport уменьшает отступы.

UI устанавливается только при наличии готового проверенного payload, поэтому нет отдельного пустого окна и ожидания сетевого/языкового ответа в открытой оболочке. Подтверждение включения живёт пять секунд от собственного DOM commit. Обновление того же generation срок не продлевает. При pagehide UI закрывается; состояние выключения, purge/политика/отзыв и ограниченный refresh также снимают устаревшую карточку.

В обычном Chrome открытый action popup может временно снимать native focus с окна сайта. Подтверждение включения ожидает возврата фокуса не более пяти секунд, с проверкой каждые 100 мс и deadline нативных чтений 500 мс. Исходные tab/window/document закрепляются до ожидания; смена вкладки, навигация, OFF или новый epoch отменяют показ. Само расширение фокус не меняет. Если меню остаётся открытым дольше срока, косметическое подтверждение пропускается; включение Firewall сохраняется.

## Доверие и действия

Новый `protect-overlay-*` — внутренний SW ↔ ISOLATED канал, а не MAIN bridge. Нет слушателя `window.postMessage`/публичного page apply. Показ и снятие адресуются через нативные `tabId/documentId`, frame 0; HTTP(S), текущий документ, видимость/фокус источника, согласие, состояние модуля и исключение перепроверяются до и после await. Generation — только маршрутизация и защита от устаревания, не аутентификация.

В SW `protect-overlay-action` проверяет extension id, native MessageSender, top frame, документ, generation и текущий контроллерный snapshot. Поля маршрутизации тела запроса запрещены. Совпадение prompt/document/revision/receiver проверяется перед построением канонического запроса Firewall. Нельзя вызвать enable, export, purge, чужой tab, произвольный URL или общую настройку через этот канал.

Closed shadow, native popover, изолированная палитра, проверка доверенного события/попадания и приватный JS client ограничивают вмешательство страницы. Они не доказывают намерение пользователя и не превращают веб-страницу в доверенный browser UI. Поэтому inline разрешены только решения `once` текущего prompt. `site`/`everywhere` и глобальная пауза открывают собственную страницу расширения с актуальной карточкой для подтверждения. Settings использует существующее единое окно управления ADR-055. Undo разрешает только IDs реальных успешных inline once-решений этого документа: максимум 32 ID на документ, 64 документа, TTL 15 минут; навигация/выключение очищают ledger.

Сведения о полях остаются прежней проекцией без значений, производных, raw URL, SDP/IP или credentials. Наблюдающие wrappers, реальные requests, редактор Custom и хранилища/согласие модуля не изменяются. Вендорские файлы побайтово прежние. Два document ID lookup в FirewallCard заменяются только при сборке overlay на собственный shadow lookup; точное число вхождений проверяется до адаптации. Document API глобально не патчится.

## Ограничения и приёмка

Страница может убрать host или мешать UI. В таком случае сообщение не является доказательством сетевой блокировки; решение подтверждает прежний backend/DNR. Workers/другие документы/внутренние страницы браузера UI этим способом не покрываются. Firefox по ADR-047 сохраняет stub Firewall.

Очереди, clone, dedup, native await и подтверждение доставки ограничены: 64 документа, 128 семантических ключей на документ/1024 всего, группировка 300 мс, интервал нового показа 10 секунд, native deadline 3 секунды. Получатель подтверждает реально непустой DOM. Отозванные generation и high-water marks не дают запоздалому SHOW восстановить закрытую карточку. После SW restart исторические findings не открываются заново; старое UI теряет полномочия и закрывается по refresh/состоянию.

Проверки: strict sender/ID/stale/receiver/action/timeout unit, typecheck/lint, native Chrome с реальными вводом и отправкой на локальный fixture, trusted once block/Undo, отдельная проверка постоянного review, отсутствие окон, viewport/RTL/темы, CSP, synthetic event и MAIN forgery, навигация/OFF/SW restart, обязательные независимые password-read probes в обоих мирах. Новых dependencies/permissions/сетевых запросов расширения нет. Пакетный Preact отдельно проверяется и пинится только по точному dependency prefix; приложение сканируется полностью.

Фактические результаты и ограничения: внутренний отчёт.
