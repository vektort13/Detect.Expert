# ADR-035 — favicon посещённого сайта в анализе и отчёте

2026-10-09. Прямое решение владельца продукта: показывать значок посещаемого сайта, получать favicon при посещении. REQ-002/005/009/010/011/012/013/015; развитие ADR-018/034.

Используется только `tabs.Tab.favIconUrl`, предоставленный браузером для действительно открытой верхней вкладки. DOM страницы не задаёт команду, tab ID, origin, document ID или произвольный адрес загрузки. До и после операции проверяются native top frame, неизменность document ID, exact origin, favicon URL и действующие consent/scope. Если native `getFrame` не предоставляет document ID, используется единственный frame 0 из существующего нормализованного `getAllFrames` adapter ADR-018: до 128 frames, private ISOLATED identity, exact URL equality с raw frame, active lifecycle и отсутствие ошибки. Native identity не заменяется при наличии; невалидный или изменённый ответ не допускается. Fallback разделяет прежний adapter budget ≤256 identity jobs / 1500 мс, отдельно от ≤4 favicon Image injections. Incognito, prerender/cached documents, схемы кроме HTTP(S), внутренние и IP-hosts исключены. Значок не является основанием для распознавания компании, антифрода или техники.

Захват выполняется через существующий `scripting.executeScript`, в ISOLATED и только frame 0. Адрес изображения временно передаётся из browser-owned `favIconUrl`; в локальное хранилище, bridge, wire и JSON-экспорт он не попадает. HTTP(S) URL ограничен 4096 символами, native data image — 65536. Изображение декодируется как изображение с `crossOrigin=anonymous`, `referrerPolicy=no-referrer`, deadline 1800 мс; размер источника после декодирования не превышает 1024×1024. Firefox может сообщать нулевые natural dimensions для корректного SVG только с viewBox: успешный native `data:image/svg+xml` load получает явный viewport 32×32; HTTP/non-SVG zero-size image по-прежнему отклоняется. Canvas используется только для уменьшения favicon до 32×32. Результат — PNG ≤16 KiB. Исключение к запрету canvas/pixels из REQ-001/005 ограничено прямо запрошенной обработкой favicon: оно не измеряет браузер, не читает canvas сайта и не расширяет контракт сенсора.

Chrome 153 в собственном loopback fixture отдаёт URL: same-origin и CORS-enabled CDN успешно декодируются; без CORS отображается локальный значок глобуса. Firefox 138.0.4 отдаёт native data image, которая декодируется локально для всех трёх fixtures без дополнительного HTTP-запроса расширения. Существующий Firefox adapter предоставляет document identity через приватный ISOLATED realm. Это не обещание работы произвольного CDN: production использует фактический browser result.

Отдельный `storage.local` key `site-icons:v1` содержит только `{version:1, entries:[{host,png,at}]}`. `host` — уже показываемый registrable domain; полные URL, path/query/fragment, сырой stack, cookies, токены и favicon-source не сохраняются. Валидация принимает только PNG 32×32 с IHDR/IDAT/IEND, без metadata chunks и хвостовых данных. До 64 сайтов, ≤512 KiB кодированных записей, TTL 7 дней; ≤4 параллельных физических injections, максимум 128 ephemeral tab/document bindings с SHA-256 digest источника. Запуск и обновление привязаны к native tab events и readiness. Повторный capture того же документа/источника подавляется; смена favicon в том же документе запускает новый capture. Обновления во время capture объединяются в один follow-up, без безграничного retry. Navigation/permission/consent races отбрасывают результат; отзыв доступа удаляет cache через сериализованную storage operation. Ошибка удаления декоративного cache не останавливает core permission/protection reconciliation.

Значок декоративный рядом с сохранённым доменным именем, размер 20/24 px, `object-fit:contain`; в печати 15 pt. Нет удалённых favicon-proxy, поиска значка по чужим сервисам или загрузок из UI отчёта. Если записи нет, используется встроенная SVG-пиктограмма глобуса. На один UI instance используется один lazy cache read и один storage listener, до 4096 subscribers с cleanup после unmount; host lookup выполняется через общую Map. Print readiness поддерживает до 4096 иконок (включая максимально допустимый Pro-отчёт примерно на 2501 иконку), отдельно ожидает bounded cache read, переход pending→ready/fallback и декодирование PNG в рамках прежнего 5-секундного общего deadline. Wire, JSON preview/export, manifest, permissions, CSP и зависимости не меняются; PDF/печать включает показанное изображение из локального cache.

Первичные источники: [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) — `favIconUrl` и доступ по существующим host permissions; [Chrome Scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting) — top-frame ISOLATED execution; [Mozilla executeScript](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/executeScript) — execution worlds и native results; [Mozilla tabs](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/tabs) — доступ к favicon через host permissions; [crossorigin](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/crossorigin) — anonymous image/CORS.

Проверки: 37 unit/adversarial cases в `scripts/test/site-favicon.test.mjs`, включая native/normalized frame identity, bounded/missing/ambiguous/error/inactive metadata, origin/ID changes и revocation при normalization, narrow loaded-native-SVG exception и negative HTTP/non-SVG/decode-failure cases, startup pruning физически устаревших/некорректных записей, обновление native favicon во время capture, 2501 shared subscribers и failure core permission reconciliation; нативные source-format/CORS fixtures `test-results/production-1.1.0/site-favicon/chrome-prototype.json` и `firefox-prototype.json`, SVG raster controls `firefox-svg-controls.json`. Production acceptance и hashes конечных пакетов фиксируются в отчёте задачи, совместно с проверкой логотипов компаний.
