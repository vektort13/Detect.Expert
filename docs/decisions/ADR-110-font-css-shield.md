# ADR-110 — Щит шрифтов в HTML/CSS для опции «Шрифты» Антидетекта

Дата: 2026-11-07. Прямое решение владельца продукта: «Вот эту опцию Шрифтов и CSS нужно реализовать. Реализацию возьми из https://github.com/ProxyShard/ShardBrowser». Повод: подпись под опцией «Шрифты» (уровень «ОС») говорила «Ограничивает шрифты текста на Canvas списком Windows … Проверка шрифтов через HTML/CSS не меняется», а строка покрытия — «Не покрыто: проверка шрифтов через HTML/CSS и точные метрики». Это решение сознательно отменяет пункт «`FontFace local()`» раздела «Не реализовано» [ADR-108](ADR-108-shardbrowser-owner-decisions.md).

## Что нашлось в ShardBrowser (REQ-015)

Публичный репозиторий `ProxyShard/ShardBrowser` — лаунчер (Tauri/React, MIT), SDK и документация. Движок, который «закрепляет набор шрифтов на уровне системы», — закрытый пропатченный Chromium, и в репозитории его нет. Есть только настройки и слова: поля профиля `fonts` и `fonts_local`, `noise.fonts` (`real` / `auto`: «скрывает небольшой детерминированный поднабор шрифтов профиля»), описание наборов шрифтов по группам и утверждение README, что подходы на JavaScript протекают через CSS и canvas. **Переносить оттуда нечего**, а [ADR-107](ADR-107-shardbrowser-ports.md) запрещает копировать код и тексты. Репозиторий использован как справочник поведения: профиль объявляет набор шрифтов, страница находит только его, шрифты хоста вне набора не видны. Одно из его заявлений не перенесено намеренно: «объявленные семейства, которых нет на машине, всё равно измеряются как присутствующие». Это движковая подмена метрик; расширение создало бы шрифт, который не умеет измерять и не должно рисовать (REQ-001), поэтому такого поведения нет и не будет заявлено.

Всё ниже — собственная реализация внутри MV3 и собственные измерения.

## Что изменено в границах

- **Строка `canvas-font-policy` действует шире Canvas.** При режиме Custom она по-прежнему подменяет семейства в `CanvasRenderingContext2D.font` и теперь ещё делает так, чтобы известные имена шрифтов из встроенного списка, которых нет в списке профиля, измерялись в документе как не установленные (DOM, SVG-текст, Canvas и OffscreenCanvas окна, во всех фреймах, которые получает профиль). Идентификатор строки, формат (9) и каталог (10) не менялись; сохранённые профили получают щит при следующей сверке регистрации.
- **Один хук с изменённым аргументом** (исключение из «оригинал ровно один раз с исходными аргументами», как у второго нормализованного сеттера Canvas в ADR-087): конструктор `FontFace` вызывается один раз с исходными `this`/`new.target`; строка источника (только примитивная строка ≤ 4096 символов) получает вместо `local("имя скрытого семейства")` токен `local("detect.expert absent")`. Больше ничего не заменяется: ни результат `check()`/`load()` (они не изменены), ни свойства `FontFace`, ни `document.fonts`.
- **Одна правка общего документ-рантайма** (`api-custom-document-runtime.js`): для уже установленного окна, которое заняла новая страница, вызывается необязательный `install.refresh(win)`. Без него щит терялся бы в `srcdoc`, `blob:`/`data:` и в same-origin фрейме, который переходит с начального `about:blank` на URL: окно переиспользуется, а таблица стилей принадлежит документу. Хэш-пин файла в `scripts/production/lint-inventory.json` обновлён (обзорное исключение innerHTML-строки не менялось).
- **Правка Canvas-политики** в `api-custom-surfaces-runtime.js`: грани щита (`unicode-range: U+10FFFF`) не считаются «зарегистрированными страницей» и не расходуют предел сканирования в 256 граней. Сгенерированные opaque-бандлы пересобраны (15 файлов `api-custom-opaque.*.js`).
- Новых permissions, CSP, сетевых обращений, каналов сообщений, зависимостей и ключей хранилища нет. Ничего не измеряется и не рисуется расширением (REQ-001); данные страницы не читаются и не сохраняются.
- Защита остаётся выключенной по умолчанию и действует только при включённом мастере и строке Custom (области «все сайты» и правила сайтов — как у остальных строк). Выключено = побайтно родное поведение (проверено).

## 1. Исследование: что работает, что протекает (измерено)

Хост владельца: Windows 11; Chromium 153.0.8010.12 (Playwright), установленный Chrome 156.0.8078.80, Firefox 138.0.4. Зонд — классический метод разности ширин («тестовое семейство, затем monospace / sans-serif / serif» против голых баз), в DOM, SVG, Canvas и OffscreenCanvas. На этой машине зонд видит 202 имени из списка в Chromium (Chrome 156 — то же) и 230 в Firefox.

| Вариант правила `@font-face` в таблице стилей, принятой документом (имена — установленные на хосте) | Результат |
| --- | --- |
| `@font-face { src: local("несуществующее") }` | **Не скрывает**: все 33 установленных имени пробной выборки остаются видны. Грань, у которой не загрузился ни один источник, не закрывает семейство: Chromium 153 берёт системный шрифт с тем же именем. Предположение «семейство станет недоступным» оказалось ложным |
| `local("то же имя")` + `unicode-range: U+10FFFF` | Скрывает 27 из 33; остаются псевдонимы и неточные имена (Magneto, Helvetica, Times, Courier, MS Sans Serif, MS Serif) |
| `url(data:font/woff2;base64,…)` + `unicode-range: U+10FFFF` | Скрывает все, грани остаются `unloaded`. Но при CSP `font-src 'self'` загрузка шрифта блокируется, грань переходит в `error`, системный шрифт возвращается, а страница получает события `securitypolicyviolation` (сообщения о нарушении CSP отправились бы на сервер сайта). Отклонено |
| **`local(Arial), local("Segoe UI"), …` + `unicode-range: U+10FFFF` + `font-stretch: 200%`** | **Выбрано.** Скрывает все, ничего не загружается, CSP не затрагивается (`local()` — не запрос), событий нарушений нет |

Почему работает: семейство, определённое гранью с действующим источником, не отдаётся платформе; единственная кодовая точка диапазона (U+10FFFF, не символ) не встречается в тексте, поэтому ни один символ не берёт глифы из грани и вёрстка переходит к следующему семейству списка — как для отсутствующего шрифта. `local()` берёт общедоступные шрифты (Arial, Segoe UI, Helvetica, Roboto, Noto Sans, DejaVu Sans, Liberation Sans, Ubuntu, Cantarell, Tahoma); нужен лишь один, найденный на хосте. Если ни один не найден, щит открыт (отказ в сторону родного поведения).

**`font-stretch: 200%`.** Если страница сама определяет веб-шрифт с тем же именем, но не всеми начертаниями, грань щита (400, normal) выигрывает подбор начертания у ближайшей страницы: Chromium 153 без `font-stretch` теряет веб-шрифт страницы в 4 из 7 запросов, когда определён только вес 700, в 5 из 7 при одном курсиве, в 6 из 7 при одном весе 300; Firefox 138 тоже расходится с родным. С `font-stretch: 200%` подбор по ширине идёт первым и ставит грань щита последним кандидатом: все пять случаев совпадают с родным, в обоих браузерах (в тесте: свой веб-шрифт веса 700 под скрытым именем отдаётся как и без щита).

**Проверки, которые не нужны** (измерено в Chromium 153, Chrome 156, Firefox 138, до и после щита): `document.fonts.check()` возвращает `true` для любого имени, установленного или нет; `document.fonts.load()` для семейства не из `@font-face` отдаёт пустой массив. Поэтому подмена этих методов не нужна и не делается (утверждение ShardBrowser README о том, что `check()` выдаёт хост-список, на этих сборках не подтвердилось). Остаётся утечка `new FontFace(…, 'local("Имя")').load()`: для установленного шрифта успешно, для отсутствующего — `NetworkError`. Её закрывает хук раздела 5.

**Доставка (тот же зонд, четыре пути).**

| Путь | Итог |
| --- | --- |
| Статический CSS content script (`css:`) | Скрывает во всех контекстах Chromium; в Firefox теряется во фрейме `about:blank`, который страница сама пишет через `document.open`. Файл статический: список зависит от профиля, динамически его не выдать |
| `scripting.insertCSS` из service worker на `onCommitted` (USER или AUTHOR) | **Проигрывает гонку** с первым встроенным скриптом страницы: 33 из 33 имён видны в верхней странице, `about:blank`, кросс-доменном фрейме и всплывающем окне |
| Таблица стилей, принятая документом в MAIN-мире на `document_start` (`adoptedStyleSheets`) | Скрывает во всех контекстах (верхняя страница, `about:blank`, `srcdoc`, кросс-доменный фрейм, всплывающее окно, shadow DOM) в Chromium и Firefox, до первого встроенного скрипта. **Выбрано** — это тот же путь, по которому уже работают все строки Custom |
| Принятие из ISOLATED-мира | Chromium — да, Firefox — не сработало (причина не выяснялась); для фреймов, созданных страницей, всё равно нужен тот же документ-рантайм, что и в MAIN |

Строгий CSP страницы (`default-src 'self'; style-src 'self'; font-src 'self'`) принятие таблицы не блокирует (проверено в обоих браузерах); для `local()` источников это не загрузка.

**Цена.** 600 граней в одном документе: Chromium — `replaceSync` ≈ 1 мс, первая вёрстка +1,1 мс, 0,02 мс на зонд; Firefox — 2 мс и +8 мс. 1000 граней: 2,4 / 1,6 мс и 3 / 15 мс. Для 600 скрытых имён (список Windows 11; до дополнения 2026-11-07 было 605) вклад в страницу — единицы миллисекунд на документ.

## 2. Что и как скрывается

- `FONT_PROBE_NAMES` (`font-probe-names.js`): 702 имени (716 с дополнения 2 от 2026-11-07: добавлены четыре региональные группы CJK, Д9), ASCII, без кавычек, обратной косой черты, запятых, точек с запятой и скобок (то же правило, что у валидатора Custom), без повторов с учётом регистра, без CSS-генериков. Состав: группы списка Windows (`fingerprint-font-groups.js`: ядро 96 = 91 имя таблиц Microsoft + пять псевдонимов платформы с 2026-11-07, Windows 11 6, Office 115, Pan-European 6), плюс 88 имён Windows вне базовой установки (языковые пакеты, Office-эпохи, Terminal; `FangSong` отброшено — это CSS-генерик `fangsong`), 88 macOS, 77 Linux/Android, 57 Adobe и коммерческих, 97 веб/Google, 26 моноширинных шрифтов разработчиков, 42 устаревших и четыре псевдонима только Firefox (`Helv`, `MS Shell Dlg`, `MS Shell Dlg 2`, `Tms Rmn`); остальные пять псевдонимов Windows (`Courier`, `Helvetica`, `MS Sans Serif`, `MS Serif`, `Times`) входят в ядро (`PLATFORM_ALIASES` по-прежнему перечисляет все девять).
- Источники: публичные списки зондирования FingerprintJS и fingerprintjs2 (MIT) и таблицы CreepJS — читались как списки имён (факты; код и тексты не копировались), таблицы шрифтов Microsoft для Windows 10/11 и Office, список шрифтов macOS у Apple, каталог Google Fonts и наборы Ubuntu, Android, ChromeOS. Список составлен и сгруппирован самостоятельно.
- **Скрыто = список минус `families` значения.** Для списка Windows 11 (102 имени) скрыто 600, для ядра Windows 10 (96) — 606, для пустого списка (заявка не-Windows) — все 702 (до дополнения 2026-11-07: 97 имён и 605, 91 имя и 611). С дополнения 2 (Д9) проб-список — 716 имён: для Windows 11 скрыто 614, для ядра Windows 10 — 620, для пустого списка — 716. Office и Pan-European скрыты, пока не включены при генерации. Имена сравниваются без учёта регистра и пробелов по краям. В страницу уходит только скрытая часть (`fontShadow`), а не весь список и не значение целиком.
- **Псевдонимы.** На хосте владельца Windows сама отвечает на `Helvetica`, `Times`, `Courier`, `MS Sans Serif`, `MS Serif` (Chrome 153 и 156), а Firefox 138 ещё и на `MS Shell Dlg`, `MS Shell Dlg 2`, `Tms Rmn`, `Helv`. Сначала они сознательно не входили в список Windows и скрывались так же, как их уже скрывала Canvas-политика; по решению владельца продукта от 2026-11-07 пять псевдонимов Chrome теперь входят в ядро списка и видимы, как у настоящего Windows-браузера (дополнение ниже). Четыре псевдонима только Firefox в списки не входят и скрыты.
- Имена вне списка в DOM по-прежнему видны, если они установлены (Canvas скрывает любое семейство вне `families`, как и раньше).

## 3. Устройство

- `api-custom-font-shield-runtime.js` (`installFontShield`): сериализуется в источник userScripts, самодостаточна, перехватывает встроенные методы один раз (кэш на функции), не вызывает методов, которые страница могла подменить. Создаёт `CSSStyleSheet`, `replaceSync`, принимает её документом (`adoptedStyleSheets` — прочитанный список страницы сохраняется, лист добавляется последним). Не бросает исключений в страницу; сбой считается в `snapshot().unavailable`.
- `api-custom-registration.js`: для строки Custom вычисляет `hiddenFontNames(families)`, кладёт `fontShadow` в запись, подключает установщик, ставит `install.refresh`. Для сайтовых правил список считается отдельно.
- **Лист принадлежит документу, не области (realm).** Окно, которое занимает новый документ, сохраняет патчи, но теряет лист. Поэтому установщик помечает область свойством-символом `Symbol.for('detect.expert/api-custom/font-shield/v1')` (функция освежения, не настраиваемое, не перечисляемое) — найти его можно с любого посредника окна и из любой копии установщика (во Firefox фрейм достигается и скриптом родителя, и собственным); документ-рантайм вызывает освежение при каждом повторном `protect(win)`; оно дёшево, когда документ тот же, и добавляет лист, когда документ новый.
- Взаимодействие с Canvas-политикой (раздел 6).

## 4. Что видит страница (REQ-014)

Щит не прячется. Страница видит: `document.fonts.size` = числу скрытых имён и список граней со статусом, `unicodeRange: U+10FFFF`, `stretch: 200%`; `document.adoptedStyleSheets.length` ≥ 1; после первого макета со скрытым семейством `document.fonts` один раз сообщает `status === 'loading'` и события `loading` / `loadingdone` (Chromium 153 и Chrome 156) или одно событие `loadingdone` без смены статуса (Firefox 138) — это измерено в native, при выключенной опции событий нет; свойство-символ на `window`; `FontFace` — прокси с родными `name` и `length`, `Function.prototype.toString` не маскируется. Страница, которая **присваивает** `document.adoptedStyleSheets = [свой]`, снимает щит с этого документа (измерено; добавление `[...старые, свой]` его сохраняет) — щит отказывает в сторону родного вида. Страница, запросившая скрытый шрифт, получает следующий шрифт своего списка, поэтому её вид может отличаться; подпись у опции говорит об этом.

## 5. `FontFace local()`

Конструктор `FontFace` обёрнут `Proxy` с ловушками `construct` и `setPrototypeOf` (вторая — дополнение 2026-11-07). Источник-строка просматривается без регулярных выражений и без приведения типов: ищутся токены `local(` (без учёта регистра) вне кавычек, имя в кавычках или без, сравнивается с таблицей скрытых (без учёта регистра); токен с экранированием, незавершённый или не простое `local(имя)` остаётся нетронутым. Скрытое имя заменяется токеном `local("detect.expert absent")`, `load()` отклоняется с `NetworkError`, как у отсутствующего шрифта. Остальные аргументы пересылаются как есть, `new.target` сохраняется (подклассы работают), исключение родного конструктора проходит. `FontFace.prototype.constructor` указывает на обёртку. После `stop()` удержанная страницей ссылка на обёртку ничего не меняет.

## 6. Canvas

Политика Canvas (заменяет любое семейство вне `families`) не менялась по поведению. В документе со щитом грани щита перечисляются в `document.fonts` раньше граней, созданных скриптом, и могли бы исчерпать предел сканирования «зарегистрированных страницей» граней (256), поэтому сканирование пропускает грани с диапазоном `U+10FFFF` (через захваченный геттер `FontFace.prototype.unicodeRange`, не считая их). Страница, определившая грань с тем же именем, по-прежнему проходит.

## 7. Не покрыто (честно)

- Имена вне встроенного списка (кроме Canvas). Фингерпринтер с собственным списком может найти установленный шрифт с необычным именем.
- `@font-face { src: local("Имя") }`, написанный в CSS самой страницы: поиск `local()` — запрос платформы, не вёрстка семейства. Перехватить без разбора и переписывания CSS страницы нельзя.
- Workers и `OffscreenCanvas` в них (нет документа и таблицы стилей; для Canvas в Worker действует отдельный путь ADR-101 при включённом движке).
- Изолированные (sandbox без `allow-same-origin`) и другие opaque-фреймы, в которые родитель не может передать профиль: измерено в Chromium 153 — все 113 скрытых и установленных имён остаются видимыми через DOM (Canvas в таком кадре скрывает всё прежней политикой «нейтральных значений»). Закрыть можно отдельным бандлом строки (вопрос владельцу).
- Точные метрики и формы глифов шрифтов списка: берутся с хоста. Шрифты списка Windows, которых на хосте нет, не создаются и не имитируются (на хосте владельца — Windows 11 — список согласован; на других хостах это не подтверждено).
- Серверное определение шрифтов; рендеринг эмодзи и шрифты запасных глифов (`Segoe UI Emoji` и подобные падают на систему сами).
- Всплывающее окно (`window.open`) проверено только лабораторным стендом (скрипт контента вместо userScripts, Chromium и Firefox), не производственным native: без жеста пользователя окно блокируется.

## 8. Откат

Снять строку Custom `canvas-font-policy` (режим Bypass/Off) или выключить мастер: после перезагрузки страницы щита нет, регистрация не содержит установщика. Полный откат ADR: удалить `font-probe-names.js`, `api-custom-font-shield-runtime.js`, вызов в `api-custom-registration.js` (импорты, `hasFonts`, `fontShadow`, `install.refresh`), условие `install.refresh` в `api-custom-document-runtime.js` (с обновлением пина), пропуск граней в `fontPolicy` (с пересборкой opaque-бандлов), тексты `fonts_hint` / `uncovered_fonts_metrics` и чип Partial. Данных в хранилище нет, миграции не нужны.

### Д2. Шум списка шрифтов

Реализация «как у ShardBrowser» (`noise.fonts` `real`/`auto` — «скрывает небольшой детерминированный поднабор шрифтов профиля»; код и тексты ShardBrowser не копировались, ADR-107): детерминированный шум самого списка на этапе генерации профиля, модуль `fingerprint-font-noise.js` (чистые функции, без chrome.* и сети).

- **Что делает.** Список Windows, который пишет генератор в пресете «Строгий», теряет около 3 % необязательных имён. Один и тот же seed при той же заявленной Windows даёт тот же список; другой seed — другой. Список остаётся обычным значением строки (`families`, ≤ 256 имён), виден и правится в редакторе строки.
- **Seed.** Тот же случайный 32-битный seed генерации (`crypto.getRandomValues` в панели; в тестах задаётся), от которого уже зависят ключи Canvas/Audio/WebGL профиля. Соль и хэш — свои (`FONT_NOISE_VERSION = 1`): значения других строк с этим выбором не связаны.
- **Семейство.** Имя вместе с именами, которые продолжают его после пробела (`Candara` + `Candara Light`, `Segoe UI` + `Segoe UI Semibold` …), — одно «семейство»: убирается целиком или остаётся целиком, и вариант никогда не остаётся без базового имени (и наоборот). Семейство с обязательным именем обязательно целиком.
- **Обязательные имена (29 корней).** Никогда не убираются: `Arial`, `Calibri`, `Cambria`, `Comic Sans MS`, `Consolas`, `Courier New`, `Georgia`, `Impact`, `Lucida Console`, `Lucida Sans Unicode`, `Microsoft Sans Serif`, `Palatino Linotype`, `Tahoma`, `Times New Roman`, `Trebuchet MS`, `Verdana` (латинский текст и умолчательные семейства Windows, от которых отталкиваются и сайты, и зонды); `Segoe UI`, `Segoe MDL2 Assets`, `Marlett`, `Symbol`, `Webdings`, `Wingdings`, `MS UI Gothic`, `Franklin Gothic Medium` (шрифты интерфейса, символов и значков Windows и признаки, по которым список читается как Windows); пять псевдонимов (платформа отвечает на них всегда, когда отвечает на сами семейства). С семействами это 39 имён из 96 у ядра Windows 10 и 43 из 102 у Windows 11 (`Arial Black`, `Calibri Light`, `Cambria Math`, `Courier` + `Courier New`, `Times` + `Times New Roman`, восемь имён `Segoe UI …`, четыре `Segoe UI Variable …`). Остальное необязательно: письменности (`Ebrima`, `Gadugi`, `Javanese Text`, `Myanmar Text`, `Nirmala UI`, `Sitka …`), восточноазиатские (`MS Gothic`, `SimSun`, `Yu Gothic`, `Microsoft YaHei` …), рукописные и декоративные (`Ink Free`, `Segoe Print`, `Segoe Script`, `MV Boli`, `Gabriola`), `Bahnschrift`, `Constantia`, `Corbel`, `Candara`, а также Office и Pan-European целиком.
- **Сколько.** K = round(0,03 × число необязательных имён списка): Windows 10 (96 имён, 57 необязательных) — 2; Windows 11 (102 / 59) — 2; с Pan-European — 2; с Office — 5 (211 / 172, 217 / 174 …); все группы (223 / 177) — 5. Это 2,4–3,5 % необязательных имён. Обход берёт семейства по возрастанию 32-битной оценки от (seed, корень семейства) — FNV-1a с солью и финализатор murmur3, только целочисленная арифметика, результат одинаков в любом движке, — и пропускает семейство, которое не помещается в остаток; поэтому убирается ровно K имён (проверено на 250 seed для каждого из четырёх коротких списков и на 40 для списков с Office). Следствие: семейства крупнее лимита (`Yu Gothic` — 7 имён, `Microsoft YaHei` и `Microsoft JhengHei` — по 4) в коротких списках не убираются никогда.
- **Регион** (до дополнения 2 на список не влиял: в модели не было региональных шрифтов; теперь Япония, Корея, Китай, Сингапур, Тайвань, Гонконг и Макао добавляют региональную группу CJK, Д9), поэтому два профиля с одним уровнем и регионом различаются только шумом: двумя именами в списке Windows (среди 400 seed для списка Windows 11 268 разных наборов из примерно 740 возможных; в 197 из 200 пар соседних seed наборы различаются).
- **Переключатель.** Одно управление: «Шум списка шрифтов» (Выкл. / Вкл.) в быстрых настройках, в форме генератора после часового пояса, с подсказкой (`aria-describedby`). **По умолчанию был выключен; с дополнения 2 включён (Д8).** Состояние — `useState` панели рядом с остальными выборами генератора (устройство, ОС, браузер, версия, GPU, экран, язык, часовой пояс): это выбор генератора, а не строка конфигурации, в хранилище и в профиль он не пишется. Нужен только пресету «Строгий» (только он пишет список): в «Совместимости» и «Сбалансированном» переключатель виден, но заблокирован (приглушён, кнопки `disabled`, класс `is-locked`, под ним подсказка), выбор сохраняется. Начальное значение при первой загрузке — «Вкл.», если сохранённая конфигурация уже содержит список Windows с шумом. «Рандомизировать» и «Новая временная личность» передают значение генератору; сам переключатель ничего не перегенерирует. Подсказка честная: списки разных профилей различаются; список не становится «более настоящим»; ничего не обещается.
- **Узнавание шума в сохранённом профиле.** Метки в конфигурации нет; `describeDevice` разбирает список строго: он — подпоследовательность списка Windows, не хватает от 1 до K имён, и это целые необязательные семейства. Результат: `fonts: 'windows'`, те же `fontGroups`, новые поля `fontNoise` (true) и `fontHidden` (убранные имена; для строки без списка Windows оба поля `null`); любой другой список остаётся `custom`. Допуск, который нельзя убрать: список Windows без одного-двух необязательных семейств, набранный вручную, неотличим от шума и считается им.
- **Управление «Шрифты» уровня «ОС».** «Windows» пишет обычный список (так шум снимается), «Как в браузере» возвращает строку браузеру, как раньше. Смена Windows 10/11 сохраняет шум: новый список получает шум с seed, выведенным из убранных имён прежнего (детерминированно, но набор имён может смениться; число убранных имён следует лимиту нового списка).
- **Согласованность.** Убранные имена не входят в `families`, поэтому щит (DOM, SVG, `FontFace local()`) и политика Canvas скрывают их так же, как любое имя вне списка; в native убранное и нативно разрешаемое имя (`Constantia`) измеряется как отсутствующее во всех контекстах.
- **Что не обещается.** Шум не моделирует реальную машину и не делает список «более настоящим», не меняет метрик и глифов, не защищает от серверного определения шрифтов; различие профилей — два имени в списке Windows 10/11 (пять — с Office). Подбирать «правдоподобные» наборы по реальным установкам нечем: измерений для этого нет.

### Д4. Ловушка `setPrototypeOf` у обёртки `FontFace`

В обёртке-`Proxy` над `FontFace` не было ловушки `setPrototypeOf`, которую интегратор Canvas добавил ко всем обёрткам Custom (ADR-112 §6): без неё `Object.setPrototypeOf(FontFace, FontFace)` принималось (родной конструктор бросает `TypeError: Cyclic __proto__ value`), и любое последующее чтение свойства функции переполняло стек — страница навсегда ломала собственный конструктор. Теперь ловушка та же, что у обёрток Canvas/Math/surfaces: при `value === обёртка` вызывается захваченный родной `Object.setPrototypeOf(target, target)` (тот же `TypeError` с тем же сообщением), любое другое изменение прототипа пересылается захваченным `Reflect.setPrototypeOf`. Ловушка действует и после `stop()` (обёртка, удержанная страницей, остаётся защищённой; сам перехват `FontFace` по-прежнему выключен). Оба нативных метода — в приватных intrinsics установщика (позднейшая подмена страницей внутри установщика не выполняется), обработчик создан с `__proto__: null` (ловушка не наследуется из расширенного страницей `Object.prototype`). Остаток тот же, что в ADR-112: `Reflect.setPrototypeOf(FontFace, FontFace)` бросает исключение, тогда как родной конструктор вернул бы `false`; цепочку через чужой `Proxy` родная проверка тоже не видит. `name`, `length` и `Function.prototype.toString` не менялись и не маскируются (правило 3). Общий помощник и `api-custom-wrapper-parity.test.mjs` не менялись; формулировка ADR-112 §6 «у неё та же ловушка ещё не добавлена» устарела — поправить её должен владелец ADR-112.

### Д8. Шум по умолчанию включён в «Строгом» (вопрос 1 из Д6 закрыт)

- **Что изменилось.** Состояние панели `fontNoise` начинается с `true` (было `false`). Если сохранённая конфигурация уже содержит список Windows, при первом показе состояние выводится из него, как раньше: список с шумом даёт «Вкл.», обычный список — «Выкл.»; нестандартный список или его отсутствие оставляют умолчание «Вкл.». Переключатель по-прежнему заблокирован вне пресета «Строгий» (только он пишет список) и остаётся выбором генератора, а не строкой конфигурации: в хранилище и в профиль не пишется.

### Д9. Региональные шрифты CJK в списках по региону (вопрос 3 из Д6 закрыт)

- **Что делает.** Список Windows, который пишет генератор в «Строгом» (и который пересобирают управления «ОС», «Регион» и «Часовой пояс»), получает группу шрифтов настоящей Windows с языком этого региона. Это шрифты пакетов «Features on Demand» (Supplemental Fonts), которые Windows ставит при включении языка. **Япония** → набор `regionJa` (17 имён), **Корея и КНДР** → `regionKo` (8), **Китай и Сингапур** → `regionZhHans` (4), **Тайвань, Гонконг и Макао** → `regionZhHant` (4); любой другой регион и «Авто» региональной группы не получают. Данные — в `fingerprint-font-groups.js` (`WINDOWS_FONT_GROUPS`: `regionJa`, `regionKo`, `regionZhHans`, `regionZhHant`), таблица «регион → группа» (`REGION_FONT_GROUPS`) лежит там же, рядом с данными группы: `fingerprint-region-data.js` сгенерирован (`gen-region-data.mjs`, «не править вручную»).
- **Источник.** Microsoft Learn, «Windows 10 font list» (https://learn.microsoft.com/en-us/typography/fonts/windows_10_font_list, страница обновлена 2024-03-18) и «Windows 11 font list» (https://learn.microsoft.com/en-us/typography/fonts/windows_11_font_list, обновлена 2022-06-16), разделы «Japanese Supplemental Fonts», «Korean Supplemental Fonts», «Chinese (Simplified) Supplemental Fonts», «Chinese (Traditional) Supplemental Fonts»; страницы прочитаны 2026-11-07, в этих четырёх разделах они перечисляют одни и те же семейства. Только английские ASCII-имена семейств или устаревших имён семейств таблицы (без локализованных названий и без начертаний вроде «Meiryo Bold»): `BIZ UDGothic`, `BIZ UDPGothic`, `BIZ UDMincho Medium`, `BIZ UDPMincho Medium`, `Meiryo`, `Meiryo UI`, `MS Mincho`, `MS PMincho`, шесть `UD Digi Kyokasho …`, `Yu Mincho`, `Yu Mincho Light`, `Yu Mincho Demibold` (Япония); `Batang`, `BatangChe`, `Dotum`, `DotumChe`, `Gulim`, `GulimChe`, `Gungsuh`, `GungsuhChe` (Корея); `DengXian`, `DengXian Light`, `KaiTi`, `SimHei` (упрощённый китайский); `DFKai-SB`, `MingLiU`, `MingLiU_HKSCS`, `PMingLiU` (традиционный). **`FangSong` не включён:** это имя совпадает с CSS-ключевым словом `fangsong`, которое `@font-face` перекрыть не может (по той же причине его отбрасывает и `font-probe-names.js`).
- **Обязательность для заявленного региона.** Шум (Д2) не убирает ни одно семейство региональной группы и ни одно базовое семейство письменности этого региона: `MS Gothic`, `MS PGothic`, `Yu Gothic` (Япония); `Malgun Gothic` (Корея); `Microsoft YaHei`, `SimSun`, `NSimSun`, `SimSun-ExtB` (упрощённый); `Microsoft JhengHei`, `MingLiU-ExtB`, `MingLiU_HKSCS-ExtB`, `PMingLiU-ExtB` (традиционный) — вместе с семействами, продолжающими эти имена после пробела. Это обязательные корни **только этого списка** (параметр `lockedRoots` в `fontNoiseModel`, `fontNoiseHidden`, `noisyFontList`, `followFontNoise`; `regionFontRoots(группа)`): 29 корней `FONT_NOISE_MANDATORY` остаются теми же и не раздуваются для других заявок — в списке без региональной группы, например, `MS PGothic` по-прежнему необязателен, и некоторые seed его убирают (проверено тестом и в native).
- **Минимум двух имён.** Для японского списка Windows 10 (113 имён, 48 необязательных) прежнее правило K = round(0,03 × N) давало бы одно имя; чтобы профили всё же различались, список «настоящего размера» (от 40 необязательных имён, `FONT_NOISE_FLOOR_FROM`) никогда не теряет меньше двух имён (`FONT_NOISE_MIN = 2`): K = max(2, round(0,03 × N)). Прежние восемь списков (у них K уже 2 или 5) и короткие списки не затронуты. Размеры: Япония 113 / 119 имён (Windows 10 / 11; после шума 111 / 117), Корея 104 / 110 (102 / 108), Китай, Сингапур, Тайвань, Гонконг, Макао 100 / 106 (98 / 104); с Office до 240 имён (< 256).
- **Откуда берётся регион и когда список пересобирается.** Генератор («Строгий»): после того как записаны строки часового пояса, заявленный регион — регион записанной зоны; региональная группа добавляется к списку Windows, который пишет «Строгий», с шумом или без — по переключателю. Управления уровня «ОС» («Регион», «Часовой пояс», «ОС») для профиля с обычным или зашумлённым списком Windows пересобирают список, только если сменилась Windows (10 ↔ 11), выбрано «Windows» явно или **сменилась региональная группа** (Япония → Корея, Германия → Япония, «Авто»); смена региона внутри группы (Китай → Сингапур) и зоны того же региона список не трогают, так что шум не перетасовывается без нужды. Шум при пересборке сохраняется (seed выводится из убранных имён прежнего списка, как в Д2). Без списка Windows (строка в «Как в браузере» или нестандартный список) управления региона и зоны строку шрифтов не создают.
- **Распознавание в сохранённом профиле.** `describeDevice` узнаёт списки Windows с региональной группой и без неё: 8 вариантов (Windows 10 / 11 × Office × Pan-European) × 5 (без группы и четыре группы) = 40, плюс восемь прежних вариантов без пяти псевдонимов (Д1); новое поле `fontRegion` — ключ группы или `null`; `fonts`, `fontGroups` (форма `{ windows11, office, panEuropean }` прежняя), `fontNoise`, `fontHidden` как раньше. Списки, сохранённые до дополнения, распознаются как раньше.
- **Проб-список.** `FONT_PROBE_NAMES`: **716 имён** (было 702; потолок 720 не менялся): в него входят все четыре региональные группы, из 33 имён 19 уже были в нём (группа «Windows вне базовой установки»), 14 добавлены (`BIZ UD…`, `UD Digi Kyokasho…`, `Yu Mincho Light`, `Yu Mincho Demibold`, `DengXian`, `DengXian Light`). Скрыто (проб-список минус `families`): список Windows 11 — 614 из 716, Windows 10 — 620, пустой список — все 716; для списков с регионом (Windows 11, без шума): Япония 597, Корея 606, Китай и Тайвань 610. Заявка с одним регионом скрывает региональные семейства всех остальных, как любое имя вне списка.
- **Не покрыто.** Прочие пакеты Features on Demand со шрифтами (арабский, бенгальский, канадская слоговая письменность, чероки, деванагари, эфиопский, гуджарати, гурмукхи, иврит, каннада, кхмерский, лаосский, малаялам, ория, сингальский, сирийский, тамильский, телугу, тайский) в списки **не входят**: для регионов с этими письменностями (Израиль, Таиланд, Индия и т. д.) региональной группы нет, как нет её у «Авто». Они уже скрыты как имена проб-списка; слово «не входят» означает, что настоящая Windows с этим языком показала бы их, а наш список — нет. Хост владельца (Windows 11, английская) этих пакетов не ставил: **ни одно из 33 региональных имён на нём нативно не разрешается** (измерено в Chromium 153, Chrome 156 и Firefox 138), разрешаются только базовые семейства письменностей. Поэтому native доказывает механизм (грани щита в `document.fonts` у скрытых и их отсутствие у видимых, измерение базовых семейств), но не измерением самих региональных шрифтов.
- **Чего не обещается.** Список — заявка, а не измерение: ни регион, ни наличие пакета на машине не определяются, шрифты не создаются и не рисуются; метрики и формы глифов берутся с хоста; серверное определение шрифтов и Workers по-прежнему не покрыты.
