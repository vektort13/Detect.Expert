# ADR-016. Store rollout/rollback и миграции

Статус: **Proposed**. Владелец: release (TBD). Реализация — E17-01; runbooks `runbooks/release.md`, `runbooks/rollback.md`.

## Контекст

CWS partial rollout доступен только расширениям с >10 000 семидневных активных пользователей — новый продукт не может обещать 1→5→25 %. CWS rollback возвращает предыдущий пакет под новым номером версии без обычного review, но на клиентах действует стандартный цикл обновлений — «исправим всем за минуту» неверно. Лимит store items (default два слота publisher). Без подключённого канала нет удалённого мгновенного выключения.

## Решение (предлагаемое)

1. Релизный артефакт: immutable build из lockfile и зафиксированного runtime; dossier — commit/build hash, версии контрактов/правил/PSL/Chrome, permissions diff, provenance сигнатур, результаты positive/negative/hostile тестов, измерения overhead, ограничения, текст обработки данных, отрепетированный план восстановления; SBOM и licenses.
2. Раскатка v1: локальные стенды → разрешённая тестовая публикация (test item, если доступен слот) → пилотная организационная группа → production. После получения права на partial rollout — проценты, hold-периоды и условия остановки фиксируются в release plan.
3. Rollback: CWS rollback либо hotfix-релиз; ожидаемое время распространения — стандартный цикл обновления Chrome; отключение проблемного сенсора — через существующую локальную/managed политику (`DisabledSensorIds`), не через исполняемый remote hotfix.
4. Миграции настроек (`storage.local` `schemaVersion`) совместимы с предыдущей версией: старый код переживает новые необязательные поля; `storage.session` очищается при update по определению — UI честно начинает новую сессию; старый content script получает `protocolOk:false` → reload required.
5. Репетиция перед каждым релизом: N→N+1→rollback с существующими настройками, отключённой сетью и несохранённым отчётом; результат и дата — в `runbooks/rollback.md`.
6. Publisher-аккаунт: аппаратные ключи, минимальные роли, разделение полномочий код/подпись/публикация; независимый reviewer проверяет permission diff и влияние на сбор данных.

## Последствия

- Первые релизы без процентной раскатки — риск принимается и компенсируется пилотом.
- `runbooks/*` содержат поля owner и «последняя репетиция».

## Приёмка

Репетиция N→N+1→rollback выполнена и задокументирована (дата, версии, результат); настройки сохранены; несохранённый отчёт корректно потерян с сообщением новой сессии; `pnpm release:verify` проходит на артефакте; dossier полон.
