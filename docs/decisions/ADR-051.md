# ADR-051 — Firewall и блокировка API в общей строке

Статус: реализация по прямому решению владельца продукта от 2026-10-20; результаты проверок — внутренний отчёт.

## Решение

В popup, боковой панели и основных настройках Chrome блокировка API и Firewall располагаются рядом. Оба используют существующие стили кнопок блокировки API: название, переход и компактное состояние. Большая дублирующая карточка состояния модуля из popup удаляется; отчёты и уведомления сохраняются.

По последующему решению владельца продукта и [ADR-053](ADR-053.md) обе кнопки Firewall переключают состояние модуля. Первое включение показывает существующее согласие на текущей странице, повторное использует сохранённые параметры; выключение не очищает постоянные настройки. Перехода в Options нет. Состояние берётся из `useProtectState`, обновляется при изменении настроек, разрешений, организационной политики и возврате фокуса. Помимо On/Off отображается отдельное предупреждение для ограниченного состояния; полное описание доступно через title и доступное имя.

Новая строка и описания её состояний локализованы на 21 язык production-интерфейса, с RTL для арабского и урду. Название Firewall сохраняется как бренд. Перевод существующих подробных экранов модуля по-прежнему русский/английский; расширение их полного каталога не входит в это изменение. Текст согласия не меняется.

Firefox сохраняет существующее ограничение ADR-047: модуль Firewall не поставляется. Пустой stub не создаёт карточку; блокировка API занимает всю строку.

## Границы и проверка

Изменения ограничены production UI, его локализацией, синхронизацией и проверками. Vendor, permissions, сетевые соединения, контракты, DNR и хранилища не изменяются. Обязательная проверка нечтения паролей и независимый review применяются по ADR-020-protect §15 и ADR-047. Нативная проверка охватывает все языки, три поверхности, светлую/тёмную темы, выключенное/активное/ограниченное состояние, геометрию и переход к согласию.
