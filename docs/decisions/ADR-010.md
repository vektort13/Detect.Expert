# ADR-010. Метрики, корпус и holdout

Статус: **Proposed**. Владелец: QA/детекция (TBD). Реализация — E09-01/E09-03, E15-01.

## Контекст

AUD-26: «FP <2 % на чистых топ-сайтах, recall ≥90 %» без ground truth. Популярность сайта не доказывает отсутствия fingerprinting; сайт без наблюдаемого маркера — не отрицательная разметка (возможен серверный антифрод). Малый набор → нельзя заявлять «точность 98 %».

## Решение (предлагаемое)

1. Три раздельные метрики: полнота наблюдения доступного API (единица — вызов/сценарий), качество интерпретации (sequence/window/session), точность распознавания вендора (rule × fixture). Не смешивать в один процент.
2. Формулы: `precision = TP/(TP+FP)`, `recall = TP/(TP+FN)`, `FPR = FP/(FP+TN)`, `coverage eligibility = observable/all declared`; знаменатель 0 → `n/a`. Для каждого сенсора: `eligible`, `observed`, `missed`, `unsupported`.
3. Корпус: локальные fixtures с известным исходным кодом и назначением, лицензии разрешают хранение; ≥300 различающихся отрицательных сессий, ≥10 классов приложений (редактор, графики, карты, калькулятор, 3D, игра, DSP, ML, benchmark, видеозвонок), несколько независимых collectors и версий в положительной части; публичные демо — smoke с датой, не истина.
4. Calibration/holdout разделены по семействам библиотек/версиям/сайтам; порог не подбирается на holdout; holdout неизменяем и версионирован; пороги утверждаются **до** оценки и фиксируются в `rules/thresholds/*.json` с версией.
5. Отчёт: confusion matrix, биномиальные интервалы, размеры групп, распределения по технике/сценарию/Chrome/OS; «проверено на N сценариях», не «точность X %». Начальные ориентиры: Math high-confidence precision ≥95 % (recall ≥80 % — исследовательский), vendor high-confidence precision ≥99 % на ограниченном подтверждённом классе.
6. Не прошедшая gate версия — `experimental` или показывает только `api-use`.

## Последствия

- Сбор корпуса — отдельная работа с provenance/лицензиями (E09-01).
- Reviewer запрещает правки порогов в PR с тестами, которые их используют.

## Приёмка

Пороги утверждены до оценки (дата в файле порогов раньше даты отчёта); holdout runner выводит версии, знаменатели, platform splits, неизвестные случаи; изменение порога без нового calibration report блокируется review.
