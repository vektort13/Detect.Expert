# ADR-063 — Browser Debug в собственном окне управления

Статус: реализовано и независимо проверено 2026-10-20; итоговый отчёт E22-16. Прямое решение владельца продукта от 2026-10-20. Продолжает ADR-055, не меняет сенсоры REQ-005 и модуль Firewall ADR-020/047.

## Область и граница данных

По дополнительному решению владельца продукта от 2026-10-21 Browser Debug открывается из «Настроек» в том же Options-документе и не показывается в основной панели вкладок. Прямой hash #browser-debug сохраняется, активной основной вкладкой остаются «Настройки»; есть кнопка возврата. Данные, разрешения и жизненный цикл раздела не меняются. Это явный интерактивный просмотр нативных данных браузера пользователем. Для этой страницы разрешается узкое исключение из REQ-005: названия, URL и идентификаторы собственных браузерных записей могут отображаться локально. Они не становятся данными детекторов, отчётов, контракта, service worker, bridge или сайта. Нет фонового сбора, слежения за изменениями, сохранения снимков в storage/IndexedDB, native messaging, чтения профиля, сетевого соединения или новых зависимостей.

Контроллер принимает вызовы только из точного верхнего собственного options.html, проверяет origin/path и исключает iframe. Прямые API вызываются из этого документа. Разрешения запрашиваются только нажатием пользователя, отдельно для раздела. Все новые API permissions являются optional; required permissions, host permissions и CSP сохраняются. Firefox исключает неподдерживаемые Chrome-only permissions. Отсутствующий API/разрешение не заменяется выдуманным результатом.

Снимки существуют в памяти вкладки. Только whitelisted metadata переходит в UI; нативные объекты и private mutation references остаются внутри драйвера/контроллера. Пароли, содержимое cookies, OAuth-токены, ключи и сертификаты не читаются. Account использует только getProfileUserInfo, без getAuthToken. Запрос cookies и site permissions требует явного HTTP(S) origin без credentials. URL browser records видны пользователю; экспорт предварительно показывает точный JSON, убирает query/fragment/userinfo из HTTP(S) URL и идентификаторы account. Экспорт — команда пользователя, не автоматическая отправка.

## Реальные возможности

15 разделов: обзор собственной среды, история, закладки, загрузки, metadata cookies, вкладки, недавние/синхронизированные сеансы, популярные сайты, список чтения, расширения, privacy, разрешения сайта, системные сведения, account и ссылки на внутренние страницы браузера. Поддержка определяется реальным namespace/методом и manifest/grant. Системные/профильные поля, которые штатный API не возвращает, отсутствуют. Внутренние страницы открываются только из статического allowlist; это не доступ к их содержимому.

Редактирование не симулирует переписывание profile databases. History добавляет URL текущим временем либо удаляет посещения точного URL. Bookmarks редактирует title/URL; move — отдельная команда, папки рекурсивно не удаляются. Download erase удаляет запись списка, не файл; файловые open/removeFile/acceptDanger отсутствуют. Cookies разрешают только удаление точной store/partition/domain/path identity после свежей проверки native winner. Вкладки — pinned/muted/activate; восстановление сеанса — только реальная snapshot session identity. ReadingList использует URL как неизменяемый ключ, редактирует title/read. Управление расширением исключает себя, component/admin и запрещённые policy действия; в Firefox только themes.

Privacy использует конечный allowlist boolean ChromeSetting: levelOfControl проверяется перед записью, после записи результат читается; clear — только для настройки, которую контролирует это расширение. WebRTC policy только читается: переход в API Guard сохраняет единственного владельца существующей политики. ContentSettings изменяется только для точного заданного origin. API не сообщает владельца исключения; UI не заявляет владение. clear не предлагается, поскольку он стирает все собственные правила данного типа, а не один origin. Если native readback не совпадает, операция сообщает not-applied; восстановление наблюдавшегося default не выдаётся за rollback.

## Отказоустойчивость

Перед изменением драйвер заново проверяет существование/identity/control и после записи читает результат. Нативная ошибка не показывается дословно и не попадает в экспорт. Не допускаются автоматические повторы мутаций. Новая загрузка, отзыв разрешения и скрытие отменяют принятие устаревшего результата. Отзыв разрешений очищает private references и UI-снимки/редактор. Скрытие сохраняет только черновик RAM; активные API-вызовы не выполняются в скрытом разделе.

Скрытие относится к переключению раздела management, а не к потере фокуса окна или переключению browser tab: одноразовая пользовательская команда tabs.activate сама меняет активную вкладку браузера. Ни одна такая смена не запускает новый сбор.

Снимок ограничен 200 строками/256 КиБ; native scan — 2000 записей, strings — 4096 символов, один срок операции — 5 секунд. Усечение явно отмечается. Незавершившаяся физическая запись удерживает mutex даже после timeout: браузерные API не предоставляют abort, повторная запись не допускается. Это локальная последовательность данного документа; внешняя смена настроек возможна между native calls, общей browser transaction нет. Частичное применение не объявляется отменённым.
