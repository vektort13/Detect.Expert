# ADR-052 — отдельное окно находок справа внизу экрана

Статус: реализация по прямому решению владельца продукта от 2026-10-20. Проверки и ограничения — внутренний отчёт.

## Решение

Разделы «Передача введённых данных» и «Запись сессии» удаляются из основного popup. Вместо постоянных карточек Chrome показывает отдельное extension-owned окно `findings.html`, только когда текущий документ имеет фактическую находку: проверяемую запись `value-match` либо существующий положительный уровень replay `replay-like`/`replay-recording` с оценённой уверенностью. Сам факт включения модуля, пустой отчёт, `signals-only`, неоценённый replay, обработчик парольного поля и непрозрачный трафик после ввода окно не вызывают. Пороговые значения детекторов и production-таблицы не меняются.

Окно располагается с отступом от правого нижнего края доступной области текущего экрана. Используются [chrome.windows](https://developer.chrome.com/docs/extensions/reference/api/windows) и Screen API собственной extension-страницы; разрешение `system.display`, DOM-инъекция на сайт и системные уведомления не требуются. Chrome выбирает допустимое начальное расположение; затем собственная страница устанавливает координаты по screen.avail*. Размер адаптируется к содержимому и доступной области экрана. Окно создаётся без перевода фокуса и содержит кнопку закрытия. Если по находке ожидается решение Firewall, существующая карточка решения включается в это же окно. Старый per-tab action popup сохраняет ручной доступ, но автоматически второе окно не открывает.

## Ограничения доставки

- Источник — только projection контроллера и доверенные события его event bus; страница не задаёт источник окна или содержимое находки.
- Актуальность проверяется до и после асинхронных вызовов по tab/document, состоянию модуля, исключению сайта и активности/фокусу исходной вкладки.
- Одновременно открыто не более одного окна находок. События объединяются, идентификаторы уже показанных находок запоминаются в ограниченной памяти; обновление счётчика той же записи окно повторно не открывает.
- Владение окном подтверждается точным URL либо собственным TAB-контекстом `runtime.getContexts` с совпадением windowId/tabId/frameId=0: Chrome скрывает URL extension-вкладки без разрешения tabs. Короткая память созданного native tabId лишь резервирует слот во время загрузки; она не разрешает закрывать документ с неподтверждённым URL.
- Фоновая вкладка ждёт активации. Навигация, закрытие вкладки, выключение/приостановка модуля и исключение сайта отменяют устаревшее окно. При старте SW текущие старые находки засеивают дедупликацию, не создавая исторических предупреждений.
- Нет нового постоянного хранилища, полей wire-контракта, чтения ввода/тел, permissions, DNR-действий или сетевых соединений. Исходный vendor и согласие не меняются. Firefox сохраняет штатные stubs модуля.
- Память ограничена 64 вкладками, 128 ключами на документ и 1024 ключами суммарно; между открытиями — 10 секунд. При исчерпании памяти новые автоматические показы этого документа подавляются до навигации/вытеснения; сведения остаются в отчёте модуля.

## Приёмка

Необходимы независимый review по ADR-020-protect §15, нативный положительный value-match и отрицательные сценарии, геометрия окна, объединение/дедупликация, гонки навигации/выключения, локализация новых элементов управления и обязательная production-проверка нечтения паролей. Нативная проверка replay-положительного детектора не выдумывается: при отключённых listen-hooks и пустых таблицах production может не достигать положительного уровня; положительные UI-состояния проверяются отдельными синтетическими fixtures.

## Уточнение оформления по макету владельца, 2026-10-20

Основное содержимое окна передачи — сразу раскрытая карточка: заголовок и сайт, фактический исход запроса, тип поля и кодировка, источник, компания, получатель, найденные данные и момент. Доказательство раскрывается отдельно. Используются glass-поверхности и элементы управления расширения. Подлинный pending prompt показывает существующие области решения и Block/Allow с сохранением проверки ревизии, результата DNR и Undo.

Положительная запись без pending prompt показывает такую же карточку фактов, без искусственного promptId и новых прав решения. После решения карточка фактов остаётся доступна рядом с результатом и Undo. Параметры из примера владельца не становятся демонстрационными фактами: компания берётся только из действующего каталога, скрипт — из имеющейся атрибуции, время — из доступного диапазона; полный URL, введённое значение и его хеш не выводятся. Уже отправленный запрос не описывается как ещё ожидающий отправки. Доставка окна, пороги и протокол не меняются.
