# ADR-015. Подпись rule pack и ротация ключей

Статус: **Proposed**. Владелец: `packages/catalog` + release security (TBD). Реализация — E20 (после E12, E17–E18).

## Контекст

MV3: логика определяется поставленным кодом; удалённые данные допустимы, интерпретатор сложных удалённых команд запрещён даже в JSON. Seed `ruleDistributionPolicy`: `localReviewedPatternsOnly=true`, `remoteDataMaySelectExistingRules=true`, `remoteNewRegexAllowed=false`, `remoteNewLogicAllowed=false`, `newMatchersRequireExtensionRelease=true`. Подпись доказывает автора пакета, не истинность правил.

## Решение (предлагаемое)

1. Начало — каталог внутри расширения. Опциональный подписанный пакет обновляет только **данные сопоставления** для конечного набора локальных matcher-типов: выбор существующих reviewed rule IDs и явно разрешённые простые параметры (`hostname_exact`, host suffix с проверкой границы метки, фиксированный path prefix, известные имена ресурсов, предопределённые идентификаторы признаков). Запрещены: regex, JavaScript, WASM, expressions, AST, HTML-шаблоны, property paths, скрипты миграции, runtime-загрузчики, новые `allOf/anyOf`.
2. Envelope: `schemaVersion`, `packVersion`, `issuedAt`, `expiresAt`, `minEngineVersion`, `keyId`, `payloadHash`, `signature`, `entries`. Подпись над каноническим представлением байтов; ключи верификации встроены; signing-key отдельно от CDN и publisher-аккаунта.
3. Лимиты пакета: размер, число записей, длины строк, сложность индексации. Неизвестная схема/подпись/ключ/несовместимый engine → пакет отвергается целиком; last-known-good продолжает работать.
4. Атомарное обновление: download → лимиты/подпись → schema validation → build indexes → self-check fixtures → commit версии. Монотонная версия против downgrade; легитимный откат — новый номер со старым содержимым.
5. Ротация ключей и реакция на компрометацию — отдельный runbook; `keyId` в envelope; период перекрытия ключей; отзыв ключа = отклонение пакетов с ним и возврат к встроенному каталогу.
6. Доставка только при `RemoteRuleUpdatesEnabled=true` (Managed) с origin из профиля сборки; Local-пакет не содержит загрузчика.

## Последствия

- Новый matcher или логика — только релиз расширения через CWS review.
- Ревизии: каждые 30 дней источники/changelog, 90 дней — сигнатуры; критичная коллизия → немедленное выключение правила следующим доверенным обновлением.

## Приёмка

Invalid/stale/revoked/tampered tests: неверная подпись, истёкший `expiresAt`, отозванный `keyId`, изменённый байт, пакет с regex/логикой, `minEngineVersion` выше текущего, downgrade → отклонение с сохранением last-known-good и диагностикой; успешный пакет применяется атомарно; прерванная запись не оставляет частичного состояния.
