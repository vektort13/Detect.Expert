# ADR-111 — Экскурсии по каждому разделу Options и общая кнопка в шапке

Дата: 2026-11-07. Прямое решение владельца продукта (дословно): «В пункте Антидетект есть "Экскурсия" нужно на каждый пункт нашего
функционала (я имею ввиду каждую вкладку добавить такую "Экскурсию" и я бы расположил её на каждой вкладке чуть левее от
"основного переключателя" а на вкладке "антидетект" убрать целое поле тамм где сейчас экскурсия и "обновить" как на
скриншоте, такое целое поле для двух опция выглядит пустой тратой пространства, то же самое на автосерфере».
Развивает экскурсию раунда 5 (ADR-108, раздел 9). Новых permissions, CSP, сети, каналов сообщений и зависимостей нет;
границы REQ-001…015 и ADR-020/047/048/049/070/075/076/109 не затрагиваются: экскурсия ничего не меняет, не читает
страницы и отчёты и не вызывает `chrome.*`.

## Что решено

1. **Экскурсия у каждого раздела Options** (12: Пульт, Detector, API Guard, Firewall, Antidetect, Автосерфер, Cookies,
   Proxy, Интеграции, Настройки, Контакты, Browser Debug), 3–7 шагов, всего 49. Каждый шаг подсвечивает настоящую часть
   своего раздела (кольцо, остальное затемнено) и в нескольких честных словах говорит, что это; тексты не называют кнопок и
   вкладок по именам и ничего не обещают (ни невидимости, ни анонимности, ни «100 %»). Движок прежний: кольцо, несмодальная
   карточка, Esc, стрелки (зеркально в RTL), Enter, Tab внутри карточки, фокус возвращается на кнопку, `prefers-reduced-motion`,
   forced colors, док к нижнему краю на узких экранах. Реестр шагов — `ui-tour-steps.js` (чистые данные), селекторы цели
   привязаны к панели своего раздела (`[data-management-panel="…"]`), поэтому часть чужого раздела взять нельзя; часть, которой
   нет (например, включённый Firewall меняет разметку), пропускается с видимой пометкой, как и в раунде 5.
2. **Экскурсия Antidetect** — прежняя (раунд 5) без шага «Proxy»: тот перенесён в экскурсию раздела Proxy (шаг «Ваши
   профили», связка профиль↔прокси), чтобы каждая экскурсия оставалась в своём разделе. Блок в контрольном списке первого
   запуска и команды палитры работают.
3. **Одна общая кнопка «Экскурсия»** (`TourButton` из `createTourEntry`, `ui-tour.js`) в строке шапки каждого раздела:
   иконка + короткая подпись (≤ 12 знаков), сразу слева от главного переключателя; у раздела без переключателя (Пульт,
   Интеграции, Настройки, Контакты, Browser Debug, Cookies) — последний элемент строки на том же месте, у inline-end.
   Порядок кластера: компактные инструменты, кнопка «Экскурсия», переключатель. Имя кнопки — её видимая подпись (без
   `aria-label`, чтобы имя не расходилось с видимым текстом), подсказка (`title`): «Пройти экскурсию по этому разделу» или
   «Продолжить экскурсию по разделу: шаг n из N»; `aria-haspopup="dialog"`. Цель нажатия 32×32. Ниже 561 px подпись скрывается
   (визуально, но остаётся в имени), кнопка становится квадратом 32 px: строка шапки не переносится ни при 340 px, ни на 21
   языке. Кнопка рисуется только на странице со слоем экскурсии (`controller.provide()`), поэтому отдельная страница API
   (`protection.html`) её не получает. Ничего не сдвигается: пока переключатель Antidetect не загружен, его место занимает
   заглушка 46×28 (`reserve`).
4. **Полоса под шапкой убрана** везде, где она была: Antidetect («Пройти экскурсию» и «Обновить»), Автосерфер («Обновить») и
   Proxy («Экспорт метаданных»). «Обновить» (Antidetect, Автосерфер) и «Экспорт» (Proxy) не потеряны: это иконки-инструменты
   (круг 32 px, имя и подсказка — прежний текст, `data-antidetect-refresh`, `data-autosurf-refresh`, `data-proxy-export`
   сохранены) в том же кластере, перед кнопкой «Экскурсия». Мёртвые правила `.workspace-secondary-actions` удалены.
5. **Прогресс**: `ui-tour:v2` в `localStorage` страницы Options — `{ version: 2, tours: { <раздел>: { completed, lastStep } } }`,
   не более 1024 знаков, только известные экскурсии, шаг в пределах числа шагов именно этой экскурсии, любая другая форма
   читается как отсутствие и удаляется. Прежнее значение `ui-tour:v1` читается один раз как экскурсия Antidetect (шаг после
   удалённого шага «Proxy» сдвигается на единицу) и удаляется при первой записи v2. Больше экскурсия ничего не хранит.
6. **Палитра команд**: по одной команде на экскурсию («Пройти экскурсию» или «Продолжить экскурсию» по состоянию, группа —
   имя раздела, английское имя раздела в поисковых словах); экскурсия раздела на экране — первая. В Firefox у модуля Firewall
   нет, поэтому нет ни кнопки, ни команды.
7. **Тексты**: Options-only модуль `ui-tour-labels.js` (115 ключей на язык × 21 язык; общая таблица переводов, background,
   popup, sidepanel и report не меняются). Русский и английский написаны вручную; **19 остальных — машинный перевод; носители
   его не проверяли** (глоссарий названий вкладок взят из самого интерфейса каждого языка). Сомнения для носителей собраны в
   `docs/translations.md`.
   Движок, реестр и тексты (около 400 КБ) загружает только страница Options: заголовки, которые строятся и для popup, боковой панели и страницы
   API (мастер-шапка, Detector), не импортируют экскурсию, а читают кнопку из `ui-tour-slot.js` — модуля без импортов, куда её кладёт оболочка Options
   (`provideTourButton`). Без оболочки (popup, боковая панель, `protection.html`) слот пуст и шапка прежняя. Юнит-тест идёт по статическим
   импортам каждой страницы и фона и падает, если до `ui-tour*.js` (кроме Options) можно дойти.

## Размещение и пределы

- **Firewall.** Шапку рисует модуль «Защита» (launcher с собственным переключателем, это сгенерированный `protect-ui.js`) и его
  собственная копия Preact, поэтому компонент страницы с её хуками (`TourButton`) внутри этой копии работать не может. Прежнее решение —
  соседний элемент с абсолютным положением (`inset-inline-end: 54px` = 46 px переключатель + 8 px) — давало порядок Tab: заголовок,
  переключатель, затем кнопка, хотя на экране она стояла между ними. По решению владельца продукта 2026-11-07 («нужен ли слот для Firewall?» —
  «да») у launcher теперь есть слот. Оболочка передаёт ему не готовый vnode, а изготовитель `tourToolSlot('firewall')` (`ui-tour.js`)
  свойством `toolSlot` острова (`ProtectIsland` → `mountIsland` → `FirewallLauncherIsland`). Модуль один раз на изготовитель вызывает его
  с `h`, `useState`, `useEffect` и языком страницы своего Preact (`LauncherToolKit`) и рисует вернувшийся компонент прямым ребёнком
  `.blocking-launcher__controls` между кнопкой-заголовком и переключателем, под границей ошибок (`ToolBoundary`: сбой кнопки оставляет на её
  месте пустоту, а launcher и переключатель продолжают работать; сбой самого изготовителя или не компонент вместо результата — то же).
  Кнопка прежняя (та же разметка и тот же контроллер экскурсии, `createTourEntry` лишь вызван с хуками модуля), модуль для неё ничего не
  читает, не шлёт и не хранит. Порядок DOM, Tab и экрана один: заголовок → «Экскурсия» → переключатель (в RTL зеркально; Shift+Tab —
  обратно). Без `toolSlot` (popup, боковая панель, строка запуска на Пульте, `options-launcher`) разметка launcher прежняя: ровно две
  кнопки. Строка — `display: flex` без переноса (`workspace-controls-host.css`), зазор 8 px, заголовок занимает свободное место,
  кнопка (32 px, ниже 561 px без подписи) и переключатель 46×28 (его ширину по-прежнему фиксирует `redesign.css`) не сжимаются;
  абсолютного правила и `position: relative` у шапки больше нет. Остров исключён из правил движения хоста (`redesign.css`), поэтому
  кнопке внутри него даны собственные плавное изменение цвета и нажатие (`scale(.97)`), как у остальных кнопок «Экскурсия». Побочное
  следствие: кнопка теперь внутри области launcher с `aria-busy` (пока Firewall переключается или грузится) — фокус и нажатие это не меняет,
  но экранный чтец может отложить её озвучивание на это время. Firefox не затронут: модуля там нет, шапка — `UnavailableFirewallLauncher`
  без кнопки, заглушка `protect-ui.js` свойство игнорирует. Нативный тест нажатиями Tab проверяет порядок и геометрию во всех 21 языках,
  палитрах и forced colors.
- **Cookies.** Оболочка передаёт рабочему месту готовую кнопку свойством `tourButton` (`CookiesApp({ active, tourButton })`), а
  `cookies-ui.js` рисует её последним элементом `.cookies-workspace-actions`, после «Экспорта»: у раздела нет переключателя, поэтому
  кнопка стоит у inline-end строки шапки. На узких окнах (до 560 px) `management-workspaces.css` отдаёт действиям отдельную строку на всю ширину;
  там кнопка прижата к концу этой строки (`margin-inline-start: auto` в `workspace-controls-ui.css`), на широких — стоит сразу после «Экспорта».
  Юнит-тест требует и свойство, и место; нативный проверяет позицию при 2576, 1180, 520 и 340 px.
- **Размер цели.** Инструменты шапки (Экспорт/Обновить/Экскурсия) — цель 32×32 в любом окне (минимум WCAG 2.2 AA — 24×24). Общее правило
  `management-ui.css` о 44 px на узких экранах на них не распространяется: размер задаёт `workspace-controls-ui.css`. Нативный тест касаний
  Proxy (`proxy-ui-visual-native.mjs`) судит эти два инструмента по 32 px, всё остальное в менеджере — по прежним 44 и 40 px; главный переключатель
  по-прежнему только фиксируется.
- Шаги, зависящие от состояния (включённый Firewall, список cookies, отчёт Detector для выбранной вкладки), в состоянии по
  умолчанию показывают то, что есть; если части нет, шаг пропускается с пометкой «недоступно здесь».
- Экранные чтецы не проверялись: проверены имена, роли, `aria-describedby`, живая область, но не озвучивание.
- **Найдено при проверке и исправлено отдельной правкой (не часть экскурсии).** В Firefox адаптер `browser-adapter.js` оборачивал события
  `webNavigation.on*` объектом только с `addListener`, поэтому очистка эффекта вкладки Detector (`detector-ui.js`, `removeListener`) бросала
  `TypeError: browserApi.webNavigation.onCommitted.removeListener is not a function`; после этого раздел, открытый сразу за Detector впервые,
  не догружался (API Guard оставался на «loading…»; воспроизведено и на сборке `dist/firefox`, собранной до этой работы). Теперь обёртка помнит
  нативный обратный вызов, зарегистрированный для каждого слушателя страницы: `removeListener` снимает именно его и обесценивает ещё ожидающую
  доставку и повтор COOP, `hasListener` отвечает как нативное событие, повторное добавление той же функции игнорируется, ошибка нативного
  `addListener` не оставляет записи. То же сделано для `webRequest.on*` и заглушки `tabs.onReplaced` (в Firefox её нет). Права, CSP, сеть и каналы
  не затронуты; `scripts/test/firefox-adapter.test.mjs` (26 проверок, 13 намеренных поломок пойманы). Нативные проверки экскурсий по-прежнему открывают
  Detector последним — порядок оставлен как независимый от этой правки.

## Как добавить экскурсию новому разделу

1. `ui-tour-steps.js`: запись в `TOURS` (id = id раздела из `MANAGEMENT_SECTIONS`, 3–7 шагов с уникальными id) и селекторы целей в
   `TOUR_TARGETS`, привязанные к панели раздела (`inPanel('<раздел>', …)`); часть страницы можно пометить `data-tour="<ключ>"`.
2. `ui-tour-labels.js`: `step_<id>_title` и `step_<id>_body` во всех 21 языках (юнит-тесты проверяют полноту, плейсхолдеры,
   честные формулировки и перевод).
3. Шапка раздела: `WorkspaceMaster` рисует кнопку сам (берёт ту, что оболочка зарегистрировала в `ui-tour-slot.js`); шапка без него — `h(TourButton, { tour })`
   из `createTourEntry` (только если модуль шапки есть лишь в Options; общий с popup/sidepanel читает кнопку из слота), последним элементом строки (перед переключателем, если он есть).
   Шапку, которую рисует другая копия Preact (Firewall), оболочка не рисует сама: она передаёт ей `tourToolSlot('<раздел>')` свойством `toolSlot`, а шапка ставит кнопку на своё место
   (между заголовком и переключателем). Юнит-тест требует, чтобы каждая экскурсия имела такое место, а нативный — чтобы кнопка стояла там, где сказано выше.
