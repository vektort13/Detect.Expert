# ADR-083 — исправления корректности после аудита Antidetect

Дата: 31.10.2026. Основание: решение владельца продукта о правильности подмен и ранее
данное разрешение исправлять найденные проблемы. Трассировка: FP-01/02/03/05/06/07
из внутреннего отчёта, ADR-048/049/060/064/066/068,
REQ-002/003/004/005/008/010/011/012/015.

## Область изменения

1. UAData.brands возвращает при каждом чтении новый FrozenArray со свежими
   изменяемыми brand dictionaries, как в native Chrome153. Выбранный внутренний
   шаблон остаётся закрытым и неизменяемым; page mutation не переносится между
   чтениями и не меняет настройки. Native getter вызывается один раз.
2. Custom-обёртки WebIDL methods/accessors, media serializers и document hooks
   не являются конструкторами. Вызов через new
   отвергается до вызова native. Receiver, arguments, native exception/rejection,
   call-once и stop/ownership сохраняются. Маскировки Function.toString/name/length
   не добавляется.
3. Load применяет именно отображённый saved-профиль к текущему draft. Pending
   импортированная библиотека, masters и остальные пользовательские настройки
   сохраняются. Load не выполняет Apply.
4. Библиотечная запись с неизменённой applied signature проходит CAS без повторных
   activation permission gates. Реальное изменение применения требует прежних
   раннего доступа/privacy и повторной проверки внутри serialized секции.
5. Возврат скрытой панели выполняет одно чтение актуального состояния. Clean view
   получает актуальные значения. Dirty draft сохраняется; новая revision ставит
   external/CAS fence. До проверки cached effective status не выдаётся за текущий.
   Ошибка чтения допускает readonly Refresh, без повтора мутаций и hidden polling.
6. При успешном **вызове enumerateDevices приложением** локальная обратная таблица
   псевдонимов может заполняться из доступных native device/group metadata ещё до
   чтения getters приложением. Список и native handles сохраняются. Нет собственной
   enumeration при установке или getUserMedia, дополнительных device calls,
   сохранения/передачи настоящих ID, разрешений или соединений.

## Граница FP-01

SHA-256 псевдоним необратим. Новый документ без локального inverse map и без
предшествующей enumeration не может восстановить настоящий ID без дополнительного
lookup, нового обратимого формата или хранения карты. Eager probing, передача
raw IDs, повтор getUserMedia и перенос native coercion после async lookup этим
решением не разрешаются. Сценарий persisted alias **до любого enumerateDevices**
остаётся открытым ограничением; ограниченная правка не объявляется полным FP-01 fix.

При конкурентных enumeration действует latest-invocation-wins: если более новый
вызов отклонён, поздний успех старого вызова не прогревает карту. Чтение ID
приложением по-прежнему заполняет её. Этот случай проверен синтетически;
проверка на реальных browser devices для него не заявляется.

## Проверки и границы

Положительные и отрицательные регрессии воспроизводят каждый исправленный
дефект; native проверки используют готовую production-сборку, BrowserLeaks,
отдельные профили и только искусственные media devices. Source/delivery hashes,
Chrome/Firefox, raw-value capture veto, off/restore, runtime performance и
независимый review обязательны для изменённых участков.

Не меняются permissions/CSP/manifest, wire-схемы и enum, формат профилей,
датасеты/иконки, сенсорные пороги, Protect, сеть и storage schema. Это исправление
семантики и управления существующим Custom, не расширение на Worker/CSS/fonts/
audio/сетевой стек и не подтверждение статистической естественности профиля.
