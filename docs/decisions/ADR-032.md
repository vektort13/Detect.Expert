# ADR-032 — явная проверка восстановления выбранной tracking-cookie

2026-10-09. Явное решение владельца продукта реализовать третий этап. REQ-004/005/009/011/012/013/015; развитие ADR-022/023/025. Для этого действия расширяется информационный режим REQ-001: допускается удаление выбранной tracking-cookie и восстановление её резервной копии как cleanup. Это не обход антифрода, не тест логина и не автоматическое сканирование аккаунта.

## Решение

Действие запускается пользователем кнопкой только для текущего главного документа и выбранной persistent non-HttpOnly tracking-cookie с проверенным правилом каталога. Авторизационные/session/token/csrf cookies исключены. UI передаёт opaque handle ADR-023. Backend проверяет полный native store/partition/domain/path/hostOnly scope; неоднозначный cookies.remove(url,name) запрещён.

Слушатель устанавливается до удаления. В течение 10 секунд backend сравнивает reappearance с исходным значением только в оперативной памяти. Raw value и его hash не выходят в UI, Pro, bridge, storage или export. Результаты: возвращено прежнее значение, создано другое, не восстановлено, отменено, ошибка. Источник восстановления остаётся unknown. По окончании первоначальная cookie восстанавливается только при прежнем разрешённом scope и отсутствии нового значения; новые данные сайта не перезаписываются. После revoke/navigation stale writes запрещены, cleanup outcome указан отдельно.

Допускается ограниченная read-only корреляция выбранной non-HttpOnly cookie со scalar strings в localStorage/IndexedDB/CacheStorage текущего origin. Значение читается и сравнивается локально в ISOLATED, не пересекает bridge; проекция содержит только storage kind и count. Совпадение не объявляется причинным источником восстановления. Имена БД, ключи, cache URLs, records и значения исключены. Вне выбранного теста эта диагностика не запускается.

## Приёмка

Полная identity, host/path collisions, HttpOnly/auth denial, different store/partition, failed removal, same/different restore, cancellation/timeout/navigation/revoke, не перезаписывать новые значения, bounded cleanup, privacy canaries. Native положительный опыт с синтетическим ID сайта и независимым fixture source, отрицательный опыт и cleanup. Pro сохраняет только валидированную metadata результата. Independent reviewer проверяет mutation/restore races.
