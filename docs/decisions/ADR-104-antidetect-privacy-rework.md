# ADR-104 — Переработка вкладки «Антидетект»: быстрые настройки, четыре уровня и честные формулировки

Дата: 2026-11-05. Прямое решение владельца продукта: переработать вкладку «Антидетект»
по его ТЗ и по исследовательскому отчёту «Проектирование anti-fingerprinting-расширения
для Chrome и Firefox» (далее — Отчёт). Явная формулировка владельца: «Всё официально и лишь
для того чтобы помочь юзерам сохранить приватность». Решение уточняет оформление, структуру
вкладки и подписи значений; логика подмены, границы REQ-001…015 и исключения прежних ADR
(048/049/060/064/065/066/085/086/087/100/101) не расширяются. Это не ADR о новых
возможностях подмены: Custom-значения остаются теми же.

## Контекст

Вкладка «Антидетект» уже содержала согласованный генератор профиля и типизированные
Custom-значения каталога format6/catalog7. Отчёт — спецификация *ответственной* подачи того
же механизма: небольшое число внутренне согласованных профилей вместо независимой случайной
подмены, меньше энтропии и, прежде всего, честные формулировки о том, что расширение может
и чего не может. Отчёт в нескольких местах корректирует ТЗ; эти правки приняты, потому что
они делают инструмент точнее и соответствуют требованиям Chrome Web Store и Firefox Add-ons
к непротиворечивым заявлениям о приватности.

## Решения владельца

1. **Четыре уровня вместо плоского списка.** «Быстрые настройки» · 01 Устройство · 02 ОС ·
   03 Браузер · 04 Сеть. Категория «Все» ADR-103 убрана: уровни её заменяют. Вкладка
   по-прежнему открывается на «Сеть».
2. **С вкладки сняты «Нативная сессия» (UI ADR-101) и «Наблюдение на странице».** Код
   движка ADR-101 остаётся в пакете, но пути его запуска из интерфейса больше нет; повторное
   подключение — отдельное решение владельца продукта. Бейджи и подсветка наблюдений сняты и с
   самих строк Антидетекта, а сбор наблюдений не включается ради этой вкладки (он остаётся
   у API Guard).
3. **Честные подписи.** Везде «значение, сообщаемое сайтам», не «ваш процессор, память,
   диск». Подмена `navigator.hardwareConcurrency`, `deviceMemory`, строк GPU и
   `storage.estimate()` не меняет реальное железо.
4. **Диск — квота, а не SSD.** Контрол «Накопитель» (512 GB…8 TB) управляет значением
   `navigator.storage.estimate().quota`, равным фиксированной доле (50%) выбранного образа.
   Реальный объём диска не раскрывается и не обещается, образ однозначно восстанавливается
   по квоте.
5. **Процессор и память: фиксированные ступени, реалистичные значения.** Процессор —
   2, 4, 6, 8, 12, 16, 18, 20, 24, 28, 32; память — 4, 8, 16, 32, 64, 128 GB. `navigator.deviceMemory`
   по спецификации не превышает 8, поэтому образ памяти выше 8 GB лишь выбирает корзину
   отчёта и отдельно не сохраняется (формат конфигурации поля для него не имеет); интерфейс
   показывает рядом реально сообщаемое значение. Пресеты и «Рандомизировать» берут
   распространённые ядра (4/8/12/16). Уточнено дополнением 2: Chrome с 147 сообщает
   корзины 2/4/8/16/32 и образ равен корзине; «не выше 8» остаётся для версий до 147.
6. **Движок один — Chromium.** Сборка предлагает Google Chrome и Microsoft Edge на
   Windows 10/11, ноутбук или настольный ПК, версии 136…153 из статического локального
   списка (без сети). Firefox, Safari и другие ОС в выбор не входят: подмена одной строки
   User-Agent под чужой движок создаёт противоречивый отпечаток.
7. **Один согласованный профиль из seed.** «Рандомизировать» строит согласованное
   устройство по 12 пунктам ТЗ; смена значений — явное действие, автоматической ротации
   нет. GPU берётся из каталога 50 реальных пар vendor/renderer (NVIDIA, AMD, Intel; строки в виде,
   который Chrome печатает для ANGLE и Direct3D 11), выбор взвешен по распространённости, а
   ядра, экран и память подбираются по классу карты; лимиты WebGL согласуются с нею. Ручные правки уровней синхронизируют зависимые значения.
8. **Карточка виртуального устройства** рядом с «Сохранёнными профилями» показывает
   ОС, браузер, процессор, память, накопитель, GPU, экран, зону и язык, шрифты и состояние
   Canvas/WebGL/Audio/Math, а Client Rects — как «Не покрыто». Под ней три честные строки:
   IP, TLS-отпечаток и движок браузера расширением не меняются.
9. **Три пресета Быстрых настроек:** «Совместимость» (только идентичность, без геометрии
   окна), «Сбалансированный (рекомендуется)» (плюс стабильные render-защиты) и «Максимальная
   защита» (плюс блок сенсорных и аппаратных API; часть сайтов может работать некорректно).
10. **Сеть — существующие контролы.** WebRTC, протоколы и native-политика сохранены;
    наверху уровня те же три честные строки. Строки UDP, QUIC и IPv6 по-прежнему не
    показываются (решение владельца продукта 2026-11-05).

## Реализация

- **Панель.** Один сохраняемый экземпляр `FingerprintProfilePanel` обслуживает вкладки
  «Быстрые настройки», «Устройство», «ОС» и «Браузер» параметром `view`, поэтому
  подготовленные правки не теряются при переходе между ними. Каждая правка идёт в preview;
  «Применить» записывает конфигурацию одним CAS, «Отмена» возвращает сохранённую.
- **Модель.** `fingerprint-device-presets.js` — чистые данные и строители значений
  (процессор, память, накопитель, GPU, экран, личность, шрифты) и `describeDevice`.
  `generateConsistentDevice` (Рандомизировать) и `applyDevicePatch` (ручные контролы)
  применяют их через прежний проверяющий сеттер: допустимы только значения доменов
  валидатора, явный Block страницы не снимается, `null` возвращает строки контрола в
  «Как в пресете». Прежний `generateFingerprintConfiguration` остаётся без изменений.
- **Размещение строк.** Для вкладки действует карта `ANTIDETECT_CATEGORY_OVERRIDES`:
  шрифты и язык/зона — в ОС; Canvas, WebGL, Audio, User-Agent и Client Hints — в Браузер;
  накопитель — в Устройство. API Guard сохраняет собственное распределение категорий.
- **Интерфейс.** Ступенчатые ползунки без промежуточных значений (значение в бейдже,
  шкала, реально сообщаемое значение под подсказкой, «Авто»), поиск зоны без сети с
  клавиатурой (combobox), иконки Windows 10/11, Chrome, Edge, GPU, CPU, RAM, диска и монитора,
  анимации только по краске внутри слоя ADR-103. Панель сохранения страницы показывается на
  «Сеть» и при несохранённых правках, а не дублирует нижнюю панель редактора.
- **Локализация.** 51 строка на 21 язык в отдельном модуле `fingerprint-device-labels.js`;
  общие таблицы не менялись.
- **Макет.** Колонки сеток вкладки и тулбара встроенного редактора теперь могут сжиматься,
  карточка уровня — контейнер для адаптивных правил формы. Это устранило горизонтальный
  выход за окно на 234–340 px в RTL, которого прежние проверки на этих вкладках не видели.

## Граница (без изменений)

- Никаких новых permissions, CSP, сети, remote code, telemetry. Всё — поверх существующих
  Custom-значений ADR-048/049 и исключений 060/064/065/066/085/086/087/100/101.
- Нет обхода антифрода, решения CAPTCHA, кликов/ввода/submit от расширения, собственного
  отпечатка, активного сканирования. REQ-001…015 действуют.
- Нет ложных обещаний покрытия. Где подмена недоступна или ненадёжна (Client Rects,
  метрики шрифтов, IP, TLS, движок, WebAssembly-рантайм, Worker), это помечается, а не
  выдаётся за защиту.
- Подмена остаётся наблюдаемой для страницы (REQ-003): «невидимость» не обещается.
- Новых Custom-типов, API и bundle этот ADR не вводит.

## Сопоставление 12 пунктов рандомизации с существующими возможностями

| Пункт ТЗ | Существующий Custom | Поддержка |
| --- | --- | --- |
| Canvas | `canvas-readback` (ADR-066) | есть, детерминированный по seed |
| WebGL | `webgl` + `webgl-capabilities`, `webgl-readback` (ADR-087) | есть |
| GPU↔WebGL | 50 пар каталога | есть, согласование в генераторе и в ручном выборе |
| Audio | `audio-fingerprint` (ADR-087) | есть |
| Шрифты | `canvas-font-policy` (ADR-087) | базовый список; точные метрики не покрыты |
| Client Rects | — | нет Custom; честно «Не покрыто» |
| Math | `math-transcendentals` (ADR-065) | есть |
| Ядра CPU | `hardware-concurrency` | есть |
| RAM | `device-memory` (корзина версии Chrome: до 147 не выше 8, с 147 до 32) | есть; для версий до 147 образ выше 8 GB не сохраняется |
| Экран | `screen-*`, `screen-geometry`, `css-media` | есть; раскладку CSS и окно не меняет |
| Накопитель | `storage-estimate` (ADR-085) | есть, как квота |
| User-Agent | `navigator-user-agent`, `client-hints`, `navigator-platform` | есть; HTTP-заголовки в Chrome следуют строкам (ADR-105) |

## Известные ограничения

- Для Chrome до 147 образ памяти выше 8 GB не входит в формат конфигурации: после
  перезагрузки панели ползунок показывает типичный образ корзины (16 GB для ноутбука,
  32 GB для настольного ПК). Сообщаемое сайтам значение при этом сохраняется точно.
  С Chrome 147 корзины 2/4/8/16/32 хранятся без потерь.
- Геометрия окна и CSS-медиа пишутся только в «Максимальной защите» (дополнение 2):
  они расходятся с реальной раскладкой, если окно меньше выбранного экрана.
- Нативный набор `math-transcendentals` проверяет 20 функций и устарел после ADR-087
  (функций 23); он продолжает находить панель Math на новом месте, а прежнее расхождение
  вынесено в отчёт. Остальные устаревшие наборы перечислены в отчёте редизайна.
- Каталог GPU — 50 адаптеров Windows. Идентификаторы устройств PCI сверены с базой pci-ids
  (2026.11.05); имена адаптеров — строки драйверов Windows, офлайн они не проверяются и
  приняты по известному именованию. Класс производительности и вес карт заданы вручную и не
  являются статистикой оборудования. Подробности — в
  [покрытии Антидетекта](../coverage/antidetect.md).

## Дополнение 2026-11-05: первый запуск в реальном Chrome

Владелец сообщил, что в его Chrome 156 «ничего не работает»: на browserleaks.com/webgl видна настоящая видеокарта, в панели красное «Не удалось сохранить настройки», кнопку «Применить» трудно найти. Воспроизведено на установленном Chrome 156.0.8078.80 с обычной установкой распакованного расширения. Причины и решения (границы REQ-001…015, permissions, CSP и сеть не менялись):

1. **Переключатель Chrome «Разрешить пользовательские скрипты» по умолчанию выключен** (ADR-049: без `userScripts` ранняя подмена невозможна). Service worker отвечал точным кодом `early-access-required`, но панель профилей не знала код и показывала общий отказ. Теперь код имеет собственное сообщение; вкладка показывает заметную плашку с точным действием, кнопку «Открыть настройки браузера» (`chrome://extensions/?id=…`) и «Проверить снова»; при возврате на вкладку (focus/visibilitychange) состояние читается заново и подсказка исчезает без перезагрузки; шапка пишет «Не применяется: пользовательские скрипты не разрешены» вместо «Нет активных правил».
2. **Мастер-переключатель блокировал панель профилей.** Его запись менялась как «чужая ревизия», панель становилась «устаревшей», «Применить» отключалась, а «Обновить» была недоступна при черновике. Теперь панель сливает новую ревизию с черновиком трёхсторонне (`mergeConfigurations`: каждое поле и каждая строка берутся у той стороны, что их изменила); блокировка остаётся только при настоящем конфликте и снимается одной кнопкой «Отбросить черновик и обновить».
3. **«Применить» была внизу правой колонки.** Рядом с «Рандомизировать» появилась кнопка «Применить», а внизу окна — плавающая панель «Применить изменения / Отменить изменения» (число изменённых значений, подсказка про новую вкладку), на всех уровнях.
4. **Раскрытие.** Карточка виртуального устройства теперь прямо говорит, что HTTP-заголовки запросов (User-Agent, Client Hints) не меняются: строка «HTTP User-Agent» на browserleaks.com остаётся настоящей, а JS-значение `navigator.userAgent` меняется.

Проверено на установленном Chrome 156: после включения переключателя и «Применить» браузер `browserleaks.com/webgl` показывает выбранную пару ANGLE/Direct3D11, картинка WebGL рисуется. Постоянный нативный набор `scripts/test/antidetect-flow-native.mjs` повторяет путь пользователя: переключатель выключен, мастер первым, «Рандомизировать», «Применить» из панели, настоящий переключатель, значения на новой странице.

## Дополнение 2 2026-11-05: живой аудит по десяти областям

Владелец повторил, что «ничего не работает», и поручил проверить каждую функцию вкладки на настоящих сайтах (browserleaks и собственные страницы) и сверить с программой-образцом. Ссылка на программу-образец не поступила; сверка с публичными проектами (CanvasBlocker, Chameleon, JShelter, Camoufox) шла только как со справкой, код оттуда не переносился. Десять областей проверены в настоящем Chromium 153 (переключатель «Разрешить пользовательские скрипты» включён) и нашли около 80 расхождений; результаты — в отчёте аудита, список исправленного и оставшегося — в [покрытии](../coverage/antidetect.md). Границы REQ-001…015, permissions, CSP и сеть не менялись. Решения:

1. **Пресет — полное утверждение.** «Совместимость» пишет только значения идентичности; «Сбалансированный» добавляет детерминированные Canvas, Audio и Math; масштаб метрик текста Canvas, список шрифтов, проекция WebGL readPixels, геометрия окна с `css-media` и блоки сенсорных и аппаратных API остались только в «Максимальной защите». Генерация лёгкого пресета возвращает строки сильного в «Как в браузере»; явный Block страницы не снимается. Причина: «Сбалансированный» ломал виджеты в iframe, WebGL-приложения, веб-шрифты и экспорт больших холстов.
2. **Генератор согласован с настоящим Chrome.** `deviceMemory` берётся из корзин выбранной версии (до 147 — 0,5…8, с 147 — 2/4/8/16/32), квота `storage.estimate` по умолчанию «Авто» (настоящий Chrome отдаёт плоскую квоту), `uaFullVersion` и `formFactors` заполнены, GREASE-бренд зависит от версии, список версий дотянут до 156.
3. **Размер окна — только у окна верхнего уровня.** inner-размер и признаки width/height/orientation выбираются у окна без opener; iframe и popup остаются native. Запросы media разбираются полностью (типы, `only`, `not`, вложенность, `or`, device-width/height, orientation, `-webkit-device-pixel-ratio`) в рамках трёхзначной логики ADR-100: неразрешённое остаётся native целиком.
4. **Явный выбор страницы выигрывает у выбранного значения** для Intl (`locales`, `timeZone`, `calendar`, `numberingSystem`): так ведёт себя настоящий браузер, а прежнее перекрытие ломало библиотеки дат и валют. Выбранные значения заполняют только пропущенное.
5. **Новое узкое исключение original-call-once (нужно подтверждение владельца).** При включённой строке `intl-formatting` в Custom и выбранной локали `Date#toLocaleString/toLocaleDateString/toLocaleTimeString`, `Number#toLocaleString`, `BigInt#toLocaleString`, `String#localeCompare/toLocaleUpperCase/toLocaleLowerCase` (и через них `toLocaleString` массивов) подставляют выбранную локаль только вместо отсутствующего или `undefined` аргумента `locales`, тем же единственным нативным вызовом с новым списком аргументов; приведения аргументов нет, `null`, `''` и `[]` остаются native. Это то же право, которое ADR-100 даёт `Temporal.Now` для пропущенной зоны; остальные методы и границы REQ-002 не затронуты. Откат — убрать установку `localeSpecs`/`localeMethod` в `api-custom-intl-runtime.js`.
6. **Отказ по Promise возвращается отклонённым Promise**, а не синхронным `TypeError`: у настоящих API, возвращающих Promise, ошибка приходит отклонением. Отказ при подмене страницей Promise, `then` и связанных статиков (ADR-100) сохранён и по-прежнему не выполняет код страницы.
7. **Пределы расширены по результатам замеров:** Canvas — 16 MP, 256 параллельных экспортов, проекция быстрее в 4,5 раза с тем же результатом; Audio — до 2^26 отсчётов, выбранная частота только у `AudioContext` без аргументов (`OfflineAudioContext`, `AudioBuffer` и явная частота остаются native), ключ шума включает origin документа; Math не меняет результат, являющийся ближайшим double к десятичному числу не длиннее 10 значащих цифр.
8. **Интерфейс говорит правду:** заметка «Antidetect выключен» на карточке устройства, предупреждение про Block без API Guard, отдельные сообщения для недостающего разрешения сети и области, строка покрытия WebGPU, форма заполняется из сохранённого профиля один раз.

**Не сделано на момент дополнения 2 (позже в тот же день сделано, ADR-105):** подмена HTTP-заголовков User-Agent и Client Hints; Workers и WebGPU `adapter.info`; чтение WebGL из FBO/PBO; эмуляция локальных полей Date; `VideoFrame(canvas)` и `captureStream`; исключение для плоских холстов (отвергнуто: обходит защиту срезами 1×1); интервал 0,3–0,9 с после запуска браузера, когда регистрация скриптов ещё не готова. Каждый пункт описан в [покрытии](../coverage/antidetect.md) как предел, а не как поддержка.

## Дополнение 3 2026-11-05: сверка с Camoufox и CloakBrowser

Владелец дал две ссылки на антидетект-браузеры (Camoufox, CloakBrowser) и поручил сверить наши методы с ними и взять лучшее. Шесть исследователей сравнили свои области (идентичность и согласованность, шрифты и Canvas, WebGL и GPU, звук и медиа, навигатор, экран и локаль, WebRTC и общий список поверхностей), измерив настоящие Chrome 156 и Edge 156 на этой машине. Код образцов не запускался и не копировался: **Camoufox** — форк Firefox (патчи движка MPL-2.0, python-библиотека и данные MIT), **CloakBrowser** — закрытый Chromium (в репозитории только обёртка MIT). Результаты — в отчёте сверки и в [покрытии](../coverage/antidetect.md). Границы REQ-001…015, permissions, CSP и сеть не менялись. Решения:

1. **Цель другая, шум остаётся.** Образцы стараются выглядеть как «обычный» браузер и проходить антибот-проверки; Camoufox убрал шум Canvas, текста и звука, считая шум самим отпечатком, CloakBrowser шумит от seed. Цель расширения — несвязываемость между сайтами, поэтому шум Canvas, Audio, Math и масштаб текста остаются как в ADR-065/066. Всё, что нужно только против антибот-защиты (скрытие автоматизации, имитация человека, CAPTCHA, правка таймингов прокси, выдуманные ICE-кандидаты), не переносится (REQ-001).
2. **Ключ шума включает сайт верхнего уровня.** Canvas, Audio и WebGL readPixels берут последний элемент `location.ancestorOrigins`, иначе origin самого фрейма: сторонний фрейм на двух сайтах видит разные значения. Значения верхних документов Canvas и Audio не изменились; readPixels раньше не имел области, его значения сменились один раз. Workers ключа верхнего сайта не видят и остаются по origin воркера.
3. **Звук: не трогать написанное страницей.** Буферы, созданные `createBuffer` и `new AudioBuffer`, читаются без изменений (настоящий Chrome возвращает записанное как есть; проверка «записать и прочитать» теперь проходит). Буферы движка (`startRendering`, `decodeAudioData`) проецируются, как раньше.
4. **Политика шрифтов Canvas.** Сравнение без учёта регистра, шрифты, зарегистрированные самой страницей в FontFaceSet, проходят (до 256 граней), допустимо до 256 имён (валидатор поднят с 64 до 256 без смены каталога: профили с более чем 64 шрифтами не импортируются старыми сборками). Список Strict — 91 имя Windows (+6 для Windows 11) вместо 14; Office (115) и Pan-European (6) — только по желанию при генерации. Имена — факты из опубликованных списков Microsoft и данных Camoufox (MIT).
5. **Генератор и данные.** Экран — панель × масштаб Windows (3840×2160 при 100% не выпадает); у каждой карты список потоков; строка WebGPU по карте в форме Chrome (vendor, architecture; device и description пустые); platformVersion Windows 11 — 19.0.0; если заявка совпадает с реальным браузером (бренд, версия, ОС), берутся его настоящие полные версии; идентификаторы зон приводятся к написанию движка. Всё, что не измерено (архитектуры кроме `turing`, списки потоков, веса масштабов), помечено в коде как эвристика.
6. **Подсказки согласованности.** 16 новых кодов (всего 29); они только предупреждают, значения не переписывают. Значения по умолчанию в форме берутся из реального браузера (бренд, версия, Windows 10/11); при несовпадении заявленной версии с настоящей показывается заметка.
7. **Среда выполнения.** `matchMedia` для `device-width/height`, `resolution` и `-webkit-device-pixel-ratio` следует строкам экрана и DPR (скрытая строка `css-media`; для opaque-фреймов бандл не создаётся); `any-pointer` и `any-hover` — множество значений; список устройств до выдачи разрешения остаётся в форме Chrome (пустые подписи); WebRTC не переписывает служебные адреса (0.0.0.0, `::`, 127/8, `::1`); link-local (169.254/16, fe80::/10) служебным не считается: настоящий Chromium собирает такой адрес интерфейса как host-кандидат (измерено), поэтому он подменяется.

**Ограничения, найденные сверкой, но не снятые.** Workers и ключ верхнего сайта; `outputBuffer` ScriptProcessor проецируется; opaque-фреймы по-прежнему отказывают для всего аудио; неявная строка media не имеет opaque-бандла (как и неявная строка intl); пустой Custom-список устройств до разрешения не скрывает виды настоящих устройств; вся геометрия остаётся скриптовой (CSS `@media`, раскладка, `visualViewport` — настоящие).

**Решения владельца (приняты 2026-11-05; реализация — [ADR-105](ADR-105-antidetect-http-headers.md) и [ADR-106](ADR-106-antidetect-continuation.md)).**
- Шум против «как у обычного браузера»: оставить как есть, перенести audio и Math в «Максимальную защиту» или сделать масштаб текста экспериментальным; редкий шум Canvas (`sparse-rgb-v1`, около 1% пикселей, без раздувания PNG плоских холстов) и слой PNG-чанка; время жизни seed Math и Canvas (сессия или профиль).
- «Максимальная защита» блокирует сенсорные и аппаратные API (пункт 9 решений владельца): образцы показывают нейтральные значения вместо удаления API (форму, которой нет ни в одном Chrome); замена изменит прежнее решение.
- Заголовки HTTP (User-Agent, Client Hints, Accept-Language): отдельная ADR и правило DNR `modifyHeaders` (можно ли ставить `sec-ch-ua*` через DNR — не проверено).
- Следующие порты: режим WebRTC `host: 'mdns'` (смена формата и каталога), Custom геолокации (только координаты, без автоматического разрешения), охват `StorageBucket` и `webkitTemporaryStorage`, подмножество голосов речи из настоящего списка, полнота часов, форма `performance.memory`, оффлайн-помощник «страна → язык и зона» (нужен текст лицензии Unicode для данных CLDR), заявка настоящей GPU на её собственной ОС, кнопка «подогнать окно».

**Константы.** Элемент `ancestorOrigins` ≤ 512 символов, длина списка 1…1024; таблица шрифтов ≤ 256 имён по ≤ 128 символов, ≤ 256 граней FontFaceSet, семейства длиннее 130 символов пропускаются; `enumerateDevices` разбирает ≤ 1024 записей; текст адреса WebRTC ≤ 39 символов; снимок окружения: `hardwareConcurrency` 1…1024, DPR (0, 16], стороны экрана 1…65535, зона ≤ 128 символов, список версий ≤ 16 записей с брендом ≤ 128 символов, чтение подсказок один раз за вид с тайм-аутом 500 мс; `WINDOW_CHROME_MIN` = 80; `WINDOWS_FONT_MAX_NAMES` = 256.
