# ADR-074: наблюдение ресурса Cloudflare Precursor

Дополнение от 2026-10-30: [ADR-076](ADR-076.md) добавляет отдельный авторизованный
источник конфигурации зоны, историю/уведомления о смене режимов и Firefox
Resource Timing. Ниже сохранено исходное решение для пассивного сетевого источника;
его `mode: unknown` не ограничивает новый независимый API-канал.

Дата: 2026-10-30. Основание: прямое решение владельца продукта исследовать Precursor,
распознавать его и сообщать подтверждённые изменения режима.
REQ-001/004/005/006/008/009/011/012/015; DET-CF-PRECURSOR-001.

## Доказательства и граница вывода

Первичные наблюдения во внутреннем отчёте
и `runtime-confirmation.json` подтверждают загрузку ресурса при обычном
посещении Luma и Stack Overflow. Тот же путь отдаёт официальный домен
Cloudflare. Узкая проверенная форма:
`/cdn-cgi/challenge-platform/h/g/scripts/precursor/[0-9a-f]{12}/main.js`.
Это наблюдаемый ресурс, а не доказательство успешного выполнения проверки.
Хэши исследованных скриптов фиксируют образцы, но не являются runtime-сигнатурой.

Состояние конфигурации зоны `off | monitor | arm` доступно в авторизованном
[Cloudflare API](https://developers.cloudflare.com/api/resources/precursor/).
Документированный публичный дискриминатор этих режимов не найден.
Interstitial настраивается независимо. Cookie, Turnstile, JSD, HTTP challenge,
отсутствие загрузчика и истечение TTL не определяют режим.
Поэтому production-снимок содержит только `mode: unknown`,
`modeDetection: false`. Уведомление «режим изменился» сейчас недоступно;
несуществующий сигнал и неиспользуемый канал записи режима не добавляются.

## Изменение

Отдельный ограниченный observer получает browser-native завершения script
запросов в проверенном namespace. Успешный статус и точный путь дополняются
проверкой MIME, HTTPS origin, native document identity, активного binding,
согласия, scope и generation. Native `getFrame` вызывается только после
дешёвого совпадения; количество реально незавершённых вызовов ограничено.
Timeout не освобождает физический слот. Ответ после clear, revoke, pause,
смены документа или generation отбрасывается.

Узкое дополнение allowlist REQ-005: из native response metadata можно
прочитать только `Content-Type`, немедленно свести его к признаку JavaScript
и отбросить. Его значение не входит в контракт, storage, отчёт или журнал.
Cookie, Authorization, тела и значения других заголовков не читаются.
Это не расширяет полномочия модуля «Защита».

Privileged `ui-get-precursor` использует отдельный строгий sidecar-контракт,
обычный `verifyUiSender` и точный documentKey. MAIN не получает нового канала.
В UI выводятся факт наблюдения ресурса, покрытие и неизвестный режим отдельно.
Существующие enum/отчёты, permissions, manifest, CSP, зависимости и исходящие
соединения не меняются. Совпадение пути на произвольном сайте не является
криптографическим подтверждением происхождения содержимого.

Состояние хранится только в памяти SW, ограничено количеством документов и
TTL 10 минут. Никаких URL, query, build ID, Ray ID, cookie или токенов.
Очистка, pause и отзыв согласия/доступа удаляют наблюдения; отсутствие данных
после перезапуска SW не превращается в Off. Чужой iframe не определяет режим
верхнего документа. Firefox без native network document identity сообщает
ограничение покрытия.

## Review и воспроизведение

Проверяются независимые positive/negative fixtures, HTML fallback, подделки
пути, ошибочные ответы, непроверенный h/b, сторонний origin, чужой документ,
timeout/реальные pending slots, навигация, revoke, clear и UI late replies.
Production source меняется ограниченным sync-скриптом; lifecycle дополнение
сохраняется также в генераторе ADR-073. Старые функциональные модули сохраняются.
Фактические команды и результаты записываются отдельно в папку задачи.

Для disable следует выключить проверенную policy и пересобрать локальный
пакет. Отключение никогда не генерирует Off или уведомление о смене режима.
Новые пути и будущие mode-маркеры требуют новых реальных fixtures и review.

При регрессионной проверке обнаружена существующая гонка Light Resume:
неактивная Pro-ветка возвращала управление до native bridge delivery.
В `resumeValueCapture` и его генератор добавлен `await resumeBridge()`;
активная Pro-ветка сохранена. Тесты исполняют фактический production-метод
с незавершённой и отклонённой доставкой. Native clear/resume прошёл в Chrome
и Firefox. Итоговые доказательства: внутренний отчёт.
