# ADR-009. Vendor matching и production gate

Статус: **Proposed**. Владелец: `packages/catalog` + reviewer сигнатур (TBD). Реализация — E12-01/E12-02.

## Контекст

AUD-10: любой известный cookie/CDN давал `high`; AUD-27: «50 проверенных сигнатур» без evidence. Seed (`catalog/vendors.seed.json`): 71 вендор, 20 правил-кандидатов, всё `productionEnabled=false`, `fixtureVerified=false`. Vendor product page подтверждает существование продукта, не сигнатуру.

## Решение (предлагаемое)

1. Две сущности: `vendors[]` (каталог: `providerId`, `productId`, `aliases`, период имени, категория, источники) и `rules[]` (кандидаты). Стадии записи: C / I / D / L; lifecycle правила: catalog → documented candidate → lab fixture verified → security/privacy reviewed → release candidate → production approved → deprecated/revoked.
2. Matcher-типы (конечный набор в коде): `hostname_exact`, `host_suffix_labels` (граница метки), `path_exact`, `path_prefix`, `path_template` (tokenized), `resource_type`, `cookie_name_exact` (optional sensor), `global_name` (без чтения значений), `dom_attribute_exact` (без чтения содержимого). Regex из seed допускаются только как локальные reviewed-шаблоны в релизе расширения с лимитом длины input, запретом backreferences/lookbehind/nested repetition и performance-тестом.
3. `allOf` — в одном document/frame/окне и одной deployment-гипотезе; дедуп `(tabSession, documentId, frameId, productId, deploymentContext)`; family-level match показывает семейство; negative evidence опровергает узкий вывод (CDN-only ≠ bot match; hCaptcha compatibility ≠ Google).
4. `vendorConfidence`: `documented-resource` — точный host+path production-правила по browser-observed запросу; `multi-signal`; `weak-signal` — page-controlled признак, UI «найден элемент интеграции»; `none`.
5. **Production gate** (registry linter, `pnpm catalog:lint`): `productionEnabled=true` допускается только при наличии `sourceClaim` + `sourceAccessedAt`, `positiveFixtureIds` ≥1, `negativeFixtureIds` ≥ обязательного набора (похожий hostname, shared CDN, documentation page с текстом кода, DOM без загрузки, aborted request, loaded-but-unused, nested iframe другого origin, late consent, SPA, self-hosted `unknown`, нет host permissions), `reviewerIds` ≥2, `reviewDueAt`, `expiryAction`, `rollbackId`, `browserVersions`. Иначе lint падает.
6. Истёкшее правило: `downgrade_to_stale_hint` или `disable` по заранее выбранной политике; никогда не «подтверждено» молча. Rebranding — alias с периодом, не смена смысла исторических отчётов.
7. Очередность: сначала точные network host+path (DataDome, hCaptcha, Turnstile, reCAPTCHA, MaxMind, Sift, GeeTest), затем ThreatMetrix, Fingerprint v4, Arkose, Yandex; Stripe — как risk telemetry; cookie/DOM/global — после отдельной проверки provenance и UX. Число кандидатов показывается отдельно от числа детектируемых интеграций.

## Последствия

- Seed остаётся выключенным до fixtures; UI не показывает вендоров в срезе 1.
- Формат evidence registry — `rules/sources/README.md`.

## Приёмка

Registry linter отвергает enabled rule без evidence/fixtures/reviewer; candidate никогда не отображается как validated production match; обязательные negatives (Cloudflare CDN-only/LB cookie; AWS challenge без Bot Control; Stripe без risk endpoint; hCaptcha с `grecaptcha`; HUMAN `_px*` коллизии; page-origin подделка) проходят; precision по rule на fixture corpus с интервалом.
