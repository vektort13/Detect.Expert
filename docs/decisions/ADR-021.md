# ADR-021. Cookie inventory, identification tabs and GTM loader evidence

Status: Accepted, implemented and independently reviewed on 2026-10-09. Explicit user requests; REQ-001/002/004/005/007/011/012/013.

The owner requested four identification tabs, cookie purpose classification and Tag Manager loading chains. The production heading becomes «Обнаруженные антифрод-системы» by explicit instruction, replacing the section-name requirement in REQ-007 only. No site safety verdict is introduced.

Cookie access is an optional `cookies` permission requested by an extension UI click. Existing host permissions are unchanged. Queries are limited to the current selected document and resource hosts observed for that document. Browser API responses are projected immediately to metadata; `value`, authorization credentials, token payloads and filesystem cookie databases are never read. Native name/domain/path/partition site are bounded transient deduplication inputs; the selected tab's store ID is used only to scope native queries. Raw identity fields, paths and opaque store/partition identifiers are never forwarded or exported. Inventory does not prove a cookie was sent. The offline catalogue retains its source licence and provenance; classification and tracking counts are separate from cryptographic claims.

DBSC response/request header **names only** can be retained when the browser supplies an authoritative document identity. Registration is an offer, not proof that a key was created. The cookie API exposes no TPM or bound-session flag. DBSC protects a session proof key, not the cookie bytes; there is no per-cookie “cannot be exported” claim. No protocol payload, refresh/challenge value, registration URL or secret is inspected. Unsupported document attribution remains unsupported.

GTM attribution uses bounded native script loading observations in Pro. Only fixed service IDs, canonical source/confidence enums and saturating counts cross MAIN → ISOLATED. Raw stack, script URL/query and container IDs stay out of the wire and report. Current-script attribution and a stack sample are distinct; temporal order and network initiator origin do not prove a loader. MAIN evidence remains `page-controlled`. No debugger permission, remote configuration evaluation, dataLayer inspection, timer/Promise replacement or native-function masking.

The canonical additional runtime readers are `packages/contracts/src/inspection.mjs`, copied byte-for-byte to production `inspection-contracts.js`. Pro pages may contain validated optional `cookies` snapshots and `tagManager` document summaries. Existing sessions without these fields remain valid. Permission revocation, pause, clear, navigation and read races must fail closed; counts are bounded and capture/export use the same projection.

Acceptance: independent semantic/privacy/false-positive review; Chrome and Firefox tests; native methods once with preserved identity/exceptions; hostile accessors, oversized input, cookie value sentinels, domain ambiguities, unsupported/declined permission, navigation/revocation races; no temporal GTM false edge; packaged permissions/CSP review. Disable by declining/revoking cookies permission or ending Pro observation.

Actual acceptance: 1157 Vitest and 326 Node cases, zero failures; Chrome 13 Cookie/GTM native checks alongside 22 Pro/graph checks; installed Firefox 138.0.4 22 native assertion groups. Final A/B semantic/privacy review accepted. The Firefox optional permission API was exercised through a trusted click with the isolated test profile suppressing the visual prompt; visual prompt acceptance is unverified. Nine fixed GTM targets were served locally, not contacted remotely. Final package hashes and evidence are in журнал приёмки 1.1.0 and внутренний отчёт.
