# ADR-029. Third-party request inventory for the current top document

Status: Implemented; independent review and native acceptance recorded in the linked coverage report. Explicit owner request of 2026-10-09. REQ-001/002/004/005/010/011/012/013/015.

The previous Third Party Surveillance panel displayed only technique IDs from child documents. Consequently a main document loading external scripts, pixels and collectors could display zero. The owner requested the external resource requests of the current top-level visit, together with removal of editorial caveats from this view.

The live inventory is scoped to the browser-authorized current top document and its currently accessible child documents. Resource rows retain the source document separately; third-party classification compares the resource with the top-level site, rather than with the embedded document. Subdomains on the same registrable site are excluded. Unknown relations are separate from confirmed cross-site request totals. The button counts cross-site request observations. Embedded-document API technique summaries remain an additional subsection.

Chrome uses existing passive webRequest permissions and native document identity for request, completion, error and redirect events across resource types. No blocking listener, debugger, request body, cookie value or response body is introduced. An initiator origin identifies a frame, not the JavaScript file. The source script stays unavailable when the browser has supplied no script attribution.

The installed Firefox lacks authoritative webRequest document identity. Its fallback reads resource timing through the existing authorized ISOLATED document bridge. The same fallback recovers a Chrome document when its network inventory has been lost after MV3 worker suspension. Once timing recovery is selected, that document keeps one timing source until reset or navigation. Timing entries are projected before crossing the bridge, remain `page-dom` / `page-controlled`, and do not invent HTTP status, completion, failure or script attribution. Browser and timing observations for the same document are never added together. No MAIN API wrapper or page-generated request is added.

The canonical request and snapshot readers live in `packages/contracts/src/third-party.mjs`, copied to `apps/production-extension/third-party-contracts.js`. The new privileged `ui-get-third-party` route requires a verified extension UI sender, root document identity, current consent and scope. Navigation, clear, pause, permission changes and retirement invalidate access to prior observations. Data and work are bounded; exact implemented limits are documented in `docs/coverage/third-party.md`.

Pro derives its third-party section from existing validated `page.resources`, so storage and export schemas do not change. Those groups may combine the visit's frames; the UI does not assign them an invented source document or initiator. Print renders every retained group. Live filtering and pagination operate locally and do not change collection.

All new labels and the concise anti-fraud empty state are translated in 21 UI languages. Owner-requested removal covers the vendor empty-state caveat, frame-selection caveat, generic no-verdict paragraph and vendor editorial paragraphs in these views. Machine coverage state, actual truncation and unavailable-data status remain factual.

No changes to manifest permissions, CSP, third-party connections, telemetry, dependencies, production detector thresholds, vendor signature activation or API return semantics.

Primary API references: [Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest), [PerformanceResourceTiming](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming), [PerformanceObserver.observe](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceObserver/observe).
