# ADR-048 — Custom и переносимые конфигурации API

Статус: реализация по прямому техническому заданию владельца от 2026-10-20. Продолжает ADR-033/045/046. Трассировка: REQ-002/003/004/005/010/011/012/015; задача внутренний отчёт.

Обновление: асинхронный MAIN/ISOLATED механизм применения этого решения заменён ранними нативными профилями по [ADR-049](ADR-049.md). Формат JSON и каталог сохранены.

Поведение переключателей обновлено [ADR-061](ADR-061.md): прямой клик немедленно сохраняет только выбранную строку и при наличии неизменного source document использует доверенный reload. Остальные черновики не записываются этим действием; описание старого общего Save ниже относится к первоначальной версии интерфейса.

## Решение

Единый редактор `protection.html` сохраняет значения ON = блокировка, BYPASS = наследование, OFF = разрешение. CUSTOM добавляет явно выбранный пользователем тестовый результат для поверхностей, перечисленных в каноническом каталоге `packages/contracts/src/api-configuration.mjs`. Общий выключатель продолжает управлять и блокировками, и Custom; новый профиль выключен. Области — общая конфигурация и точный hostname. Правило сайта переопределяет общее, BYPASS наследует его. Исключённый сайт не получает ни блокировки, ни Custom.

Авторизация на изменения REQ-001/002/005/013 дана этим техническим заданием только для Custom: выбранные пользователем значения разрешено сохранять в локальных настройках, экспортировать и передавать в MAIN для подмены соответствующего результата. В выбранной ветке Custom успешный результат и идентичность Promise могут изменяться намеренно. Это не распространяется на наблюдающие hooks, пароли, поля форм, тела запросов и модуль «Защита». MAIN не получает привилегированных команд, доступа к хранилищу или возможности менять конфигурацию. Маскировки `toString` нет; отсутствующие API, физические устройства, потоки и разрешения браузера не создаются.

## Каталог и JSON

- 105 постоянных ID в фиксированном порядке: прежние 89 и 16 отдельных параметров Navigator, Screen, Window и Intl. Из них 37 допускают типизированный Custom. Каталог сообщает тип, поддержку, ограничения и предустановленные значения.
- Формат `detect.expert/api-configuration`, `formatVersion: 1`, `catalogVersion: 1`. Экспорт включает все API, метаданные и стандартные пресеты, режимы, библиотеки пользовательских значений, выбранные значения, `settings` и все точные сайты. Неактивные и пустые поля не опускаются.
- Значения явно помечаются: `{kind:"unset"}`, `{kind:"undefined"}`, `{kind:"null"}` либо `{kind:"value",value:...}`. Пустая строка — обычное значение `value:""`. Null/undefined принимаются только для указанных каталогом API. CUSTOM с unset запрещён.
- Порядок ключей, API, сайтов, значений библиотек и вложенных объектов детерминирован. В переносимом файле нет локальной revision, времени экспорта и случайных ID.
- До 1000 пользовательских значений на API, 128 сайтов и 4 МиБ UTF-8 на конфигурацию. Эти пределы проверяются до применения; обход глубины и размера также ограничен.
- В JSON запрещены повторяющиеся ключи, API ID, имена свойств за пределами схемы, неизвестные API, недостающие поля, повреждённые типы и неизвестные версии. Стандартный каталог проверяется на соответствие версии; импорт не является интерпретатором кода или произвольных правил.
- Старый формат настроек `protection:v1` (`schemaVersion:1`) преобразуется без потери прежних блокировок, preset и исключённых сайтов. Неизвестные будущие версии отвергаются с сохранением текущих настроек.

## Хранение и применение

SW — единственный писатель конфигурации через существующий доверенный UI channel. `api-configuration:v1` хранит `{revision,configuration}`. Переносимая конфигурация и её прежняя проекция `protection:v1` записываются одним `storage.local.set`; прежний pending-маркер сохраняет восстановление после прерывания. Запись проверяет optimistic revision; отказ storage и некорректный импорт не меняют подтверждённое состояние в памяти. Сохранённые библиотеки переживают перезапуск браузера.

Для Custom старое индивидуальное правило проецируется в `allow`, чтобы запрет preset не скрывал выбранную поверхность. Новые scalar-параметры обрабатываются собственным installer. Старые launcher/master продолжают работать; их изменения объединяются с библиотеками Custom без потери последних.

Зарегистрированы два собственных скрипта на уже разрешённых HTTP(S)-сайтах: MAIN installer и ISOLATED relay. Relay получает конфигурацию только из SW; сообщения MAIN никогда не пересылаются в SW. MAIN повторно проверяет ID и типы; недоверенная страница может менять свой собственный realm, как и без расширения, но не настройки расширения. Идентичность документа берётся из `MessageSender`/webNavigation. Для уже открытых документов Chrome используется только exact-document injection. Firefox при отсутствии такой возможности требует явного перезагружения вместо перехода к небезопасному frame-only injection.

Конфигурация поступает асинхронно после готовности ISOLATED: исполнение до первого inline-скрипта не гарантируется. Изменения действуют в зарегистрированных document realms; workers/worklets, CSS media queries, HTTP User-Agent/Client Hints, ранее сохранённые ссылки и реальное оборудование не подменяются. Более подробная матрица — `docs/coverage/api-custom.md`.

## Интерфейс

Вместо второго списка используется единый редактор. В каждой строке четыре режима; Custom недоступен там, где нельзя корректно реализовать выбранный тип результата. Списки содержат поиск, стандартные и пользовательские значения, Create New Value, редактирование и удаление. Модальное Save сохраняет библиотеку, выбранное значение и текущую конфигурацию; Cancel не пишет настройки. Остальные изменения можно сохранить общей кнопкой.

Import JSON / Export JSON находятся над списком. Экспорт предварительно показывает полный файл. Импорт показывает различия и применяется только отдельной кнопкой; отмена предпросмотра не пишет данные. Отмена уже применённого импорта использует предыдущую конфигурацию и актуальную revision, не перезаписывая конкурентные изменения.

## Проверка

Чистые тесты: полный каталог и порядок, JSON round-trip, отрицательные структуры/версии/дубли, 100+ значений, теги пустых состояний, миграция, scope/preset priority. Runtime: native receiver/исключения, отсутствие API, владение дескриптором, восстановление, поздний ответ после stop, отсутствие побочного чтения аргументов. Controller: неверный sender, stale revision, атомарный отказ storage, совместимость прежних настроек и cleanup. Нативный Chromium: интерфейс, CPU=16, сохранение и перезапуск, импорт/экспорт/отмена, длинный список и компактная ширина. Фактические результаты — в отчёте задачи.

Новых permissions, CSP, зависимостей, сетевых соединений и remote data packs нет.
