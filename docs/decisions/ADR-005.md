# ADR-005. documentId, reducer, BFCache и prerender

Статус: **Accepted** (2026-09-12). Владелец: `packages/background` (reducer).

## Контекст

AUD-05: очистка на `onBeforeNavigate` теряла отчёт при отменённой навигации. Chrome допускает несколько документов на вкладку (активный, prerender, BFCache); `documentId` сохраняется при переходах состояний одного документа; `frameId` документ не идентифицирует. `webRequest` и `webNavigation` не имеют общего порядка; BFCache-восстановление не вызывает `onDOMContentLoaded`. SW теряет память при остановке.

## Решение

1. Сущности: `DocumentReport(documentId)`, `FrameBinding(tabId, frameId, documentId, parentDocumentId?, frameType, documentLifecycle)`, `TabProjection(activeTopDocumentId)`, `NavigationAttempt`, `RouteSegment`. Активный верхний документ — `frameType: outermost_frame` + `documentLifecycle: active`.
2. Таблица обязательного поведения — `docs/architecture/overview.md` §4 (перенос ТЗ II A7): pending на `onBeforeNavigate`, переключение на `onCommitted`, отмена не очищает, SPA обновляет `RouteSegment`, BFCache возобновляет тот же `documentId`, prerender хранится отдельно, iframe navigation = новый `documentId`, `tabs.onReplaced` перепривязывает, `tabId=-1` не атрибутируется, close/discard — по retention.
3. Out-of-order: батчи для неизвестного `documentId` — карантин ≤2 с и ≤128 записей на расширение; merge после commit; после timeout — orphan с `channel-gap`, без ложной атрибуции последнему URL.
4. Дедупликация `(documentKey, bridgeSessionId, batchSeq)`; watermark `lastCommittedBatchSeq` на `(documentKey, bridgeSessionId)`; кумулятивные счётчики — merge max в namespace `sensorBootId`. ACK после согласованной записи snapshot + watermark одной операцией `storage.session.set`.
5. Reducer — чистая функция `(state, event) → state'` в `packages/background/reducer` с event-типами `navigation:*`, `batch`, `ack-persisted`, `permission:*`, `policy:*`, `ui:*`, `ttl-tick`; побочные эффекты (storage, ACK) — в отдельном слое. Для одного `documentId` — последовательная очередь; разные документы независимы; один read-modify-write snapshot одновременно из popup и background запрещён (UI только читает проекции).
6. Hydration при старте SW: listeners регистрируются синхронно на верхнем уровне; обработчики ждут общий readiness promise с ограниченным буфером; восстановить bindings/watermarks/версии; reconciliation с `tabs.query` + `webNavigation.getAllFrames`; расхождение → `channel-gap`.
7. Обновление расширения: новая сессия; старый content script с несовместимым `schemaVersion` → `protocolOk: false` → `bridge-stop`; UI: reload required.
8. `pageshow/pagehide`, `document.prerendering` — только диагностика сенсора; browser lifecycle первичен. `unload` не используется как точка сохранения.
9. Incognito: `not_allowed` в v1; будущее включение — отдельный ADR (`split`, отдельные namespaces, доказанная очистка).

## Последствия

- Отчёт живёт дольше навигационной попытки; UI показывает `documentKey`/host заголовком и явно переключает контекст.
- Prerender-находки не смешиваются с видимой страницей до активации.
- TTL неактивного документа 10 мин, LRU в пределах 4 MiB; BFCache-возврат после истечения показывает `truncated`.
- Требуется trace-корпус реальных событий Chrome (E02-01) для fixtures reducer.

## Приёмка

State transitions + trace fixtures (E05-01): redirect, abort, reload, SPA push/replace/fragment, BFCache back/forward, prerender activate/cancel, iframe reuse, `tabs.onReplaced`, renderer crash, SW restart, extension update, stale batch после commit нового документа. Старые события не попадают в новый `documentId`; отменённая навигация сохраняет отчёт; повтор batch не удваивает; orphan помечен причиной.

## Планировщик TTL

P02 / F171, 2026-09-13 (REQ-009/REQ-011, A10). Без нового permission очистка неактивных документов выполняется на старте SW после hydration и сверки живых frame identities, до повторной привязки живых документов; далее перед `webNavigation.onCommitted`, `tabs.onRemoved`, при приёме батча и привилегированном UI-запросе. Общая амортизация — не чаще одного sweep за 30 секунд; best-effort `setInterval` работает только при живом worker. Проверка до rebind не позволяет восстановлению BFCache продлить уже истёкшую историю. Удаление snapshot проходит через очередь документа; индекс сохраняется с актуальной ревизией. Устаревшие tab projections удаляются после успешного `tabs.query`. Ошибка/null `getAllFrames` не считается доказательством отсутствия документа: binding сохраняется, диагностика деградирует; существующая fail-closed политика scope по-прежнему очищает наблюдения при неподтверждённом доступе.

TTL 600000 мс — критерий истечения, а не гарантия пробуждения worker к этому сроку. Без событий задержка не ограничена; событие внутри окна амортизации откладывает sweep до следующего события после окна. UI ru/en и data inventory раскрывают это ограничение. Закрытие вкладки по существующей политике удаляет её отчёты сразу; browser-тест прерывает эту запись настоящим `ServiceWorker.stopWorker`, оставляет неактивный snapshot и проверяет его TTL-удаление после навигации с согласованным индексом. Дополнительный unit-корпус проверяет все четыре триггера, границы TTL/30 с, сохранение активного документа и LRU.

Общий бюджет 4 MiB рассчитывается по `getBytesInUse(null)`, включая индекс и прочие ключи; размер жертв вычитается по `getBytesInUse(['doc:…'])`. JSON не заменяет доступную оценку Chrome. При недоступности API используется прежняя оценка snapshot; она не доказывает фактическое потребление памяти Chrome. Quota rejection даёт `degraded/truncated`, не более трёх попыток записи (двух повторов) и общий cooldown 5 с. После освобождения места повтор батча сохраняет snapshot и watermark; исторический `truncated` остаётся. Неизвестные тестовые мусорные ключи автоматически не удаляются: бюджет приложения не может компенсировать стороннее заполнение session.

После асинхронного измерения жертва повторно проверяется: активированный или уже удалённый документ не вытесняется. Перед усечением активных отчётов очередь удалений завершается и общий размер измеряется повторно, чтобы конкурентное закрытие вкладки не давало ложный `truncated`.

Прогон и ограничения: отчёт P02, [SW restart](../coverage/sw-restart.md).
