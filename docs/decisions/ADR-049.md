# ADR-049 — раннее применение Custom и закрытие обходов native значений

Статус: реализация по прямому решению владельца продукта 2026-10-20 проверить отсутствие раскрытия исходных значений и правильную точку перехвата в Chrome/Firefox. Владелец подтвердил приоритет ранней подмены; последующее уточнение: после запуска браузера и при первом посещении каждого нового сайта выбранные значения должны работать автоматически, без повторной загрузки сайта. Изменение настроек уже исполняющегося документа остаётся отдельным случаем.

Продолжает и заменяет раздел асинхронного применения ADR-048. REQ-002/003/004/005/010/011/012/015; E22-02. Разрешения и новая точка применения независимо проверены по первичной документации и нативным браузерным fixtures. Формат переносимого JSON и wire enum каталога не меняются. Модуль «Защита», его разрешения, чтение полей и vendor-код не меняются.

## Воспроизведённые ошибки

Прежний `document_start` MAIN устанавливал только слушатель, а значения приходили позднее из SW через ISOLATED/window.postMessage. Самый первый inline-скрипт получал реальные CPU, platform и screen. После ожидания ответа эти же тесты проходили, поэтому прежний нативный сценарий не проверял раннее применение. Публичный `Symbol.for(...).stop` и сообщения stop/apply-empty открывали восстановление native. Сохранённый wrapper после последующей переустановки также мог обратиться к исходному API.

Отдельные обходы: MediaDeviceInfo.prototype getters/toJSON и InputDeviceInfo.getCapabilities; WebGL getParameter со строковым/дробным/объектным GLenum; дополнительные поля Client Hints, storage и media results. Пустые фреймы и document.write создают новые realm, из которых можно заимствовать native getter и вызвать его на Navigator родителя.

## Решение

1. Нативный `userScripts.register` регистрирует **один замкнутый MAIN-скрипт с выбранными данными** на глобальную/точную конфигурацию сайта, `document_start`, `allFrames:true`. Никаких ожиданий SW/storage/Promise внутри bootstrap. В скрипт входят проверенные выбранные значения и собственный self-contained installer; библиотеки, отчёты и наблюдённые параметры туда не входят. Нет eval, Function, remote code или произвольного пользовательского JS.
2. Chrome получает необходимое `userScripts` в required permissions и требует пользовательский Allow User Scripts. Firefox предоставляет API с версии 137 и требует optional-only `userScripts`, запрашиваемое отдельным доверенным нажатием. Старые браузеры/отказ/выключенный доступ показываются как недоступность Custom; включение Custom без готового API отвергается до записи. HTTP(S) host permissions, CSP, сетевые возможности и зависимости не расширяются.
3. Native регистрация сохраняется при обычном перезапуске браузера, а конфигурация — в storage.local. После завершённой и проверенной регистрации для обычного старта и новых посещений не нужна перезагрузка страницы. Обновление самого расширения очищает userScripts; controller восстанавливает их асинхронно при старте, и навигация до завершения reconcile не объявляется защищённой. Данные уже исполняющегося документа неизменны: после изменения профиля новая конфигурация относится к следующим документам; Save and reload предназначено только для уже открытой страницы. Полученное до включения расширения значение нельзя отозвать из памяти сайта.
4. Удалены применяемые через страницу stop/apply listeners и публичное восстановление оригиналов. Файлы v1 оставлены инертными для совместимости старых регистраций; controller снимает эти регистрации. Все handles и native descriptors остаются в замыканиях.
5. Установщик патчит владельца native дескриптора в соответствующем MAIN realm. Media metadata привязывается к объекту через приватный WeakMap и перехватывается также на нативных прототипах. Дополнительные поля результата очищаются; opaque WebGL arguments не читаются/не преобразуются повторно и не возвращают чувствительную native строку.
6. Синхронное наследование применяется к доступным пустым фреймам/окнам. Собственный persistent scripting bootstrap с `matchOriginAsFallback:true` передаёт текущий Window в apply-only capability родителя/создателя. Capability не принимает значения, не возвращает originals и не умеет stop. Обработчики создания/доступа к фреймам и раннего load закрывают синхронные пути до возврата управления странице. Внутренняя логика использует заранее захваченные intrinsics.
7. На смене профилей новые регистрации добавляются перед обновлением и удалением старых, чтобы переход к site exception не оставлял окно native. При ошибке сохраняется последняя установленная конфигурация и показывается ошибка применения. Отзыв доступа и OFF снимают будущие регистрации; существующий документ сохраняет свою подмену до выхода/перезагрузки.

Нативные обёртки не маскируются. Wrapper detection, физические устройства, HTTP User-Agent/Client Hints, CSS, worker/worklet realm и полный календарный движок не становятся частью этого механизма. Нельзя делать вывод «никаких исходных характеристик нельзя определить» из проверки перечисленных JavaScript metadata API. Opaque sandbox/data realms и пределы количества фреймов требуют отдельных доказательств и не объявляются покрытыми без нативного теста.

## Проверка

Fixtures исполняют собственный первый inline-скрипт, а не automation init script. Проверяются inline/microtask/DOMContentLoaded/load, prototype.call, сохранённые getters, заимствованные getters из свежих realm, window.frames, Node/DocumentFragment, srcdoc, document.write, popup, повторная конфигурация, сообщения stop/apply-empty, запуск сохранённого браузерного профиля до открытия UI/SW и перенос JSON. Отдельно проверяется совместимость прежних 89 блокировок и модуля «Защита».

Фактические результаты и ограничения — внутренний отчёт.

## Первичные источники

- [Chrome userScripts](https://developer.chrome.com/docs/extensions/reference/api/userScripts): MAIN, document_start, сохранение/обновление регистраций и Allow User Scripts.
- [Mozilla userScripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts): optional-only permission и доступ API.
- [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts): ранняя инъекция, порядок файлов, origin fallback.
- [Mozilla content scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Content_scripts): различия worlds и ограничение document_start для пустых фреймов.
