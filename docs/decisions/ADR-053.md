# ADR-053 — переключение Firewall из общей строки

Обновление 2026-11-01: по прямому решению владельца продукта [ADR-098](ADR-098-direct-firewall-activation.md) заменяет описанные ниже activation dialog/checkbox одним явным кликом. Канал включения, версия/digest, сохранение настроек и проверки controller не меняются.

Дата: 2026-10-20. Прямое решение владельца продукта: кнопка Firewall включает и выключает модуль вместо перехода в настройки. Последующее решение: высота верхней панели языка/настроек/пина — 30 px.

## Решение

Обе кнопки Firewall в popup, sidepanel и основной странице Options вызывают один переключатель. При выключении используется существующий `session.disable(false)`: сохраняются согласие, выбранные функции, режим, исключения и постоянные данные. Повторное включение с действующим согласием вызывает `session.enable` непосредственно из пользовательского события. При первом включении или новой версии согласия существующий `ProtectConsentDialog` открывается на текущей странице. Текст, обязательный checkbox и версия согласия не меняются; перехода в Options нет.

Состояние отображается только по ответу controller, без оптимистичного ON. Повторные клики блокируются. Ошибки, недоступность и managed policy не изображаются успешным переключением. Подписи следующего действия, ожидания и ошибки локализованы на всех 21 языках; подробные сообщения и диалог сохраняют прежнюю RU/EN локализацию с корректными lang/dir. Стрелка перехода с кнопки Firewall удалена.

## Узкое изменение привилегированного канала

Это явное дополнение к ограничению «enable только из Options» в ADR-020-protect §6 / ADR-047. Только `ui-protect-enable` дополнительно разрешён из собственных `popup.html` и `sidepanel.html`. Существующий `verifyUiSender`, ID и origin расширения сохраняются; URL проверяется по точному pathname. `findings.html`, `firewall.html`, вложенные/похожие пути, чужие расширения и content senders не допускаются. Sender не подменяется. Настройки и снятие исключений остаются Options-only.

Для launcher с действующим согласием текущие features/preset берутся внутри serialized controller из сохранённых настроек: устаревшее состояние UI не перезаписывает изменения Options. Первый/обновлённый consent использует подтверждённый draft. Managed policy, версия согласия, permissions, persist-before-activation и cleanup DNR сохраняются.

Vendor остаётся побайтовой копией 722fae8. Production adapter `src/patches/protect-controller.ts` подключён через REDIRECTS. Тест сравнения с vendor ограничивает отличия импортами, allowlist enable/resume и обработкой ошибки записи OFF.

## Отказ хранилища при OFF

Модуль останавливается до сохранения OFF. При отказе записи выполняется один повтор той же настройки. Успешный ответ возвращается только после сохранения. Если обе записи отклонены, текущий SW остаётся остановленным, возвращается storage-unavailable и показывается ошибка. Настройки не удаляются, скрытого purge и возврата ON в текущем SW нет. При полном отказе storage старое сохранённое ON может остаться на диске; сохранение OFF через перезапуск в этом состоянии не гарантируется и не объявляется успешным.

## Проверка

Независимый review trust boundary и UI, focused controller/locale tests, production build, typecheck/lint, unit suite, реальные клики и сохранение состояния, ошибки хранения и managed policy. Обязателен зелёный production privacy gate с независимыми tripwire в обоих мирах по ADR-020-protect §15. Фактические результаты: внутренний отчёт.

Firefox сохраняет ограничение ADR-047: модуль Firewall не поставляется. Высота общей верхней панели 30 px применяется в обеих сборках.
