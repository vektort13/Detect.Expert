# ADR-108 — Решения владельца по сверке с ShardBrowser (раунд 5)

Дата: 2026-11-06. Прямое решение владельца продукта от 2026-11-06: «Мои решения — сделай максимально правильную реализацию, максимально близкую к реальной», затем «Продолжай делать всё, что можешь. Сверяйся с [ShardBrowser](https://github.com/ProxyShard/ShardBrowser). И сделай красивый прокси-менеджер тоже». Закрывает пункты раздела «Решения владельца (не реализованы)» [ADR-107](ADR-107-shardbrowser-ports.md), которые можно выполнить честно внутри расширения. Продолжает ADR-060/066/070/071/101/105/106/107.
ShardBrowser использовался только как справочник для чтения: его код и тексты не копировались и не запускались (лаунчер MIT, ui-kit MIT другого владельца, иконки — свои лицензии); все переносы — независимая реализация, запись в `NOTICE` не нужна. Новых permissions, CSP, сетевых обращений расширения, каналов сообщений, телеметрии и зависимостей нет. Версия 2.0.0.
Принцип раунда (REQ-015): значения, ошибки и форма объектов должны совпадать с настоящим Chrome; то, что нельзя сделать правильно без доступа к движку, не делается, а причина записана ниже. Полумера, которая создаёт новое расхождение, хуже отсутствия меры.

## Что изменено в границах

- **Формат 9 / каталог 10** (раздел 1): теги и заметки в записи профиля, тип `media-codecs`, значение `proxy_only` политики WebRTC. Каталог 9 раунда 4 заморожен побайтно, потому что собранный с ним выпуск уже установлен у владельца.
- **ADR-105, дополнение**: одно действие `remove` для `X-Client-Data` (правило 300109) — только пока применённая Custom-идентичность называет не Google Chrome (раздел 2). Список остаётся закрытым, диапазон 300100…300119 и priority 1000 не меняются.
- **ADR-060, дополнение**: для Firefox выбор политики WebRTC расширен значением `proxy_only` (раздел 3).
- **ADR-101, дополнение**: конфигурации MediaCapabilities без ключевой системы выполняют родной вызов страницы до конца, а ответ только понижается; приватное реле и backend обслуживают только конфигурации с ключевой системой (раздел 4).
- **Canvas** (ADR-066/106/107): полупрозрачные пиксели помечаются одним сохранённым состоянием, а не ±1 (раздел 5).
- **ADR-070/071, дополнение**: профили HTTP и HTTPS, поведение SOCKS5 по RFC 1928/1929, типизированный запрос `diagnose`, метка страны, история ручных проверок (раздел 6); новый менеджер прокси (раздел 7).
- **Библиотека и интерфейс** (ADR-066/103): теги и заметки, корзина на 7 дней, временные профили, связка профиль↔прокси (раздел 8), экскурсия по Options (раздел 9).
- **Новые ключи `storage.local`** (только локально, bounded, строгая проверка формы при чтении, не входят в экспорты, отчёты и логи): `proxy-check-history:v1`, `fingerprint-trash:v1`, `fingerprint-temporary:v1` (плюс маркер в `storage.session`), `identity-bundles:v1`; в `localStorage` страницы Options — только состояние интерфейса `proxy-view:v1` и `ui-tour:v1`. Опциональное поле `country` в `proxy-configuration:v1` и поля `tags`, `note` в записи профиля внутри `api-configuration:v1`.

## 1. Контракт: формат 9 / каталог 10

`API_CONFIGURATION_VERSION = 9`, `API_CONFIGURATION_CATALOG_VERSION = 10`; 158 строк, 56 Custom. Каталог 10 отличается от прежнего каталога 9 (заморожен, состояние раунда 4) одной строкой `media-capabilities` (тип `media-codecs`).

- **Заморозка каталога 9.** SHA-256 `JSON.stringify(API_CONFIG_CATALOG_V9)` = `2200ab966b82da57e0245cbc79d7ad3d3428675f8c8e554a48f58cc1c4f648a0`; модуль `api-configuration.js` сборки раунда 4 — `fc7c6548124b8f0ea73a6b4ba95b03d2c26b9d326670811a04a4e812df4b2c5a`. Настоящий экспорт той сборки (`scripts/test/api-configuration-catalog9-export.fixture.json` — состояние раунда 4, текущий формат 9 / каталог 10; 3 профиля, 4 сайта, Custom-строки Canvas, сети, медиа, голосов и WebRTC) строго мигрирует; значения только каталога 10 отклоняются внутри каждого прежнего формата.
- **Запись профиля библиотеки** получает `tags` и `note`. `tags`: 0–8 строк по 1–24 единицы UTF-16, без повторов с учётом регистра, хранятся по возрастанию кодовых единиц. `note`: 0–500 единиц, допускается перевод строки LF; CR, прочие управляющие C0/C1 и bidi-символы запрещены. Базовый валидатор не проверяет безопасность символов; запись из интерфейса и импорт отклоняют небезопасные теги и заметки кодом `unsafe-label` (запись сохраняет прежнее значение той же записи профиля, импорт ничего не прощает).
- **Политика WebRTC** `proxy_only` допустима только в формате 9; форматы 2–8 знают три прежних значения.
- **Миграция.** Принимаются прежняя пара (каталог 9, формат 8 — состояние раунда 4) и все более ранние в текущий формат 9 / каталог 10; значения `media-capabilities` получают `hidden: []`, профили — `tags: []`, `note: ''`.

## 2. X-Client-Data (дополнение ADR-105)

Настоящий Google Chrome добавляет к запросам на хосты Google заголовок `X-Client-Data` (идентификаторы вариаций). Custom-идентичность, которая называет не Google Chrome, не должна его нести. В закрытый список добавлено ровно одно действие: `remove` заголовка запроса — правило 300109, priority 1000, те же 13 типов ресурсов, исключение инициатора-расширения, без `urlFilter`, никогда `set`; значение заголовка расширение не читает. Строка таблицы: `client-data | 300109 | remove | X-Client-Data | Custom client-hints без бренда «Google Chrome» либо Custom navigator-user-agent, называющий другой продукт`.

Когда правило активно: только пока применяется Custom-идентичность (мастер Antidetect, готовый ранний реестр, область all-sites, те же условия, что у остальных правил) и выполнено любое из двух: список брендов строки `client-hints` не содержит «Google Chrome» (пустой список тоже) либо User-Agent строки `navigator-user-agent` называет другой продукт (Edge, Opera, Firefox, Samsung Internet, Yandex Browser, Vivaldi, явный токен `Chromium/`, Safari без токена Chrome). Голый токен `Chrome/` и `CriOS/` остаются заявкой Chrome; заявка без узнаваемого продукта не угадывается. Отсутствие заголовка у заявки Chrome ничему не противоречит (профиль без идентификаторов вариаций его не шлёт), присутствие у заявки Edge или Firefox — противоречие.

Измерено (локальные серверы, имена `www.google.com`, `www.youtube.com`, `fonts.googleapis.com` отображены на 127.0.0.1, доверие по SPKI сертификата, внешней сети нет): установленный Chrome 156.0.8078.80 без идентификаторов вариаций — 0 из 53 https-запросов с заголовком; Chrome 156 и Chromium 153.0.8010.12 с идентификаторами, заданными ключом `--force-variation-ids`, — 52 из 52 и 34 из 34: навигация, iframe, fetch (в том числе keepalive), XHR, script, image, stylesheet, sendBeacon, favicon, скрипт и fetch выделенного воркера, со страницы Google и чужой страницы. Рукопожатие WebSocket, plain http и не-Google хосты заголовка не получают; Edge 156.0.4314.58 с тем же ключом — 0 из 43. Правило `remove` на 13 типах убрало заголовок: 0 из 34 и 0 из 30 против 32 из 35 и 27 из 30 без правила; после снятия правила заголовок вернулся. Не измерено: профиль с настоящим семенем вариаций, настоящие Opera, Samsung Internet, Yandex Browser, Vivaldi и Chrome для iOS (правило снимает заголовок у заявки любого из них по тому же принципу), запросы из service worker чужого сайта.

## 3. WebRTC `proxy_only` в Firefox (дополнение ADR-060)

Значение есть только в `privacy.network.webRTCIPHandlingPolicy` Firefox (Firefox 138.0.4: схема `privacy.json`, значение `media.peerconnection.ice.proxy_only`) и строже `disable_non_proxied_udp`: весь трафик WebRTC идёт только через прокси, без прокси, передающего UDP, звонки не работают (измерено: Firefox 138.0.4 без прокси — 0 ICE-кандидатов против 4 на базовой линии, `iceGatheringState` остаётся `new`). Chrome 153 и 156 отклоняют значение своим API. Значение предлагается только в сборке Firefox (страницы `moz-extension://`) и считается применённым только после чтения через нативный API: точное `proxy_only` и `controlled_by_this_extension`. В Chrome значение скрыто; сохранённый выбор показывается заблокированным, нативная настройка не записывается ни одним вызовом, а применение (сохранение при включённом мастере Antidetect) отклоняется фиксированным кодом `webrtc-policy-unsupported`. При активном модуле «Прокси» действует более строгое из двух значений. Не проверено: Firefox 128 (нижняя граница `strict_min_version`).

## 4. Кодеки только вниз (дополнение ADR-101)

Custom `media-capabilities` может только понизить то, что сообщает этот браузер (решение владельца продукта 2026-11-06).

- **MediaCapabilities.** Конфигурация без `keySystemConfiguration` больше не прерывает MAIN-вызов: родной `decodingInfo`/`encodingInfo` страницы выполняется до конца, и ответ возвращается пониженным: `supported` = родной И выбранный И ни одно семейство из списка скрытых не названо в кодовых строках аудио/видео; `smooth` и `powerEfficient` дополнительно требуют родной И выбранный И `supported`. Остальные собственные поля родного ответа сохраняются. Приватное реле и backend обслуживают только конфигурации с ключевой системой (Custom true отклоняет их, Custom false остаётся виртуальным unsupported). Причина отказа от схемы «backend отдаёт родные флаги»: измерено, что результат service worker отличается от результата страницы (`powerEfficient` для AV1 и VP8, WebRTC H.264), и «И» по данным backend мог бы поднять флаг выше того, что сообщает браузер страницы.
- **Один список скрытых семейств** (`h264`, `h265`, `av1`, `vp9`, `vp8`, `aac`, `opus`, `vorbis`, `flac`, `mp3`, `dolby`) для `MediaCapabilities`, `HTMLMediaElement.canPlayType`, `MediaSource`/`ManagedMediaSource.isTypeSupported` и `MediaRecorder.isTypeSupported` в окнах и их same-origin фреймах. Оригинал вызывается один раз с исходными `this` и аргументами, родные `''`/`false` никогда не поднимаются, читается только примитивная строка в первых 512 единицах UTF-16 без приведения; неверный получатель, не-строки и исключения остаются родными. `supported: false` делает недоступным любой запрос, называющий кодек; запросы с одним контейнером остаются родными. Dolby Vision (`dvh1`, `dvhe`) считается семействами `dolby` и `h265`.
- **Профиль «всё включено без скрытых семейств» — это родной ответ**: ничего не устанавливается.
- **Пределы.** Непрозрачные документы (`about:`, `blob:`, `data:`) оставляют `canPlayType`/`isTypeSupported` родными, а `decodingInfo` отвечает сразу нативным по форме all-false; в выделенном Worker флаги понижаются, но скрытые семейства не применяются (второе чтение словаря страницы запустило бы пользовательский код); объект `String` обходит скрытие; строки длиннее 512 единиц не разбираются; `WebCodecs.isConfigSupported`, EME, `RTCRtpSender/Receiver.getCapabilities` и `ImageDecoder.isTypeSupported` списку не следуют.
- **Что меняется для существующих пользователей.** Сохранённые значения прежних каталогов (с 1 по 9) мигрируют с `hidden: []` и теперь означают «родной И выбранный» (раньше `supported: true` принудительно давало `true` даже там, где браузер отвечал `false`); пресет «всё включено» стал полностью родным; обычные вызовы больше не ограничиваются по частоте и их ошибки — родные.

## 5. Canvas: полупрозрачные пиксели (ADR-066/106/107)

Канал полупрозрачного пикселя (0 < alpha < 255) хранится premultiplied-байтом q ≤ alpha и читается по арифметике движка, поэтому сдвиг на ±1 обычно даёт значение, которое не вернёт ни один движок. Выбранный пиксель (тот же выбор пикселя, канала и направления, что у непрозрачных) двигается на одно сохранённое состояние (q ± 1, затем ± 2; у Firefox до ± 3), где q = round(v·alpha/255), и получает байт, который движок сам возвращает для нового состояния. `stable-rgb-v1` двигает все три канала (хэш по трём состояниям и `alpha ^ 254`, у непрозрачного — его байты и 1). Экспорт пишет плитку целиком через `putImageData`, поэтому PNG помеченного пикселя совпадает с PNG настоящего холста с этим значением. Непрозрачные и полностью прозрачные пиксели дают байт-в-байт прежний результат.

Измерено (`scripts/test/canvas-translucent-native.mjs`): 65 024 пары (alpha, значение) = 32 639 состояний по шести путям чтения и шести путям PNG. Chromium 153 и Chrome 156: premultiply и `getImageData` округляют; CPU и GPU расходятся только в 615 состояниях с ровно половиной уровня (450 пар), такие значения не используются. Firefox 138.0.4 и 153.0: premultiply = ceil, `getImageData` = floor (423 состояния на единицу ниже), PNG = округление; берутся только байты, одинаковые при floor и при округлении. Помечается 100% читаемых значений в Chromium и 88,9% в Firefox (почти не сдвигаются alpha 6, 10, 30, 34, 102, 170). Копия рисунка с прозрачностью 0,99 (alpha 252) помечается во всех 40 ключах корпуса в обоих движках. Семейство движка определяется по членам вендора, а не по значениям `navigator`.

Остаются настоящими: полупрозрачные байты `readPixels` WebGL-холстов, движок без измеренной арифметики, `getImageData` с другим `colorSpace`. **Пересмотрено [ADR-112](ADR-112-canvas-sparse-v2.md):** экспорт WebGL-холста (`toDataURL`, `toBlob`) берётся из 2D-копии и помечает полупрозрачные пиксели так же, как экспорт 2D-холста с теми же пикселями (раньше он оставался родным, а его зеркало `drawImage` было помечено, и страница видела разницу); `readPixels` по-прежнему возвращает premultiplied-байты и меняет только непрозрачные пиксели. Не проверено: Firefox после перехода на округление в основной ветке (исходники прочитаны, бинарник не запускался; правило построено так, чтобы быть верным при обеих арифметиках), Firefox на ARM, Chromium на не-NVIDIA GPU. Стоимость: 1920×1080 `toDataURL` с `globalAlpha` 0,99 — 75,8 мс против 80,2 мс до изменения (настоящий — 31 мс).

## 6. Прокси: companion и расширение (дополнение ADR-070/071)

Подробности и измерения — [docs/coverage/proxy.md](../coverage/proxy.md). Здесь — решения.

- **Профили HTTP и HTTPS.** Без логина браузер подключается к прокси сам; с логином — через loopback SOCKS5-реле companion, которое открывает `CONNECT` к прокси (HTTPS: TLS 1.2+ по системному хранилищу, проверка не отключается) и передаёт Basic-авторизацию. Только TCP; Digest, NTLM, Negotiate, HTTP/2 `CONNECT` и SOCKS4 не поддерживаются. Подключение с логином проверяет только ответ сервера: логин проверяется первым запросом или кнопкой проверки, и интерфейс говорит об этом.
- **SOCKS5 по RFC 1928/1929** на обеих сторонах реле: предложение методов `[00]` без логина и `[00, 02]` с логином с выбором по ответу сервера, коды ответов 1–8, терпимость к номеру версии в ответе RFC 1929 (как у curl). Новые фиксированные коды `proxy-denied`, `network-unreachable`, `host-unreachable`; `auth-required` при ответе 407 без логина.
- **Типизированный `diagnose`.** Запрос `endpoint: { type, host, port }` для HTTP/HTTPS без логина: companion сам открывает соединение с прокси, ничего не сохраняя; принимает только эти три ключа. Временная запись в хранилище DPAPI для проверок не используется.
- **Сроки.** Установка соединения реле — не больше 25 с; проверка — одним бюджетом 12 с.
- **Метка страны** — собственная заметка пользователя (ISO 3166-1 из офлайн-таблицы): не определяется, не ищется по IP, не уходит в companion.
- **История ручных проверок** в `proxy-check-history:v1`: записи-«стоянки» (подряд идущие успешные проверки с одним внешним IP схлопываются), 30 записей на профиль, 100 профилей, срок 30 дней, переключатель «Сохранять историю проверок» (по умолчанию включён), очистка с подтверждением. Внешний IP — адрес самого прокси; в экспорты и отчёты не входит.
- **Совместимость.** Понижение версии расширения не поддерживается: прежние сборки отклоняют конфигурацию с `country` и HTTP/HTTPS (строгие наборы ключей). Новый companion принимает прежнего клиента; старый companion не знает новых типов, и расширение показывает «обновите companion».

## 7. Менеджер прокси (интерфейс)

Страница Proxy перестроена в языке ADR-103 («Спокойное стекло»); протокол, состояние и хранилище прокси не менялись.

- **Состав.** Карточка маршрута (состояние словом и значком, профиль, «Подключить», четыре переключателя защит, раскрывающиеся «Маршрутизация», «Анализатор соединения», «Companion»); настоящая ARIA-сетка (roving tabindex, `aria-sort`, названные столбцы; клавиши: стрелки, Home/End, Space, Shift+стрелки, Ctrl/Cmd+A, Enter, Delete, `c`, `/`, Escape); фильтры-чипы со счётчиками (тип, результат проверки, страна), сортировка, плотность, выбор столбцов; плавающая панель выбора; пакетная проверка «выбранные/все» (очередь в интерфейсе, прогресс, «Отмена», итог; каждый результат пишется в историю, как одиночная проверка; сейчас по одному, потому что служба сериализует операции); панель деталей с честными ограничениями типа, числом связанных профилей, графиком задержки с текстовой альтернативой и лентой истории («внешний IP изменился»); лист «Добавить/Изменить» (сегменты типа, умная вставка без секретов, ошибки у полей, глаз у пароля, выбор страны, помощник сессии); двухшаговый импорт; скелетон (ждёт 150 мс, держится не менее 400 мс), пустое состояние и состояние ошибки; карточки на телефоне ниже 700 пикселей (цели 44 пикселя, чипы фильтров 40), RTL, 7 тем, forced colors, reduced motion.
- **Хранилище.** Новый ключ `proxy-view:v1` — `localStorage` страницы Options: `{ version: 1, density, columns, sort, dir }` (не более 1024 символов, строгая проверка, любое отклонение — значения по умолчанию, без данных профилей), сброс — «Сбросить вид» в меню столбцов. Ключ `identity-bundles:v1` страница только читает (число связанных профилей).
- **Подсказка «регион совпадает/отличается»** в списке прокси не строилась: страница не читает хранилище Antidetect, а `identity-bundles:v1` содержит только связи; вердикт не выдумывался. Подсказка `proxy-country-region` живёт в редакторе Antidetect (раздел 8).
- **Проверено.** 113 юнит-тестов интерфейса и 19 тестов модели; нативные проверки в Chromium и Firefox: ступени раскладки (две панели от 1100 пикселей, наложение 701–1099, карточки ниже 700), нет горизонтальной прокрутки на ширинах от 320 до 1280, цели касания, контраст AA по вычисленным цветам (13 380 текстов и значков в 56 состояниях семи тем в Chromium, 11 376 в 42 состояниях шести тем в Firefox), обход только с клавиатуры, движение 100–200 мс и без него при reduced motion, 21 язык, нет ошибок консоли; 100 профилей — страница снова готова за 448 мс в Chromium, медиана фильтра 59 мс. Намеренные поломки: 28 из 28 в юнит-тестах и 5 из 5 в нативных.
- **Пределы.** Экранные чтецы не проверялись. В Firefox нет настоящего обхода Tab, наведения, forced colors и reduced motion (WebDriver). Результаты пакетной проверки в Chromium идут от управляемой подмены службы (настоящая требует companion). `proxy-permission-native.mjs` и варианты `--native-auth` в этом проходе не запускались. Переводы 59 новых строк на 19 языков без проверки носителями.

## 8. Библиотека профилей: теги, заметки, корзина, временные профили, связка с прокси

- **Теги и заметки** — поля записи профиля (раздел 1). Редактирование в панели просмотра: теги как чипы (ввод Enter или запятой, подсказки из уже использованных, счётчики n/8 и длины), заметка с счётчиком; фильтр по тегам со счётчиками; поиск по метке, тегам и заметке; дублирование копирует и то и другое; переносятся вместе с профилем в экспорте библиотеки.
- **Корзина на 7 дней** (`fingerprint-trash:v1`). Сначала пишется копия, затем профиль удаляется из конфигурации (при сбое второго шага профиль остаётся в библиотеке); «Отменить» после удаления — восстановление из корзины. Вид «Корзина (N)»: имя, время удаления, счётчик дней (последние сутки — янтарным), «Восстановить», «Удалить навсегда», «Очистить корзину» с подтверждением; при занятом идентификаторе восстановленный профиль получает новый. Не более 32 записей и 1,5 МиБ (вытесняются старейшие, интерфейс сообщает), срок 7 суток, обрезка при каждом чтении и записи; 60 с льготы защищают только что записанную копию от гонки с обрезкой. Хранится только на этом компьютере, не экспортируется.
- **Временные профили** (`fingerprint-temporary:v1` + маркер `fingerprint-temporary-live:v1` в `storage.session`). Профиль из библиотеки или сгенерированная личность применяется только на сеанс браузера; снимок прежнего состояния (до 256 КиБ) сохраняется. Если запись есть, а маркера нет, браузер перезапускали: service worker возвращает прежнее состояние при запуске, до регистрации скриптов, тем же CAS-путём (возврат никогда не отклоняется). Повторный запуск не наслаивается: прежним остаётся исходное состояние. Сгенерированная личность не попадает в библиотеку (есть явное «Сохранить в библиотеку»). Баннер «Временный профиль активен» с кнопкой «Завершить». Приватные ключи шума в снимок не копируются: они производные от применённых строк.
- **Связка «профиль → прокси»** (`identity-bundles:v1`, машинно-локально, не экспортируется). Выбор сохранённого прокси из раздела Proxy через Options-only порт; предупреждение (с подтверждением), если прокси уже связан с другим профилем. «Применить вместе с прокси» применяет профиль, затем просит раздел Proxy подключить связанный прокси: клик пользователя — явное подключение, `autoConnect` не создаётся; результаты двух шагов показываются отдельно. Подсказка `proxy-country-region` сравнивает собственную метку страны прокси с регионом профиля и предлагает «Подогнать регион» (предпросмотр правки существующих строк региона).
- **Проверено.** 1116 юнит-тестов области; нативные проверки в Chromium и Firefox, включая настоящий перезапуск браузера с возвратом временного профиля в Chromium; 35 намеренных поломок из 35 пойманы. Найдено и исправлено при реальных прогонах: гонка обрезки только что записанной копии корзины, потеря тега при двух событиях до перерисовки в Firefox, «+2» в RTL и обрезанный список прокси.
- **Пределы.** Возврат временного профиля после перезапуска в Firefox проверен только юнит-тестами (фикстура даёт новый UUID расширения при каждом запуске). Нет массовых операций в корзине и над тегами. Запись корзины или временного профиля прежнего формата отбрасывается, поэтому смена формата требует миграции. Путь «Применить вместе с прокси» проверен нативно только с прямым HTTP-прокси; отказ в разрешении и прокси с companion (VLESS, OpenVPN) проверены фейками. Переводы на 19 языков без проверки носителями.

## 9. Экскурсия по интерфейсу

`ui-tour.js` — чисто интерфейсная функция Options: не читает страницы, отчёты и настройки профилей, не вызывает `chrome.*`, не использует сеть; единственное хранилище — `localStorage['ui-tour:v1']` страницы Options (`{ version: 1, completed, lastStep }`, не более 64 символов). Восемь шагов: уровни, генератор и пресеты, регион, подсказки редактора, библиотека, связка с прокси и раздел Proxy, «Применить» и проверка, финал. Подсветка кольцом, всплывающая карточка `role="dialog"` с `aria-modal="false"` (ничего не становится inert или aria-hidden), «n / N», «Назад», «Далее», «Пропустить»; управление Esc, стрелками (в RTL зеркально), Enter и Tab; объявления через `ui-announcer`; фокус возвращается на кнопку запуска; отсутствующая цель пропускается с видимой пометкой; на узких экранах карточка стыкуется к нижнему краю, кнопки всегда в зоне видимости. Входы: кнопка в контрольном списке первого запуска, команда палитры, ссылка рядом с «Обновить». Тур сам не запускается. Тексты (30 ключей на 21 язык) лежат в модуле только для Options `ui-tour-labels.js`, а не в общей таблице переводов, поэтому размер бандлов background, popup, sidepanel и report не меняется. Дополнено [ADR-111](ADR-111-guided-tours-and-header-actions.md): экскурсии есть у каждого раздела Options, запускает их кнопка в шапке (ссылка рядом с «Обновить» убрана), прогресс хранится как `ui-tour:v2`, шаг «Proxy» перенесён в экскурсию раздела Proxy.

Проверено: 42 юнит-теста; нативные тесты настоящими нажатиями клавиш в Chromium (14 проверок) и Firefox (12); контраст не ниже 4,5:1 во всех семи палитрах (минимум 4,82); 9 намеренных поломок из 9 пойманы. Пределы: экранные чтецы не проверялись; эмуляция reduced motion и forced colors только в Chromium; масштаб 200% имитируется уменьшением окна; проверки касанием нет; переводы без проверки носителями.

## Не реализовано и почему

- **Частота кадров.** Видимой частоты обновления нет в API страницы; её единственный наблюдаемый след — интервалы `requestAnimationFrame`, которые задаёт композитор. Правка меток времени в JavaScript создаёт расхождения между `rAF`, `performance.now()` и реальным кадром, то есть новый признак вместо меры. Нужен патч движка.
- **`FontFace local()`.** Список разрешённых шрифтов для `local()` нельзя применить честно: разрешение шрифтов в CSS (`@font-face`, `font-family`) и измерение вёрстки через DOM обходят любую обёртку, а подмена `status`/`loaded` у `FontFace` — заметный признак. Остаётся покрытие `canvas-font-policy` (контекст Canvas).
- **Масштаб текста (`canvas-text-metrics`)** оставлен как есть: известный предел — измерение через DOM обходит строку; удаление строки молча сбросило бы настройки пользователей. Предел виден в документации покрытия.
- **Раскладка клавиатуры** (`navigator.keyboard.getLayoutMap`) отложена: в headless Chromium карта пуста, проверенные таблицы раскладок нужно брать из CLDR, а точное воспроизведение `KeyboardLayoutMap` требует собственного класса итератора (`[object KeyboardLayoutMap Iterator]`). Пока Strict по-прежнему блокирует этот API (известное явное исключение).
- **Скрытые семейства кодеков** в Worker и непрозрачных документах (раздел 4); **полупрозрачные байты `readPixels`** (раздел 5; экспорт WebGL-холста помечается с ADR-112).

## Известные пределы

Переводы новых строк на 19 языков перепроверены независимыми проходами модели (331 правка из 4256 строк; таблица для носителей — внутренний отчёт), но носителями не проверены; экранные чтецы не проверялись; Edge не проверялся; в Firefox 128 `proxy_only` не проверялся; Digest/NTLM-прокси и нестандартные провайдеры не проверялись.
