# ADR-107 — Переносы из сверки с ShardBrowser

Дата: 2026-11-06. Прямое решение владельца продукта от 2026-11-05: «Изучить [ShardBrowser](https://github.com/ProxyShard/ShardBrowser) и сравнить
каждый наш механизм и его реализацию с этим опенсорс продуктом. Нужно взять всё самое лучшее, включая интерфейс». Сводка исследования — внутренний отчёт сверки. Продолжает ADR-048/049/060/064/065/066/085/086/087/100/101/104/105/106.
Код и тексты ShardBrowser не копировались (лаунчер MIT, ui-kit MIT другого владельца, иконки — свои лицензии); все переносы — независимая реализация,
запись в `NOTICE` не нужна. Новых permissions, CSP, сетевых обращений расширения, каналов сообщений, телеметрии и зависимостей нет. Версия 2.0.0.

## Что изменено в границах

- **Приватные ключи профиля** для звука, WebGL readPixels и Network Information из корня ADR-106 (раздел 1).
- **Снимок этого браузера в странице настроек** (раздел 8): только память, только собственная страница Options, без рисования, `readPixels`, компиляции шейдеров,
  хранения, сообщений, экспорта и логов. Это узкое уточнение REQ-001 («расширение не измеряет само»): чтение собственных параметров браузера для честных
  подсказок, а не проба по решению сайта.
- **Явное действие «Подогнать окно под экран»**: `chrome.windows.update(текущее окно, { state: 'normal', width, height })` только по нажатию; без новых permissions.
- **Значения в форме Chrome** (раздел 5) остаются в рамках исключений Custom ADR-048/085/100: `MemoryInfo`, сеть, `usageDetails`, согласованность уведомлений с
  Permissions/Push, фильтр настоящих голосов, сопоставление устройств по виду. Ничего не создаётся: голоса и устройства только отбираются из настоящих.
- **Метки в конфигурации** (раздел 6): импорт и новые записи отклоняют управляющие и bidi-символы; сохранённые конфигурации загружаются как раньше.

## 1. Приватные ключи профиля

`profile-noise-seed.js`: `RowNoiseSeed` и назначения `audio-fingerprint:v1`, `webgl-readback:v1`, `network-information:v1` (HMAC-SHA256 от корня `storage.local` и
применённого профиля, как у Canvas и Math). Регистрация прикрепляет `entry.audioKey`, `entry.webglKey` (+ `entry.canvasKey`, если в той же области активен Canvas),
`entry.networkKey`; ключ обязателен ровно для Custom-строки со значением, иначе TypeError. Переносимые `seed` в значениях звука и WebGL остаются только частью
идентичности профиля: опубликованный JSON профиля больше не позволяет вычислить и снять шум.

## 2. Canvas `sparse-rgb-v1` (уточнение до выпуска)

Исследование показало, что прежнее правило «1% пикселей» оставляло холсты с малым числом непрозрачных пикселей полностью настоящими («Hello, world!» 220×30 на
прозрачном фоне — в 66% ключей). Алгоритм уточнён на месте (каталог 9 его не меняет): N = ширина×высота; пиксель i = y·ширина + x; SipHash-2-4 под прежним
ключом над `SPR1` | ширина | высота | k; двигается только пиксель с alpha 255, один канал на один уровень с отражением у границ.

| Зона | Правило |
| --- | --- |
| N ≤ 65 536 | каждый пиксель; ячейка k = 8 пикселей; пиксель 8k+j берёт байт j результата: канал = (байт & 127) mod 3, направление = старший бит |
| 65 536 < N ≤ 262 144 | каждый пиксель; ячейка k = серия из 16 пикселей с общим каналом и направлением |
| N > 262 144 | серия = clamp(floor(floor(N/100)/1024), 1, 8), один раз на 100·серия пикселей; 1% |

Все шесть тестовых холстов помечены во всех 40 ключах (Chromium 153 и Firefox 153). PNG плоского холста (исходный / sparse / stable, байт): 512×512 — 7 125 /
44 949 / 331 587; 2560×1440 — 76 122 / 148 674 / 4 658 145 (Chromium). **Не выпущено в раунде 4 (выполнено в раунде 5 — [ADR-108](ADR-108-shardbrowser-owner-decisions.md), раздел 5):** отметка полупрозрачных пикселей — Chromium и Firefox по-разному
премультиплицируют (round и ceil) и расходятся в 37 401 из 65 024 пар (значение, alpha); поэтому копия рисунка с прозрачностью 0,99 по-прежнему читается
настоящей (известный пробел; проект для владельца — в отчёте). Сравнение «залить прямоугольник и сравнить» обнаруживает шум по замыслу.

## 3. WebGL readPixels совпадает с экспортом Canvas

`readPixels` основного буфера повторяет проекцию Canvas побайтно (тот же алгоритм и ключ сайта, строки перевёрнуты); при одной строке `webgl-readback` —
ключ `webglKey`. Измерено: расхождение `readPixels` и декодированного `toDataURL` — 0 байт в Chromium 153 и Firefox 153 (было 3107 из 8192). Известный предел:
в «Сбалансированном» (Canvas без `webgl-readback`) `toDataURL` холста WebGL проецируется, а `readPixels` остаётся настоящим — так было и раньше.

## 4. Звук и текст

- Ключ звука — `audioKey`; проецируются и четыре чтения `AnalyserNode` (dB — относительный шаг, байты — редкие ±1; ±Infinity, NaN, 0, 0/255 и 128 точны);
  в непрозрачных фреймах они отклоняются до нативного вызова.
- Кэш спроецированных каналов: 500 чтений `getChannelData(0)[i]` на 44 100 сэмплах — 0,34 мс вместо 55 мс (утечка по времени закрыта); буферы `inputBuffer`
  не кэшируются (Chromium переиспользует один объект).
- `outputBuffer` ScriptProcessor считается записанным страницей и не проецируется (снят предел ADR-104).
- `measureText`: целое значение остаётся целым (`round`), float32 — float32 (`fround`).

## 5. Значения в форме Chrome

| Поверхность | Поведение при Custom |
| --- | --- |
| `performance.memory` | настоящий `MemoryInfo`, новый объект на каждое чтение, геттеры прототипа; лимит — выбранный, used/total — живые нативные, не выше лимита |
| Network Information | значения — «сырые»; на каждый сайт множитель 0,90 + (SipHash(networkKey, host) mod 21)·0,01; rtt — шаг 50 мс до 3000, downlink — 50 кбит/с до 10 Мбит/с; тип из сырого rtt по порогам Chrome 156 (≥ 272 → 3g, ≥ 1420 → 2g, ≥ 2010 → slow-2g); без `type` на настольном |
| Хранилище | в Chromium добавлен `usageDetails` (`{}` при usage 0) |
| Уведомления | `permissions.query` notifications/push и `PushManager.permissionState` согласованы с `Notification.permission` |
| Голоса | значение `{languages}` отбирает настоящие голоса по языку, настоящий голос по умолчанию первым; пустой нативный список не меняется |
| Устройства | строки накладываются по виду устройства, лишние отбрасываются |

## 6. Контракт: каталог 9 / формат 8

Текущий каталог 9 (формат 8): 158 строк, 56 Custom. Каталог 8 раунда 3 (ADR-106) уже собран в выпуск и установлен у владельца, поэтому он заморожен байт в байт
(SHA-256 каталога `6a8d1b4a…`); настоящий экспорт той сборки строго мигрирует в каталог 9 при импорте и при загрузке из хранилища. Каталог 9 отличается от 8
в семи строках: пресеты в форме Chrome (`network-information`, `storage-estimate` с квотой = usage + 10 ГиБ, `performance-memory` 4 395 630 592, `clock-precision`
0,1 мс, `navigator-plugins` — пять встроенных PDF Chrome), новый тип `speech-voices` (`[]` или `{languages}`), имя и причина `audio-fingerprint` (AnalyserNode).
Метки: импорт и новые или переименованные метки отклоняют U+0000–U+001F, U+007F–U+009F, U+061C, U+200E/U+200F, U+202A–U+202E, U+2066–U+2069 (код
`unsafe-label`); `validateApiConfigurationWrite(next, previous)` для записей из интерфейса, загрузка и миграция не строже прежнего.

## 7. Генератор и подсказки

Случайный выбор согласуется с этим браузером (только случайный; ручной выбор остаётся и вызывает подсказки): карта с числом потоков ≤ настоящего и, если видеокарта
известна, того же производителя; экран не меньше настоящего окна (иначе экран остаётся настоящим); память не выше настоящей. На 64 000 генерациях (4 окна × 4 числа
потоков × 2000 seed × 2 типа устройства) — ни одного противоречия. Списки языков везде в форме Chrome (`[локаль, язык, en-US, en]`); список версий доходит до
настоящей (до 24 версий вперёд); для Chromium-заявки квота не пишется (Chrome сам сообщает usage + 10 ГиБ). Подсказок 41 (+11: `memory-above-real`,
`language-timezone`, `proxy-locale-host`, `webgpu-missing`, `real-gpu-software`, `real-gpu-limits`, `real-gpu-vendor`, `real-gpu-webgpu`, `storage-quota-shape`,
`plugins-pdf`, `clock-precision-shape`). Чистые помощники (только предпросмотр): `issueFix` для восьми механических кодов, `retargetIdentityVersion`,
`fitWindowTarget`; высота рамки окна Chrome 87 / Edge 84; окно сессии ADR-101 получает заявленный размер.

## 8. Снимок этого браузера

Читается один раз на открытие страницы: `deviceMemory`, `performance.memory.jsHeapSizeLimit`, видеокарта (один контекст WebGL2/WebGL: `WEBGL_debug_renderer_info`,
две строки ≤ 512 символов и шесть параметров, затем `loseContext`), WebGPU (`requestAdapter` не дольше 4000 мс, без устройства) и состояние прокси (не дольше 4000 мс).
Отсутствие факта показывается как «не проверено».

## 9. Интерфейс

- **Редактор:** предупреждения под своим полем (`aria-describedby`), уровень словом и значком; «Как в браузере · N» и бегунок на настоящем значении; источник значения
  («Настоящее / Из региона / Задано»); «Эта видеокарта (настоящая)»; объяснение «Заявлено / У этого браузера»; кнопки «Показать», «Исправить» (только предпросмотр),
  «Обновить заявку до Chrome N», «Подогнать окно под экран»; причина недоступности «Применить»; изменения «было → стало»; «Сохранить мои изменения» при конфликте;
  комбобоксы с защитой IME, постоянным «Нет результатов» и отдельной отметкой выбранного.
- **Библиотека** (`fingerprint-library-ui.js`): панель просмотра сохранённого профиля, одна позиция табуляции и клавиши (стрелки, Enter, F2, Delete, Ctrl/Cmd+Z),
  переименование на месте, дублирование, удаление с отменой 8 с, факты в строках, отметка «подходит этому браузеру», фильтры со счётчиками и снимаемыми
  метками, пустые состояния по причине, строка о том, что профили не разделяют cookies и хранилище сайтов.
- **Оболочка:** `ui-announcer.js` (две постоянные live-области), `ui-shortcuts.js` (Ctrl/Cmd+S внутри своей области, защита от ухода с несохранённым, команды
  палитры); чек-лист первого запуска; тема следует выбранной, а не системе; кольцо фокуса контрастом 4,85:1 и выше, 3 px при повышенном контрасте; блок
  `prefers-contrast: more`; отступы прокрутки под липкими панелями; проверка IP при уходе с поля; палитра с уровнями и командами (ранжирование по словам, без
  истории); «Изменено» словом на вкладках уровней.

## 10. Прокси и cookies

Массовый импорт прокси: до 1000 строк, предпросмотр с причинами по строкам (11 кодов), дубликаты, лимит 100 профилей, сохранение по одному через прежний путь DPAPI,
«Проверить импортированные» и «Удалить не прошедшие»; вставленный текст стирается при отмене, скрытии и уходе со страницы. Фильтр результатов проверки, значки DNS и
TLS, кнопка «Случайная сессия», честные строки (прямые домены, WebRTC через TURN по TCP, TCP/IP-отпечаток — у сервера прокси, а для OpenVPN — у собственного сетевого
стека компаньона). Cookies: импорт массивов Playwright/Puppeteer (`expires` в секундах, `-1` — сессионная; `partitionKey` строкой, `{sourceOrigin}` или
`{topLevelSite}`) через прежний предпросмотр.

## 11. Проверки

Реестр нативных наборов и проверка, что ни один не забыт; запуск групп с итоговым отчётом; сквозная нативная проверка согласованности профиля во всех фреймах;
проверка честности формулировок; проверка расхождения документов с каталогом; три устаревших нативных набора восстановлены.

## Известные пределы

Копия Canvas с прозрачностью 0,99 (закрыта в раунде 5, ADR-108); `readPixels` в «Сбалансированном»; Workers и Service Workers; в Firefox не проверены mDNS, фильтр голосов и подгонка окна;
переводы новых строк на 20 языков не проверены носителями; нейтральные значения и лимит кучи измерены на одной машине (32 ГБ), для других классов не выдумываются.
