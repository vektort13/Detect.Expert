# ADR-027. Отдельная диагностическая сборка Chrome для DBSC

DBSC-часть решения отменена [ADR-044](ADR-044.md) от 2026-10-10.

Status: Accepted, implemented; прямое решение владельца продукта 2026-10-09. REQ-004/005/007/010/011/012/015, ADR-021/023/025.

Обновление 2026-10-10: разделение поставки ниже заменено [ADR-040](ADR-040.md).
DBSC включён в единственную Chrome-сборку. Семантика inspector и trust boundaries
этого ADR сохранены; отдельный target больше не выпускается.

Новое решение расширяет границу ADR-023: проверять browser-reported членство cookie в DBSC-сессии. Официальный chrome.debugger требует обязательный permission; optional debugger и DevTools frontend не заменяют этот transport. CDP не сообщает TPM attestation. HEAD Chromium и версия установленного браузера проверяются раздельно; ни hardware backing, ни cookie encryption/exportability не выводятся из DBSC.

Общие Chrome/Firefox сборки сохраняют прежние permissions. Явная сборка --browser chrome-dbsc добавляет только debugger и minimum_chrome_version=153, использует ту же базу и не входит в --browser all. Cookie panel в ней предлагает запуск/остановку проверки только по клику. В обычных сборках показана недоступность session inspection. Cookie permission, consent и host scope остаются обязательными.

Контроллер attach к выбранной top-level вкладке, подписка до enable, команды только Network.fetchSchemefulSite и Network.enableDeviceBoundSessions. Network.enable, request/response headers, bodies и network logs не включаются. Browser DBSC subscription относится к широкому NetworkContext: поэтому валидный чужой schemeful site отбрасывается до чтения session identity/cravings. Нечитаемые site/initial records, потерянные lifecycle updates и переполнения делают membership unknown; потеря update очищает старое сопоставление, не оставляет stale positive.

Session IDs и полные native cookie identities существуют лишь в bounded transient background memory. Нет ключей, challenges, proof material, refresh payload, cookie values, session IDs в UI/Pro/storage/export. Публичный state имеет только текущий documentKey, fixed status, counts и truncated. Per-cookie boundSessionStatus: matched | not-observed | unknown — отдельное optional поле metadata. Matched означает членство в browser-reported session, а не защиту текущего запроса или TPM. TPM остаётся «браузер не сообщает»; красный подтверждающий TPM-замок и «не экспортируется» не присваиваются.

Сопоставление сохраняет native domain leading dot/hostOnly, name, path, Secure, HttpOnly, SameSite, store и expiry; partition/FPI, неполные records и неоднозначный контекст остаются unknown. Scope сессии и членство cookie разделены. Limits: 32 sessions/256 cravings/128 KiB вместе с очередью, 32 queued events/256 admitted events, TTL 60 секунд, native timeout 1 секунда/initial 3 секунды/8 physical jobs. Revocation, pause, navigation, stop и detach немедленно стирают identities и отменяют late operations; cleanup только своего target, failed detach не разрешает новый attach поверх остатка.

Источники: проверка Chromium 153 и проекта спецификации. Независимый review: 74 semantic/privacy/race tests. Manifest/capture review. Native тест использует собственный пустой профиль и localhost, не меняет системные сертификаты/профили/учётные записи. Его нулевой initial inventory не выдаётся за подтверждение настоящей положительной DBSC-сессии или TPM; положительная tuple/lifecycle логика проверяется fixtures.
