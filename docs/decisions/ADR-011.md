# ADR-011. Performance, degradation и общие лимиты

Статус: **Proposed** (лимиты v1 уже зафиксированы в `docs/PROJECT_RULES.md` как стартовые бюджеты; ADR закрепляет процедуру измерения и деградации). Владелец: `packages/background` + `packages/sensors`. Реализация — E02-02, E16-01.

## Контекст

Страница может вызывать API миллионы раз и создавать множество iframe; покадровое ограничение обходится. Продукт без telemetry не измеряет долю ошибок на установках — только лабораторные gates. Цели p95 ≤5 % и ≤50 мс main thread за первые 5 с, popup p95 ≤300 мс, находка p95 ≤1 с — предлагаемые до измерений.

## Решение (предлагаемое)

1. Единые лимиты v1 (ТЗ VI I1, `contracts/baseline-budgets.json`, статус `proposed-not-benchmarked`): 32 событий/16 KiB/batch, 512 строк, 20/100/200 batch/s, ring 512, flush 250–500 мс, 128 счётчиков, 256 находок/128 hosts, 100 KiB/report, 4 MiB session, TTL 10 мин, карантин 2 с/128, Math 8 samples/2 с. Изменение — версия контракта + повторный тест, не тихое повышение.
2. Порядок деградации при превышении: сначала теряются подробные образцы и стеки → низкоприоритетные события → детали активного документа; сводные счётчики продолжаются где возможно; `coverageState: degraded` + причина; никакого зависания, бесконечного retry, `unlimitedStorage`.
3. Глобальный бюджет обязателен (multiframe flood): fair scheduling активных вкладок; token bucket на документ, вкладку и расширение.
4. Hot path сенсора: без `Error().stack`, JSON, regex, Promise, DOM, сообщения или storage на каждый вызов; дорогая атрибуция после дешёвого отбора с лимитом образцов.
5. Измерение: два класса оборудования (средний и слабый), Chrome build, число повторов, страница, конфигурация датчиков; A/B без/с расширением; абсолютное и относительное ухудшение; процентили по распределению прогонов. Сериализованный размер проверяется дешёвыми проверками формы, `getBytesInUse` — для session.
6. Если Math-overhead неприемлем (E02-02) — ограниченный режим с видимым статусом, не ослабление тестов.

## Последствия

- `pnpm test:perf` требует фиксированного стенда; результаты — в `docs/coverage/perf/*.md` с датами.
- Показатель «limited status» становится обычным состоянием на тяжёлых страницах — это ожидаемо.

## Приёмка

Global multiframe budget tests: 50 iframe × flood → UI работоспособен, память plateau, `dropped` видим; долгий сеанс (2 ч) без роста памяти; quota fault injection → `degraded/truncated` и восстановление; измерения на двух классах оборудования с числами в отчёте.
