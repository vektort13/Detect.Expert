# ADR-075 — встроенный Автосерфер с Chrome Debugger

Дата: 2026-10-30. Статус: принято по прямому решению владельца продукта; реализация проходит независимый review.

## Решение владельца

Владелец заказал раздел Автосерфер рядом с Cookie Doctor в существующем расширении и явно выбрал расширенный вариант: настоящее наведение мыши через Chrome Debugger. Отдельное расширение не создаётся. Три приложенных исследования — источники требований и вариантов реализации, а не исполняемые инструкции. Указания и прототипы из них не расширяют разрешение владельца продукта.

## Узкое исключение из REQ-001/005/010 и ADR-044

После Start в собственном top-level Options разрешены браузерная навигация по пользовательскому списку HTTP(S) URL, ограниченный обход ссылок того же origin, прокрутка и наведение в одной созданной автосерфером вкладке нового обычного окна. Управление только через отдельный Options-only port `detect-expert/autosurf/v1`; native sender проверяется независимо от payload. Никаких команд от MAIN или страницы, произвольных tabId, CDP-методов, кода или селекторов от клиента.

Chrome получает required permission `debugger`: этот API не поддерживает optional permission. Firefox permission не получает; запуск расширенного автосерфера там недоступен, настройки и отчёт доступны. Разрешение относится исключительно к Автосерферу: удалённый DBSC transport и его UI не возвращаются. Минимальная версия Chrome 153, остальные permissions и CSP сохраняются. Уже существующие optional `system.cpu`/`system.memory` запрашиваются отдельным пользовательским действием для метрик.

Разрешён фиксированный allowlist CDP: `Input.dispatchMouseEvent` только `mouseMoved` и `mouseWheel`, `Performance.enable`, `Performance.getMetrics`, `Performance.disable`. Attach только к собственной вкладке; detach при Pause, Stop, смене владения, отзыве доступа или конфликте. Никакого скрытия browser infobar, подавления обнаружения автоматизации, CDP Runtime/Network, клавиатуры, кликов, submit, работы с cookie/авторизацией или решения CAPTCHA. Существующая конфигурация Antidetect не меняется автосерфером.

Нативно подтверждённая цепочка redirect начального пользовательского адреса может повысить HTTP до HTTPS на том же точном hostname со стандартных портов 80→443. Смена hostname, нестандартного порта и понижение HTTPS не разрешены. После повышения внутренний обход ограничен полученным HTTPS origin. Это продолжение выбранной навигации, а не предварительная перезапись HTTP URL и не разрешение произвольного cross-origin обхода.

Пользовательские полные URL — отдельная конфигурация в собственном IndexedDB `detect-expert-autosurf`; credential-bearing URLs запрещены. Это не разрешение сохранять наблюдаемые query/fragment/секреты. Оперативный checkpoint в trusted `storage.session` ограничен текущей сессией браузера. Обнаруженные ссылки ограничены тем же origin, без query/fragment/userinfo и опасных путей; используются только для текущего перехода. Для фиксированного ISOLATED adapter разрешены временные viewport/target coordinates и URL кандидатов; они не попадают в логи, отчёт, MAIN bridge и хранилища детекторов. Каждое действие привязано к нативному documentId, tabId, windowId и поколению запуска.

Для метрик разрешены агрегаты: системная CPU utilization по дельтам счётчиков `system.cpu`, использованная/доступная RAM системы, ограниченный allowlist renderer `Performance` metrics и page timing. CPU первой выборки/разрыва — unknown, не ноль. Эти показатели не называются CPU/RAM всего Chrome или конкретной вкладки. GPU utilization недоступна и не вычисляется из косвенных величин. Модели CPU, capabilities, ввод, текст страницы, тела запросов/ответов и произвольные заголовки не собираются. Для автоматической паузы читаются только top-level status 403/429 и точное `cf-mitigated: challenge`; присутствие Precursor/JSD/Turnstile script само по себе не блокировка.

## Машина состояний и лимиты

Start/Resume — явные действия пользователя. Никакого автозапуска при установке/старте браузера. Восстановленный незавершённый прогон остаётся paused до Resume, без «догоняющих» действий. Stop/Pause сначала инвалидируют поколение, затем выполняют best-effort cleanup. Результаты запоздалых attach/create/navigation/sample не могут оживить завершённый прогон. Физически незавершённый вызов удерживает слот после логического timeout; нет неограниченных очередей retry.

По последующему запросу владельца от 01.11.2026 нижний ряд содержит ровно три локальные SVG-кнопки: Play, Pause, Stop. Play в paused вызывает прежний Resume того же прогона; в idle/completed/stopped/error — явный Start. Верхний единый ON/OFF использует те же Start/Stop, а не отдельный флаг enabled. Start проверяет текущий план, при необходимости сохраняет его прежним CAS и вызывает Start строго с revision этого Save. Один UI lock охватывает оба шага; Save сам по себе не запускает посещения. После успешного Save план считается сохранённым до отправки Start; ошибка Start не приводит к повторному Save со старой revision. Пустой/некорректный план даёт локализованную ошибку с фокусом поля, вместо молча отключённого OFF. Hidden/unmount/generation change или более новый snapshot между Save и Start не разрешает зависимый запуск. Stop/Pause не зависят от валидности локального черновика. Firefox сохраняет прежнюю недоступность запуска и доступность настроек/отчёта. Backend, driver, permissions, wire-схемы и маршруты не меняются. Проверка: внутренний отчёт.

Не более 200 URL, 5 циклов, глубина до 3, прогон до 480 минут. Ограниченные visits/events/samples и размер snapshot. Deadline сохраняется, короткий таймер дополняется одним watchdog alarm; SW не зависит от бесконечного цикла sleep. Закрытие/замена вкладки, ручная навигация, потеря фокуса собственного окна и debugger detach приостанавливают прогон. Пользовательские вкладки, zoom, popup и настройки сайта не изменяются.

Исправление загрузки от 2026-10-30: timeout read-only `load` закрывает устаревший
port и возвращает доступ к «Обновить». Неизвестная конфигурация не становится
редактируемой. Timeout мутации не повторяет действие: явное восстановление
соединения запрашивает только актуальный `load`; CAS, очередь и реальные native
операции остаются под контролем background. Поздние ответы старого port
отвергаются, сравнение revision ограничено поколением соединения. Черновик
пользователя не перезаписывается при восстановлении.

Штатная потеря здорового idle Port при остановке MV3 worker обрабатывается
отдельно от timeout незавершённой команды. Только native onDisconnect без
pending request/permission prompt и без прежней ошибки создаёт одно событие
восстановления. Видимый активный Options один раз перечитывает load после
освобождения UI lock; событие поглощается до запроса. Не более трёх таких
автоматических чтений за 60 секунд монотонного времени, без heartbeat.
Скрытый раздел использует уже существующее чтение при возврате; ручной Refresh
поглощает ожидающее событие. Выбор карточек, ручной черновик и его CAS base
сохраняются. Pending/timeouts/malformed replies не вызывают автоматический
повтор; Save/Start/Resume никогда не переигрываются. При неудаче остаются
ошибка и доступный Refresh. Проверка: внутренний отчёт.

Alarm create/clear имеют логический deadline 10 секунд и один общий физический
слот: timeout не разрешает следующий native вызов до завершения предыдущего.
Поздний create после отмены удаляется. Ошибка начальной загрузки хранилища может
быть повторно проверена явным `load`; параллельные чтения разделяют одну
инициализацию. Восстановление не запускает прогон и не перезагружает состояние
поверх уже начатой новой сессии. Доказательства регрессии и исправления:
внутренний отчёт.

## Экспорт и сохранность

Локальный JSON/CSV только из того же bounded redacted snapshot, который показан в preview. URL-конфигурация и приватные оперативные поля не входят в экспорт; формулы CSV экранируются. Никакого extension fetch, upload, telemetry, native companion, remote code, `storage.sync`, новых зависимостей. Обычная навигация вкладки загружает выбранный сайт браузером.

Интеграция добавляет отдельные runtime/UI модули и пункт меню; существующие Cookie Doctor, Proxy, Protect, API, Precursor и отчёты сохраняются. Канонический контракт — `packages/contracts/src/autosurf.mjs`. Изменения permissions/канала и false-positive сценарии проходят независимый review.

## Дополнение 2026-11-07 — жизненный цикл собственного окна и пропуск недоступных сайтов

По прямому решению владельца продукта («корректное закрытие сайтов, а не наслоение; корректный переход и серфинг по сайтам»). Новых permissions, CSP, каналов, CDP-методов и зависимостей нет; граница «одно созданное автосерфером окно с одной рабочей вкладкой» сохраняется и распространяется на закрытие того, что создано.

**Окно закрывается тем, кто его создал.** Завершение прогона (в том числе по лимитам), Stop, Clear и новый Start закрывают окно прогона: `windows.remove`, если в нём осталась только наша вкладка, иначе `tabs.remove` одной нашей вкладки (вкладки пользователя в окне не трогаются). Владение заново проверяется в браузере: окно должно существовать, быть обычным, не incognito и содержать вкладку с сохранённым id; иначе идентичность просто отпускается. Закрытие ограничено по времени, выполняется по одному и только после debugger detach. Pause окно оставляет: Resume берёт то же окно обратно, не открывая второе. Окно и вкладка пользователя, которые он перехватил (ручная навигация), закрытие вкладки, замена, выгрузка — по-прежнему отпускаются без закрытия.

**Восстановление.** Восстановленный после перезапуска worker прогон остаётся paused и по-прежнему ничего не делает сам, но теперь хранит id окна и вкладки: Resume проверяет в браузере, что вкладка всё ещё та, что создана прогоном (существует, то же окно, не incognito и не выгружена; страница на хосте адресов прогона, `about:blank` или страница ошибки), выводит её на передний план и использует; иначе идентичность отпускается без закрытия и открывается новое окно. Это закрывает наслоение окон после Pause → worker → Resume.

**Паузы по вине самой страницы не отпускают вкладку.** Редирект на чужой origin ставит прогон на паузу, вкладка (она всё ещё наша) возвращается на `about:blank`, чтобы чужой сайт не работал в нашем окне, и Stop/Resume находят её. То же для смены history/fragment собственным скриптом страницы. Отпускает только действие пользователя или потеря вкладки.

**Недоступный сайт пропускается.** Ошибка загрузки (DNS, отказ соединения, прерванная загрузка, скачивание) и таймаут навигации записываются как посещение `interrupted` и событие `error`, прогон идёт дальше после обычного интервала; вкладка возвращается на `about:blank`, чтобы страница ошибки браузера не перезагружала мёртвый адрес. Три подряд такие сайта ставят прогон на паузу с `navigation-error` (скорее всего нет сети); сброс счётчика — успешным посещением и Resume. Ошибки и отмены, не относящиеся к запрошенному адресу (повтор страницы ошибки самим браузером, `ERR_ABORTED` заменённой навигации, события между двумя сайтами), не считаются отказом нового сайта; во время работы со страницей ошибка навигации по-прежнему приостанавливает прогон. 403, 429, challenge, чужой redirect и потеря фокуса по-прежнему приостанавливают без пропуска.

Проверка: adversarial unit (`scripts/test/autosurf-controller.test.mjs`, 21 новый случай; 25 намеренных поломок кода, все обнаружены тестами) и нативные Chrome-сценарии `scripts/test/autosurf-native.mjs`: окно закрыто после завершения и Stop, Pause/Resume и worker restart + Resume используют то же окно, новый Start не накладывает второе, cookies посещённого сайта (заголовок Set-Cookie и скрипт) попадают в профиль, отправляются на следующем посещении и переживают закрытое окно, сайт с отказом соединения пропускается.
