# ADR-085 — Storage Custom без получения исходной квоты

> Уточнено [ADR-106](ADR-106-antidetect-continuation.md): тот же снимок отдают `StorageBucket.prototype.estimate` и deprecated `webkitTemporaryStorage`/`webkitPersistentStorage` (раздел 6).

Дата: 31.10.2026. Прямое решение владельца продукта «фикси» для FP-12/13 после повторного
аудита. REQ-002/003/004/005/010/011/012/015, ADR-048/049/083/084.
Артефакты: внутренний отчёт.

Последующее [ADR-086](ADR-086.md) расширяет пассивную identity проверку на
ранее сохранённые managers доступных same-origin Windows. Ограничение ниже
про неизвестные foreign managers относится к исходной версии ADR-085;
актуальные registry/discovery semantics и оставшаяся недоступная область — ADR-086.

## Проблема

Native StorageManager.estimate создаёт dictionary и разрешает Promise до
Custom projection. ECMAScript resolution читает inherited then, а добавление
Promise.then читает constructor/species исходного Promise. На BrowserLeaks в
Chrome/Firefox подтверждены два способа получить исходную quota при выбранной
другой quota. Захват then или последующее изменение результата их не закрывает.

Первичные алгоритмы: [Storage estimate](https://storage.spec.whatwg.org/#dom-storagemanager-estimate),
[Promise Resolve Functions](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise-resolve-functions),
[SpeciesConstructor](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-speciesconstructor).

## Узкое исключение из original-call-once

Только при активном `storage-estimate: Custom` успешный ответ формируется из
проверенных выбранных quota/usage **без вызова native estimate**. Операция не
получает настоящую квоту, не меняет реальные лимиты/данные и не запускает
persist/persisted/permission/backend/сеть. Остальные async Custom и observer
контракты этим исключением не меняются.

1. Обёртка native Navigator.storage getter вызывается только при реальном
   обращении страницы. Original getter вызывается один раз с теми же this/args;
   результат/throw сохраняются. Возвращённая native identity запоминается в
   закрытом WeakMap с cap1024 для общих inherited installations. Установка не
   читает storage/navigator и не запрашивает quota самостоятельно.
2. Для зарегистрированной identity estimate возвращает новый настоящий Promise
   с выбранным свежим mutable dictionary целевого realm. Captured constructor и
   прототипы не вызывают поздние page constructors/getters. Private async
   scheduler с `await undefined` откладывает resolve; нет публичного then/species
   на скрытом native-result Promise. Page thenable lookup получает только
   выбранные значения. Уже созданный virtual snapshot сохраняется после stop.
3. Prototype/instanceof/toStringTag не доказывают WebIDL brand. Для неизвестного
   this вызывается captured estimate **с приватным заведомо невалидным объектом**,
   не с переданным receiver. Native WebIDL brand rejection возвращается напрямую
   без then/projection. Этот native call не достигает получения quota. Тем самым
   сохраняется native error path, но original this намеренно отличается.
4. Fake, Proxy и genuine foreign manager, который не прошёл getter регистрации
   этого private registry, получают native brand rejection. Зарегистрированные
   manager из общих inherited realm поддерживают borrowed calls. Независимые
   ранее открытые/непокрытые realm и заранее захваченные original handles не
   объявляются полностью совместимыми. Cap/ошибка регистрации не разрешают raw
   quota fallback. Отсутствующий native estimate не создаётся.
5. OFF/Allow/Bypass не устанавливают virtual behavior. После stop будущий вызов
   retained wrapper делегирует original с настоящими this/args/native identity;
   cleanup снимает только принадлежащие installer descriptors. Документы по
   ADR-049 остаются неизменными до навигации.

Это два явных отличия REQ-002 только для указанного Custom: успешный original0;
неизвестный receiver original1 с приватным invalid this. Не разрешается
пропускать original у остальных API или менять общие Promise/Object prototypes.

## Границы совместимости и наблюдения

Если настоящий captured Navigator.storage accessor имеется, но установить его
обёртку нельзя, допускается bounded fallback **только по фактическому вызову
estimate**: captured Window.navigator descriptor и captured storage getter на
известном Window/Navigator дают аутентичную identity для сравнения. Читается
только собственный descriptor Window.navigator (get либо data value);
затем native storage getter проверяет brand Navigator. Наследованные accessors
и свойства переданного receiver не читаются. Это пассивный
lookup интерфейса, не quota/backend/persist probe. При установленном getter hook
fallback не запускается. Missing/data-only storage, cap или ошибка lookup не
разрешают передавать неизвестный this в native quota operation; сохраняется
rejection/unavailable. Установка по-прежнему getter не вызывает. Такой fallback
не требует временного изменения неизменяемого getter или отката estimate к raw API.

Virtual estimate не проверяет наличие свободного диска и не предсказывает
native backend/policy/internal-error/timing outcomes. Это async выбранный metadata
snapshot, не успешное измерение реального хранилища. Opaque guards и отсутствие
secure-context API сохраняют прежние отдельные границы; quota0 не означает opaque.

При Custom поверх ранее установленного observer пропуск original также может
пропустить внутренний estimate counter; обратный порядок допускает наблюдение
наружной обёрткой. Ради счётчика нельзя возвращать raw native quota operation.
Новый MAIN/privileged канал не добавляется; composition проверяется отдельно.

Target prototype fallback при удалённых/подменённых globals и wrapper Function
realm имеют прежние ограничения ADR-084. Нет маскировки native source, скрытого
iframe/Worker, внешнего соединения, raw-value store/bridge или новых permissions.

## Проверки

RED/GREEN FP-12/13, свежие native Chrome/Firefox BrowserLeaks, обычный результат,
throwing/reentrant inherited then, constructor/species getters, forged/Proxy/
foreign receiver, unused arguments, fresh records, child realm, caps, descriptor
ownership, OFF/Bypass/stop, privacy scan, source/dist/ZIP и independent review.
Полная натуральность всех fingerprint surfaces этим исправлением не заявляется.
