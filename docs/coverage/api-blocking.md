# Блокировки API — 1.1.0

Актуальное расширение WebAssembly — [ADR-059](../decisions/ADR-059.md), [покрытие](webassembly.md): 126 правил API Guard и 16 отдельных Custom-параметров, всего 142 записи каталога v2. Исходные 105 записи/order/metadata сохранены с миграцией v1. Новые WebAssembly операции собраны в сворачиваемую группу; общий namespace switch сохраняется. Интерфейс на 21 языке, общий код Chrome/Firefox с условным наличием API.

Последующее расширение WebRTC — [ADR-060](../decisions/ADR-060.md), [матрица](webrtc-custom.md): те же 142 ID/order, WebRTC Custom; format2/catalog3 с замороженной строгой миграцией v1/v2. Общие режимы ON/BYPASS/OFF сохраняют значения блокировка/наследование/разрешение.

По [ADR-061](../decisions/ADR-061.md) переключатели сохраняют только выбранную строку сразу и применяют её к привязанному документу через проверенный reload; остальные черновики не записываются. WebGL ON закрывает object/boxed/callable context names через native DOMString conversion до создания GL, сохраняя Canvas2D и нативные brand/coercion errors. Chrome153/155 и Firefox138 проверены; итоговый отчёт.

## Фильтр категорий

Перед первой группой стоят шесть чипов. Фильтр меняет только вид:
- скрывает строки других категорий и пустые группы, порядок не меняет;
- ничего не сохраняет и не меняет правила;
- при каждом открытии страницы выбран All.

## Правила с бейджем «Частично»

У этих 8 правил тот же канал в том же документе остаётся доступен через другой стандартный API. Обходы описаны по спецификациям и **нативно не проверялись** (candidate).

- **События движения и ориентации** (`device-motion`). `addEventListener('devicemotion' | 'deviceorientation', …)` продолжает получать события: удаляются только конструкторы и слоты `on…`. Полный запрет потребовал бы читать тип события, а это запрещено.
- **Маяки при уходе со страницы** (`send-beacon`). Данные можно отправить через `fetch(…, { keepalive: true })`, через `fetchLater`, если правило `fetch-later` выключено, или обычными запросами в `pagehide`/`visibilitychange`.
- **Отложенные запросы** (`fetch-later`). Остаются `fetch(…, { keepalive: true })` и `navigator.sendBeacon`, если правило `send-beacon` выключено.
- **Асинхронный доступ к cookies** (`cookie-store`). Остаются `document.cookie`, если правило `document-cookie` выключено, и HTTP-заголовки `Cookie`/`Set-Cookie`.
- **Доступ скриптов к cookies** (`document-cookie`). Остаются `cookieStore`, если правило `cookie-store` выключено, и HTTP `Set-Cookie`. После удаления присваивание `document.cookie = …` создаёт обычное свойство документа, а не cookie.
- **Запись в буфер обмена** (`clipboard-write`). Остаются `document.execCommand('copy')` и `clipboardData.setData()` в обработчике события `copy`.
- **Запросы доступа к сторонним cookies** (`storage-access`). `document.hasStorageAccess()` открыт. Ранее выданное разрешение может активироваться HTTP-заголовками Storage Access Headers, где браузер их поддерживает. Встроенный фрейм затрагивается только правилом global ON или правилом для хоста фрейма.
- **Проверки Private State Tokens** (`private-state-tokens`). Закрыты только `hasPrivateToken` и `hasRedemptionRecord`. Выпуск и погашение токенов идут через параметр `privateToken` у `fetch()`/XHR и атрибут `privatetoken` у iframe. Аргументы не читаются, поэтому эти пути не блокируются.

## Режимы и индикация

ON задаёт запрет. OFF разрешает API, в том числе поверх пресета. BYPASS удаляет отдельное правило и наследует preset/global. Общий master OFF выключает все запреты, сохраняя настройки. Наблюдение имеет отдельный выключатель. Limited (4) и Strict (9) не расширены автоматически, чтобы обновление не добавило запретов на ранее работавшие сайты.

Иконка панели браузера отражает общие переключатели:
- наблюдение OFF — серая, без бейджа;
- наблюдение ON и блокировка ON — зелёная, с белым `ON` на зелёном нативном бейдже;
- наблюдение ON без блокировки — исходная синяя, со счётчиком техник текущей вкладки.

Выключение наблюдения имеет приоритет. Ошибка регистрации блокировок не включает зелёный статус. Статус относится к общему переключателю; отдельные разрешения и исключения сайта остаются в настройках. Размер и скругление бейджа задаёт браузер. Проверки toolbar.

## Применимость и пробелы

**Где действуют правила.** Document-start MAIN scripts в доступных HTTP(S) documents и frames, по точному hostname. После выключения восстанавливаются принадлежащие расширению descriptors. Повторное включение в том же документе требует reload.

**Что правила не делают.** Отсутствующий браузерный API не эмулируется, non-configurable descriptors не заменяются. Не блокируются:
- внутренние worker/worklet contexts и Service Worker;
- ссылки, сохранённые до установки;
- уже открытые потоки, выданные разрешения и зарегистрированные фоновые задачи.

**Пробелы по ADR-046:**
- **Фреймы без собственного URL** (`about:blank`, `srcdoc`, `blob:`, `data:`, `window.open('')`) не получают правил. Нативный evidence `frameGap` в Chrome 153 и Firefox 138: в созданном страницей `about:blank`-iframe при включённых 89 правилах остались `hardwareConcurrency` и `Worker`. Исправление — отдельный будущий ADR.
- **HTTP-уровень не блокируется:** заголовки Client Hints, `Set-Cookie`, NEL/Reporting, Storage Access Headers, выпуск Private State Tokens, серверный fingerprint.
- **Правила встроенных фреймов** `storage-access`, `fedcm-user-info` и `private-state-tokens` действуют по хосту фрейма, а не вкладки.
- **Удаление свойств заметно само по себе:** браузер становится редким. Невидимость и анонимность не обещаются.
- **Наблюдение hook.main** по скрытому или обёрнутому API может отсутствовать или быть неполным. `document-cookie` снимает и наблюдательный дескриптор `cookie`, stop восстанавливает его. Это взаимодействие нативно не проверялось (candidate).
- **Firefox 138.0.4:** у 43 из 89 правил нет устанавливаемых точек, правило сообщает `unavailable`. В Chromium 153.0.8010.12 таких правил 4. API могут отличаться между браузерами, версиями и ОС.
