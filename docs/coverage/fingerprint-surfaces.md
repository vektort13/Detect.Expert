# Поверхности браузерного fingerprint — E22-19 / ADR-066

Продолжение актуального аудита: [ADR-100 — Temporal/CSS/Promise](fingerprint-continuation.md). Историческая исследовательская матрица ниже не заменяет текущие source-bound проверки и их ограничения.

Актуальные исправления и измерения: [аудит ADR-095](fingerprint-production-audit.md).
Матрица ниже сохраняет исследовательский контекст E22-19. Её 45 семейств и исходные
280 ключей пользовательского скрипта не являются исчерпывающим перечнем отпечатков.
Новый независимый реестр содержит 151 пересекающийся именованный вектор из
FingerprintJS/CreepJS/Firefox RFP; соответствие исходников отделено от native-проверок.

Исследование и аудит исходников от 2026-10-21. Основа состояния — E22-18: 143 API, 39 типизированных Custom, format3/catalog5. Изменения E22-19 описываются отдельным ADR и проверками; наличие рекомендации в этой матрице не означает реализованную подмену. Список охватывает 45 семейств, а не заявляет исчерпывающий перечень всех будущих Web API.

**Изменения E22-19:** format4/catalog6 сохраняет порядок всех 143 API и добавляет библиотеку до 128 полных глобальных профилей в общем бюджете 4 МиБ. Типизированных Custom теперь 40: изменена только metadata существующего Canvas ID. Генератор, preview, ручное редактирование и библиотека используют прежний CAS; library-only commit не снимает открытые guards. Canvas `stable-rgb-v1` имеет статус **fixture-validated в проверенной Window области**: по 6 native semantic/color/realm сценариев в Chromium 153, Chrome 155 и Firefox 138; по 12 production composition сценариев Chrome 153/Firefox 138. Подтверждённые обходы прежних MAIN visual/API-results каналов закрыты общей однонаправленной политикой: активный Custom запрещает raw value/image/RTC endpoint выдачу, сохраняя счётчики наблюдений. Package gate закрепляет финальные source/dist/ZIP bytes. Границы Canvas — одна проекция до 4 × 1024² пикселей, максимум 4 ожидающих encoders с общей площадью 8 × 1024² пикселей, только opaque RGB с отклонением 1; worker/WebGL readPixels/translucent alpha не меняются. [Текущая реализация и статус](api-custom.md), [полные профили](antidetect.md).

«Естественный профиль» здесь означает согласованные тестовые значения и сохранённую семантику API. Это не доказательство принадлежности к статистически массовой группе устройств. Для последнего нужен независимо собранный репрезентативный корпус; такой корпус в проекте отсутствует. Спецификация подтверждает доступность поверхности, а не её индивидуальную энтропию или эффективность защиты.

W3C рассматривает fingerprint как комбинацию активных и пассивных признаков, включая сетевые слои. Смена только JS metadata не закрывает остальные каналы. [W3C guidance](https://www.w3.org/TR/fingerprinting-guidance/). Официальное описание Brave показывает архитектуру session/site farbling; это реализация внутри браузера, а не подтверждение равных возможностей расширения. [Brave](https://brave.com/privacy-updates/4-fingerprinting-defenses-2.0/). Firefox применяет native policy с контекстом документа, framing page, режимом и исключениями; это существенно шире подмены свойств в Window. [Firefox implementation](https://firefox-source-docs.mozilla.org/toolkit/components/resistfingerprinting/resistfingerprinting/implementation.html).

## Как читать статус

- **Custom** — существующий код изменяет перечисленные JS результаты в доступных Window realms, когда включены master и соответствующий Custom.
- **Block** — в каталоге есть запрет соответствующей операции; это не её эмуляция и не обещание одинакового покрытия всех браузеров/реалмов.
- **Native** — отдельная имеющаяся нативная browser policy с проверяемым readback.
- **Candidate** — предложение, для которого нужны ADR, контракт, semantic/privacy/native fixtures и независимый review.
- **Outside** — текущая архитектура расширения не меняет этот слой.

Все перечисленные существующие Custom сохраняют отсутствие API: extension не создаёт отсутствующий browser feature, физическое устройство, разрешение или кодек. Подмена начинается на document_start; уже захваченные native references не отзываются. Worker/worklet, HTTP и CSS по умолчанию остаются исходными. В неподдерживаемых opaque realms отдельный neutral/deny guard не равнозначен полной эмуляции.

## Правила коррелированного профиля

Эти правила — вывод аудита и проектные рекомендации, а не утверждения спецификаций о «правильном отпечатке».

1. **Одна атомарная конфигурация.** Generate, Load и Import preview не записывают данные. Save as profile сохраняет только библиотеку; Apply сохраняет активную глобальную конфигурацию при прежнем состоянии master. Library-only commit не снимает guards. CAS revision защищает от второй вкладки. Profile identity/label не попадает в страницу; secret не попадает в JSON.
2. **Не смешивать типы памяти.** `deviceMemory` — coarse API bucket; `performance.memory` — heap metadata. В Chrome147 изменились buckets: Android 1/2/4/8, другие платформы 2/4/8/16/32. Старый общий cap8 нельзя переносить в актуальный desktop preset. Произвольный Custom остаётся инструментом тестирования. [Chrome147](https://developer.chrome.com/release-notes/147), [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/deviceMemory).
3. **OS и browser — разные измерения.** OS tuple связан с platform/oscpu/CH; engine family/version, availability и actual codecs остаются реальными. Сквозной переход Chrome→Safari одной строкой не реализуется.
4. **Экран — не viewport.** `availWidth≤width`, `availHeight≤height`, положительный DPR, согласованные depth и orientation. Реальные layout/CSS остаются отдельным каналом. Preset не должен автоматически менять accessibility preferences.
5. **Locale и timezone не выводятся однозначно из IP.** Допустимы travel/VPN/multilingual сценарии. Несовпадение — диагностическая связь, а не причина отклонять пользовательский тест. Для timezone отдельно отмечаются fixed offset/DST ограничения.
6. **GPU metadata не означают GPU capabilities.** Совпадение WebGL/WebGPU vendor strings желательно, но не разрешает объявлять unsupported feature/limit. Native adapter null или rejected Promise сохраняются.
7. **Device aliases имеют scope.** Один deviceId/groupId внутри выбранной сессии согласован между покрываемыми getter/toJSON/capability путями. Псевдоним не является physical serial, stream или permission. Пустой device list должен оставаться допустимым явным сценарием.
8. **Случайность — стабильная и ограниченная.** Не Math.random на каждый getter. Случайный seed сессии, domain-separated derivation, один alias mapping и bounded memory. Origin key и top-level-site key различаются: один third-party origin в двух сайтах не должен ошибочно называться site partitioning.
9. **Native ошибки — часть профиля.** this/brand, порядок coercion, throws, Promise behavior, descriptors, typed arrays и missing API должны иметь semantic fixtures. Не использовать normal-looking success для обхода реально отсутствующей возможности.

## Приоритеты реализации

**Реализовано в E22-19:** библиотека до 128 полных профилей, генератор согласованных наборов, preview, ручное редактирование API, поиск/переименование/удаление, единый импорт/экспорт и проверка связей. Это использует существующий CAS без нового permissions/CSP/network channel. По отдельности выбранные CPU/RAM/screen/language/GPU параметры уже доступны; объединение не расширяет их runtime coverage автоматически. Новый Window Canvas runtime прошёл отдельные native и production composition gates в указанной области. Следующий отдельный Candidate — Web Audio readback; он не включён этим изменением.

**Следующий candidate:** Web Audio readback с aliasing/live-buffer, decode, DSP и native resource проверками. Для него нужен отдельный ADR: произвольное изменение generic native object не разрешается прежним metadata контрактом. Canvas получил свой отдельный контракт ADR-066; его runtime/evidence описаны в [coverage](api-custom.md).

**Отдельное исследование:** defaults Intl/timezone с историческими датами, шрифты/metrics и coherent geometry. Не следует включать их непроверенную эмуляцию автоматически вместе с device preset.

**За пределами расширения:** замена TLS/QUIC/TCP стека, физического GPU/driver, системных fonts/codecs, настоящего IP route и другого browser engine. Native browser policies могут дать более широкое покрытие, но требуют собственного opt-in/readback и не должны тайно применяться выбором профиля. [Chrome privacy](https://developer.chrome.com/docs/extensions/reference/api/privacy), [Firefox privacy](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/privacy/websites).

## Минимальный verification plan

Для каждой реализуемой поверхности нужны: original-call-once и brand/error/coercion; Allow/Bypass/Custom и dormant values; first inline/navigation/BFCache; borrowed prototype calls; same-origin/opaque/cross-origin iframe; настоящий worker baseline; отсутствие sends/storage observed values; master OFF; CAS/stale/import rollback; Chrome/Firefox и неподдерживаемый native API. Для paired-channel семейства нужен собственный fixture server/CSS/worker comparison, без внешнего сканирования.

Проверка одной JS строки не доказывает отсутствие исходных признаков в других каналах. В этой матрице нет обещаний обхода антифрода/CAPTCHA, маскировки Function.toString, успешной авторизации или «100% покрытия». Ссылки фиксируют исследованные первоисточники; release support определяется фактическими тестами конкретных Chrome/Firefox сборок.
