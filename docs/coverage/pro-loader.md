# Pro Tag Manager loader coverage

REQ-002/004/005/011; ADR-021. Implementation: `scripts/production/loader-sensor-runtime.mjs`, serialized by `scripts/production/sync-loader-runtime.mjs` into both production MAIN bundles. This module has no external calls, dependencies, new permissions or persistence. Ending Pro observation disables capture; the existing token lifecycle clears its aggregates.

The sensor observes direct native `Node.appendChild`, `insertBefore`, `replaceChild` operations on a script and primitive-string `HTMLScriptElement.src` assignments to a connected script. A successful native insertion is counted only when the script is connected afterwards and still classifies to the prepared service. A detached script's initial `src` assignment is not counted separately. Reinserting the same observed script/service/confidence does not increment its row; connected `src` assignments count operations, including repeated assignments. These counts are observations of loading operations, not browser request counts, HTTP success, or confirmation that the destination script executed. The existing BrowserRequestSensor owns the single script src wrapper and calls the private loader observer alongside its unchanged extension-resource observer; DET-059 script-src coverage is retained.

Source evidence is either a captured native `Document.currentScript` getter resolving to the documented GTM resource (`exact-resource`) or a GTM URL at an actual frame location in a bounded stack (`sampled-stack`). Every row remains `evidenceSource: page-hook`, `integrity: page-controlled`. No parent link is inferred from a shared network initiator origin, proximity in time, or simultaneous resources. Page-controlled code/sourceURL can imitate such evidence; this is not browser-authenticated ancestry.

Limits per Pro token: 18 target/confidence combinations, 512 distinct script marks, 64 fallback stack samples, eight inspected stack frames, 8192 transient stack characters, 4096 URL characters. Counts saturate at 2147483647. Limit exhaustion, unsupported native getters/URL parsing, non-data stacks, non-native Error constructors, or unsafe own/inherited Error formatter settings set `loaderTruncated`. Missing installation support remains limited after resets. URL/Error global accessors are not invoked at bootstrap; a missing or known non-native URL constructor/getter disables this classifier without aborting the other sensors. Raw stacks, URL/query/fragment strings and container IDs are discarded within the observed call and never appear in rows, messages or exports. Only one decoded Google `id` parameter is admitted; repeated IDs are rejected as ambiguous.

Targets are fixed canonical IDs for Google Analytics, Google Ads, Facebook Pixel, Hotjar, Criteo OneTag, Microsoft Clarity, TikTok Pixel, LinkedIn Insight and Bing UET. Documented HTTPS resources are required; protocol-relative Criteo/Bing documentation admits HTTP and HTTPS. Facebook scope is only the verified `en_US/fbevents.js` endpoint. Clarity scope is a single alphanumeric project segment; mobile/UET subpaths are excluded. Google `GT-` is a shared Google tag and is not attributed to an individual destination; `G-` is Analytics, `AW-` is Ads, and numeric `UA-...-...` is legacy Analytics. The inconsistent `GA-` placeholder in one Google example is not admitted as a production prefix.

Not captured: parser-inserted scripts, document.write/innerHTML, modules/imports, workers, insertion of a parent subtree/DocumentFragment containing scripts, append/prepend/replaceWith/setAttributeNS, connected setAttribute-only reloads, TrustedScriptURL/object setter inputs, first-party/proxy endpoints, rewritten/custom SDK loaders and arbitrary downstream/transitive ancestry. No timer/Promise wrapping, dataLayer/config inspection, payload access, probes, remote code evaluation or function-source masking is used.

Unit coverage (2026-10-09): 34 loader cases against the actual serialized modules and original-preserving native API stand-ins; 7 existing Pro value cases; 14 coverage observer cases. Native browser acceptance is maintained by the integration owner separately. Unit tests exercise exact host/path/scheme/product matching, duplicate query IDs, function-name/query stack false positives, disconnected insertion, reentrant target changes, count saturation, bounded memory/samples, snapshot isolation, original identity/exceptions/once-only calls, hostile argument accessors/coercion, prototype/iterator replacements, inherited formatter accessors, bootstrap URL subclass/accessor replacement, stopped/paused/cross-token observation, unsupported installation, shared DET-059 script src observation and final-only bounded metadata separated from full API chunks. Node's URL is a JavaScript implementation: build-time helpers have an explicit trusted-URL adapter, while actual serialized browser calls use strict default native admission. The serialized tests use transparent trusted URL API stand-ins; native browser acceptance remains separate.

The wire final batch carries `rows: []`, `loaderRows` and `loaderTruncated`; prior API chunks have no loader metadata.
