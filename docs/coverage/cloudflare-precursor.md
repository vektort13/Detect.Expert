# Cloudflare Precursor — область доказательств и проверки

## Размещение в интерфейсе

По решению владельца продукта от 2026-11-01 вход в настройки расположен в пункте API группы «Инструменты», перед Settings. Локальный маршрут `#integrations` не меняет прежний `#api` раздела API Guard. Кнопка открывает прежнюю собственную top-level `precursor-settings.html`: форма токена, sender validation и разрешённые API-запросы не переносятся в Options и не расширяются. Вход доступен без выбранной страницы.

Во внешнем Inspector карточка отображается только после валидированного `presence: observed` текущего документа. Loading, отсутствие наблюдений, неподдерживаемый API, пауза, утрата доступа, ошибка и смена документа не создают карточку. Polling продолжается при скрытой карточке, когда документ доступен; позднее наблюдение может показать её. Подключённая зона и её режим сами по себе не доказывают наблюдение ресурса. Встроенный Detector отключает этот компонент и его polling. Фактические проверки переноса: отчёт.

Обновление ADR-076: собственная страница подключения принимает Zone ID и API token,
проверяет имя зоны через Zone Details, читает `off|monitor|arm` из version 1.0
Precursor API. Токен только в памяти браузерной сессии, TRUSTED storage.session;
после остановки worker соединение восстанавливается с новой проверкой API.
После закрытия браузера нужно подключиться снова. Без свежего ответа последнее
значение сохраняется как последнее известное, не текущий режим.
История — максимум 128 наблюдённых изменений; опрос раз в минуту, freshness 3 минуты,
ручное обновление с cooldown, ошибки/429 с backoff. Системные уведомления включаются
отдельной кнопкой optional permission; история доступна и без них. В карточке
страницы конфигурация показывается только для точного имени зоны, без догадок
для делегированных поддоменов. Произвольные чужие сайты без API-доступа по-прежнему
не раскрывают достоверный режим. API никогда не получает URL посещённых страниц.

Firefox дополнен bounded ISOLATED Resource Timing: точный приватный документ,
same-origin HTTPS script, проверенный путь, native successful status и JS MIME.
Источник `browser-resource-timing`, покрытие partial. Firefox 138 подтвердил
getters в настоящем браузере; браузеры без требуемых getters не дают положительный
результат. Пустой буфер не означает Off. Новые доказательства и фактические
ограничения: внутренний отчёт.

Дата исследования: 2026-10-30. Идентификатор интеграции: `DET-CF-PRECURSOR-001`; проектное решение — ADR-074. Требования: REQ-001/004/005/006/008/009/010/011/012/015; [ADR-008](../decisions/ADR-008.md), [ADR-009](../decisions/ADR-009.md), [ADR-057](../decisions/ADR-057.md). Идентификатор интеграции не добавляется этим документом в прежний числовой wire enum техник. Эта запись описывает проверенные источники и требования приёмки, а не объявляет незавершённые проверки пройденными.

Машиночитаемая карта доказательств: mode-evidence.json. Независимое исследование и фактические публичные посещения: research-independent.md.

## Режим конфигурации и наблюдаемая активность

Актуальная документация различает Off, Monitor и Armed. В API последнее значение называется `arm`, а в интерфейсе настройки — Arm. Monitor собирает сигналы без их применения к bot score и Challenge clearance; Armed позволяет применять их; Off отключает Precursor. Настройка `show_interstitial` и правила для отдельных запросов существуют отдельно от режима. [Документация Precursor](https://developers.cloudflare.com/cloudflare-challenges/precursor/).

Monitor и отдельная настройка Interstitial опубликованы 19 октября 2026 года. Interstitial может использоваться в Monitor: сам показ проверки не устанавливает Armed. Изменение правила только для `/checkout` не означает изменение режима всей зоны. [Официальное изменение](https://developers.cloudflare.com/changelog/post/2026-10-19-precursor-monitor-mode/).

`GET /zones/{zone_id}/precursor` — авторизованный конфигурационный API. Текущая модель содержит необязательный `mode: off | monitor | arm`, `show_interstitial` и упорядоченные `rules`. Отсутствующий `mode` не равен Off. Авторизованные запросы к этому API в рамках исследования не выполнялись; интеграция аккаунта не является частью пассивного детектора. [Справочник API](https://developers.cloudflare.com/api/resources/precursor/), [получение конфигурации](https://developers.cloudflare.com/api/python/resources/precursor/methods/get/).

В прочитанном официальном TypeScript SDK ещё присутствуют deprecated `default_mode: off | min-friction | max-security` и `enforcement_rules`. Они описывают прежнюю настройку enforcement. Преобразование этих значений в Monitor/Armed без отдельного подтверждения не допускается. [Прочитанный исходник SDK](https://raw.githubusercontent.com/cloudflare/cloudflare-typescript/main/src/resources/precursor/precursor.ts).

## Границы выводов

Получены положительные наблюдения **ресурса**: обычная навигация Luma загрузила canonical loader с 302 и затем JavaScript с 200 по `/cdn-cgi/challenge-platform/h/g/scripts/precursor/{version}/main.js`; отдельное публичное получение canonical loader с официального `www.cloudflare.com` подтвердило redirect на тот же origin и ту же форму пути. Это получение официального ресурса не доказывает его инъекцию в страницы `www.cloudflare.com`. Прочитанный version segment — ровно 12 lowercase hex. Browser version, response metadata и SHA-256 публичных скриптов приведены в runtime-observations.json. Эти результаты получены независимым исследованием. Они поддерживают presence fixture; режимы посещённых зон независимо не установлены.

Правило `cf-precursor-versioned-loader-v1` принимает только успешную browser-native загрузку `script` с точным проверенным versioned path, JavaScript Content-Type и same-origin binding текущего документа, дополнительно подтверждённым native `webNavigation.getFrame`. Из заголовков читается только значение Content-Type; HTML fallback с 200 отклоняется. Нельзя расширять правило на `h/b`, произвольный сегмент, общий `/challenge-platform`, XHR endpoint или canonical 302 без отдельного review. Совпадение native URL и MIME само по себе не аутентифицирует вендора: чужая страница может скопировать путь и MIME. UI описывает наблюдение ресурса по проверенному шаблону, не успешное исполнение или достоверность зоны.

В изученных официальных источниках **не найден документированный публичный маркер режима**, который расширение могло бы пассивно прочитать на произвольном сайте. Это результат проведённого поиска; он не доказывает отсутствие любого implementation-specific маркера. Проверка такого кандидата требует независимой метки конфигурации зоны и повторяемых наблюдений.

| Наблюдение | Допустимый вывод | Что из него не следует |
| --- | --- | --- |
| Проверенный ресурс именно Precursor | Ресурс наблюдался в указанном документе | Monitor, Armed, успешная проверка посетителя или режим всей зоны |
| `cf-mitigated: challenge` | Ответ Cloudflare Challenge Page | Что причиной был Precursor или что включён Armed |
| JSD или Turnstile | Наблюдение соответствующего отдельного продукта | Наличие или режим Precursor |
| Имя `cf_clearance`, его появление или обновление | Общий механизм Cloudflare clearance | Режим Precursor или его изменение |
| Повторные beacon/XHR, обработчики pointer/keyboard/focus | Наблюдаемая техника, если её зафиксировал сенсор | Идентичность вендора, факт чтения содержимого полей или режим |
| Признаков не наблюдалось | Нет наблюдений в доступной области и периоде | Off или переход в Off |
| Независимо подтверждённая конфигурация зоны | Конфигурационный режим на момент получения | Выполнение скрипта в каждом документе и причина конкретного Challenge |

`cf-mitigated` одинаково обозначает разные Challenge Page. [Контракт заголовка](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/). `cf_clearance` зашифрован; его обновляет также JSD. [Clearance](https://developers.cloudflare.com/cloudflare-challenges/concepts/clearance/). JSD может не быть включён заранее, поэтому отсутствие JSD не определяет Armed. Precursor bundle формируется динамически; фиксированный хеш всего bundle не заменяет проверенную сигнатуру. [Описание реализации](https://blog.cloudflare.com/introducing-precursor/).

## Контракт пассивного наблюдения и переходов

Наличие ресурса и режим хранятся раздельно. Пока нет проверенного источника режима, результат режима — `unknown`. Допустимые конкретные значения конфигурации — только `off`, `monitor`, `arm`; неизвестные строки, прежние поля и конфликты не превращаются в известный режим. Это требования к реализации, а не изменение канонической wire-схемы этой документацией.

Текущая реализация принимает в `precursor-state` только `mode: unknown` и `capabilities.modeDetection: false`. UI в popup/sidepanel показывает состояние выбранного точного документа в Light и Pro; кадры не объединяются. Панель не является разделом исторического Pro export. Она запрашивает `ui-get-precursor` раз в секунду; одновременно допускается только один незавершённый native message Promise на UI factory. Через шесть секунд отображается недоступность, но слот освобождается только при фактическом завершении Promise. Навигация, busy/clear, отключение и повторный mount не позволяют позднему ответу восстановить старое наблюдение. Уведомлений об изменении неизвестного режима нет.

Источник и integrity сохраняют каноническую семантику: browser network подтверждает сетевое событие; DOM, global и MAIN payload остаются page-controlled. Даже native запрос к похожему пути не аутентифицирует конфигурацию Cloudflare. Нельзя повышать уверенность присутствия до `documented-resource` только потому, что продукт документирован.

Переход режима требует двух независимо подтверждённых различных значений одного scope с известным порядком и актуальностью. Первое известное значение, потеря наблюдения, таймаут, pause/revoke/clear и переход `unknown → known` не создают уведомление «режим изменился». Возврат к известному значению после разрыва наблюдения не устанавливает время изменения внутри разрыва. Появление ресурса может быть отдельным событием присутствия, но не переименовывается в изменение режима.

Привязка документа/frame/tab и поколение доступа берутся из браузера. Дочерний iframe не задаёт режим верхнего сайта; разные origins нельзя объединять по registrable domain. Историческое наблюдение не переносится на новую вкладку или навигацию. BFCache, SPA и запоздалые события проверяются отдельно.

Сохраняются только allowlisted enum/rule ID, существующее безопасное представление host/path, насыщаемые счётчики и ограниченные метки времени. Никаких cookie values, токенов, request/response bodies, полных URL, сырого stack, координат или текста клавиш/полей. URL сопоставляется до redaction, а динамические сегменты не попадают в состояние. Расширение не запрашивает Precursor endpoint, не вызывает его JS и не инициирует challenge. Очереди, история, дедупликация и уведомления имеют явные лимиты.

| Локализация панели и используемых coverage labels | Полнота 21 языка проверена UI tests, включая ui-locales; это не ручная редакторская проверка каждого языка |

Для production presence нужны положительные metadata-only captures с независимой атрибуцией ресурса, source provenance, точный matcher с типом ресурса/MIME/успешным завершением, два reviewer, browser versions, срок пересмотра и процедура отключения. Полученные runtime observations и отдельный native fixture проверяют именно эту область. Для будущего включения **определения режима** дополнительно требуется независимо размеченный набор Off/Monitor/Armed, оба Interstitial defaults и path override. Синтетическая fixture проверяет matcher/состояние, но не подтверждает реальную сигнатуру вендора или режим зоны.

Обязательные отрицательные случаи: CDN-only, JSD-only, Turnstile-only, общий Challenge Platform path, документация с примером кода, DOM без загрузки, похожий host/path, query/fragment с ключевым словом, копия пути на чужом origin, HTTP error/abort, redirect на другой origin, повторный request ID, loaded-but-unused, кеш, late injection, отсутствие permissions, сторонний iframe, SPA/BFCache, revoke/clear/pause, stale callback, дубликаты, malformed mode, deprecated mode, конфликтующие данные и истечение лимитов/TTL.

Для Chrome сохраняются известные ограничения renderer memory cache; для Firefox — ограничения авторитетной network source-document identity поддерживаемого адаптера. Они описаны в [существующей совместимости Cloudflare](cloudflare-compatibility.md) и не снимаются DOM fallback.

## Отключение и сопровождение

Runtime policy presence: `PRECURSOR_POLICY` в [precursor-observer.js](../../apps/production-extension/precursor-observer.js), `enabled: true`, stage `production-approved`, review due `2027-01-28T00:00:00Z`. Правило не повышает unknown mode до конкретного значения. Rollback `disable-cf-precursor-versioned-loader-v1`: установить `enabled: false` в этой локальной policy, проверить `node scripts/production/sync-precursor-runtime.mjs --check`, выполнить focused tests и пересобрать проверяемые пакеты. Это процедура сопровождения сборки; отдельный пользовательский переключатель не заявляется. Существующие Turnstile/JSD и остальные детекторы сохраняются.

Отключение прекращает новые наблюдения, удаляет сохранённые записи и инвалидирует pending callbacks. Физические слоты освобождаются только после завершения native-вызовов. Отсутствие записи не переинтерпретируется в Off. Истёкший review выключает presence detection этой policy. Permissions, CSP, внешняя сеть и модуль «Защита» не меняются. Уведомления о режиме не реализованы ввиду отсутствия подтверждённого сигнала.
