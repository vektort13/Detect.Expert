# Карта запросов Pro — проверенное покрытие

2026-10-09. Общая production-база `apps/production-extension`, версия 1.1.0. REQ-004/005/007/010/011/013/014/015; ADR-007/017/018/020.

В полноэкранном отчёте остановленной Pro-записи добавлен интерактивный граф посещений и доменов ресурсов. Выбор домена выделяет связанные посещения и показывает запросы, завершения, ошибки запросов, перенаправления, HTTP-статусы, сводку типов и таблицу посещений со ссылками на подробный отчёт. Фильтры выбирают все/сторонние домены и тип ресурса. Клавиатурный фокус сохраняется после перерисовки.

Источник — уже валидированная текущая Pro-сессия, относящаяся к одному `siteKey`. Фильтры не меняют данные или защиту. `pro-request-graph.js` не использует browser API, storage или внешнюю сеть. Нет новых permissions, зависимостей, wire-полей, маршрутов privileged UI, детекторных порогов или runtime vendor rules.

## Пределы

| Величина | Лимит |
| --- | ---: |
| Обход посещений | 100 |
| Обход групп ресурсов | 5000 суммарно, 500 на посещение |
| Посещения на диаграмме | 24 |
| Домены на диаграмме | 48 |
| Связи на диаграмме | 240 |
| HTTP-статусы на входную группу | 16, как в существующем Pro |
| Объединённые HTTP-статусы | Все известные коды 100–599, до 500 разных кодов |

Количество скрытых из диаграммы посещений, доменов и связей отображается. Сводные счётчики включают все подходящие обработанные группы; подробности выбранного домена могут содержать посещения, не поместившиеся в диаграмму. Превышение предела входных данных отдельно отмечается. Число групп не является числом исходных файлов: Pro объединяет очищенные шаблоны URL.

`requestCount` означает наблюдавшиеся запросы. `completedCount` включает ответы с HTTP 404/500 и не обозначает успех приложения. Ошибки запросов включают отказ, отмену и блокировку; карта не определяет их причину. HTTP-коды не теряются при объединении более 16 групп.

При удалении/замене Pro-записи `storage.session` служит только сигналом инвалидации. Открытый отчёт сразу сбрасывает старый snapshot и запрашивает данные через прежний `ui-pro-get`; применяет только последний ответ для того же остановленного session ID. Значения события `storage.onChanged` не используются как содержимое отчёта. Печать повторно проверяет запись.

## Измерение

Локальный Node v25.2.1, синтетические 100 посещений / 5000 групп / 50 доменов, 10 разогревов и 30 измерений: агрегация **12,93 мс median / 17,29 мс p95**. Вход обработан полностью; диаграмма 24/48/240, исключено из отображения 76/2/4760. Исходные измерения: `.tmp/pro-graph-performance.json`, SHA256 модуля `5a1f913f05410ce7e9ae5f56e0733b377bfddd7eaed835e20cdde37ec87c4721`.

Это измерение чистого UI-helper в Node на одном ПК, без DOM, рендера, доставки, storage и полного browser/extension overhead. Hooks и hot path страницы этой задачей не менялись.

## Ограничения и артефакты

Сессия ограничена одним сайтом; межсайтовой долговременной истории нет. Карта наследует пропуски Pro и browser network attribution. Subdomains, query, идентификаторы и некоторые адреса уже удалены/обобщены до графа. Связь не доказывает передачу содержимого, владение ресурсом, зависимость скрипта или конкретный антифрод-продукт. Содержимое сообщений WebSocket/WebTransport, серверные обращения и CNAME-цепочки не наблюдаются.

Chrome outbound-check охватывает наблюдённые HTTP(S) context requests после запуска браузера: разрешены только точные origin/port локальных fixtures. Зарезервированные `shared-graph.example.com` / `other-graph.example.net` направлены через host-resolver rules на 127.0.0.1; proxy отключён. В этой области внешних HTTP(S)-запросов и uncaught ошибок не наблюдалось. Firefox smoke не включает самостоятельный outbound monitor; утверждение о полном трафике Firefox не делается.
