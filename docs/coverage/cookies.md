# Cookie inventory и пять вкладок идентификации

REQ-004/005/007/011/012/013; ADR-021/022/023/024. Production: `apps/production-extension/cookie-inspector.js`, `identification-ui.js`; канонические дополнительные wire readers: `packages/contracts/src/inspection.mjs`. Каталог и provenance: публичные базы и Shodan, первоначальная база, предыдущее расширение анализа.

## Доступ и данные

`cookies` — optional API permission. Оно запрашивается явной кнопкой в UI; обязательные host permissions и CSP не расширены. Наблюдение за сайтом и согласие на сбор проверяются отдельно. Выбранный tab определяет единственный store через getAllCookieStores; подмена другим/default store при недоступности или неоднозначности запрещена. Inventory читает metadata всего текущего top-level сайта: домен, поддомены и все пути. Дополнительно доступны cookies выбранного документа и, при авторитетной browser document identity, наблюдавшихся resource hosts. Это сохранённые cookies в данной области, а не доказательство их отправки или чтения JavaScript.

В metadata UI/Pro/export входят безопасное имя, нормализованный домен, категория, владелец/назначение, confidence, rule IDs, ссылки на источники, Secure, HttpOnly, SameSite, hostOnly, session/expiry и факт partitioning. Этот metadata snapshot не содержит Cookie values, payloads/JWT, raw path, store ID и непрозрачный partition identifier. Отдельный live UI ответ значения разрешён ADR-023 по явному клику. Динамические суффиксы известных имён маскируются (`_ga_*`), но физически разные cookies сохраняют отдельные строки и счётчики. Raw name/domain/path/partition site используются в ограниченных временных native identities для дедупликации и локальных live handles. Metadata projector не читает `value`.

По прямому решению владельца продукта добавлен отдельный Pro-канал наблюдаемых исходящих Cookie headers: точные имена и значения сохраняются локально в активной записи и выводятся в сводной таблице PDF. Этот канал не использует cookie jar или live handles, сохраняет значения только разрешённых записываемых запросов и не расширяет Light/очищенный JSON. Связь с нативным документом, переходы, ограничения и проверка описаны в [ADR-037](../decisions/ADR-037.md) и [Pro report coverage](pro-report-1.1.0.md).

Partition queries выбирают текущий top-level site; данные других partitions отбрасываются. Firefox 138 не даёт используемой здесь авторитетной webRequest document identity: resource-host расширение inventory недоступно. First-party metadata выбранного store/документа и поддержанные native partition queries работают. Inventory coverage остаётся partial: snapshot не доказывает всю активность сайта. Ошибки permission/API/identity показывают фактическое состояние функции.

## База и счётчики

Локально поставляется 6 687 записей: 2 266 из закреплённой Apache-2.0 Open Cookie Database, 443 правила с первичными источниками, 492 MIT metadata-записи cookie-audit/CookieBlock и 3 486 нормализованных IAB declarations; 355 upstream OCDB platform groups. Runtime компилирует 6 673 правила; предел — 8 192. Четырнадцать записей с недопустимыми именами остаются исследовательскими данными. IAB GVL 180: обработаны 1 226 vendor endpoints, получены 1 131 документ, 95 недоступны или неподдержаны. Подробности и hashes — исследование источников.

Никаких runtime загрузок или выполнения правил из внешнего источника нет. Общественная запись с применимым domain context сохраняет confidence `community`; отсутствие domain context и auth-name collisions дают `unknown/ambiguous`. Для отличительного неизвестного имени показывается отдельное поле «Совпадение имени в справочнике», owner пустой, tracking=false; общие session/id/auth имена исключены. IAB owner явно обозначает автора декларации, не автоматически производителя; документация производителя приоритетнее. Однозначная документированная mixed-purpose запись сохраняет owner/purpose/sources, category unknown и tracking=false. Подстрока домена не считается совпадением. Tracking=true только для принятых analytics/advertising rules. Security, consent, necessary/functional и unknown не увеличивают красный Cookie badge. Категория описывает документированное назначение, а не вердикт о легитимности конкретного сайта.

Shodan: выполнены 39 агрегатных запросов по опубликованным именам, все успешны, 30 имеют ненулевой total. Это совпадения поисковых терминов в индексе, а не подтверждение производителя, назначения или фактического использования cookie конкретным сайтом. IP/баннеры/значения cookie не собирались; результат не меняет runtime классификацию. [Результат](../../packages/catalog/research/cookies-2026-10/shodan-cookie-counts.json).

Под заголовком «Обнаруженные антифрод-системы» — четыре вкладки: «Активная идентификация», «Пассивная идентификация», «Third Party Surveillance», «Cookie». Активный badge считает различные сопоставленные техники вызовов страницы; пассивный — различные наблюдённые техники; третий — различные техники других доступных документов; Cookie — tracking cookies. Третья вкладка по прямому решению заменяет прежний раздел других документов: его frame scope включает также same-site/same-origin дочерние документы и не устанавливает стороннего владельца. Повторы вызовов не увеличивают количество разных техник. Вкладки поддерживают клавиатурный выбор, red badges и отдельные панели; narrow popup использует два столбца независимо от ширины окружающего viewport.

Cookie view автоматически читает уже разрешённые metadata, включая счётчик на скрытой вкладке; permission prompt возникает только по кнопке. Epoch/document guards отбрасывают устаревшие ответы. Снимок текущего документа включается в активную Pro-запись и показывается той же проекцией в полном отчёте/печати. Clear, pause, смена scope/consent/permission и навигация отменяют допуск старого read; после async API и Pro flush выполняется повторная проверка. Отзыв cookies permission удаляет сохранённые Cookie snapshots.

В кнопке Cookie и вверху панели показан totalCount: все уникальные доступные inventory cookies до ограничения отображения. При наличии сторонних cookies отдельно показан siteCount текущего top-level сайта. Красный badge сохраняет число распознанных tracking entries. Остальные cookies считаются среди отображённых entries. При ограничении сканирования/памяти/вывода общий счётчик помечен «≥». Старые Pro snapshots без optional полей сохраняются: total равен entries.length, siteCount не выдумывается.

Tracking cards выделены цветом: analytics и advertising различаются. Известные владельцы получают локальные SVG компании из фиксированного набора icons/brands; provenance/CC-BY-4.0 attribution поставляются с расширением. Другие владельцы имеют нейтральную монограмму. Generic framework/CMP convention не выбирает логотип конкретной компании. Анализ объясняет Secure, HttpOnly, SameSite, session/expiry, domain scope и partitioning; значение cookie не анализируется и не декодируется.

## Очистка текущего сайта

Первая кнопка панели выполняет ui-clear-site-cookies только по явному клику trusted extension UI. Background проверяет sender, consent, permission, выбранный и top-level document, затем получает store из tab. Caller не может передать URL, домен, store или partition. Удаляются cookies top-level registrable domain, его поддоменов и всех путей в этом store, включая Secure/HttpOnly и текущую top-level partition. Сторонние сервисы, другие сайты, stores/containers и partitions сохраняются. При неизвестной registrable relation допускается только точный host.

Повторный клик блокируется; destructive command не повторяется автоматически. UI сохраняет старые счётчики до результата, показывает фактически подтверждённые removed/failed counts и перечитывает metadata. Navigation/revocation/store/access generation changes останавливают дальнейшее удаление. Same-site Pro snapshots и старые inventory reads инвалидируются до/после операции. Unresolved native remove блокирует новые cleanup/read операции после timeout до завершения физического Promise; uncertain removal не повторяется. Cookie path, name и partition identity остаются временными native API аргументами и не входят в ответ/отчёт. Непредставимый без изменения path считается failed/partial.

DBSC inspector, debugger permission и DBSC/TPM-поля удалены из панели и отчёта. Старые metadata snapshots читаются с удалением только sessionBinding и boundSessionStatus. [ADR-044](../decisions/ADR-044.md).

## Лимиты и отключение

64 document records с TTL 10 минут, 24 resource hosts/document, 48 queries/read, до четырёх queries в группе, дедлайн прохода 3 секунды, query timeout 1 секунда. До восьми физически ожидающих API jobs и двух read operations; одинаковые document/epoch/scope reads объединяются. Native scan до 1 024 результатов на query / 4 096 на операцию; output до 256 entries / 96 KiB metadata; временные dedup identities до 128 KiB. Превышение отмечает truncated/partial, не вызывает бесконечного retry. Cleanup: одна операция, дедлайн 8 секунд, native API timeout 1 секунда, UI timeout 15 секунд, scan до 4 096 / 1 024 на query и до 128 KiB временных identities. Wire ограничивает строки, списки rules/sources и document identity.

Отключение: отклонить/отозвать optional cookies permission; для прекращения Pro snapshot — остановить запись. В обычных сборках новых зависимостей, внешних соединений, uploads, debugger permission и чтения файлов профиля браузера нет. Фактические unit/native результаты и окончательные архивы перечислены в покрытии выпуска.

Firefox compatibility: native installed 138.0.4 подтверждён. До Firefox 133 выбор native remove среди совпадающих путей отличается; overlapping same-name paths могут оставить cookies, actual failed/partial status и повторный inventory это сохраняют. FPI-enabled Firefox требует firstPartyDomain query context; здесь неподдержанный query fail-closed/partial, без общего перечисления partitions. Другие Firefox containers отдельно native не проверены; selected-store isolation покрыта unit fixtures.

## Значение cookie

В открытой Cookie панели кнопка «Показать значение» делает один privileged запрос для current-site native identity. Current top-level site и его поддомены в selected store/current partition получают opaque live handles отдельно от канонического metadata snapshot; другие resource-host rows не получают value handle. Values не читаются при inventory/скрытом badge polling. UI показывает одновременно одно значение, отдельно отмечает пустую строку и усечение. HTML/control/bidi отображаются текстом; JWT/значение не декодируется. Hide/refresh/clear/panel closing/navigation/pause/permission и origins-only revocation сбрасывают held UI text и late reply admission. Live блок скрыт при печати; Pro/report/export не имеют value controls.

Backend повторно проверяет trusted UI, consent, selected/top documents, scope/permission/store/current partition, epoch/access generation и exact native identity, затем читает own value descriptor. Native getAll requery ограничен 1 024 строками; ≤2 logical/physical reveals, deadline 5 s, job timeout 1 s. Handles живут ≤60 s с cleanup timer, ≤512 / 128 KiB retained identities. Значение ответа ≤16 384 UTF-16 code units, с truncated=true при превышении. Refresh текущего view, epoch/navigation/clear/revocation инвалидируют background handles; hidden/unmount сбрасывают UI, оставшиеся background identities истекают по TTL. Нет значений в persistent storage/Pro/MAIN.
