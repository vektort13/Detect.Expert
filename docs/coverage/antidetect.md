# Antidetect — E22-17/18/19/22/24 / ADR-064/065/066/068/104

Управление по ADR-090: верхний ON/OFF немедленно сохраняет только `antidetectEnabled` через прежний CAS. Остальные, в том числе временно отключённые, поля черновика сохраняются до отдельного Save/Cancel. Switch показывает принятый master; ошибка, конкурентная revision, скрытый или ожидающий ответ не означают успешного включения. Индикатор использует saved master и registration; пустая включённая конфигурация остаётся inactive с пояснением в заголовке. Reads API/Antidetect не ждут Autosurfer/Proxy. ## Полные профили

Профиль содержит стабильный ID, название, preset, native WebRTC policy и все158 API scope rows:mode/selected/settings. Master/site overrides/user libraries при загрузке сохраняются. До128 профилей и остальные данные делят лимит4МиБ UTF-8. Экспорт детерминирован, empty/unset/null/undefined сохраняют состояния в рамках типа.

Генератор «Рандомизировать» (ADR-104) строит одно согласованное устройство: Windows 10/11, Google Chrome или Microsoft Edge (версии 136…156, статический список без сети), GPU и WebGL из каталога 50 адаптеров Windows (маскированные vendor/renderer WebKit и ANGLE в unmasked-паре, лимиты D3D11; выбор взвешен по распространённости), экран как панель × масштаб Windows (CSS-размер = панель / масштаб; 3840×2160 при 100% не выпадает), ядра из списка потоков самой карты (эвристика, не телеметрия) и образ памяти по классу карты (офисная встроенная графика не получает 4K и 24 потока), строку WebGPU `adapter.info` в форме Chrome (vendor и architecture по карте, device и description пустые), `deviceMemory` из корзин выбранной версии (Chrome до 147 — 0.5…8, с 147 — 2/4/8/16/32), UA, UA-CH (порядок и написание GREASE-бренда зависят от версии, полная версия — `X.0.0.0`; если заявка совпадает с реальным браузером, берутся его настоящие полные версии и platformVersion; для Windows 11 по умолчанию 19.0.0) и `platform` по выбранной ОС и версии. Квота `storage.estimate` остаётся как в браузере, пока пользователь не выбрал размер накопителя (тогда — 50% образа). Остальное определяет пресет, и пресет — полное утверждение: при генерации более лёгкого пресета строки более сильного возвращаются в «Как в браузере», явный Block страницы не снимается. «Совместимость» — только значения идентичности, поведение страниц не меняется; «Сбалансированный» — плюс детерминированные по seed Canvas-readback, Audio и Math; «Максимальная защита» — плюс масштаб метрик текста Canvas, список из 91 имени шрифта Windows (плюс 6 для Windows 11), проекция WebGL readPixels, геометрия окна с `css-media` и блок сенсорных и аппаратных API (может ломать сайты). Прежний генератор recipes остаётся в коде (`generateFingerprintConfiguration`), в интерфейсе не используется; движок браузера остаётся настоящим Chromium, Firefox/Safari и другие ОС в выбор не входят. Проверки выявляют конфликты OS, языка, экрана, GPU metadata и deviceMemory buckets; они не являются оценкой статистической распространённости оборудования. Генератор не меняет native network policy и не восстанавливает dormant WebRTC IP/relay/DTLS значения из OFF/BYPASS/ON. Выбранный Custom профиль WebRTC, если он уже задан этим режимом, сохраняет его routing/certificate настройки.

Generate, Load и ручное изменение API сначала меняют preview. Save as profile, Rename и Delete изменяют только библиотеку: backend пишет один configuration record, не останавливает открытые guards, не меняет legacy revision/pending и не перерегистрирует scripts. Apply использует прежний CAS и общую проверку permissions. Внешняя revision или отзыв доступа инвалидируют черновик; сохранённая ошибка применения не выдаётся за rollback или готовность native hooks.

### Библиотека: теги, заметки, корзина, временные профили, связка с прокси, экскурсия ([ADR-108](../decisions/ADR-108-shardbrowser-owner-decisions.md))

- **Теги и заметки** — поля профиля (до 8 тегов по 24 единицы UTF-16 без повторов с учётом регистра; заметка до 500 единиц, допускается перевод строки): переносятся в экспорте библиотеки, ищутся и фильтруются со счётчиками; небезопасные символы (управляющие, bidi) отклоняются при записи и импорте.
- **Корзина на 7 дней** (`fingerprint-trash:v1`): удаление сначала пишет копию, затем убирает профиль; «Отменить» и «Восстановить»; не более 32 копий и 1,5 МиБ; хранится только локально, в экспорт не входит.
- **Временный профиль** (`fingerprint-temporary:v1` и маркер в `storage.session`): применяется только на сеанс браузера и возвращает прежнее состояние по «Завершить» либо при запуске после перезапуска браузера, до регистрации скриптов. Сгенерированная личность не попадает в библиотеку. В Chromium перезапуск проверен настоящим перезапуском браузера; в Firefox — только юнит-тестами.
- **Связка «профиль → прокси»** (`identity-bundles:v1`, локально): выбор сохранённого прокси, предупреждение при общем выходе, «Применить вместе с прокси» (явное подключение по нажатию, `autoConnect` не создаётся), подсказка `proxy-country-region` по собственной метке страны прокси и «Подогнать регион». Метка страны — заметка пользователя, не определяется и не проверяется.
- **Экскурсия** по Antidetect (раунд 5, [ADR-111](../decisions/ADR-111-guided-tours-and-header-actions.md)): 7 шагов (шаг «Proxy» перенесён в экскурсию раздела Proxy), несмодальная карточка, управление с клавиатуры, сама не запускается; ничего не меняет в настройках. Её запускает компактная кнопка «Экскурсия» в шапке вкладки (слева от главного переключателя) и блок в контрольном списке первого запуска; полоса «Пройти экскурсию / Обновить» под шапкой убрана, «Обновить» стало иконкой в том же кластере (`data-antidetect-refresh`). Прогресс — `ui-tour:v2`.

Ключ шума Canvas, Audio и readPixels включает сайт верхнего уровня: сторонний фрейм на двух сайтах видит разные значения (в Worker ключ остаётся по origin воркера); аудио-буферы, созданные страницей (`createBuffer`, `new AudioBuffer`), читаются без изменений. По [ADR-112](../decisions/ADR-112-canvas-sparse-v2.md) новые Сбалансированный и Строгий профили используют Canvas `sparse-rgb-v2`: выбранный канал непрозрачного пикселя получает ключевой младший бит (не больше одного уровня; до 512×512 подвижна примерно половина ненасыщенных пикселей, выше — около 1% кандидатов и половина от них), каналы 0, 1, 254, 255 не двигаются, холст до 262 144 пикселей и до 4 цветов возвращается как нарисован, а образ, который мы уже подвинули, читается без изменений (круговой обход PNG не двигает пикселей). Сохранённые профили `sparse-rgb-v1` (около 1% непрозрачных пикселей на один уровень; PNG плоского холста 2560×1440 в Chromium 153: 76 КБ → 148 КБ против 4,6 МБ у `stable-rgb-v1`) и `stable-rgb-v1` не изменены. Приватные ключи Canvas и Math живут весь срок применённого профиля. Полупрозрачные пиксели (0 < alpha < 255: сглаженные края, заливки с альфой, копия рисунка с `globalAlpha` < 1) тоже помечаются, но не на ±1 уровень: Canvas хранит канал premultiplied-байтом q ≤ alpha, движок отдаёт его по своей арифметике, и значение ±1 обычно недостижимо ни для одного движка. Выбранный канал двигается на одно сохранённое состояние, и пиксель получает байт, который движок сам возвращает для нового состояния (тот же выбор пикселей, канала и направления, что у непрозрачных; `stable-rgb-v1` двигает все три канала). Измерено в Chromium 153 и Chrome 156 (округление; CPU и GPU расходятся только в 615 состояниях с ровно половиной уровня, они не используются) и в Firefox 138.0.4 и 153.0 (premultiply = ceil, `getImageData` = floor, PNG = округление; берутся байты, одинаковые при floor и при округлении). Сдвигается 100% читаемых значений в Chromium и 88,9% в Firefox (почти не сдвигаются alpha 6, 10, 30, 34, 102, 170). Остаются настоящими: полупрозрачные пиксели WebGL-холстов, движка без измеренной арифметики и `getImageData` с `colorSpace`, отличным от холста |
| Client Rects | — | — | Custom-подмены в каталоге нет: честно показано как «Не покрыто» |
| Сеть | WebRTC, WebSocket, WebTransport, native policy | Описано в таблице выше | IP, TLS/HTTP2/QUIC-отпечаток и движок браузера расширение не меняет: строка у карточки и на уровне «Сеть» |

Каталог видеокарт: 50 адаптеров Windows. NVIDIA — 24 (15 настольных от GTX 1060 6GB до RTX 4080 и 9 ноутбучных от GTX 1650 Ti до RTX 4070 Laptop GPU), AMD — 11 (8 настольных от RX 580 до RX 7800 XT и три встроенных `AMD Radeon(TM) Graphics`: Renoir, Cezanne, Rembrandt), Intel — 15 (11 встроенных HD, UHD, Iris Plus, Iris Xe и четыре Arc). Строки имеют вид, который Chrome печатает для Direct3D 11 через ANGLE, например `Google Inc. (NVIDIA)` и `ANGLE (NVIDIA, NVIDIA GeForce RTX 2080 SUPER (0x00001E81) Direct3D11 vs_5_0 ps_5_0, D3D11)`. Идентификаторы устройств PCI сверены с базой pci-ids (версия 2026.11.05, pci-ids.ucw.cz): для всех 50 карт модель по базе совпала с карточкой. Имя адаптера в базе PCI отсутствует: это строка драйвера Windows, и офлайн её подтвердить нельзя. Написание принято по известному именованию драйверов и не подтверждено ни документацией производителя, ни оборудованием; наименее надёжны общее `AMD Radeon(TM) Graphics` у встроенной графики AMD, `Radeon RX 580 Series` у RX 580 и `Intel(R) Arc(TM) Graphics` у Meteor Lake. Класс производительности (1 офисная … 4 топовая) и вес карты заданы вручную: они делают случайный профиль правдоподобным (4K только у топовой настольной карты, 1366×768 только у офисного ноутбука, 12 потоков и больше у топовых карт), но не являются статистикой оборудования. Пять карт прежнего каталога сохранили идентификаторы и строки, чтобы сохранённые профили узнавали свою карту. Записываются шесть параметров WebGL, одинаковых для всех карт. Измерение на Chrome 156 показало, что у настоящей GPU и у программной WARP различаются только четыре параметра (`MAX_VERTEX_UNIFORM_VECTORS`, `MAX_VERTEX_UNIFORM_COMPONENTS`, `MAX_COMBINED_VERTEX_UNIFORM_COMPONENTS`, `MAX_SAMPLES`), поэтому на типичном хосте строка лимитов ничего не меняет и нужна для хостов с другим бэкендом; `extensions` не записываются. Архитектура WebGPU по карте — эвристика по поколению GPU, измерена только для `turing`.

Где строки редактора лежат по уровням: «Устройство» — процессор, память, накопитель, экран, сенсорные точки, Math; «ОС» — платформа, язык, зона, Intl и шрифты; «Браузер» — User-Agent, Client Hints, Canvas, WebGL, WebGPU, Audio, метаданные Navigator. API Guard сохраняет собственное распределение категорий.

## Первый запуск и переключатель Chrome

Chrome 138+ выдаёт расширению `chrome.userScripts` только после того, как пользователь включит «Разрешить пользовательские скрипты» на странице расширения (программно это невозможно). Пока переключатель выключен, расширение не может применить Custom до скриптов сайта и не делает вид, что применило: сохранение строк при включённом мастере отклоняется кодом `early-access-required`, вкладка «Антидетект» показывает плашку с точным действием, кнопкой открытия `chrome://extensions/?id=…` и «Проверить снова», а при возврате на вкладку состояние перечитывается само. Firefox использует необязательное разрешение `userScripts` с кнопкой «Разрешить». Проверено на Chrome 156.0.8078.80 и Chromium 153.

Строка «HTTP User-Agent» на сайтах проверки (например, на browserleaks.com) — заголовок запроса. По [ADR-105](../decisions/ADR-105-antidetect-http-headers.md) в Chrome при области «все сайты» и готовом раннем реестре он следует `navigator.userAgent`, а Accept-Language и Sec-CH-UA — выбранным строкам; в Firefox, при исключениях отдельных сайтов или без ранних скриптов заголовки остаются настоящими (состояние видно на уровне «Сеть»). Настоящими остаются IP, отпечаток TLS/HTTP2, `Width`/`Save-Data`, подсказки воркеров и значения внутри Workers.

## Живой аудит 2026-11-05: что проверено и что осталось пределом

Функции вкладки проверены в настоящем Chromium 153 с включённым переключателем «Разрешить пользовательские скрипты»: устройство, экран, WebGL и GPU, Canvas и Audio, Math, часы и поверхность браузера, идентичность и Client Hints, локаль и время, медиа и прочие API, сеть и WebRTC, жизненный цикл и интерфейс. Значения читались в первом скрипте страницы и после загрузки: в основном окне, в same-origin и cross-origin iframe, в about:blank и srcdoc, в popup и в Worker. Сравнение шло с чистым Chromium с эмуляцией зоны и локали и с публичными проектами (CanvasBlocker, Chameleon, JShelter, Camoufox) как с внешним справочником; код оттуда не переносился. ## Сверка с Camoufox и CloakBrowser (2026-11-05)

Образцы: **Camoufox** — открытый форк Firefox (патчи движка под MPL-2.0, python-библиотека и данные под MIT); **CloakBrowser** — Chromium с закрытыми C++-патчами (в репозитории только обёртка под MIT, бинарник проприетарный, нужен ключ). Шесть исследователей сравнили свои области с нашими строками; значения Chrome 156 и Edge 156 измерены на одной машине (Windows 11, сборка 26200). Код образцов не запускался и не копировался.

**Различие целей.** Образцы стараются выглядеть как «обычный» браузер и проходить антибот-проверки. Camoufox прямо пишет, что шум (Canvas, ширина текста, звук) сам является отпечатком, и убрал его; CloakBrowser, наоборот, шумит от seed. Цель расширения — не давать связывать пользователя между сайтами, поэтому шум Canvas, Audio, Math и масштаб текста остаются, а спорные места вынесены в решения владельца продукта (ниже). Приёмы против антибот-защиты (скрытие автоматизации, имитация человека, CAPTCHA, правка таймингов прокси, выдуманные ICE-кандидаты) не переносятся: REQ-001.

### Что перенято (независимая реализация)

| Идея | Что сделано у нас |

### Что остаётся настоящим при заявке другой ОС

Все образцы повторяют: заявлять ту ОС, на которой запущен браузер. Randomize всегда заявляет Windows; на другой ОС остаётся настоящим то, что движок берёт у системы и чего расширение достичь не может.

| Что | Почему |
| --- | --- |
| Пиксели Canvas и WebGL, растеризация шрифтов, эмодзи | рисует система и драйвер |
| Установленные шрифты вне встроенного списка, `system-ui`, шрифты запасных глифов, системные шрифты CSS | щит ADR-110 закрывает только имена из встроенного списка (DOM, SVG, Canvas окна); остальное, включая `@font-face { src: local() }` в CSS страницы, видит настоящее |
| Ширина полосы прокрутки, цвета системы, поведение клавиатуры | часть движка |
| Диапазон эфемерных портов WebRTC | порт выбирает ОС |

## Canvas: проверенные readbacks и ограничения

`stable-rgb-v1` прошёл native Canvas fixtures Chromium 153, Chrome 155 и Firefox 138: по 6 сценариев, а production composition Chrome 153/Firefox 138 — по 12 сценариев. После подтверждённых обходов через прежние visual/API-results каналы добавлена общая однонаправленная политика: любой активный Custom выключает raw API-results/Pro values, Canvas previews и RTC endpoint snapshots этого observer runtime, сохраняя обычные счётчики наблюдений. Проверены оба порядка установки, metadata-only Custom, поздняя очередь, доступный child и opaque frame; выключенный Custom сохраняет positive controls. Проекция меняет на 1 полностью непрозрачные RGB каналы, а полупрозрачные — на одно сохранённое состояние (см. строку «Canvas, WebGL, Audio») при покрываемых ImageData/URL/blob readbacks. Alpha, полностью прозрачные пиксели и исходный рисунок сохраняются. Максимум одной проекции — 4 × 1024² пикселей; ожидающие encoders делят лимит 4 операции и 8 × 1024² пикселей. Unsupported float16/context/color/coercion и исчерпание бюджета не возвращают исходный bitmap.

Ключ Canvas отдельный от Math, выводится из локального корня в storage.local и применённого профиля (ADR-106) и отсутствует в переносимых профилях. Область — доступные Window Canvas/OffscreenCanvas realms; Worker/worklet Canvas, WebGL readPixels и текстовые metrics не меняются. В недоступных opaque frames пять покрываемых методов отказывают; это не эмуляция такого frame. Исправление native Chrome crash parent/child contextAttributes подтверждено separate-realm bindings и native fixtures. Chrome поддержал 8 GL sRGB/P3 веток; Firefox —4 sRGB, а 4 GL P3 экспорта закрываются отказом при доказанной native Canvas2D несовместимости с P3. [Полная матрица Canvas](api-custom.md), [исследование 45 семейств fingerprint](fingerprint-surfaces.md).

Работающие документы сохраняют прежний профиль до навигации/reload; уже прочитанные значения и захваченные ранее ссылки отозвать нельзя. При последующих новых переходах подтверждённая document-start регистрация применяется до первого скрипта сайта. Первая установка, обновление расширения и восстановление native access асинхронны; промежуток до успешной регистрации не объявляется покрытым. Opaque недоступные realms удерживают metadata нейтрально; предел синхронного наследования — 1024 realms. Нет маскировки Function.toString, сетевого VPN/прокси, HTTPS-сертификатов или изменения системного стека.

Native fixtures используют только собственные HTTP/STUN/TURN узлы и одноразовые профили. Genuine IPv6 candidate objects проверяются; на тестовом хосте нет маршрутизируемого IPv6 NIC, сетевой IPv6 маршрут не проверен. Firefox 138 не отдаёт transport.dtlsState в getStats; DTLS подтверждается настоящими fingerprint и передачей datachannel напрямую и через локальный TURN. WebTransport resourceType принят Chrome, но настоящего HTTP/3 fixture-сервера нет: end-to-end QUIC/WebTransport соединение не заявляется проверенным.

Финальная E22-19 проверка: полные Profiles — по 7 native сценариев, UI — по 8, Early Custom — по 66 снимков Chrome/Firefox; Math — по 7; Chrome protocol —7. Package gate проверяет 82 точных source/dist copies, 42 locale deliveries по 248 ключей, 5 исторических миграций, неизменные manifest и полные детерминированные ZIP. Package evidence.

| --- | --- |
| Имена вне встроенного списка (кроме Canvas) | Скрыть можно только то, что названо; фингерпринтер с собственным списком найдёт установленный шрифт с необычным именем |
| `@font-face { src: local("Имя") }` в CSS самой страницы | Поиск `local()` — запрос платформы, а не вёрстка семейства; CSS страницы не разбирается и не переписывается |
| Шрифты остальных пакетов Features on Demand (арабский, иврит, тайский, индийские письменности и др.) | В списки не входят: региональной группы для этих регионов нет (как и у «Авто»); в проб-списке они скрыты, настоящая Windows с таким языком их показала бы |
| Workers и `OffscreenCanvas` в Worker | Нет документа и таблицы стилей |
| Изолированные (sandbox без `allow-same-origin`) фреймы и другие opaque-области | Родитель не может передать профиль; измерено в Chromium 153: 113 из 113 скрытых и установленных имён остаются видимыми через DOM (Canvas скрыт прежней нейтральной политикой) |
| Страница, присваивающая `document.adoptedStyleSheets = […]` | Её присваивание снимает таблицу щита с документа (добавление `[...старые, своя]` её сохраняет): щит уступает родному виду |
| Точные метрики и формы глифов; шрифты списка, которых нет на машине | Берутся с хоста; расширение не создаёт и не рисует шрифты |

Что видит страница о самом щите (REQ-014): `document.fonts.size` и список граней (`unloaded` / `loaded`, `unicodeRange: U+10FFFF`, `stretch: 200%`), одна принятая таблица в `document.adoptedStyleSheets`, однократные события у `document.fonts` после первого макета со скрытым семейством (`loading` и `loadingdone` в Chromium и Chrome, одно `loadingdone` в Firefox; при выключенной опции их нет), свойство-символ `detect.expert/api-custom/font-shield/v1` на `window`, прокси вместо `FontFace` (с родными `name` и `length`; запрещает замкнуть цикл прототипов через себя тем же `TypeError`, что и родной конструктор, — ADR-112 §6, `Function.prototype.toString` не маскируется). Страница, запросившая скрытый шрифт, получает следующий шрифт своего списка и может выглядеть иначе — это сказано в подписи у опции.
