# Proxy — E22-25 / ADR-070

Вкладка Proxy находится между Cookies и Контакты. Она имеет собственные профили, маршрутизацию и состояние, независимо от API Guard, Antidetect и Firewall. Управление через точный собственный Options и отдельный validated runtime port; обычные страницы и content scripts не могут сохранять профиль или менять proxy. [Архитектура и новые разрешения](../decisions/ADR-070.md), [проверенные первичные источники](proxy-research.md).

## Возможности

| Протокол | Реализация | Хранение и границы |
| --- | --- | --- |
| SOCKS5 без пароля | Chrome PAC / Firefox onRequest | Host/port metadata в local; native host не нужен |
| SOCKS5 с паролем | Loopback relay Go companion → RFC1929 upstream | Пароль в Windows DPAPI; Chrome не реализует SOCKS5 auth сам |
| HTTP / HTTPS без логина | Chrome PAC `PROXY` / `HTTPS` (без DIRECT после директивы); Firefox `proxy.onRequest` с `type: 'http'` / `'https'`, `failoverTimeout: 1` и конечным `null` | Host/port metadata в local; companion не нужен ([ADR-108](../decisions/ADR-108-shardbrowser-owner-decisions.md)) |
| HTTP / HTTPS с логином | Браузер направляется на loopback SOCKS5-реле companion, которое открывает CONNECT-туннель к прокси и передаёт Basic-авторизацию | Логин и пароль в Windows DPAPI; Digest, NTLM и Negotiate не поддерживаются; реле переносит только TCP |
| VLESS | Локальный pinned Xray, TCP/RAW, WS, gRPC, XHTTP; TLS/REALITY | URL/UUID в DPAPI; параметры строятся по allowlist, произвольный Xray JSON и insecure TLS не принимаются |
| OpenVPN | Userspace go-openvpn + gVisor → loopback SOCKS | Inline CA/cert/key, TCP/UDP transport, AEAD; нет системного TUN/TAP или изменения маршрутов/DNS ОС |

Профили имеют поиск, фильтр и редактирование; SOCKS URL, host:port, legacy host:port:user:pass, VLESS URL с Markdown escaping и self-contained .ovpn разбираются отдельно. Максимум 100 metadata профилей, 256 доменов на список, 256KiB OpenVPN profile, 512KiB native frame. Kill Switch включён и не допускает DIRECT fallback для проксируемой цели. Секреты очищаются в UI после успешного сохранения, Cancel, unmount, ухода, скрытия и BFCache; отказ в доступе/ошибка оставляет точный RAM draft для повторной попытки. Отложенный permission grant не запускает скрытый Save/Connect. UI — 21 локаль, цветные protocol cards, RTL/dark/narrow.

Первый optional nativeMessaging grant в уже работающем Chrome153 не создаёт отсутствующий runtime.connectNative. Вместо ошибочного permission-required показывается явное восстановление: однократный restart расширения при выключенном Proxy с повторным открытием собственной вкладки. Несохранённые поля при этом нужно ввести заново; secrets/draft не переносятся через storage. Строгий marker содержит только version/время, потребляется до открытия, действует60s и не управляет URL. Активный маршрут не перезапускается. Firefox138 сохраняет сразу после grant. Это проверено реальными optional Allow/Cancel и DPAPI readback; required-native fixture не заменяет эту проверку. [ADR-070, E22-27](../decisions/ADR-070.md).

Metadata download содержит настройки без native credentials. Дополнительный менеджер [ADR-071](../decisions/ADR-071.md) предоставляет явный Copy JSON одного профиля или коллекции со всеми connection данными: login/password, VLESS URI, OpenVPN config/certificates/keys и routing/privacy/autoconnect settings. Такой bundle выдаётся только в ответ собственного Options и записывается в clipboard по нажатию; не попадает в storage, broadcast, snapshot или отчёт сайта. Запрашивается optional clipboardWrite, без clipboardRead. AutoConnect задаётся явно; OFF сохраняет профили. При оставшемся enabled и autoConnect=false после запуска native-профиль остаётся blocked до Connect/Disconnect. Старые соединения, уже открытые до настройки proxy, не пересоздаются расширением.

Менеджер показывает цветной protocol badge, адрес, активность, результат последней ручной проверки, IP/HTTP/время при наличии, поиск/фильтрацию/сортировку и row actions. Непроверенный профиль остаётся непроверенным. Проверка одного/видимого списка не меняет browser routing или selectedId: temporary helper закрывается после запроса, действующий тот же профиль использует свой tunnel. Для другого OpenVPN при активном OpenVPN возвращается active-vpn, чтобы не разорвать серверную сессию с тем же сертификатом. Batch последователен, Cancel/уход останавливает следующие проверки; начавшаяся bounded native операция завершается физически перед снятием lock. Explicit Edit загружает полную конфигурацию только по нажатию и очищает её при уходе.

«Проверить соединение» выполняется только явно: редактируемый HTTP(S) адрес, результат DNS/TLS/HTTP, валидный выходной IP при наличии и время запроса. Результат не выводится из успешного запуска listener: проверка проходит через выбранный действующий профиль. HTTP 403/503 означает полученный ответ сайта, а не ошибку proxy-аутентификации. URL и результат не входят в storage/export и очищаются при уходе из раздела; cookies/Authorization браузера не передаются, redirects не выполняются. Даже прямой SOCKS5 использует native companion для этой ручной диагностики; само подключение без пароля остаётся доступным без companion. Проверка HTTP/HTTPS без логина идёт через типизированный запрос `diagnose` с `endpoint: { type, host, port }`: companion сам открывает соединение с прокси, ничего не сохраняя, а действующий маршрут не затрагивается; старый companion отвечает `invalid-input` на неизвестное поле `type`, и профиль показывается как «обновите companion».

## Массовый импорт и список (ADR-107)

- **Импорт списка.** До 1 МиБ текста, 1000 непустых строк, строка до 16 384 символов (SOCKS — до 4096), имя до 96 символов. Форматы: `host:port`,
  `host:port:user:pass`, `user:pass:host:port` (порядок выбирается явно), `user:pass@host:port`, `socks5://`, `socks5h://`, `[IPv6]:port`, `vless://` (фрагмент URL —
  имя по умолчанию). Имя — текст после пробела и «#»; строка, начинающаяся с «#», — комментарий; CRLF/CR/LF и BOM допустимы; «#», «@», «/», «?» внутри пароля
  сохраняются (логин заканчивается последним «@»).
- **Предпросмотр.** Причины по строкам (11 кодов: `invalid-line`, `unsupported-scheme`, `invalid-host`, `invalid-port`, `invalid-credentials`, `invalid-vless`,
  `invalid-name`, `wrong-order`, `openvpn-config`, `duplicate`, `too-many-lines`), без отклонённого текста; дубликат — тот же тип, хост, порт, логин и пароль;
  совпадение адреса с сохранённым профилем — только предупреждение. Свободных мест 100 минус сохранённые.
- **Сохранение.** Необязательное разрешение компаньона запрашивается один раз внутри нажатия и только если есть логин или VLESS; строки сохраняются по одной
  через прежний путь DPAPI; первая ошибка останавливает запуск. Затем — «Проверить импортированные» (ручная проверка) и «Удалить не прошедшие» (только импортированные,
  последняя проверка которых не прошла; активный профиль не удаляется).
- **Секреты.** Вставленный текст и разобранные строки живут только в памяти Options и стираются при отмене, Escape, закрытии, скрытии, `pagehide`, смене раздела
  и размонтировании. В предпросмотре виден логин, пароль — никогда.
- **Список.** Фильтр «прошли / не прошли / не проверены» по результатам ручных проверок; значок результата со своим символом; значки DNS и TLS только при
  `remoteDns`/`tlsVerified`; поиск и по `host:port`; одинаковые имена показывают адрес.
- **Случайная сессия.** Формат по умолчанию `-session-{session}`; токен — 10 символов a–z0–9 из `getRandomValues`; меняется только совпадающий хвост логина или
  пароля; живёт в редакторе.
- **Честные строки.** Прямые домены видят настоящий IP и обычный DNS; защита WebRTC оставляет звонки только через TURN по TCP; TCP/IP-отпечаток (p0f) — у сервера
  прокси (SOCKS5, VLESS), а для OpenVPN — у собственного userspace-стека компаньона, не у компьютера пользователя.

## HTTP/HTTPS, SOCKS5, метка страны и история проверок (ADR-108)

- **Профили HTTP и HTTPS.** Без логина браузер подключается к прокси сам; с логином — через loopback SOCKS5-реле companion, которое открывает HTTP/1.1 `CONNECT` к прокси (для HTTPS — TLS 1.2+ с проверкой сертификата по системному хранилищу, без параметра отключения проверки, SNI только для имён) и передаёт `Proxy-Authorization: Basic`. Имя назначения передаётся прокси и не разрешается локально. Ответ прокси читается с ограничением 8 КиБ и 10 с, без перенаправлений; байты, пришедшие сразу после заголовков, передаются в туннель. Обычные http-сайты тоже идут туннелем `CONNECT`: некоторые HTTP-прокси запрещают его на порт 80, это читается как `proxy-denied`.
- **Честные границы.** HTTP-прокси видит имя назначения каждого туннеля; участок «браузер/companion → HTTP-прокси» не шифруется, и Basic-логин проходит его открытым текстом; HTTPS-прокси шифрует этот участок. Подключение к HTTP/HTTPS-прокси с логином проверяет только ответ сервера (TCP, для HTTPS ещё сертификат): логин проверяется первым `CONNECT` или кнопкой проверки, и интерфейс говорит об этом. Digest, NTLM, Negotiate, HTTP/2 `CONNECT` и SOCKS4 не поддерживаются; `BIND` и `UDP ASSOCIATE` отклоняются кодом 7.
- **SOCKS5 по RFC 1928/1929.** Greeting без методов получает `05 FF`; команда кроме `CONNECT` — код 7, ненулевой RSV — код 1, неизвестный ATYP или пустое имя — код 8; ошибки реле отображаются в коды 2–6. Исходящий greeting предлагает `[00]` без логина и `[00, 02]` с логином и следует методу, который выбрал сервер: метод 00 не получает логина, метод 02 проходит RFC 1929 (проверяется только байт статуса, как у curl), метод FF означает `auth-failed` при предложенном логине и `auth-required` без него. Ответы upstream передаются браузеру без изменений.
- **Фиксированные коды.** Добавлены `proxy-denied`, `network-unreachable`, `host-unreachable` (ответ SOCKS5 0x04 больше не читается как `dns-failed`). Ответ 407 без логина и сервер, выбравший метод 02 при предложенном «без логина», дают `auth-required`. Проверка сохранённого профиля различает 407, 403 и 502; проверка действующего маршрута через реле показывает 407 и 403 одинаково как `proxy-denied`.
- **Сроки.** Установка соединения реле ограничена 25 с от приёма до ответа на `CONNECT` (установленный туннель не ограничивается); проверка соединения идёт одним общим бюджетом 12 с.
- **Метка страны.** Необязательное поле профиля — двухбуквенный код ISO 3166-1 из офлайн-таблицы регионов. Это собственная заметка пользователя: страна не определяется, не ищется по IP, не передаётся companion и не попадает в запись хранилища; Antidetect читает её только из снимка настроек (подсказка о регионе). `PROXY_VERSION` остаётся 1, поле необязательное; прежние сборки отклоняют конфигурацию с `country` и HTTP/HTTPS-профилями (строгие наборы ключей), поэтому понижение версии не поддерживается.
- **История проверок.** `storage.local['proxy-check-history:v1']` = `{ version: 1, enabled, items }`; пишется только страницей Options после завершённой ручной проверки. Подряд идущие успешные проверки с одним внешним IP схлопываются в одну запись («стоянку»: `firstAt`, `lastAt`, `checks`); проваленная проверка или другой IP начинают новую. Запись содержит результат, код, время ответа, признаки DNS/TLS, HTTP-статус и внешний IP прокси, каким его увидела проверяемая страница. Пределы: 30 записей на профиль, 100 профилей, срок 30 дней, строгая проверка формы при чтении. Не хранятся проверяемый адрес, хост, порт и логин прокси и ответы; в экспорты, отчёты и логи история не входит. Переключатель «Сохранять историю проверок» включён по умолчанию; при выключении запись прекращается, а существующие записи остаются до очистки. Очистка одного профиля и всех идёт с подтверждением; история профиля удаляется при его удалении и при смене подключения.
- **Совместимость.** Новый companion принимает прежнего клиента (лишние ключи возможностей `http` и `https` игнорируются). Старый companion не знает типов `http` и `https`, и расширение показывает «обновите companion» до отправки чего-либо. Хранилище профилей с HTTP/HTTPS нельзя открыть старым companion.
- **Интерфейс менеджера (ADR-108, раздел 7).** Карточка маршрута, ARIA-сетка с клавиатурной моделью, фильтры-чипы со счётчиками, панель деталей с историей и графиком задержки, лист «Добавить/Изменить», двухшаговый импорт, пакетная проверка «выбранные/все» (по одному, с отменой), карточки на телефоне, RTL, 7 тем; вид списка (плотность, столбцы, сортировка) хранится только как `proxy-view:v1` в `localStorage` страницы Options. Подсказка «регион совпадает/отличается» в списке не строится: вердикт выдавать нечем, подсказка о регионе живёт в редакторе Antidetect.
- **Проверено.** Go: `go vet`, `gofmt`, `go test -race`; намеренные поломки Go-кода убиты своими тестами. JS: настоящий exe через родные кадры (кадры из Node, не из браузера); реальные Chromium и Firefox: маршрутизация через локальный HTTP-прокси, удалённое разрешение имён, отсутствие прямого соединения после остановки прокси, HTTPS-схема прокси с самоподписанным сертификатом. Не проверено: браузерный прогон с companion по native messaging для HTTP/HTTPS, Digest/NTLM, провайдеры с нестандартным поведением; переводы 30 новых строк на 19 языков носителями не проверены.

## DNS и отказ

Chrome генерирует обязательный PAC с SOСKS5 endpoint, без dnsResolve/isResolvable и без DIRECT после SOCKS5. Firefox возвращает [ProxyInfo, null], proxyDNS=true; listener регистрируется до асинхронного чтения настроек и ожидает startup barrier. Поэтому остановка локального listener не становится прямым запросом к сайту. При отключении снимается только собственный слой. Переход к чужому расширению/enterprise owner показывается как conflict; их настройки не перезаписываются. Firefox read-only settings.get распознаёт статические owners, но конкурирующие onRequest listeners не имеют общего полного ownership API.

SOCKS сохраняет destination domain в ATYP=3; локальный relay не резолвит его. Xray отправляет domain через VLESS с AsIs. Userspace OpenVPN использует DNS внутри туннеля: полученные от сервера адреса и туннельный resolver, UDP/TCP DNS без fallback к системному resolver. Синтаксическая ошибка, неподдерживаемая directive, auth, DNS, endpoint, TLS/REALITY, engine и timeout отображаются фиксированными кодами/фазами, без сырых логов и server error text. Ready listener означает применённый маршрут; доступность каждого сайта не выводится из одного состояния процесса.

DNS для явно direct-доменов/локальных исключений остаётся обычным. Имя самого proxy endpoint при необходимости bootstrap разрешается браузером/ОС; буквальный IP этого не требует. Browser proxy не объявляется перехватом всего системного UDP/QUIC. WebRTC получает native disable_non_proxied_udp только при включённой опции и privacy grant; один физический controller агрегирует её с Antidetect, включая startup. Prediction выключается своим слоем и восстанавливается с readback, error handling и deferred restore под чужим owner.

## Компаньон

Отдельный `Detect.Expert-Proxy-Companion-windows-x64.zip`: host/engines, installer/uninstaller, checksums, лицензии и соответствующие исходники. Регистрация HKCU для конкретных extension IDs, без admin/services/autostart. Profile vault caller-scoped и DPAPI user-bound; второй процесс того же caller не может параллельно перезаписать файл. Engine config идёт через stdin; plaintext config file не создаётся. Windows Job Object завершает child при аварии host; явный Disconnect закрывает loopback endpoint. В рабочем расширении нет загрузки обновлений engines или subscriptions.

**Где скачать (интерфейс, ADR-070, 2026-11-07).** Помощник (companion) не входит в пакет магазина: владелец публикует архив `Detect.Expert-Proxy-Companion-windows-x64.zip` в Releases публичного репозитория `github.com/vektort13/Detect.Expert`, а вкладка Proxy ведёт на страницу последнего выпуска. Расширение само не обращается к GitHub, не скачивает, не устанавливает и не запускает архив: пользователь нажимает обычную ссылку «Скачать с GitHub» (`<a target="_blank" rel="noopener noreferrer">`, текст ссылки — не адрес), страница открывается в новой вкладке без opener и referrer, дальше распаковка и установщик — действия пользователя.

Предупреждающая карточка в стеке сообщений под карточкой маршрута говорит прямо: помощник нужен для VLESS, OpenVPN и SOCKS5/HTTP/HTTPS-прокси с логином; прокси без логина работают без него. Карточка показывается, только когда состояние уже загружено и помощник не известен как доступный (это то же состояние, что `proxy_workspace_companion_missing`; расширение помощника само не опрашивает, поэтому «не известен» включает «ещё не проверяли», а разрешение `nativeMessaging` остаётся необязательным и не запрашивается). Пока состояние загружается, карточки нет; она остаётся, пока идёт проверка, и исчезает, когда проверка или подключение нашли помощника. Её нельзя закрыть навсегда, она ничего не хранит (ни `storage`, ни `localStorage`, ни таймеров) и ничего не запрашивает. Над карточкой — прежние сообщения об ошибках, под ней — прежняя строка состояния помощника с «Шаги установки» и «Проверить компаньон». Та же ссылка повторена в разделе «Компаньон» рядом с шагами установки; строка шага теперь говорит, что архив берётся на GitHub (Releases).

Адрес — одна константа `PROXY_COMPANION_DOWNLOAD_URL` в `apps/production-extension/proxy-shared.js` (единственный литерал в исходниках Proxy и в текстах; в `lint-inventory.json` записан как reviewed static URL), форма закреплена юнит-тестом: `https`, хост `github.com`, путь `/vektort13/Detect.Expert/releases/latest`, без порта, логина, запроса и фрагмента. Строки — `proxy_workspace_companion_notice_title`, `_notice`, `_download`, `_new_tab` и изменённая `_install` на всех 21 языках интерфейса (non-ru/en — машинный перевод без носителя). Это изменение только интерфейса: новых разрешений, CSP, сетевых запросов расширения, каналов и зависимостей нет.

Текущая собранная native поставка — Windows x64. Direct SOCKS5 использует оба браузера на desktop ОС; готовый keychain/native installer для macOS/Linux не заявляется. OpenVPN TAP/compression/CBC, внешние config/includes/scripts/plugins, неподдерживаемые certificate-pin/cipher directives и новые VLESS encryption/transport options отвергаются явно. CA-scoped IP OpenVPN profiles сохраняют CA chain и ServerAuth EKU; если задано verify-x509-name, имя также проверяется. DTLS/браузерные HTTPS сертификаты Antidetect эта задача не меняет.

Фактические native, DNS, crash и provider результаты, версия engines, checksum поставки и нерешённые границы фиксируются в отчёте E22-25.

## Геолокация внешнего IP (необязательно)

Необязательный блок Proxy Manager Geolocation API (ADR-109) показывает в списке прокси страну, город, сеть, тип и признаки провайдера для внешнего IP *ручной* проверки. Он выключен по умолчанию, ничего не меняет в маршруте, DNS и Kill Switch и не определяет страну для метки профиля. Интерфейсы, привязка полей четырёх провайдеров, статус проверки (что подтверждено живьём, а что кандидат) — [proxy-geolocation.md](proxy-geolocation.md).
