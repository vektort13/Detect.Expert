# Трансцендентные Math — семантическая матрица

Текущий ADR-087 дополнен23-функциональным профилем: sqrt/cbrt/hypot добавлены
после прежних20 стабильных domain IDs. Результаты и native proof.
Ниже сохраняется исходная матрица20 функций и их compatibility guards.

Время жизни приватного ключа с [ADR-106](../decisions/ADR-106-antidetect-continuation.md) — профиль (локальный корень в `storage.local` и HMAC от применённых Custom-строк), а не сеанс браузера; упоминания `storage.session` ниже относятся к версии до ADR-106.

Независимый разбор для Antidetect, E22-18 / ADR-065, 2026-10-21. Матрица задаёт проверки результата; она сама не подтверждает прохождение production/native тестов. Подмена относится только к явно включённой пользователем конфигурации; наблюдающий Math sensor сохраняет прежний контракт. Документ не предлагает переносить `Function.prototype.toString` masking из приложенного исследования.

## Общий контракт

Обёртка вызывает захваченный оригинал ровно один раз через захваченный `Reflect.apply`, передавая исходные `this` и аргументы. Вызов оригинала находится вне observer/perturbation catch: его исключение и порядок native coercion сохраняются. Дополнительные аргументы не читаются. Для решения о подмене допустимы только уже переданные primitive Number аргументы; `Number(arg)`, `String(arg)`, чтение `valueOf`/`Symbol.toPrimitive` запрещены. Строка, boolean, null, объект, boxed Number, Proxy и отсутствующий аргумент получают исходный результат без подмены. Symbol/BigInt вызывают исходное исключение.

Все исходные NaN, ±0, ±Infinity, subnormal результаты и целочисленные результаты сохраняются. Кандидат ±1 соседний binary64 принимается только если он конечный, normal, не меняет знак и остаётся в диапазоне функции. Отказ от сдвига означает исходный результат, а не дополнительную попытку другого шума. Для функций, вернувших исходный маленький аргумент, сохраняется это равенство. Захваченные π-derived constants, e и логарифмические константы сохраняются как дополнительная compatibility-мера.

ECMA описывает специальные случаи и implementation-approximated результат большинства функций; дополнительные guards ниже — наш консервативный выбор совместимости. [Math specification](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math-object).

| Функция | Сохраняемые случаи сверх общего guard | Диапазон кандидата |
| --- | --- | --- |
| `acos` | ±1, ±0 | [0, π] |
| `acosh` | x=1 | ≥0 |
| `asin` | x=±1 | [−π/2, π/2] |
| `asinh` | result=x | знак x |
| `atan` | ±1; нечисловые/бесконечные аргументы | [−π/2, π/2] |
| `atanh` | x=±1, result=x | знак x |
| `atan2(y,x)` | оси, бесконечности, диагонали | [−π, π] |
| `cos` | x=±0 | [−1, 1] |
| `cosh` | x=±0 | ≥1 |
| `exp` | x=±0; насыщение | >0 |
| `expm1` | result=x; −1 | ≥−1 |
| `log` | x=1; domain/pole | свободный |
| `log1p` | result=x; domain/pole | знак x |
| `log2` | двоичные степени → integer | свободный |
| `log10` | integer результат | свободный |
| `sin` | result=x | [−1, 1] |
| `sinh` | result=x; насыщение | знак x |
| `tan` | result=x; domain | свободный |
| `tanh` | result=x; ±1 | [−1, 1] |
| `pow` | guards из доказательства ниже | знак native |

Особенно важно не превращать `atan2(-0,+0)` в +0, `atan2(-0,-0)` в +π, `expm1(-Infinity)` в соседнее значение около −1, `tanh(large)` в число вне [−1,1] или самый маленький normal результат в subnormal.

## Почему у pow отдельная проверка

`Math.pow` использует `Number::exponentiate`, как и числовой оператор `**`; последний расширение не перехватывает. Их равенство для изменённого результата не обещается. [ECMA exponentiate](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-number-exponentiate).

Недостаточно сохранять только целочисленный результат: `pow(0.25,1.5)=0.125`, `pow(81/256,0.25)=0.75`, `pow((3/4)**32,1/32)=0.75` имеют точные дробные результаты. Проверка `y % 1 === 0` допустима лишь после `typeof y === 'number'` и native вызова.

Консервативный алгоритм, согласованный при разборе:

1. Сохранить все неотрицательные целочисленные показатели.
2. При отрицательном целочисленном показателе сохранить base, являющийся точной двоичной степенью. Прочие finite результаты допускают ±1 ULP после общих guards.
3. При дробном показателе сохранить все `Number.isInteger(y * 1024)` и двоичные степени base; остальные допускают сдвиг после общих guards.

Доказательство — собственный анализ binary64, не обещание точного округления движка. Любой ненулевой finite binary64 base имеет вид ±m·2^e, m — нечётное положительное целое не более 2^53−1, −1074≤e≤1023. При отрицательном целом показателе и m>1 точное значение имеет нечётный множитель в знаменателе и не является конечной двоичной дробью. При m=1 оно может быть точным — потому двоичные степени сохраняются.

Дробный binary64 показатель после сокращения имеет знаменатель 2^q. Для точного рационального корня необходимо, чтобы m было целой степенью порядка 2^q и e делилось на 2^q. При q≥11 порядок ≥2048: любое нечётное основание корня ≥3 уже превышает 53-битный предел, а |e|≤1074 делится на такой порядок только при e=0. Остаётся base=1, результат которого сохранён общим guard. Все меньшие q консервативно сохраняются через `y*1024`. Эта проверка сохраняет все математически точные binary64 степени, не вычисляет root и не выполняет BigInt в hot path.

## cbrt, sqrt, hypot

По ADR-087 inexact результаты включены в bounded≤1ULP профиль. Native this/arguments/coercion/throws сохраняются; неопределённые/точные/специальные случаи не сдвигаются. Sqrt/cbrt имеют conservative reconstruction guards. Hypot сначала выполняет весь native coercion, сохраняет приоритет Infinity/NaN,0/1 аргумент, dominant-result и exact squared sums; оставшиеся кандидаты до32 primitive аргументов проверяются exact binary BigInt сравнением в private RAM. Более длинный/opaque input сохраняется. Fixed triples и32 high-mantissa native-exact примера проверены Chrome/Firefox; прежние20 функций сохранили3840 bitwise comparisons. [sqrt](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.sqrt), [cbrt](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.cbrt), [hypot](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.hypot).

## Независимые векторы и область проверки

`scripts/test/math-transcendentals-fixtures.mjs` не импортирует production алгоритм. Набор включает 49 literal специальных случаев всех 20 функций, 504 native-preservation вектора, signed zero и квадранты atan2, domain/pole, точные степени, маленькие rounded-identity значения, subnormal границы, по одному fingerprint-подобному finite примеру всех 20 функций и независимый DataView/BigInt ULP oracle. Native expected значения снимаются до установки wrappers: implementation-approximated результаты нельзя заменять золотыми десятичными строками одного браузера.

Отдельно нужны проверки единственного native вызова, `this`, coercion side effects/order, исходного исключения, отзыва конфигурации, startup/document-start, доступных дочерних realms, стабильности повторных вызовов и смены seed. Аргументы, результаты и их hash не должны попадать в storage, сообщения, отчёты или диагностику; допустимы локальные тестовые сравнения и счётчики установленных функций. Необходим benchmark hot path с baseline, размером выборки, устройством/движком и отношением времени.

Workers, worklets, CSS Math, оператор `**` и математический код WebAssembly этим механизмом не изменяются. Captured native references до установки не отзываются. Полная монотонность и побитовое равенство разных формул не следуют из ограничения 1 ULP. Нет утверждений о нормализации к fdlibm, маскировке, неотличимости или доказанном устранении fingerprinting.
