# Уведомления Firewall

Текущее поведение с 2026-10-20 определено [ADR-058](../decisions/ADR-058.md) и [матрицей popup внутри страницы](protect-overlay.md): автоматические уведомления больше не создают отдельные окна Chrome. Собственный заголовок и закрытие находятся в закрытом дереве UI страницы. Описание ниже относится к заменённой реализации ADR-052/054.

## Историческая реализация отдельных окон

Реализация: [ADR-052](../decisions/ADR-052.md), `apps/production-protect/src/findings*.ts` и `src/ui/findings-*.ts*`. Фактические проверки: внутренний отчёт.

Подробная карточка по макету владельца и её финальные проверки: отчёт.

Из основного popup удалены постоянные разделы передачи введённых данных и записи сессии. Автоматическое окно появляется только для актуального документа с включённым модулем и соответствующей функцией, при `value-match` с непустым списком кодировок или оценённом положительном replay (`replay-like` / `replay-recording`). Исход запроса остаётся отдельным фактом: совпадение может иметь состояние sent/stopped/unknown. Обычный ввод, парольный обработчик, opaque-after-input и replay none/signals-only окно не открывают.

Chrome показывает отдельное окно расширения справа внизу доступной области экрана, с отступом 16 px при достаточном размере экрана. Ширина до 420 px, высота адаптивная до 760 px; маленькая рабочая область уменьшает размеры и отступы. Окно не перехватывает фокус при автоматическом создании. Раскрытие деталей меняет размер с сохранением выбранного пользователем фокуса. Закрытие, Escape и изменение актуальности страницы учитываются независимо в SW и UI.

Карточка передачи показывает событие, метки типа поля/кодировки и пять строк фактов сразу, без раскрытия общего раздела «Подробнее». Доказательство раскрывается отдельно. Существующий pending prompt сохраняет выбор области, Block/Allow, действительный результат применения правил и Undo. Без prompt используется отдельный read-only компонент `TransferFindingCard`: он не создаёт promptId и не отправляет решений. После решения факты остаются доступны рядом с результатом. Сведения другой записи/endpoint не теряются при устранении дублирования основной карточки. Оформление — glass-поверхности расширения, светлая и тёмная темы, forced colors. Детали компании, скрипта и времени выводятся только в доступной точности projection.

Доставка ограничена одной открытой карточкой-окном, группировкой 300 мс и интервалом 10 секунд. Фоновая вкладка ждёт активации в выбранном окне браузера. Одинаковая находка по её техническим признакам не открывается повторно из-за увеличения счётчика, нового evidenceId или обновления доставки. Смена документа и выключение/исключение сайта закрывают старое окно. При перезапуске SW уже известные находки не создают исторические предупреждения, а открытое собственное окно принимается под управление заново.

Лимиты памяти: 64 вкладки, 128 ключей на документ, 1024 суммарно. При исчерпании лимита автоматические показы этого документа подавляются до навигации/вытеснения; обычный отчёт остаётся доступен. Нового постоянного хранилища и изменений wire-контрактов нет.

Владение окном определяется по собственному URL или доверенному runtime TAB-контексту, а не по одному номеру окна. Начальная загрузка лишь резервирует слот по созданному native tabId и не разрешает закрытие неизвестного документа. Permissions не расширялись: `tabs`, `notifications` и `system.display` не добавлялись. Firefox сохраняет прежние инертные stubs модуля.

Новые заголовки и действия локализованы на 21 язык, включая ar/ur RTL. Подробные унаследованные сведения остаются RU/EN. Положительные replay-состояния проверены UI fixtures; нативное достижение положительного replay в текущем production-наборе с отключёнными listen-hooks и пустыми таблицами не подтверждено.

Команды: `pnpm test:protect:findings`, `pnpm test:protect:ui`, `pnpm test:production`. Нативная проверка окна и production privacy gate включены в `pnpm release:verify`. Прежняя команда `node scripts/test/protect-firewall-popup-native.mjs` перенаправлена на актуальную проверку отдельного окна.

Отдельно от находок, по [ADR-054](../decisions/ADR-054.md), успешное явное включение показывает временное подтверждение `activation-toast.html` справа внизу экрана. Оно не является находкой, не переводит фокус и закрывается через 5 секунд. Загрузка UI, восстановление ON при старте, no-op и отказ окна не создают; OFF/изменение прав/политики отменяют ожидающее подтверждение. Постоянный нейтральный OFF-комментарий удалён из production launcher и Options, ошибки и незавершённое снятие правил остаются видимы. Проверка — `pnpm test:protect:activation`, также включена в `test:protect:ui` и release gate.
