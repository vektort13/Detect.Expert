# P08 — ручной smoke брендированного Chrome

Основание: ADR-002, REQ-006/007/013/015, ТЗ V §7–8 и VI I5. Статус: **не выполнено**. Автоматический Chromium harness проверяет другую среду; пустые `channels` в `browser-support.json` не означают поддержку Stable/Beta/Extended Stable.

С Chrome 137 официальный Chrome не принимает `--load-extension`. Поддерживаемый ручной путь — `chrome://extensions` → Developer mode → Load unpacked. Источник: [объявление команды Chromium Extensions](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/1-g8EFx2BBY). Не переносить результат headless Chromium в `verifiedBuilds` как результат брендированного Chrome.

## Подготовка

- [ ] Записать дату, ОС, масштаб ОС, канал и полную версию из `chrome://version`, ревизию репозитория и SHA-256 проверяемого пакета.
- [ ] Выполнить из корня `pnpm build` (в PowerShell при заблокированном ps1 — `pnpm.cmd build`). Не использовать `dist/test`: тестовый профиль имеет статический grant.
- [ ] Открыть отдельный тестовый профиль Chrome. На `chrome://extensions` включить режим разработчика, выбрать «Загрузить распакованное расширение» / Load unpacked и каталог `dist/local`.
- [ ] Убедиться, что ошибок manifest/CSP/SW нет. Закрепить кнопку расширения на панели инструментов.

## Popup и область наблюдения

- [ ] Открыть реальную кнопку popup: до выбора области показывается выключенное наблюдение; нет обещаний безопасности сайта.
- [ ] На HTTP(S)-странице включить наблюдение с этого момента; виден late-start и предложение перезагрузки. После перезагрузки состояние соответствует фактически доступной области.
- [ ] Проверить страницу без находок: виден текст о периоде/доступной области и coverage рядом. Нет зелёного сигнала доверия.
- [ ] Проверить паузу/возобновление и выключение области, переход на другую страницу и отзыв разрешения. Объяснения и host соответствуют текущему документу.
- [ ] Открыть popup на `chrome://settings`: наблюдение недоступно, не показывается безопасность страницы.
- [ ] Проверить светлую/тёмную тему, текст не меньше 12 CSS px, отсутствие горизонтального скролла. Сохранить PNG и отметить фактический размер popup. Автоматические 44 фикстурных PNG не доказывают достижимость всех состояний в этой сборке Chrome.

## Боковая панель и клавиатура

- [ ] Открыть настоящую боковую панель кнопкой popup; сменить активную вкладку и проверить обновление контекста.
- [ ] Проверить масштаб 100 % / 200 %, минимальную доступную ширину native panel, все четыре раздела, длинные строки, раскрытые карточки и диалог экспорта. Записать фактическую CSS-ширину. Если Chrome ограничивает ширину/масштаб, записать ограничение; CSS-эмуляция 160/180/200 px не считается native-проверкой.
- [ ] Включить системную контрастную тему / forced colors: рамки поля поиска, карточек, кнопок и клавиатурный фокус различимы. Проверить системное уменьшение движения.
- [ ] Пройти Tab / Shift+Tab, стрелки / Home / End в разделах. У каждой кнопки, поля и элемента раскрытия есть понятное имя; фокус не теряется.
- [ ] Открыть preview экспорта клавишей Enter. Проверить удержание фокуса в диалоге и возврат на кнопку экспорта после «Отмена» и Escape. Сохранение — только после отдельной кнопки; содержимое совпадает с preview.

## Screen reader

- [ ] Записать название/версию screen reader (например, установленного NVDA), браузера и язык RU/EN. Повторить для обеих локалей.
- [ ] В разделе «Техники» выполнить поиск с результатом и без результата. Ввод остаётся в поле; результат объявляется вежливо, изменения объединяются не чаще раза в 2 с, последний результат не теряется.
- [ ] Очистить поиск и сменить раздел до отложенного объявления: устаревший результат не произносится. Обновления отчёта не создают поток объявлений каждого вызова API.
- [ ] Проверить чтение host, coverage, ограничений, доступных имён и диалога. DOM/ARIA-автотест не доказывает фактическое произношение assistive technology.

## Фиксация результата

Для каждого канала отдельно записать passed/failed/непроверено, наблюдаемые дефекты, PNG/видео, версии и проверяющего. Обновлять `browser-support.json` только фактическими результатами с указанием области проверки. Не отмечать этот чек-лист выполненным на основании автоматических тестов P08. Замер DOMContentLoaded → полезный DOM + возможность paint не включает открытие нативного окна и не доказывает задержку compositor presentation.
