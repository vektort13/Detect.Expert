## Что запрашивать у пользователя

В срезе 1 запросить вручную версию расширения, версию Chrome и описание шагов без адресов и личных данных; по возможности — воспроизведение на синтетической странице. Кнопки «Диагностика» в options нет (F064, E14-01 #8). Обычный экспорт отчёта содержит host и не имеет опции его исключения (E14-01 #3), поэтому не заменяет диагностический отчёт. **Не запрашивать**: посещённые URL, экспорт отчёта с hosts чувствительных сайтов, скриншоты с личными данными, cookie/токены. После реализации E14-01 #8 и privacy-проверки можно обновить процедуру для отдельного preview без hosts/paths.

## Классификация обращений

| Тип | Действие |
| --- | --- |
| «Сайт показал X, это опасно?» | Ответ по шаблону: расширение не оценивает безопасность сайта; объяснить уровни наблюдение/интерпретация/вендор; ссылка на «Ограничения» |
| «Ничего не найдено — значит сайт чистый?» | Нет: «за этот период в доступной области находок нет» + перечень пробелов coverage (workers, WASM, CSS, DNS, серверные проверки) |
| «Расширение сломало сайт» | S1/S2 по `runbooks/incident.md`; запросить версии и шаги по процедуре выше, синтетическое воспроизведение; проверить differential suite на похожем сценарии |
| «Ложное распознавание вендора» | Зафиксировать `ruleId`/`ruleVersion`; правило → review; negative fixture; не создавать исключение для домена автоматически |
| «Где мои отчёты после перезапуска?» | По дизайну: отчёты живут в сессии (ADR-007); сохранённый экспорт — у пользователя |
| «Сайт видит расширение» | Известное ограничение (REQ-015); маскировка не планируется |
| «Нужна поддержка incognito / workers / файлов» | Не поддерживается в v1 (ADR-005, coverage matrix); зарегистрировать как запрос |
| Запрос на данные / удаление (GDPR) | Local: данных у разработчика нет; Managed connected: процедура tenant (ADR-014) |

## Реестр известных ограничений

Ведётся в `docs/coverage/matrix.md` §4 и на вкладке «Ограничения» UI. Ответ поддержки ссылается на них, а не формулирует новые обещания.

## Эскалация

S1 → owner + security немедленно; S2 → owner в рабочий день; S3 → backlog с меткой `support`.

## Шаблон ответа (RU)

```
Здравствуйте. detect.expert показывает, какие обращения к браузерным API и какие сетевые запросы наблюдались на странице, и с какими известными сервисами они могут быть связаны. Это не оценка безопасности сайта и не доказательство слежки: карточка «Использован API» означает только факт вызова, «Есть признаки вычисления отпечатка» — гипотезу с указанной уверенностью, «Распознанные сервисы» — совпадение с каталогом. Отсутствие находок означает, что в доступной области за период ничего не наблюдалось; workers, WebAssembly, CSS и серверные проверки расширению не видны.
Если вы считаете, что отображение ошибочно, пришлите, пожалуйста, версию расширения, версию Chrome и описание шагов без адресов сайтов и личных данных. По возможности опишите воспроизведение на синтетической странице. Диагностический экспорт в этой версии ещё не реализован; обычный экспорт отчёта содержит адрес хоста, присылать его не требуется.
```
