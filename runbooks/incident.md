# Runbook: инцидент

Владелец: Vektor T13, контакт — репозиторий · Последняя репетиция: не проводилась · Основание: ТЗ V §10, §2; ADR-016.

## Severity-матрица (черновик)

| Sev | Признак | Целевая реакция |
| --- | --- | --- |
| S1 | Утечка данных (чувствительное значение в storage/экспорте/логах), незаявленный исходящий трафик, компрометация publisher/signing key, ломающая страницы регрессия hook на массовых сайтах | Немедленно: остановить распространение, начать rollback |
| S2 | Ложный vendor match с публичным эффектом, систематический ложный `possible-fingerprinting` на обычных приложениях, потеря отчётов/дедупликации | В течение рабочего дня: hotfix или отключение правила/сенсора |
| S3 | Ошибочный текст UI, отдельные состояния coverage не отображаются, деградация производительности на узком классе страниц | Следующий плановый релиз |

## Процедура (ТЗ V §10)

1. **Оценить тяжесть** по матрице; зафиксировать: версия расширения, `catalogVersion`, `schemaVersion`, Chrome build, воспроизведение (synthetic fixture, без URL пользователей), дата.
2. **Остановить дальнейшее распространение**, если доступно: снять с публикации/приостановить раскатку в CWS; для пилотной группы — уведомить администраторов.
3. **Сообщить** поддержке и администраторам managed-организаций (шаблон ниже). Без подключённого канала (Local) удалённое мгновенное выключение невозможно — не обещать.
4. **Отключить проблемный сенсор/правило** существующей политикой (`DisabledSensorIds`, `expiryAction: disable`) там, где канал уже есть (Managed). Отключение не является исполняемым remote hotfix.
5. **CWS rollback** (`runbooks/rollback.md`) либо hotfix-релиз через `runbooks/release.md` (сокращённый gate только по решению owner, privacy-тесты не пропускаются).
6. **Проверить восстановление**: синтетические проверки на стенде, подтверждение от пилотной группы, отсутствие повторения в диагностике.
7. **Post-mortem** (в течение 5 рабочих дней): причина, почему gate не поймал, изменение тестов/ADR, обновление `docs/coverage/matrix.md`.

## Специальные процедуры

- **Компрометация publisher/signing key**: отозвать ключ, ротация (ADR-015), уведомление, аудит опубликованных версий, повторная публикация с новым ключом.
- **Ложный vendor match**: правило → `stale`/`disable`, фиксация `ruleVersion` и reproduction, добавление negative fixture, review двумя reviewer перед повторным включением. Пользовательская жалоба не создаёт автоматически исключение для домена.
- **Подозрение на утечку**: воспроизвести на канарейках `fixtures/privacy/`; если подтверждено — S1, не публиковать детали до фикса (policy disclosure ниже).

## Диагностический отчёт от пользователя (приватный шаблон)

Только: версии (расширение, правила, схема, Chrome major), коды ошибок датчиков/reducer, capability flags, synthetic fixture для воспроизведения. Без посещённых URL, экспортов с hosts чувствительных сайтов, скриншотов с личными данными.
