# Runbook: rollback

Владелец: Vektor T13, контакт — репозиторий · Последняя репетиция: не проводилась · Основание: ТЗ V §10, ADR-016.

## Факты, которые нельзя забывать

- CWS rollback возвращает предыдущий опубликованный пакет **под новым номером версии** без обычного review; в магазине появляется быстро, на установленных клиентах действует стандартный цикл обновлений. «Исправим всем за минуту» — неверно.
- Local-установки не имеют канала удалённого выключения; Managed — только через существующие политики (`DisabledSensorIds`, `PinnedRulePackVersion`).
- `storage.session` очищается при update/rollback — несохранённые отчёты теряются, UI начинает новую сессию.
- Миграции `storage.local` совместимы назад: старый код обязан пережить новые необязательные поля.

## Процедура

1. Решение owner об откате (ссылка на инцидент `runbooks/incident.md`).
2. Определить целевую версию (последняя известная хорошая, с её dossier).
3. Выполнить CWS rollback либо опубликовать hotfix со старым содержимым и новым номером версии.
4. Зафиксировать: время, версии (с → на), item ID, кто выполнил.
5. Уведомить поддержку/администраторов (шаблон в `runbooks/incident.md`), указать ожидаемое время распространения (цикл обновления Chrome).
6. Проверка: чистый профиль получает откатанную версию; настройки (`storage.local`) сохранились; протокол между новым SW и старыми content scripts обрабатывается (`protocolOk`), UI показывает требование reload.
7. Post-mortem и обновление этого runbook.
